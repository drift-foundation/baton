## Blocking findings

1. **[P1] Reject integration delivery in consent posture.** In
   `v12/python/src/baton_v12/worker_manager/oci.py:1295`, the new family is
   appended independently of the posture restrictions enforced for ordinary
   mounts. `OciAdapter` also lacks the execution-only check already applied to
   source delivery. Probe `consent_posture` calls real `start` with consent and
   no supplementary group: `ps`, then one `run`, then a successful runtime id.
   Its vector carries writable result and target mounts. The initial probe
   with a supplementary group correctly refused on the older group guard;
   removing that unrelated operand reaches this defect. Require execution
   posture at both accepted public consumption surfaces before exposure.

2. **[P1] Bind the integration participant to the runtime being started.**
   `oci.py:2032` compares only attempt id. The final proof at `oci.py:2217`
   revalidates the boundary against its own profile, without comparing the
   request participant. Probe `foreign_participant` starts one engine runtime
   labelled `baton.foreign` using the assignment granted to `baton.merge`.
   Require the full relevant start/delivery identity agreement, including
   participant and selected integration profile/instructions, at use; preserve
   existing identity guards and wrong-attempt no-cleanup behavior. Comparing
   the stored assignment to itself through its original profile is insufficient.

3. **[P1] Check host overlaps against every other mount family and root.**
   `integration/oci_delivery.py:219` and `_no_overlap` check only the three new
   sources; its extra-source operand is never supplied. `oci.py:1295` checks
   container targets only. Probe `workspace_equals_target` starts successfully
   with the exact same host directory RW at `/output` and `/target`. Its final
   fixture uses the ordinary absolute-source contract and workspace mode2770;
   earlier attempts refused on those unrelated fixture errors, preserved in
   prior results. Compare target/namespaces with inputs, workspace, nominated
   source evidence, credentials, launch and exchange sources in both host-path
   containment directions. The fixed container-target enumeration does not
   establish this host separation.

4. **[P1] Make target posture and complete custody revalidation mandatory.**
   `prove_target_posture` at `oci_delivery.py:575` has no production caller.
   Probe `target_mode_755` reaches one run with an incompatible target, unchanged
   mode755. `revalidate_boundary` at line447 compares directory inodes without
   re-adopting the configured group/modes. Probe `late_result_mode` changes the
   result directory to0777 during the duplicate lookup and still reaches run.
   The published reader (`integration/runtime.py:873`) proves bounded regular
   content but no file mode: `writable_published_assignment` composes with the
   assignment mode0666. Enforce the recorded root/namespace/file posture and
   canonical ancestry, configured runtime group and compatible target access
   before launch and again at the final use point. Bind the group rather than
   allowing the adapter and delivery to carry unrelated group choices. Include
   directory traversal permission in the root posture; group-write alone does
   not establish directory access. Refuse without mode repair.

5. **[P1] Deliver recovery and observed-mount enforcement as usable boundaries.**
   The only minting API (`oci_delivery.py:339`) always requires a fresh grant;
   `reconstruct_after_block` cannot reconstruct the previously bound capability
   after a public target block. The old in-memory object can inspect, but a new
   manager lacks a safe public adoption path for inspection/stop after staleness.
   Conversely `_retained_binding` at line308 always publishes on absence:
   `reconstruct_missing_binding` silently recreates a removed companion with
   identical bytes. Separate initial publication from strict read-only recovery;
   recovery must require retained provenance and current trusted filesystem
   identity without regranting writable execution.

   Actual observation is likewise optional today: `start` returns success after
   `ps/run` without inspection, ordinary `observe` reports running with no
   integration binds, and only the uncalled `integration_mounts_agree` reports
   disagreement. Wire a required observation/adoption path so missing, foreign
   or unreadable mounts stay uncertain/held through the consumer's lifecycle;
   preserve the ability to positively stop an exact runtime after grant loss.
   The helper itself misses ancestor shadowing: `observed_ancestor_shadow`
   adds `/run/baton/integration` over the three expected binds and receives
   no disagreement. Check both containment directions and exact multiplicity.
   Prove these cases through the actual adapter and durable runtime/recovery
   path, not only by feeding hand-authored lists to a standalone comparator.

6. **[P2] Freeze the nested capability values.** `IntegrationMountBoundary`
   blocks attribute assignment but stores mutable dictionaries in `assignment`,
   `profile` and the `sources` tuple (`oci_delivery.py:137`). Probe
   `nominal_boundary_is_shallow_frozen` edits all three through public attributes
   and `boundary_mounts` returns the changed access flag. Retain privately owned
   immutable values or defensive public views. This demonstrates the promised
   immutability failure; it does not claim those edits bypass the separate final
   retained-binding comparison in `start`.
