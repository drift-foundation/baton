## P2 — identical continuation retries fail after admission

In `tools/acp-baton-bridge/src/operator_control.mjs`, `handle()` checks
`sameTarget(request, this.record)` before looking for an existing continuation
request ID. `prompt()` replaces that record's bridge/session/turn target with
the newly executing turn. Consequently the exact continuation request which
was accepted moments earlier now fails with `stale held target`, both while
executing and after completion. An operator whose response was lost cannot
retry the original request to retrieve its committed result, contrary to the
README's same-request-ID/same-payload idempotency guarantee.

Independent deterministic reproduction: create a cancelled held turn, accept
request r1 against its recorded target, begin the continuation, and repeat the
identical request. Result: `stale held target`. Finish with an observed r1
acknowledgement and released settlement; the identical retry still fails with
the same error. The retained diagnostic journal is
`/tmp/w195314-review-retry-hfV2Xt/operator.json` (operator convenience only).
No provider, socket, production Work or process was involved in this probe.

Retain the accepted request's original target and exact payload for retry
comparison separately from the current active turn target. An exact duplicate
should return status without dispatching again; a changed target or payload
must still refuse. Preserve stale-cancel protection. Add focused assertions for
identical and conflicting retries during execution and after completion, rather
than only the current queued-request duplicate test. Keep this within the
existing operator-control implementation and test ownership.
