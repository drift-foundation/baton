## Finding

### P1 — the causal validator still accepts impossible state tails and contradictory endings

`worker_manager.exchange._caused` now correctly requires a receipt, requires
an `answered` state for every operation named in the terminal's answered
prefix, and requires the next operation to be `faulted` for a faulted ending.
But after that point it rejects only a remaining state whose value is
`answered`. It accepts `dispatched` or `faulted` events for operations that
cannot have been reached, accepts a `lost` ending beside positive fault
evidence, and accepts `lost` after every commanded operation is already
answered.

`/tmp/repro-w81857-causal-tail.py` demonstrates four accepted contradictions:

```text
later-operation-before-prefix {'state': 'lost', 'states': [{'operation': 'work', 'state': 'dispatched'}], ... 'unreadable': None}
lost-but-fault-observed {'state': 'lost', 'states': [{'operation': 'describe', 'state': 'faulted'}], ... 'unreadable': None}
lost-after-every-operation-answered {'state': 'lost', 'states': [{'operation': 'describe', 'state': 'answered'}, {'operation': 'work', 'state': 'answered'}], ... 'unreadable': None}
state-after-fault {'state': 'faulted', 'states': [{'operation': 'describe', 'state': 'faulted'}, {'operation': 'work', 'state': 'dispatched'}], ... 'unreadable': None}
```

The first sequence reaches `work` before `describe` has completed. The second
says loss despite having positively observed a fault. The third says loss
after the entire sequence is positively answered. The fourth reaches `work`
after the sequence already stopped faulted on `describe`. Each violates the
pinned requirement that missing, conflicting, and reordered worker documents
refuse or project incomplete, and none is a history the reference worker can
publish.

Validate the exact reachable state vector, not only the answered subset:

- an answered terminal has the full answered vector;
- a faulted terminal has exactly its answered prefix, the next operation
  faulted, and no later state;
- a lost terminal may have its answered prefix and at most the next operation
  dispatched, but no faulted state, no later operation, and not a fully
  answered sequence.

Add all four controls above, plus the positive lost controls at each legitimate
crash boundary. The candidate added a correction decision to `FINDING.md`
stating the weaker rule. Append an explicit supersession/clarification there
so that the weak rule and the corrected exact-vector rule do not remain live
beside each other.
