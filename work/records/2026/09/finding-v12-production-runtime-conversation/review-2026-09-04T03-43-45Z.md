## Findings

### P1 — a crash after output freeze permanently suppresses the rest of the ending

`job_manager.projection._observed_state` gives any frozen output precedence
over the exchange and projects the disposition as terminal. `EXCHANGE_OWED`
then asks `conclude` only for `answering`. But
`tools.single_worker._SingleWorker.ending` freezes before intake, retention,
the exact-generation Authority pass, and cleanup. A process death after
`request_freeze` therefore leaves durable frozen output, and every restarted
sweep reports `completed` without ever replaying the remaining owed acts.
A refusal after the Authority pass but before cleanup has the same permanent
leak. This violates the approved restart-safe ending order and can report Work
complete while its assignment remains live and its result has not reached the
review Route.

The new
`tests/job_manager/test_exchange.py::TheEndingIsLevelTriggeredToo::test_a_frozen_output_ends_the_asking`
asserts the unsafe inverse and must be replaced with crash-boundary coverage
that proves each remaining substep is replayed until the whole ending is
settled. The focused reproduction prints:

```text
{'projected_state': 'completed', 'conclude_calls_added': 0, 'spoken': []}
```

### P1 — a crash-created staging file permanently wedges command publication

Both manager `exchange.publish_command` and worker `_publish` use one fixed
`.publishing` name with `O_EXCL`. They clean it only when their own exception
handler is still running. If the process dies after creation and before rename,
the staging file survives; the next incarnation finds no final document and
fails `O_EXCL` on every attempt. A genuinely concurrent second manager hits
the same unhandled `FileExistsError`. The existing test performs two sequential
calls after the final file already exists, so it does not exercise either
required restart or race window.

The reproduction leaves the final command absent and prints:

```text
{'failure': 'FileExistsError', 'final_exists': False, 'staging_survives': True}
```

Publication must converge from stale/competing staging state without adopting
partial bytes, clobbering a conflicting final document, or weakening the
no-follow and durability guarantees. Add manager and worker crash/race cases at
the staging/write/fsync/rename boundaries.

### P1 — worker-controlled secret text crosses the supposedly safe event projection

`exchange._decoded` accepts any bounded string for scalar event members, and
`observation` returns `receipt.accepted_at`, `terminal.fault_code`,
`terminal.disposition`, and `terminal.manifest_digest` without a durable-secret
walk or closed value validation appropriate to each member. Because the
provider shares the event namespace's container identity, it can replace these
files. A byte ceiling is not a credential-safety boundary.

With a registered live bearer in `accepted_at`, the reproduction prints:

```text
{'state': 'working', 'projected_accepted_at': 'worker-event-bearer-9999999999999999999999999999999999999999', 'secret_crossed': True}
```

This contradicts the pinned W61599 boundary and the proposal's own claim that a
registered secret cannot cross a durable event document. Validate canonical
timestamp/digest/vocabulary shapes, enforce ending-dependent nullability, and
apply the durable-secret boundary before any worker value enters the status or
sweep projection. Add positive and negative cases on worker-authored receipt,
state, and terminal files, not only on the manager-authored command.

### P1 — a stopped worker with a receipt and no terminal is still reported running

`projection._observed_state` treats only `execution_runtime == "uncertain"` as
exceptional; every other observation carrying a runtime id is delegated to the
exchange mapping. Consequently a `quiescent` or `destroyed` runtime plus a
receipt and no terminal maps exchange `working` to the stage's active word.
The manager does not derive the pinned incomplete/lost status from the durable
receipt plus exact runtime observation, so a worker that died mid-turn recreates
the original defect's truthful-status failure.

The reproduction prints:

```text
{'runtime': 'quiescent', 'exchange': 'working', 'projected_state': 'running'}
```

Combine the runtime axis with exchange state: only an actually running runtime
with a valid receipt can earn the active word. Quiescent/destroyed/otherwise
incompatible states must project the ruled incomplete/lost/exceptional outcome
without authorizing replay. Add each runtime-axis cross-product needed to keep
silence from being interpreted as progress.

### P1 — the terminal's output-manifest digest is never enforced

The untrusted terminal carries `manifest_digest`, but
`_SingleWorker.ending` never compares it with the independently validated
`request_freeze` result. An `answered` terminal naming `null`, arbitrary text,
or another manifest can therefore drive the entire success ending whenever a
separately valid `output.json` exists. This defeats the digest correlation the
terminal member was added to provide.

Require a canonical SHA-256 digest on an answered terminal and compare it to
the validated frozen manifest before intake, retention, pass, or cleanup.
Faulted/lost endings must carry the exact ruled null shape. Add mismatch,
missing, malformed, and matching controls through the real ending composition.
