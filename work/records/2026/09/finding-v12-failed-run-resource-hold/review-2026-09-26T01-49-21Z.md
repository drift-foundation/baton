## P1 — a second restorer overwrites an admitted successor and returns success

Confirmed on candidate04741974 with the preserved independent reproduction
`review_restore_overlap_20260926.py`. A enters profile restoration after committing
intent/revocation. B, on another real ControlStore handle, adopts that intent,
restores and commits completion. A successor is then granted through grant_writer
and writes a real disposable file. A resumes its profile effect and overwrites
that file. A's completing `store.transact` replays B's committed result, so its
callback's stale-state checks never execute. Both calls return the same success
document while the line is writing for the successor whose bytes were lost.

The profile effect is a labelled deterministic file write standing in for checkout
restoration; real stores, recovery calls and successor admission are exercised.
No Git, engine, provider or deployed store is involved. This independently proves
the handoff's disclosed race, including false success after the damaging effect.

The resumed-intent branch in restore_abandoned_correction treats a revoked writer
and shared recovery intent as permission for any caller to perform the external
act. Neither proves the previous executor stopped. The same abandoned assignment
generation identifies the recovery subject; it does not identify an exclusive
restoration executor. `_restoring` protects only one connection. Exactly one
intent/revocation/completion record is not exactly one external restoration.
The author concurrency test checks record/result uniqueness and misses this.

## Required bounded correction, already selected

Owner270482 explicitly requires: "preserve exclusive restoration ownership
through short durable transactions" and "prevent concurrent restorers and
successor admission during restoration, and keep uncertain execution held".
Therefore the source/PLAN assertion that fixing this race is unauthorized is
superseded by this review's reading of the explicit selection. No new owner
decision is needed merely to implement that requirement. Reuse existing machinery
where sufficient; if necessary helper/path changes are required, record exact
ownership and explain the bounded extension before editing. Do not invent a
global second lease system or move filesystem I/O back under the DB lock.

Separate recovery identity/replay from ownership of its in-flight external act.
Only an admitted executor may restore; a competing/restarted caller must refuse
or remain held until prior execution is positively settled. Completion and
release must match that executor's ownership episode/generation. A post-effect
stale check alone cannot recover overwritten bytes; prevent the overlap before
the profile is entered. Preserve unresolved execution as held, rather than
treating presence of intent or revocation as evidence of executor death.

Retain no-I/O-under-lock and unrelated DB progress checks, normal restoration,
settled retry/replay, stale completion and successor exclusion. Add deterministic
paused-profile contention that measures external crossings and successor bytes,
including a caller already past preliminary reads, and unresolved execution on
reopen. Existing11 tests may remain green while this P1 persists; strengthen
the concurrency evidence rather than loosening the required outcome.

The independent probe records this exact candidate's unsafe schedule and contains
observational assertions about its two crossings and returned success. Preserve
it unchanged; a corrected candidate may refuse earlier. Add an author-owned
