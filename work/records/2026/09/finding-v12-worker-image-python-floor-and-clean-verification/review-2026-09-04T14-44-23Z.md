## Findings

### P1 — predictable verifier directories can be replaced by provider-created symlinks

`claude_agent.py` creates `verification-home` and `verification-ephemera` only after the untrusted provider turn. The provider receives a sibling path beneath the same scratch directory and can therefore precreate either predictable verifier path as a symlink. `_ephemera(..., exist_ok=True)` and its subsequent `chmod` follow that link; verifier `HOME`, `PYTHONPYCACHEPREFIX`, `TMPDIR`, and `XDG_CACHE_HOME` then resolve through attacker-selected storage.

A focused probe precreated both paths as links to the candidate before `_verify()`. Verification returned success, `HOME` resolved to the candidate, and `cache`, `pycache`, and `tmp` were created inside it. Later publication filtering does not satisfy the accepted contract that verification roots and caches stay outside the candidate, and following a provider-controlled link is itself a containment failure.

Provision every predictable provider/verifier root exclusively and without following links before the provider runs, or use already-owned unpredictable roots. Validate each component as an ordinary directory beneath the exact scratch root and refuse foreign links rather than repairing them. Add a regression in which the provider precreates these names as symlinks and prove that verification never follows them or writes into the candidate.

### P1 — candidate snapshot opens special files and can hang after the bounded command

`_candidate_snapshot()` distinguishes only symlinks from everything else; every non-symlink path is opened and hashed. A successful verification command can leave a FIFO in the candidate. The post-command snapshot then blocks indefinitely opening that FIFO, outside the subprocess timeout. A focused probe created a FIFO and replaced `open` with a guard; `_candidate_snapshot()` attempted the guarded FIFO read.

Use `lstat`/no-follow, type-aware traversal. Never open a non-regular entry; an added FIFO, socket, device, or other special type must yield a bounded typed `_Lost`. Avoid the check/open race for regular files by opening no-follow and validating the descriptor type where supported. Add FIFO and socket regressions, including the post-command path.

### P1 — verification cleanup silently tolerates retained child-controlled files

The child knows the ephemera root through `TMPDIR`. `_verified()` ends with `shutil.rmtree(ephemera, ignore_errors=True)`, so an obstructed cleanup silently leaves command output and caches on disk. A focused probe made the owned outer directory non-traversable from the subprocess hook; `_verified()` returned the child status while the ephemera tree still existed. This contradicts the plan's removal guarantee and the diagnostic claim that raw child output is not retained durably.

Do not ignore cleanup failure. Remediate permissions safely within the already-owned root or return/raise a typed operator failure that names the exact residue without exposing child bytes. Add a regression which forces cleanup obstruction and proves there is neither silent success nor unreported residue.

### P1 — the temporary root is not proven outside the retained proposal

Bare `tempfile.mkdtemp()` honors Python's ambient temporary-directory selection. `_verified()` receives `proposal` but does not use it. When the effective temp root is configured beneath the proposal, `verification.out`, `pycache`, `tmp`, and `cache` are all created beneath retained proposal storage, contradicting the comment and accepted boundary that verification ephemera is outside the proposal.

A focused probe set the effective tempfile root to `proposal/ambient-tmp`; the command received all three cache/temp paths beneath that directory. Select an explicitly external owned root or validate the created root's resolved containment before executing. Refuse proposal/candidate descendants. Add the ambient-temp-inside-proposal regression.
