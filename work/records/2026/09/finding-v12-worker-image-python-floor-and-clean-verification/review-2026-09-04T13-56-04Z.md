## Findings

### [P1] The alleged committed-baseline image proof stages the dirty checkout

`v12/python/tests/manager/test_dogfood_image.py:255-260` copies `src`, `tests`,
and `tools` directly from the working tree. That is not the "unchanged
committed v12 baseline" named by the test, FINDING acceptance, PROGRESS, and
gate evidence. The proposal manifest itself records numerous other Works'
dirty paths under those directories at packaging time, and the W85497
candidate's own test/operator bytes are also present. Consequently
`baseline_unchanged: true` proves only that compilation did not change that
dirty staged tree; it does not prove that this image compiles the declared
committed baseline.

Stage the exact committed tree (and bind which commit was staged) for the
baseline probe, then regenerate the exact-image evidence. Keep the writable
mount and pre/post byte comparison: those are the right cache-clean controls.

### [P1] The bounded diagnostic retains unbounded child output in memory

`v12/python/tools/dogfood_operator.py:3148-3151` uses
`stdout=subprocess.PIPE`, so `subprocess.run` accumulates the entire stream in
memory for as long as the 900-second command runs. `_shown` truncates only
AFTER the child exits. A focused reproduction using the proposed `_verified`
returned a 200,000-byte `CompletedProcess.stdout` while displaying 4,203
characters. The existing shouting-command case therefore proves a terminal
display bound, not the memory/resource bound its prose claims.

Drain the combined stream while retaining at most the diagnostic tail, for
example through a private temporary/spooled file owned inside the already
ephemeral root, and add a regression that distinguishes bounded capture from
bounded printing. No child-authored bytes may enter a durable result.

### [P1] The claimed complete candidate snapshot omits entries and hashes files unboundedly

`v12/python/tools/dogfood_operator.py:3181-3200` records only names yielded in
`os.walk(...).files`. It ignores directories and directory symlinks. A direct
reproduction took `{}` before and after adding an empty `__pycache__`, so
`_unchanged_by_verification` accepts that cache entry despite the finding's
complete-entry and candidate-clean requirements. The same helper computes
each digest with `reading.read()`, introducing memory proportional to the
largest candidate file instead of streaming it.

Make the snapshot a bounded, type-aware inventory of every relevant entry and
stream file hashing. Add at least an empty-directory/cache mutation case and a
large-file/chunked-read discriminator; cover link/type changes according to
the retained-candidate contract rather than silently omitting them.

### [P1] Claude child temporary roots are named but not created

`v12/worker/claude_agent.py:405-432` creates only the outer ephemera directory,
then points `PYTHONPYCACHEPREFIX`, `TMPDIR`, and `XDG_CACHE_HOME` at three
absent children. The code's own comment says an absent directory may be
ignored. A direct probe of the proposed environment found all three paths
absent, and Python presented with that `TMPDIR` selected `/tmp`. The current
test checks only that the strings are outside `candidate` and under scratch;
it never checks that the roots exist or that the child actually selects them.

Create the three private roots with the intended modes before starting either
child, and test both their filesystem existence and an actual temporary-file
selection. This preserves the closed environment while making the PLAN's
private-scratch boundary true rather than declarative.

The reviewer reproduction that demonstrated the missing-`TMPDIR` fallback left
the policy-required non-destructive temporary directory
`/tmp/w85497-parent-4s2ajm8x` for operator cleanup.
