## P1 — converting the held descriptor back to a name loses its binding

_HeldCheckout.place returns os.readlink(`/proc/self/fd/N`), then checks that
pathname with stat. Git receives the ordinary pathname and resolves it later.
The probe copies a disposable repository to a distinct foreign object, pauses
at the runner boundary, renames the nominated checkout and substitutes a
symlink to the foreign one. reset changes the foreign tracked scratch before
the later validation refuses; the held original remains dirty. This is the
same failed check-to-effect handoff, despite the descriptor being open.

A research-only runner experiment passes `/proc/<parent-pid>/fd/<held-fd>`
directly as Git's -C operand, retaining the descriptor until commands finish.
Under the same interleaving, it restores the held original and preserves the
distinct foreign tree. The existing argv-only runner works in this deployment:
the child resolves the live parent's descriptor reference, not a readlink
pathname. This is demonstrated feasibility, not an implemented/accepted fix;
revalidate safe metadata/object binding and refusal on unavailable capability.
