## Blocking findings

1. **Preflight still does not enforce mapping.** The new observer and predicate
   remain disconnected; single_worker.worker_preflight contains only a comment
   describing the intended call. Updating existing fake engines to model the
   new boundary is authorized work, not a reason to accept a disabled guard.
   Complete the wiring and deterministic launch-level refusal tests after fixing
   the helper below. HOME/cache, two-direction 0600/0700 checks, remaining
   compatibility decisions and written update/recovery instructions also remain.

2. **Probe initialization deletes resources this call does not own.**
   `observe_runtime_identity` constructs the fixed `.identity-probe` name and
   calls `shutil.rmtree(..., ignore_errors=True)` before creation. Independent
   fixture places previous-attempt evidence there; the helper deletes it and
   succeeds. This also conflicts with simultaneous calls, and the default
   container name uses only PID. Use unique attempt-owned resources under a
   validated/pinned deployment root; never recursively remove a pre-existing
   directory merely because its name matches. Cleanup must target only the
   resource whose creation/identity this invocation owns.

3. **Cached observations are not tied to the actual engine or deployment.**
   `_OBSERVED` keys `_engine(engine)` (just docker/podman), image and UID/GID.
   Independent reproduction switches both EnginePort and deployment directory
   after a successful probe. The second engine is unavailable, but receives zero
   calls and its caller gets the old matching identity, accepted by the predicate.
   Endpoint/context or daemon mapping changes behind the same engine name are
   likewise absent from the key. Failed observations are also cached indefinitely
   under that key, preventing a repaired same-key deployment from retrying.
   Remove reuse or prove/bind the actual engine, deployment, filesystem and
   freshness assumptions. Repeating a tiny preflight probe is preferable to an
   unprovable success cache; caching was not required by the owner.

4. **A symlink can masquerade as ownership evidence.** The helper uses isfile
   and stat, both following symlinks. The independent simulated engine creates
   only a link to an existing manager-owned file outside the probe directory;
   the result is accepted as a matching runtime observation. Require a fresh,
   non-symlink regular result opened relative to the owned directory with
   no-follow identity checks, and preserve the no-hardlink/confinement boundary.
   This simulation demonstrates faulty validation, not an observed real-engine
   attack. Do not infer runtime-created ownership from arbitrary pointed-to data.

5. **A bounded client call is not bounded container lifetime.** The timeout
   simulation records only `run`; no cleanup engine act follows the exception.
   `_engine_run` uses subprocess.run(timeout=...), which terminates/reaps the
   local CLI. The daemon-side helper can outlive that client; `--rm` applies when
   the container exits, not proof that the timeout stopped it. Record and reclaim
   the exact owned helper through the engine boundary with bounded handling;
   preserve/report unresolved cleanup rather than silently claiming removal.
   Ignoring rmtree errors in finally also cannot prove resource cleanup. Actual
   daemon leakage was not executed or observed during this review.
