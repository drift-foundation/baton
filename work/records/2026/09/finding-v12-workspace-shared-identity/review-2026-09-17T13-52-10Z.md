## Required corrections

1. **Removal still uses an ID prefix, not the authenticated full ID.**
   `_reclaim_probe` requests `ps --format '{{.ID}}'` without `--no-trunc`.
   Docker's [formatter implementation](https://raw.githubusercontent.com/docker/cli/master/cli/command/formatter/container.go)
   truncates `ContainerContext.ID()` when truncation is enabled; the
   [CLI reference](https://docs.docker.com/reference/cli/docker/container/ls/)
   documents `--no-trunc` for full IDs. The deterministic prefix-replacement
   scenario authenticates the original nonce, replaces that object with another
   full ID sharing the prefix, and observes removal of the unrelated modeled
   object followed by a successful identity result. This is a simulated identity
   collision/interleaving, not a claim that it occurred on the installed engine.
   Obtain and validate a full immutable object ID, authenticate that object, and
   remove only that exact ID. Existing `list_vector` already uses `--no-trunc`.
   Cover full-ID retention and replacement refusal; a fixture accepting arbitrary
   short IDs does not establish the stated immutable-identity guarantee.
2. **An ownership-read exception bypasses engine settlement.**
   `observe_runtime_identity` calls `_probe_owner` before `_reclaim_probe`, while
   its `finally` only removes the local directory. `_probe_owner` can propagate
   an `os.fstat` error. Injecting an ownership-read `OSError` after modeled run
   success yields only a `run` call: no listing, inspection or removal, and no
   unresolved helper diagnostic. Guarantee engine settlement after an attempted
   run even when observation/validation raises. Preserve the primary failure
   and identify any resource whose cleanup cannot be established. Exercise this
   path alongside normal run failure/timeout and cleanup failure cases.

Then finish the already authorized production preflight wiring and fake-engine
