## Findings

### 1. Pre-grant integrity revalidation was removed (blocking)

`workspaces.py:1019`, `prove_line_integrity`, drops the original post-traversal
owner/link-count/mode recheck. Closing each child bounds descriptors, but also
means a previously checked file can acquire an outside hardlink before the walk
finishes and the line is granted. This was rejected by the prior implementation.

Independent deterministic reproduction injects `os.link` when opening the second
sibling, targeting the first visited file. The historical `_provision_line_access`
read from Git HEAD refuses before granting root access; the submitted candidate's
`prove_line_integrity` followed by `establish_line_access` succeeds with link count
2 and root mode 02775. The historical root remains 0700. No production store,
engine or worker was involved. This is a regression within the explicitly retained
race/integrity boundary, not proof of an observed production exploit.

Repair the invariant with bounded descriptors and add an interleaving regression.
Do not reintroduce descriptor retention proportional to entries, and do not count
the present static hardlink fixture as coverage for a link added after first check.
Any reliance on exclusive access must be enforced and demonstrated at the real
publication boundary, rather than asserted in a comment.

### 2. Shared execution identity remains incomplete (blocking)

The author correctly labels the submission partial. `oci.py:181` and
`custody.py:1672` still pin 65532:65532. The new capability only derives current
manager euid and configured workspace group; no compatible engine mapping has
been established or carried through these vectors. Worker-created 0600/0700
entries still defeat manager consumption. Conversely, removing normalization
without changing launch leaves manager-created restrictive contents inaccessible
to the old worker identity. Do not deploy this partial combination.

Finish the existing owner scope: trusted identity across applicable execution
and custody, early incompatible/unknown mapping refusal, consent distinctions,
private writable HOME/cache, and preserved credential, input/review and cross-Job
mount boundaries. Revalidate the older ownership decisions explicitly. Required
compatibility and supported installed-update/recovery instructions are still
missing. Ordinary deterministic verification and test edits need no new approval.

### 3. Operation-count evidence must measure actual operations

The new permission-count test asserts `PERMISSION_ACTS`, a counter manually
incremented by the product beside two calls. It would miss an added chmod/chown
that does not increment that counter. The M3 reversal probe increments the same
counter in its inserted loop rather than actually restoring permission syscalls,
so its kill does not establish that blind spot is covered. Instrument actual
permission calls/traversal boundaries in tests for small and larger unrelated
trees; a production global test counter is not sufficient independent evidence.

### 4. Earlier baseline evidence was overwritten (repair recorded)

The author reran `reproduce-review-194488.py`, whose fixed output path replaced
the previously digest-bound JSON. The candidate rerun is useful evidence, but
cannot occupy the old baseline locator. FINDING records exact old/new digests,
the saved candidate-rerun file, and restoration from recovered original bytes.
Recovered baseline bytes match the original handoff digest exactly. No earlier
review journal was edited. Use fresh output names for subsequent runs.
