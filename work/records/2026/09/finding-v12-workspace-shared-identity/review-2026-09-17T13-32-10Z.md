## Blocking corrections

1. **Removal status is ignored.** In `observe_runtime_identity`, the returned
   document from `port([engine, "rm", "--force", helper], ...)` is discarded.
   An engine command normally reports failure with a nonzero status, not a Python
   exception. Independent simulation returns run=0 and rm=1, retains the modeled
   helper, and still receives a matching identity. The new `removes=False` test
   raises OSError, so it misses this ordinary failure mode. Evaluate command
   outcomes and distinguish exact verified absence from unreachable/unknown or
   failed removal. A normal --rm auto-removal may leave nothing for the explicit
   removal; that requires safe absence handling, not treating every rm error as
   success. Preserve actionable identity/evidence for unresolved resources.

2. **Force removal lacks proof that this invocation owns the container.**
   With the public `name` operand naming an existing unrelated object, simulated
   run returns status 125/name conflict; finally still issues rm --force for that
   name and removes the unrelated modeled object. Name generation lowers
   collision probability but cannot authenticate current ownership. Bind creation
   and cleanup to an invocation-specific proof/object identity, and refuse to
   remove an object that has not been authenticated as this probe. Test collision,
   failed creation and replacement, not only the happy-path name equality.

3. **Directory pin check is separated from destructive use.** `_remove_probe`
   lstat-checks the recorded dev/inode, then calls path-based rmtree, which obtains
   a new object at that pathname. Independent interleaving moves the owned root
   after the pin check, creates a different directory with a sentinel at the
   original name, and lets rmtree continue. It deletes the replacement and returns
   successfully; the original owned directory survives at its moved name. The
   existing test supplies an already-mismatching pin before the function starts
   and misses this interval. Use identity-bound directory operations and preserve
   replacement contents; do not add another unbound pre-check as the fix.

4. **The original acceptance remains unfinished.** Mapping validation is still
   a comment in production preflight. Update fake engines and enable the real
   guard, then complete private HOME/cache, 0600/0700 access both directions,
   credential/custody/input compatibility and written unexecuted update/recovery
   instructions. These are already authorized. No additional review/permission
   is required merely to implement the necessary fixture support.
