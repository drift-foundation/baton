## Remaining acceptance blockers

1. **Mapping refusal is not enforced.** Production search finds only the export
   and definition of `supported_identity_mapping` in workspaces.py. Nothing in
   launch, custody or worker preflight calls it. Current `worker_preflight`
   constructs the static adapter but never obtains a host-side observation.
   Unknown/remapped engines can therefore reach execution despite passing the
   new direct helper tests. Wire the observation into the real preflight/start
   boundary, before affected Job execution effects, with bounded resources and
   cleanup/failure handling. An observation must belong to the selected runtime
   and deployment, not be a caller-supplied pair that merely matches the request.
   Any reuse must be invalidated by relevant engine/identity changes. Test matching,
   mismatched, absent and failed observations through that boundary using a
   deterministic engine substitute, including proof that refusal prevents launch.
2. **Writable private HOME/cache and filesystem acceptance remain absent.**
   Overriding the image UID may leave image-owned home paths unwritable. Finish
   private writable locations without mounting unrelated host homes or widening
   credential/Job access. Verify manager-created and worker-created 0600/0700
   entries in both directions under the selected execution arrangement. Keep
   read-only input/review mounts and unrelated Job/credential isolation tests.
3. **Compatibility and recovery documentation remain absent.** Explicitly
   revalidate the credential mode, custody normalization and input readability
   assumptions. Compatibility may justify retaining them; it is not another
   owner approval gate. Record supported mapping and actionable remedies. In
   particular, the helper's suggestion to run the manager under the observed
   mapped UID is not a universal fix: changing manager euid also changes the
   next requested container UID. Do not promise that remedy without a supported
   mapping rule and a repeated compatibility check. Provide a written update and
   supported recovery procedure preserving the failed Work/attempt, without
   executing it or introducing duplicate submissions.

The owner already authorized these implementation choices and deterministic
verification. Continue the remaining scope; no additional review gate is needed
merely to connect the helper or complete compatible HOME/credential behavior.
