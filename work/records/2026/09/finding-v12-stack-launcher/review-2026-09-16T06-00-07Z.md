## Remaining corrections

### C1 [P1, R2/R4] Keep ownership when visibility becomes unknown during cleanup

stack.py:_stop_admitted (around724–739) and _unwind (around520–534) wait/check
only for LIVE, then clear the record for every other result. UNKNOWN after the
initial admission check therefore becomes apparent completion. A controlled
process-observation fault after signalling reproduced both paths: the actual
owned sleeper remained alive, but both deleted its record; stop returned0 and
printed `stopped: manager`. The probe simulates the visibility transition at
the normal process-inspection boundary and makes no assertion that a real
permission change occurred on this host.

Require positive GONE before clearing/announcing completion. Preserve UNKNOWN
through every wait, post-signal check and unwind; retain its record and report
non-success/unresolved. Add live-to-unknown regression cases for both stop and
failed-start cleanup. The existing initially-unknown tests do not cover this.

### C2 [P1, R1/R3] Unwind already admitted processes on ordinary spawn failures

stack.py:_start_admitted around589 catches only StackRefusal. _spawn can raise
OSError from log opening, Popen or record writing, so a publisher failure after
manager admission bypasses _unwind. The reproduction uses the real _spawn for
an owned manager sleeper, then injects a publisher OSError: the exception
escapes and the manager remains live. Its record survives, so this particular
case is an unresolved half-start, not an unrecorded orphan.

Ensure every failed admission path unwinds already admitted processes while
preserving the original concrete error and any unresolved ownership. Test the
second-process spawn/record failure as well as the existing first-process
record-write failure. Interruption cleanup must not erase unknown ownership.

### C3 [P1, R3] Bind readiness to serving initialization, not observer publication

stack.py:_await_ready around462–501 proves only that both recorded PIDs exist
and the snapshot mtime changed. stage_execution.py:observation_from constructs
StageObservation from held_configuration; it does not perform the Authority
session, worker-preflight and integration initialization performed by factory /
operations_from. Thus a fresh read-only snapshot is not acknowledgement that
the serving factory composed. A manager delayed or stopped before initialization
can coexist with a publisher that reads a valid empty store.

The narrow readiness-boundary check uses owned stand-ins and a controlled
snapshot: with manager process state T (SIGSTOP), _await_ready still succeeds.
This confirms the gate accepts without a serving acknowledgement; it is not
claimed as a full deployed failure or a failed real factory run. The static
observer/serving distinction supplies the missing causal link. A successful
ordinary idle composition does not test this ordering.

Require a positive acknowledgement tied to the current serving process and
configuration after serving initialization; retain observer publication as the
separate observation check. Exercise delayed/failed serving initialization
while the observer can read successfully, and stale acknowledgements across
restart. Pin any necessary small existing-entry-point adapter path in PLAN
before editing, as the accepted scope already requires. No general scheduler
redesign or live qualification is requested.

### C4 [P2, R4] Validate snapshot shape and observation time before runtime reporting

stack.py:runtime_boundary catches top-level JSON errors but traverses jobs,
stages and episodes outside that guard. `{"jobs":[null]}` produces AttributeError
instead of unknown; stop can consequently crash after it has already signalled
processes. It also calls any object with a jobs list observed without validating
the status schema or canonical observation, and dates it only from file mtime.
These are weaker checks than the existing viewer's status-document reader.

Reuse the accepted status shape/time semantics or validate the same boundary
locally before traversal. Malformed/unobserved/stale input must report unknown,
not crash or imply zero active execution. Add nested malformed cases and a
freshly copied document carrying an old observed_at; retain the source timestamp
distinction already documented by JOB-VIEWER.md.
