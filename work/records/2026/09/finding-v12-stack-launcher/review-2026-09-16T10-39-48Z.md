## E1 — documented interpreter override is not an executable (medium)

`v12/justfile:116`, `v12/STACK.md:27`, and environment.py's refusal messages
recommend `just setup PY=/usr/bin/python3.13`. PY is a recipe parameter, not a
named option: a real `just --dry-run setup PY=/usr/bin/python3.13` expands to
`--python "PY=/usr/bin/python3.13"`. `_version_of` tries that literal path and
refuses, including when the interpreter named after the equals sign exists.
An operator whose default Python is too old therefore receives a broken remedy.

Correct the command interface or all examples/refusals consistently. A positional
`just setup /path/to/python3` fits the current recipe. Add a focused invocation
check exercising just argument expansion and the named-interpreter boundary;
searching recipe prose does not establish this behavior. No dependency download
is needed to verify argument forwarding.

and only then writes ownership. A failed first pip install leaves the directory
without a marker. The next `just setup` labels its own partial environment
foreign and refuses, suggesting removal or another path. Running the supplied
pip command manually cannot write the missing marker either, so the four stack
commands continue refusing an otherwise completed environment.

first call creates an interpreter stand-in and returns simulated index failure;

without a marker. This is offline lifecycle evidence, not a real failed download.
The existing failed-install test starts with a stale *marked* environment and
misses this fresh-install path.

interruption, without accepting a genuinely foreign/incompatible environment,
