## Changes requested

### V1 — ambient Git settings can hide ordinary untracked source

Confirmed in tools/build_stamp.py:capture: `status --porcelain` does not force
untracked reporting. A read-only invocation with status.showUntrackedFiles=no
omits the existing untracked tests/tools/test_version.py; adding
--untracked-files=all reports it. The same capture function, with its status read
scoped to that file to isolate this setting from unrelated tracked changes,
returns dirty=false. This is not a claim that the full current checkout is clean;
it proves that the selected ordinary-untracked rule depends on user settings.
A checkout whose only change is untracked source can therefore be stamped clean.

Make the observation explicitly enforce the selected dirty boundary regardless
of this setting, retaining staged/unstaged handling and unknown on failed reads.
Add a deterministic command-boundary regression whose fixture honors untracked
flags/config rather than always returning whatever the assertion expects.

### V2 — generated output participates in the dirty stamp

Confirmed read-only status reports ordinary untracked:
`v12/python/build/out/`, `v12/python/build/work/` and
`v12/python/packaging/build-stamp.json`. The spec writes the stamp under packaging
and capture counts all reported entries. These paths are not ignored in this
checkout. Thus the comments and test assumption that packaging output is ignored
are false, and a subsequent build can say dirty solely because of its prior
outputs/stamp. The current dirty tree does not prove an actual clean-build result.

Keep generated build output and the stamp out of source-dirtiness accounting by
an explicit narrow artifact boundary (ignore exact generated paths or place
artifacts outside source accounting); preserve ordinary untracked product files
and tracked source changes. Do not make all untracked files invisible. Record
any ignore/path changes in the plan and test repeated capture with generated
artifacts present plus a genuine untracked source positive control. The current
ignored-output test supplies empty status and does not test that boundary.

### V3 — published repository-option commands do not match the recipe

Confirmed by `just --dry-run`, no bootstrap/build executed. Expanding STACK.md's
examples with real two positional operands gives:
- `just bootstrap INPUT DEST --no-repositories`: DISTRO becomes
  --no-repositories, EXTRA is empty; the recipe attempts realpath on the flag.
- `just bootstrap INPUT DEST --repository-source /other/checkout`: DISTRO becomes
  --repository-source and EXTRA is /other/checkout. The option never reaches the
  bootstrap parser as documented.

Make the published examples executable through the actual recipe, or document
its exact supported empty-DISTRO/quoted-EXTRA form; preserve the normal two-operand
command. Check the actual wrapper expansion/argv with a stub, not only the Python
parser. EXTRA currently splits with read -a, so do not imply that ordinary shell
quoting inside this string preserves a source path with spaces. Keep source path
resolution consistent with where the operator supplied it. No actual clone is
needed for this verification.
