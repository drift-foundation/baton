# Review — default liveness projection, first implementer round

Date: 2026-09-01T14:24:19Z  
Reviewer: `baton.codex`  
Work: `W61599`  
Disposition: **changes requested; projection slice 5a is not end to end**

The control-store half is coherent and the focused tests are green. Schema 14
keeps the count and manager instant together; the writer accepts a repeated
total without advancing its stored instant, refuses a decrease, and changes no
other attempt column; and the reader distinguishes no such attempt from an
attempt with no projection. The exact implementer selection independently ran
1,083 tests in 5.846 seconds and passed.

Those facts do not establish the operator-facing projection. The deployment
counts the wrong stream, and it invokes a potentially blocking publisher on
the thread whose uninterrupted drain is a transport requirement.

## [P1] The counter never sees the live Claude session stream

`tools/dogfood_operator._Channel` counts the outer `docker exec` process's
stderr (`tools/dogfood_operator.py:3610-3619`). The Claude adapter's actual
provider stream is somewhere else:

- `ClaudeAgent._ran_provider` owns a private pipe for provider stdout and reads
  it inside the container (`v12/worker/claude_agent.py:417-528`);
- provider stderr is explicitly `subprocess.DEVNULL` at lines 515-517; and
- neither `baton_worker.py` nor `dogfood_entry.py` writes progress to stderr.

Consequently, a provider can be producing native session activity while the
new manager projection remains absent. Outer worker diagnostics or a crash can
increase the counter even though they are not native-session progress. This is
the same visibility gap W61599 exists to close, so the first half is a durable
counter API but not the claimed end-to-end liveness projection.

The new tests do not cross this boundary. They run arbitrary Python children
that write directly to stderr, then assert `_Channel` counted those fixture
bytes. No case drives `ClaudeAgent` (or another real adapter) through the
worker entry and proves a native-session observation reaches
`attempt_activity_of` before the turn ends.

Required correction: identify one real provider-safe source of native-session
growth and carry its cumulative count through a closed worker/deployment seam.
For Claude, the current final JSON stdout is not necessarily an incremental
native session, while its private native JSONL was the live source observed in
W52821; the implementation must prove the chosen source changes during a real
turn. Keep all content container-private. Add a production-seam case proving
first growth reaches the manager before provider completion and that unrelated
outer stderr is not mislabeled as native-session growth.

## [P1] A slow observer blocks the required stderr drain

`_Channel._drain` calls `_report` synchronously after each chunk, and `_report`
calls the injected observer on that same pump thread
(`tools/dogfood_operator.py:3610-3619`, 3631-3654). Catching an exception only
helps after the call returns. `_activity_observer` opens and writes SQLite
synchronously, and `ControlStore.open` configures a 5,000 ms busy timeout. A
busy store can therefore stop the pump for five seconds per attempted report,
allow the stderr pipe to fill, and backpressure the worker. A collaborator
that hangs rather than raises can stop it indefinitely. That contradicts the
recorded decision that publication failure is dropped so diagnostics can
never wedge the session.

Independent reproduction used a blocking observer and a child writing
2,000,000 stderr bytes. After 200 ms the child was still running and the pump
had stopped at its first 4,096-byte report:

```text
poll_while_observer_blocked None first_total 4096
ending 0 final_total 2000000 calls 2
```

Releasing the observer allowed the child and drain to finish, directly showing
that observer latency controls transport progress. The existing fault test
raises immediately and therefore cannot catch this class.

Required correction: the byte-drain path may only update bounded in-memory
state. Publish from an independent, bounded/coalescing path whose blocked or
failed store operation cannot stop reads, session completion, or teardown.
Add a deterministic test that holds the publisher blocked while a stream
larger than the pipe capacity is fully drained and the child exits.

## [P2] A zero-byte stream receives a false "latest activity" instant

The approved projection defines `activity_at` as the manager receipt time for
the latest observed **activity**, and the writer says a repeat is not activity.
Nevertheless `_drain` always publishes at EOF, including `_seen == 0`, and the
first `observe_activity(..., bytes_observed=0)` stamps both columns. The added
test explicitly expects a silent worker to publish `[0]`. A future summary can
therefore render a recent `updated` age for a stream that produced no byte,
while the code and ruling describe that instant as latest activity.

Required correction: either leave the projection absent until positive
growth, or record a separate ruled observation instant distinct from latest
activity. Do not use a zero-byte EOF notification to freshen the activity age.
