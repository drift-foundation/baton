## P1 — bootstrap is not constructed by stage_execution.operations_from

The claim that one constructor covers both pooled and bootstrap deployments is

worker_operations call. Both source files are already selected, so correcting

## P1 — a discarded composition cannot remember its unresolved predecessor

The packet repeats the desired rule that a new composition starts no ingestion
worker while an old one remains unresolved, but gives no owner retaining that
fact or admission operation consulting it. StageExecution._closers reports
failures from its own instance; it does not gate another operations_from call.
With only the named fields/hooks, close can time out, a caller can discard the
object, and the next factory can create another worker. This is a reasoned
design interleaving, not an executed product defect.

Specify a retained admission owner shared by both factories across same-process
recomposition, its identity key, bounded retained state and atomic nonblocking
acquire/release rule. Keep an unresolved slot occupied until the old helper is
positively stopped; suppress diagnostics when admission cannot be obtained.
For example, a shared process-lifetime registry can enforce that condition if
its registry lock is never held during filesystem/store I/O, enqueue never waits
for it and entries are not discarded on timed-out close. Clearly delimit true
process exit versus another composition in the same still-running process;
do not claim process-local state excludes an unrelated live manager process.
Choose the concrete mechanism now, rather than leave an acceptance sentence as
its implementation. Reuse the selected blocked-close/recompose test, with two
distinct composition objects and proof that helper count does not grow.
