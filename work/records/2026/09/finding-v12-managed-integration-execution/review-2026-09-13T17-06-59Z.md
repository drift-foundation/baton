## Capacity source findings — correct before claiming conditions1/2 complete

These findings come from the complete preserved module and pending tests. They
are static implementation findings, not runtime reproductions against a schema
that is no longer present. The author14-pass report establishes only those14

**P1 — Admission does not bind an actual claim to the root and member.**
admit_integration_execution (line216) checks only the assignment's outer three
member names and participant equality with the caller-supplied plan. It neither
owns the nested work_ref/generation nor relates them to the planned Work/root
Authority; it never validates the claimed attempt/offer/profile/input through
their owners. The plan participant itself is not checked against the root's
configured integration actor. Registration copies caller job_id/authority_uuid/
work_id without comparing them to the actual allocation's stage/episode binding.
Its stage-kind check uses a string suffix, not the owned stage relation.

The preserved fixture creates a real Job allocation but supplies arbitrary
prepare/apply Work/offer/attempt strings and assignment dictionaries. It performs
no corresponding Authority Work creation or Worker Manager offer/claim. Both
phases even name the same invented Work. These tests do not prove actual child
claim identity or the required parent-apply attempt binding.

Required: enforce the accepted actual Job/stage/episode/Authority/root binding,
configured actor, exact planned Work/offer/attempt/profile/input and actual fixed
claim evidence. Own all boundary values and relations. Register both phases with
the parent's actual apply attempt and the preparation's separate real Work. Use
real temporary owners at the normal fake-provider boundary in tests. Do not
assume a caller dictionary or table existence proves the external owner acted.
If some bindings are enforced by restored schema constraints, include those exact
bytes and demonstrate the constraints; the missing schema prevents that review now.

**P1 — Serial occupancy alone does not enforce phase/admission eligibility.**
Admission checks root.lifecycle=open and absence of another live member, but not
that its allocation is still reserved. An allocation placed in recovery-required
can therefore remain eligible by these checks. It also permits apply as the first
admission and after failed preparation: no check requires a completed successful
preparation, its collected result, or the authorized derived candidate/grant.
SectionA of the accepted design explicitly requires those conditions. Enforce
them atomically with admission and test apply-first, failed/uncollected preparation,
foreign/stale authorization and quarantined root negatives. Planned phases should
not be considered a valid complete orchestration merely because a nonempty list
has no duplicate phase names.

**P1 — Arbitrary text can end a live member and make capacity releasable.**
end_integration_execution (line288) checks only that evidence is nonempty text,
then writes state=ended. The preserved positive release test ends an admitted
member with evidence="no collected report" and releases its root. That is not
the owner-validated fixed-attempt exclusion required by the design. Other tests
use "host verification produced no status" and "collected output and stop proof"
as strings, with no stop/fence owner behind them. Outcome is separated from state
syntactically, but the exclusion decision has no validating owner.

Consume exact owner-validated ending/no-start evidence bound to this member and
preserve uncertainty as recovery-required. A nonempty locator must be resolved
and validated, not accepted because it is text. The module defines the
recovery-required state but exposes no operation to enter/reconcile it. Implement
the accepted journalled recovery/ending behavior within the approved module;
report any genuinely missing additional boundary before editing outside scope.
Reject wrong attempt/assignment/runtime, stop order only, uncollected evidence,
uncertain exclusion, and attempts to turn a cancelled-never-admitted plan into
an ended successful execution. Exact replay and changed-evidence collision must
remain meaningful after those checks.

**P2 — Required release-path and race evidence is absent.**
The test named test_an_admitted_member_refuses_to_release calls scheduler.release
with the INTEGRATION_COMPLETED reason. It does not drive _completed_integration
through the actual completion-observation branch, as the accepted condition2
specifically requires. Neither the release-once test nor the14-case set tests two
competing admissions, admission versus begin-ending, or actual duplicate release.
Add those owner-driven cases, retain the quarantine and ordinary allocation
negatives, and prove the release guard in the restored _move transaction.

The approved design already requires these corrections. They are not new
architecture choices, a wider execution allowance or justification for a generic
protocol redesign. Conditions1/2 are not independently accepted as complete.
