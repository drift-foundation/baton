## Blocking finding

### P1 — a foreign offer winning after `_delegate`'s check is recorded as performed

`job_manager/manager.py::_delegate` proves the binding only when its first
`receipt_of(canonical_id)` read already finds a row. If that read returns
`None`, another Job manager can commit the same derived `offer.issue` identity
for different intent before this manager's `admit` reaches the Worker Manager.
The canonical `issue_offer` then refuses `operation-collision`; `_delegate`
catches the refusal, reads the now-present foreign row, sets `performed = True`,
and calls `_record` without proving that row. The local Job store therefore
records another store's offer as its own `performed` act and the sweep reports
success for an act it did not perform.

This is the remaining half of the same fail-open identity boundary. The new
tests cover a foreign row present before the sweep and a foreign row present
before `_delegate`'s first read, but none installs it between that read and the
canonical call.

I reproduced the exact boundary with the candidate package and a deterministic
operations seam: the initial reads returned absence; `admit` installed a
well-formed `offer.issue` record carrying another `input_digest` and raised
`refused/operation-collision`. `sweep` returned:

    {"act": "admit", "outcome": "performed",
     "operation_id": "offer.issue:offer:job-a/implementation"}

and `receipt_rows` contained that operation with `state: "performed"`. No
exception escaped and the foreign act was durably adopted under the wrong
provenance.

Correction acceptance:

- Every non-null canonical record obtained by `_delegate`, including the row
  read after a delegated call or refusal, is proved against the persisted
  Job/stage intent before `_record` can write it or the sweep can report it.
- A foreign winner in the read/call window raises
  `refused/operation-collision`; it creates no Job-store receipt and is never
  reported as `performed`, `adopted`, or `refused` for this Job.
- Add a deterministic race regression at this boundary, while retaining the
  sequential collision, status refusal, and genuine restart-adoption cases.
