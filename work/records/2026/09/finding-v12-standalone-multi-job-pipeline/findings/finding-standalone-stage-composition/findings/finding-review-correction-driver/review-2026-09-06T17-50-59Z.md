## [P0] The semantic owner readers still return unbound immutable fields

`review_of` (`review_cycles.py:177-203`) compares only `attachment_id` and
`checkpoint_id` with the committed attach result. The attach result does not
carry the row's runtime attempt, generation, reviewer worker, participant,
principal, or line; those exist in the committed signature, which the owner
reader never adopts. I rewrote the attachment's foreign-key-valid
`runtime_attempt_id` from `review-attempt-1` to `writer-attempt-1`.
`review_of` returned `writer-attempt-1` without refusal. Because
`review_driver._attached_attempt` trusts that answer, the ending can again
stop and freeze a different runtime.

`verdict_of` (`review_cycles.py:206-249`) claims to prove every member but its
`bound` map covers only nine. It omits the persisted reviewer identity fields,
base/head/tree/path-set account, `review_result` and its digest, and the review
fence and its digest. Rewriting `review_result_digest` to another well-formed
SHA-256 value was accepted and returned. That lets correction scheduling
consume a verdict document whose retained evidence contradicts its committed
act.

At the owner, adopt the committed signature/result and cross-bind every
immutable attachment/verdict member. Parse retained result/fence JSON through
their existing owners and recompute both digests. Add member-by-member or
equivalent corruption tests that specifically include attachment attempt and
verdict retained digests.

`custodian_image_digest` is non-null, while the custody boundary requires
text. It checks profile verbs but not the profile's `name`. More importantly,
neither ending compares that name with the selected development line before
calling `_quiesced`.

I supplied a fully callable profile named `other-profile` to an implementation
ending prepared under `test-profile`. The adapter recorded one stop before

comparison exists on the review ending. A malformed non-null custodian
identity likewise passes `_typed` and reaches the later custody owner after
the stop.

Own both static text identities and compare the profile name with the line
resolved from the owner-bound writer/attachment before the first stop. Add
implementation and review negatives proving malformed identity and valid
wrong-profile inputs make zero stop calls.
