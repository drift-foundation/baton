## [P0] The first correction accepts any verdict identity

`advance_correction` validates only that `verdict_id` is syntactically an
identity (`episodes.py:496-498`). `_corrected_line` proves the line is
`correction-ready` and that the checkpoint is current, but it neither receives
nor reads the verdict (`episodes.py:402-448`). Therefore the first call with
`verdict_id="verdict-somebody-elses"` succeeds and persists that false identity
in the correction result (`episodes.py:509-518,573-579`). The existing test
tries a wrong verdict only after a legitimate correction committed, so it
observes the checkpoint-keyed operation collision without testing initial
authorization (`test_review_driver.py:312-322`).

Add an owner-provided typed verdict read and prove the supplied verdict is the
exact current `changes-requested` verdict before writing. The first-call bogus
case must refuse with both stage episodes untouched.

## [P0] Caller stage documents choose what the transaction advances, and the
allocation proof races the write lock

The function reads `stage_id`, `kind`, `job_id`, and `work_id` repeatedly from
the caller's dictionaries and never re-reads the corresponding Job Store rows
(`episodes.py:469-513`). `_live_episode` then selects rows only by those
caller-provided stage IDs (`episodes.py:372-380`). Mutating a real stage
document's Job/Work/kind fields can make the preflight claim two unrelated
stored stages form one pair, after which the transaction updates those stage
IDs directly.

Separately, `_unheld` checks allocations before `store.transact` acquires its
write transaction (`episodes.py:522-541`). The transaction guards only episode
liveness (`episodes.py:546-567`), so a scheduler reservation committed between
those points survives while both successor episodes open. That violates the
required atomic no-live-allocation precondition.

Own the exact stored stages and repeat both allocation checks inside the same
transaction that ends/opens the pair. Add caller-mutation and injected
reservation-at-cutpoint regressions; both must leave the pair unchanged.

## [P0] Ending selectors are not cross-bound before irreversible work

`end_implementation` performs quiescence, observation, freeze, intake,
retention, and publication for `attempt_id`, then separately freezes the
caller-selected `writer_id` (`review_driver.py:244-302`). It never proves the
writer row's `runtime_attempt_id` and generation identify that attempt. Two
live lines can therefore publish A's output and return B's checkpoint.

`end_review` has the same split: it freezes and retains the selected attempt,
then records a verdict for an independently selected attachment
(`review_driver.py:314-345`). `record_verdict` correctly proves its own
attachment, but nothing says that attachment belongs to the attempt whose
output this driver just processed and reports.

Re-read and bind writer/attachment ownership before `_quiesced`, and add
cross-wire cases proving the adapter is not stopped and no durable ending act
occurs.

## [P1] The composite discovers missing capabilities and malformed stop
answers after calling the adapter, while its documented held branch is absent

Only the publication seam is typed before work (`review_driver.py:97-102`).
`_quiesced` calls `adapter.stop` directly and then calls `.get` on its answer
before `reconcile_runtime` checks `list`/`observe`
(`review_driver.py:105-134`). Later collection, retention, cleanup, and port
capabilities are likewise discovered only after earlier external acts. A
missing method raises raw `AttributeError`; an adapter with `stop` but no
`list` is stopped before refusal.

Also, the `end_review` contract says stale, ambiguous, or unreadable evidence
returns the explicit `held` outcome, but any such refusal from
`record_verdict` currently escapes before the outcome branch
(`review_driver.py:326-364`). Either return a typed held account for those
review-evidence failures or narrow and document the public contract; do not
classify caller-malformed arguments as evidence.
