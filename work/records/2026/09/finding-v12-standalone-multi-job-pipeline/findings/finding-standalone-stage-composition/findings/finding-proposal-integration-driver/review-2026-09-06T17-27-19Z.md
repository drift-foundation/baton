## [P0] Settlement can commit without a replayable release

`execution.complete_integrated` calls `settle_integrated` and
`release_lease` as separate durable acts. `driver._terminal` treats any
integrated entry as fully terminal: it reads the Authority receipt and returns
without examining or ending the lease.

I reproduced the exact crash state by running an integration through its
uncompleted result, committing `settle_integrated`, and then entering the
terminal driver path with an exact receipt. The returned/state/lease tuple was
`integrated / integrated / live`. The API reports success while the target's
one-live-lease exclusion permanently prevents the next writer.

If `release_lease` raises after settlement, the catch that calls
`hold_interrupted` is not a valid recovery either: `block_target` requires the
live lease's entry to be `leased`, while this one is already `integrated`.

Make the terminal path resume this tail. After reading the exact existing
receipt, an integrated entry with its exact live lease may reconstruct the
assignment and replay the stored settlement into `complete_integrated`; that
replays settlement and performs release. An already released lease remains a
read-only terminal replay. Neither path may call the Authority integration act
or runtime port.

The regression must inject the cutpoint between settlement and release, enter
through restart, assert zero Authority-integration/runtime calls, assert the
exact receipt read, observe the lease released, and prove the next queued
entry can receive its grant. Keep absent/mismatched lease or receipt states
fail-closed.
