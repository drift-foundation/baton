## [P1] Reconcile-before-record still loses the preparation ending

`worker_manager/attempts.py:1493-1499` calls `_named_before_recording` before
`_record_preparation_failure`, and `_named_before_recording` calls
`reconcile_runtime` at line 1513. A successful reconciliation durably attaches
the runtime and changes the Job projection from `claimed` to `running` before
the preparation-failure row exists. `job_manager/manager.py:180-184` invokes
the launch capability only for `claimed` stages. A process death in this
interval therefore removes the very level-triggered obligation that was meant
to close the interval: the next manager observes `running`, never re-enters the
composition, and never writes the exceptional ending.

This is the residual window reported in `PROGRESS.md`, but it is not an
acceptable loss direction for this Work. In the post-start missing or
contradictory launch cases, the deployment already proved that it could not
carry the stage further. Projecting that stage as an ordinary running success
after restart contradicts the pinned exceptional, non-retried failure rule and
the restart acceptance boundary.

The new regression at `tests/tools/test_single_worker.py:1057-1099` does not
exercise this interval. Its injected `claimed` checkpoint is raised in
`single_worker.start` before `record_attempt`, activation, `_prepared`, runtime
identification, and the preparation-record write. It proves recovery from an
earlier crash, not from the new gap between the two durable acts.

A focused probe interrupted `_record_preparation_failure` after successful
runtime reconciliation on the post-start missing-launch path. The next tick
made no engine call and reported no launch result:

```text
after_crash_state: running
after_later_tick_state: running
runtime_id: runtime-single-1
preparation_failure: null
launch_root_exists: false
later_tick_started: []
later_engine_calls: 0
engine_starts: 1
```

Make identification plus the preparation ending crash-resumable without an
intermediate durable projection that removes the work from the owed set. An
atomic owner commit after external identification, or an explicit durable
pending obligation that remains level-triggered until both facts are recorded,
would satisfy the boundary; merely changing the order between the same two
independent durable acts cannot. Add a regression that interrupts exactly
after reconciliation and before the ending write, then proves a later process
converges to `exceptional` with the runtime named, one start, no replacement
launch bytes, and no bearer reread.
