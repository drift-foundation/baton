## P1 — a claimed stage becomes exceptional on its next restart

`worker_manager.events.TERMINAL_OFFER_STATES` correctly includes `claimed`
because the offer is terminal. `job_manager.manager.apply_offer_state`,
however, uses that whole set as the set of states that end the STAGE episode.
It records `claimed` as `episodes.ended_state`. `projection._observed_state`
then sees no live episode, classifies every non-replaceable ending as
`exceptional`, clears the current offer/attempt identities, and no longer
observes the continuing attempt's runtime or output.

The retained real-manager reproduction
`/tmp/w73629-claimed-restart-repro.py` performs issue, accept, first restart and
claim, then a second restart. It reports:

```text
before: {'state': 'claimed', 'episode': 1,
         'offer_id': 'offer:job-a/implementation',
         'attempt_id': 'attempt:job-a/implementation'}
after:  {'state': 'exceptional', 'episode': None,
         'offer_id': None, 'attempt_id': None}
history: [(1, 'claimed')]
```

The new accepted-offer test stops immediately after the first restart performs
the claim, so it misses the next attachment that applies canonical `claimed`.
Distinguish terminal offer settlement from the end of a stage execution.
Preserve the current episode through claim, or create an explicit continuation
model before ending it. Add a real two-restart regression that proves the same
current offer/attempt and claimed, running, or completed evidence survives and
still controls dependent-stage eligibility.

## P2 — the read-only attachment path is unreachable

`tools/job_manager.py` adds `_ReadOnly.attach` and `_ReadOnly.drain` and states
that a status run drains regenerated assertions without recording anything.
`_status` calls `status` directly, while `status` calls only the canonical
observation reads; neither invokes those new methods. The retained
`/tmp/w73629-status-attach-repro.py` recovers the Worker Manager without a Job
Manager sweep and then reads status with the control store. Canonical offer
state is `abandoned-after-restart`, but the result remains `offered` and the
episode ending remains null.

Pin which contract is intended. If read-only status is a consumer attachment,
implement a truthful non-mutating overlay and regress it. If only the serving
reconciler attaches, remove the unreachable methods and claims and narrow the
durable wording so an operator is not told status consumed a fact it ignored.
