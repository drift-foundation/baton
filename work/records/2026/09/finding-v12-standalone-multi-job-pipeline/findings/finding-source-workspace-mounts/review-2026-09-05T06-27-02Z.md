## Findings

### [P1] Concurrent first pins overwrite the durable custody identity

`pin_boundary_identity` reads through `boundary_identity_of` at
`v12/python/src/baton_v12/worker_manager/attempts.py:547`, decides absence in
Python, and executes an unconditional `UPDATE` at line 560. `ControlStore`
opens SQLite with `isolation_level=None` at
`v12/python/src/baton_v12/worker_manager/store.py:261`, so the read and update
are separate autocommit transactions. There is no conditional predicate,
savepoint, or post-write comparison tying the decision to the write.

An independent deterministic probe used two real `ControlStore` connections
and synchronized them immediately after both absence reads. Both calls
returned success for different identities, no call refused, and the last
writer silently replaced the first pin:

```text
evidence /tmp/w71917-pin-race-tf8rtvks
answers [((1, 11), (2, 22)), ((3, 33), (4, 44))]
failures []
stored ((3, 33), (4, 44))
```

This is not merely a stale return. If two incarnations compose on opposite
sides of a directory replacement before either pin commits, the replacement
identity can overwrite the original identity and then satisfy the restart
gate. The operation's documented write-once property is therefore false at
the exact concurrency boundary where durable evidence matters.

Make the first write a compare-and-set over all four nullable columns and
decide exact replay versus collision against the row in the same savepoint or
transaction. Add a two-connection regression that forces both callers through
the absence observation before either can complete; exactly one differing pin
must succeed, the other must refuse, and the stored value must equal the
successful answer. Preserve exact-repeat idempotence.

### [P2] The schema history names version 15 but the constant is version 16

`schema.py:86-96` explains the source pair as schema 15 and then sets
`SCHEMA_VERSION = 16`. The new workspace pair is documented beside the
columns, but the version history never says what 16 adds. Add the schema-16
workspace-identity entry so a refused old store can be related to the actual
cutover rather than to the previous source-only schema.
