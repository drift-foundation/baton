## Findings

### [P0] The worker never executes the new source profile or uses the disk workspace

`tools/single_worker.py:300` validates and stores `given["source_profile"]`,
but no production caller imports or invokes
`baton_v12.source_profiles.checkout_plan`; the only production matches for
that package are its own exports and definitions. There is likewise no
runtime field carrying the Git declared base into the worker. The worker
image is unchanged and `v12/worker/Dockerfile.claude:94-95` copies only the
existing worker and agent modules, not `baton_v12.source_profiles`.

The actually shipped execution remains
`v12/worker/claude_agent.py:335-338`: create scratch, choose a candidate under
that scratch, and `_copy_tree(/input/source, candidate)`. That scratch remains
the 64 MiB `/tmp` boundary. The new profile module produces plans but no
component executes those plans. Consequently the central acceptance path —
copy-safe Git checkout in the persistent workspace, exact-base verification,
and a real operation beyond the tmpfs ceiling — is absent.

This is observable in the candidate's existing composed-root regression:
`TheCertifiedWorkerReachesTheDeliveredTask.test_a_work_request_over_the_composed_root_reaches_the_provider`
ends `faulted` with `TaskRefusal`, while the same test passes on the baseline.
The candidate now gives the fake engine an empty source mountpoint, but neither
the fake nor the worker performs the promised profile checkout. Correct the
production connection and make the composition test exercise the real
read-only-source-to-workspace transition.

### [P0] Cleanup can traverse and delete a same-filesystem bind mount

`src/baton_v12/worker_manager/workspaces.py:2072-2078` treats a descendant as
a mount boundary only when its `st_dev` differs from the workspace root.
Linux bind mounts preserve the bound directory's device number. A source or
foreign directory bind-mounted from the same disk can therefore pass this
test; the subsequent bottom-up walk can unlink its contents. That contradicts
the finding's explicit requirement that cleanup never remove foreign,
symlinked, or replaced material and creates a source/data-loss path.

Do not infer mount identity from `st_dev`. Cleanup needs an actual mount-ID or
mount-table boundary, or a construction that never recursively walks a mount
target. Add a same-filesystem bind-mount regression at the authorized boundary
where the required namespace capability is available.

### [P1] The Git plan verifies that the base exists, not that it is checked out

`src/baton_v12/source_profiles/checkout.py:123-140` composes `git clone
--no-hardlinks --no-local <source> <checkout>` followed only by `git -C
<checkout> rev-parse --verify <declared>^{commit}`. Clone checks out the
source's current HEAD. `rev-parse` merely proves that the declared commit is
present. If source HEAD is newer or on a different branch while still
containing the declared commit, both commands succeed and the worker edits the
wrong revision. `checkout_plan` adds no checkout/reset/detach step after those
two operations (`checkout.py:193-194`).

Make the worktree itself equal the resolved declared commit and verify its
active HEAD/worktree state before authority opens. Add a repository fixture
whose source HEAD differs from an existing declared base; the current argv
shape test cannot detect this defect.

### [P1] Restart re-nominates a replaced source instead of rejecting it

`src/baton_v12/worker_manager/source_boundary.py:612-622` explicitly says that
the pinned inode is recomposed from current configuration after process
restart. The restart tests nominate the same unchanged directory in both
incarnations, so they do not exercise replacement between adoption and
recovery. If the nominated path is replaced while the manager is down, the
new process mints a boundary for the replacement and accepts it. In addition,
the nomination descriptor is closed before the engine later resolves the
path, leaving a same-incarnation substitution window.

Persist and recover enough manager-owned identity to reject a replaced source
before runtime start, and keep path resolution tied to the validated object
through handoff. Add crash/restart and same-incarnation replacement races that
actually substitute the nominated directory.

### [P1] Workspace quota is declared but not enforced against worker writes

`WorkspaceQuota` validates numeric ranges. During adoption,
`source_boundary.py:690-702` only checks that the backing filesystem currently
has at least `quota.max_bytes` available; `max_entries` is not applied to the
mounted workspace at all. OCI then supplies an ordinary writable bind mount.
The byte/entry ceiling code in `workspaces.py:826-979` governs copied retained
manifests, not the worker's live workspace writes. A worker can therefore
exceed both advertised limits.

Either enforce the live disk quota/entry boundary or stop describing these
values as a quota/ceiling and record the intentionally weaker capacity-only
contract. The current finding and deployment text require an explicit bounded
workspace, so the latter would require a superseding decision rather than a
silent documentation change.

### [P1] The candidate breaks an existing faulted-terminal observation test

Candidate setup removes `self._temporary`, but the pre-existing
`AFaultedTerminalWrittenByTheRealWorkerCanBeObserved.test_a_real_observing_status_run_mutates_no_durable_state`
still dereferences `self._temporary.name` at
`tests/tools/test_single_worker.py:2735`. The candidate errors with
`AttributeError`; the baseline passes. Give this test an explicit directory
outside its digested durable root while preserving the W85500 no-mutation
assertion.
