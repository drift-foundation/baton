## Findings

### [P1] The diagnostic-noun witness cannot prove a public caller boundary

`workspaces.mount_table` and `workspaces.mount_points` are exported public
operations with a `what` parameter. The new `STATED_OWNERS` entries say that
this noun is this build's own literal and that no caller can supply it. The
registered witness only walks internal AST call sites and accepts constants,
joined strings, or a forwarded local name. It never calls either public
operation with caller data.

That stated fact is false. A caller can directly invoke either operation with
any `what`. On the documented unreadable-mount-table refusal path,
`mount_table` interpolates the object directly into the message without first
passing it through `contracts.errors.label_of`. An independent discriminating
probe replaced `MOUNTINFO` with a nonexistent path and passed an object whose
`__format__` raises. Both `mount_table` and `mount_points` executed caller
formatting and escaped with `RuntimeError: caller formatting executed` instead
of the closed `ContractRefusal`. `check_disk_backed` already demonstrates the
correct ownership shape by applying `label_of(what)` before use.

Own and bound the public diagnostic operand at its real receiving boundary,
and add behavioral probes that drive arbitrary caller values through both
public operations' refusal path. A source scan of the component's own call
sites cannot establish what an external caller may supply.

### [P1] The OCI stated-owner witness never invokes the entry it names

The new `WITNESSES` row for
`("caller", "oci.py:OciAdapter.__init__", "source_delivery")` names
`test_a_source_delivery_is_owned_where_the_binds_are_composed`. That method
calls `oci.run_vector(..., source_delivered={...})` directly. It never
constructs `OciAdapter`, never supplies its `source_delivery` operand, and
therefore cannot exercise the constructor's exact-type rule or the later
constructor-to-start forwarding it claims to witness.

Add a witness that reaches `OciAdapter.__init__.source_delivery` itself and
distinguishes its owner from `run_vector.source_delivered`. If the intended
claim is delegation to `_source_mount`, the test must also demonstrate that
the constructor-held capability is the value later consumed there; the
current direct `run_vector` call bypasses that path entirely.
