## Findings

### [P0] Bottom-up cleanup still deletes nested material before recognizing its mount root

`worker_manager/workspaces.py:2166-2179` walks with `topdown=False` and checks
whether `current` is a mount only after `os.walk` has recursively visited its
children. The new tests put one file directly at the mocked/real mount root;
that shape is yielded at the mount root before its file is unlinked, so the
tests pass. A mount containing a subdirectory is different: the subdirectory
is yielded first, its files are unlinked, and only afterwards does the walk
reach the mount root and refuse.

Independent probe, with the device number unchanged and `mount_points`
reporting the parent as mounted:

```text
/tmp/w71917-review-cleanup-guil1l7v
ContractRefusal policy denied
victim_exists False
nested_exists True
mount_exists True
```

The refusal therefore arrives after data loss. Detect and prune mount roots
before descent (or use an equivalent descriptor-relative traversal that never
enters them), and add a discriminating mounted tree with at least one nested
directory and file. The existing direct-child tests must remain too.

### [P1] A source boundary is not bound to the assignment roots the OCI adapter mounts

`source_boundary.SourceBoundary` records the workspace and input mountpoint it
was proved against, but `oci._source_mount` at `oci.py:927-992` consumes only
the source half. It never checks the boundary's workspace or mountpoint against
the `assignment_roots`/assignment mounts supplied to `run_vector`.

I composed a genuine boundary against attempt A, then passed it to a start
vector carrying attempt B's genuine allocated roots. Attempt B's workspace was
also the source nominated for A. The vector was accepted and contained:

```text
type=bind,source=.../attempt-b/workspace,target=/output,readonly=false
type=bind,source=.../attempt-b/workspace,target=/input/source,readonly=true
```

Evidence remains at
`/home/sl/src/baton/.w71917-review-crosswire-ypuosnmc`. The same host directory
is writable through `/output`, so the read-only source claim is false. Bind the
typed boundary to the exact allocated roots it proved, refuse a boundary from
another assignment before composing argv, and add a cross-assignment case
where the foreign source aliases the live workspace.

### [P1] The validated source object is still reduced to a re-resolved path before engine start

The dossier and PLAN item 10 already state this accurately. After
`adopt_source_boundary` proves `(device, inode)`, `boundary_mounts` returns
`boundary.source.place` (`source_boundary.py:686-701`), and
`oci._source_mount` calls `canonical_source`, which resolves the pathname
again (`oci.py:956-966`). The engine then resolves that pathname once more.
Replacing the directory after adoption can therefore substitute another
object without any later comparison to the pinned identity.

This is an explicit acceptance property, not optional hardening: what the
engine binds must be the object the manager proved. Re-proving immediately
before vector composition narrows one interval but does not close the
adapter/engine interval.

### [P1] The dogfood sender accepts malformed values for both new task-contract members

`dogfood_operator.held_task` adds `source_profile` and `declared_base` to the
closed member set, but its value checks at `dogfood_operator.py:676-725` still
cover only the prior fields. The worker validates the new profile vocabulary,
base shape, and pairing, so the two ends no longer enforce the same predicate.
For example, the sender accepted and returned unchanged:

```python
dict(TASK, source_profile=7, declared_base=[])
```

That moves a malformed-document refusal from preflight to a failed runtime,
contrary to the existing sender-side contract. Validate the two new fields and
their pairing through the profile owner, and extend the both-ends tests to ask
the actual predicates rather than only comparing member/schema constants.

### [P2] The image test weakens “nothing from the manager is copied” into an incomplete denylist

`test_claude_agent.py:1897-1922` replaces the prior assertion that no COPY
source contains `baton_v12` with checks for only `worker_manager`, `contracts`,
and `authority`, plus a destination-name check. A future COPY of another
manager module such as `attempts.py`, `offers.py`, or `credentials.py` to a
top-level destination would pass while violating the test's stated property.
This is a material weakening, despite `PROGRESS.md` claiming no assertion was
weakened.

Permit the exact `python/src/baton_v12/source_profiles` source and reject every
other source under `baton_v12`, rather than approximating the manager boundary
with a blacklist. The multiline worker-control COPY check should also retain
its prior destination assertion rather than checking only the continuation
line.
