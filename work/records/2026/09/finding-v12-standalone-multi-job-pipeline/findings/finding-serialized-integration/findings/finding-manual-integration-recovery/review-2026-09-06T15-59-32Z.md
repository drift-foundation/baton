## Finding

### [P0] The stated last runtime cutpoint still precedes fallible status reads

The correction makes the second `_runtime()` result authoritative over the
first quiescence witness, but it is not the last pre-mutation observation.
After that read and its state check, `abandon_held_lease()` calls `_status()`.
That function performs fresh `entries_of()` and `lease_of()` coordinator reads,
builds digests and mutates the locator document before `abandon_lease()` is
called. The manager can move to `uncertain` during that work and the obsolete
quiescent snapshot is still used to abandon.

The deterministic reproduction
`/tmp/w101493_final_cutpoint_gap.py` performs the real manager transition from
`quiescent` to `uncertain` during `_status()`'s lease read. The operation then
returns the older state and abandons the lease:

```text
returned runtime state: quiescent
current manager state: uncertain
lease state: abandoned
```

This remains the exact acceptance-boundary failure from the first review: the
explicit recovery action ends the grant after work performed beyond the proof
has allowed that proof to become stale. Cross-store atomicity is neither
expected nor available, but the recorded design requires the positive manager
observation to be the immediate cutpoint, not merely a check followed by an
avoidable status projection.

Correction boundary: complete every fallible delivery, coordinator and answer
validation before the authoritative manager read. After that read, validate
its state and use the same row to finish only inert in-memory answer fields,
then call `abandon_lease()` without another projection or external read in
between. Add the reproduction's interleaving and prove it is observed by the
last manager read and refuses with a live lease. Retain successful exact replay
without adding a fallible post-mutation read.

## Corrected findings

The delivery and returned status are now owned before coordinator mutation, so
an invalid delivery raises while the lease remains live. Successful
abandonment returns a preflighted projection with only `lease_state` advanced,
and an exact replay remains available after the manager advances to
`destroyed`.

Routine status now exposes only the closed runtime hold reasons or the
leaf-owned `integration-held` classification. An arbitrary coordinator block
reason and detail, including credential-shaped content, remain behind the
blocked-account digest and retained evidence location and do not appear in the
serialized status.
