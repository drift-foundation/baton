## Findings

### [P1] Adoption still follows and ignores mode drift on the manager-created integration root

`materialize_delivery` creates `root/integration` at mode `0700`, then creates
the assignment and result namespaces below it. `adopt_delivery` never opens or
proves that parent. Instead it opens the two absolute child paths with
`O_NOFOLLOW`; that flag applies only to each final child component, so an
intermediate `integration` symlink is followed.

A deterministic probe moves the intact `integration` directory aside, places a
symlink at the fixed `integration` name, and observes successful adoption. A
second case changes the integration root from `0700` to `0755` and is also
adopted. Thus an arbitrary correctly shaped tree reached through a replaced
parent can still be reported as the manager's own delivery. This is the root
half of the first review's finding that `isdir` followed “the root and both
namespaces”.

Open and prove the manager-created integration root itself with no-follow and
its exact established mode, then open/prove the child namespaces descriptor-
relative to that root. Add intermediate-root symlink, non-directory and wrong-
mode regressions. Keep the existing child mode/type/group cases.

### [P1] The removed caller-witness schema remains exported and contradicts the manager observation

The correction removes the caller-authored witness document from composition,
but `runtime.__all__` still exports `WITNESS_MEMBERS` and
`prior_runtime_witness`. `WITNESS_MEMBERS` still declares
`attempt_id`, `execution_runtime`, and `evidence`; the manager-derived helper
returns only `attempt_id` and `execution_runtime`. The VCS vocabulary test even
continues to treat that obsolete tuple as a live boundary schema.

The public contract therefore advertises a closed document that no function
returns and whose `evidence` member belongs to the superseded caller claim.
Remove the obsolete schema/export and make the manager read an internal helper,
or define one coherent manager-observation document and test that its exact
members match the returned value. Do not leave the old witness shape as a
public compatibility surface; this candidate is not yet accepted or deployed.

### [P2] Live publication prose still specifies the superseded `rename` step

`publish_assignment`'s docstring still says the five-step mechanism publishes
with `rename` and syncs “the rename”. The corrected implementation and the
newer `_publish_once` documentation correctly require no-clobber `link`.
Likewise the module introduction says there is “no second file transport” while
the owning finding has narrowed that statement to no second transport
*mechanism* and explicitly authorizes this separate delivery.

Update the live code contract to describe the mechanism actually reviewed.
The history and supersession remain in FINDING; contradictory present-tense
instructions should not remain beside the corrected code.
