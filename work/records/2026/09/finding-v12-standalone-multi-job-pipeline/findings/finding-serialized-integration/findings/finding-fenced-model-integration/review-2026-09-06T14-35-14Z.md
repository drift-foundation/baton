## Findings

### [P0] Queued evidence and the Authority target are never revalidated at execution

The parent contract's required execution order starts by re-reading the
immutable eligibility surfaces and proving Authority's current target revision
still equals the proposal base under the live lease. That is necessarily a
second check: admission can be valid when an entry receives its rank and stale
when it eventually reaches the head of the queue.

`integrate_next` calls `grant_lease` and `runtime.compose_assignment`, then
immediately publishes the assignment and invokes `port.run`. Neither this
module nor any function it calls receives an Authority/session or Job source,
calls `admit_candidate`, or reads the entry's `expected_target_revision`,
proposal, candidate, checkpoint or verdict. `compose_assignment` proves only
the current coordinator grant, stored profile kind and prior-runtime state.
Consequently Authority may advance the canonical target or accepted producer
evidence may cease to agree while an entry waits, and this assembly still gives
the stale entry writable access and can settle it integrated.

Correction boundary: under the granted relationship and before `port.run`,
re-resolve the existing entry's complete accepted account from the same
Authority, Worker Manager and Job producers admission used, including the
current canonical target, and cross-bind it to the coordinator entry. Do not
rebuild account members from caller values. Add a deterministic case that
admits against revision A, advances Authority to B before the grant/execution,
and proves the model is never invoked and target bytes remain unchanged.

### [P0] The quiescence witness can predate the runtime that writes the result

`_quiescent` reads the Worker Manager row for `assignment.attempt_id` after the
port returns, but the port contract is only an arbitrary callable `run`; it is
not bound to the manager lifecycle for that attempt. Nothing proves that the
runtime which just wrote the result is the runtime represented by the row.

The positive fixture demonstrates the hole rather than closing it.
`ExecutionCase.integrate` records the attempt as `destroyed` before calling
`execution.integrate_next`; `integrate_next` then invokes `port.run`, whose
fake writes a fresh result, and `_quiescent` accepts the old terminal state.
Thus a writer runs after the observation offered as proof it can no longer
write. The test passes precisely because the injected port is free to act
outside the manager state being trusted.

This violates the format-neutral safety promise that Baton mechanically owns:
settlement may release the target only after the same writer that received its
writable assignment is positively observed stopped. Bind the port invocation
to the current manager attempt's start/observation lifecycle, and drive the
positive case through a legal sequence in which that attempt is non-quiescent
while it runs and becomes quiescent only after its result is published. A
pre-existing `quiescent` or `destroyed` state must not authorize a newly
invoked writer.

### [P1] The clean-import and pre-mutation-refusal tests prove no target behavior

The child acceptance boundary requires one clean model-driven import and an
ordinary preflight refusal that changes no target bytes. The fake model writes
only `result.json`; no case gives it candidate bytes, changes a target path on
success, snapshots target bytes/modes before refusal, or verifies them after
any negative path. `INTEGRATED["imported_paths"]` and its verification member
are prose in the model's untrusted claim. The existing happy path therefore
marks an entry integrated and releases its lease when no candidate byte was
imported at all.

Keep the generic core VCS-neutral, but make the injected test port actually
perform a bounded transformation against a disposable target. Prove success
changes exactly the declared path and verification observes those final bytes;
prove ordinary refusal, stale evidence/fence and malformed output leave every
target byte and mode unchanged. Also cover the promised live-grant change
between model completion and settlement rather than treating a result document
whose fence was fabricated differently as that race.
