## Findings

1. **Cross-binding is required, but digest equality as proposed is wrong.**
   `integration_checkpoint` proves custody eligibility and Authority proves
   policy eligibility. A queue entry must bind and re-resolve both. However,
   W71918's checkpoint digest hashes its checkpoint-evidence envelope, while
   Authority candidate and worker-control proposal-manifest digests name other
   aggregates. The correct invariant compares shared semantic fields—Authority,
   Work/assignment provenance, base/head, expected target, retained object
   transport and reviewed path/scope—and preserves every native digest. It does
   not require unrelated digest values to be equal.

2. **The reported revocation path does not exist in W71918.** A line grants a
   later writer only from `correction-ready`; only `changes-requested` reaches
   that state, and it creates no integration eligibility. `accepted` ends the
   only review, makes the line terminal accepted, and permits neither another
   verdict nor another writer/freeze. The current-checkpoint checks in
   `integration_checkpoint` detect integrity violations, not ordinary
   revocation. W71878 therefore needs no checkpoint-revoked queue state for the
   accepted provider. It does need the already-required typed revalidation
   account: ordinary pre-mutation policy/scope/target failure terminally refuses
   the entry; integrity or ambiguity retains the fenced target for repair.

3. **The target-key warning is valid.** The W71918 line is Authority/Work scoped.
   The queue lock is deployment/profile target scoped. `canonical_target_id`
   must come from trusted target configuration and must never be derived from
   line, Authority, Work, proposal, checkpoint or mutable revision identity.
