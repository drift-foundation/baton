## P1: an uncertain external/local alias is treated as a definite clear

Collection identity uses the same may-origin join as ordinary origin strings.
A branch where a name has no local collection identity contributes no value,
so joining it with a branch where the name aliases landing leaves a singleton
landing identity. `Assignments.visit_Call` then treats that singleton as proof
that clearing the receiver must clear every alias of landing.

With _view reading source, target and writable, the retained fragment is:

```python
def public(adapter, other, condition):
    landing = []
    for mount in getattr(adapter, "mounts", None):
        landing.append(mount)
    alias = landing
    if condition:
        alias = other
    alias.clear()
    _view(landing[0])
```

When condition is true and other is a separate list, clearing other leaves
landing intact. Discovery must preserve adapter.mounts.source/target/writable
for that path. Candidate `_through_helpers` returns an empty set. Reversing the
initial alias and branch assignment fails identically. Thus an unknown/external
mutation erases a known local-list origin without definite alias evidence.

The contrast controls pass: unconditional alias=landing followed by clear emits
no mount members; clearing an unconditional external alias retains landing's
members; choosing between landing and another known local list also retains
them. The issue is specifically loss of the unknown/non-local alternative at
the join, not a request for arbitrary Python alias analysis.

Requested correction: distinguish possible local identity from identity proven
on every reaching path. Preserve an unknown/non-local alternative, or equivalent
list-specific certainty information, so a singleton set of known candidates
does not become a definite-alias proof. A clear can erase another alias's origins
only when the shared identity is definite. Keep this correction local to the
new collection metadata; do not alter accepted origin joins merely to change
this count. Add both retained external/local branch-order witnesses and retain
the definite-clear, two-local-list, reassignment and external-mutation controls.
