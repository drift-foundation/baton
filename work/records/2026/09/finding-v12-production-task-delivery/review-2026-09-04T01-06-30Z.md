## P1 — staging substitution publishes an unproved object

`tools/single_worker.py::_published_task` closes the descriptor that wrote and
proved `task.json.composing`, then makes the final publication from that
mutable pathname. Another creator can unlink and replace the staging name in
that interval. With `follow_symlinks=False`, `os.link` hard-links a replacement
symlink itself at `task.json`; it does not refuse it. The operation then
unlinks the staging name and returns success without comparing the published
object to the proved descriptor.

The durable deterministic probe
`evidence/reproduce_staging_substitution.py` substitutes at the `os.link` seam
and reports:

```text
{'refused': None, 'final_is_symlink': True, 'foreign_bytes_published': True, 'held_bytes_published': False}
```

This preserves the same integrity failure one pathname earlier: production
can freeze and start over task material this composition neither held nor
proved. Keep the final-name decision bound to the descriptor/inode that was
written and proved. A staging-name substitution must be impossible or refuse
before final publication; it must not unlink a foreign replacement as though
that pathname still denoted this operation's inode. The refusal must reach the
existing preparation journal and start no runtime. Add a deterministic
regression at the proved-descriptor/final-publication interval, covering a
linked replacement and exact held-byte identity at the final name.

The correction pass only added authorized focused cases; no existing test
assertion was deleted or weakened.
