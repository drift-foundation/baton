## P1 — final-name collision is overwritten instead of refused

At `tools/single_worker.py::_published_task`, `O_EXCL | O_NOFOLLOW` protects
only `task.json.composing`. The separate initial `lexists(task.json)` check is
followed by `os.replace(staged, task.json)`, so another creator can win that
interval and then have its file silently replaced.

The durable deterministic probe
`evidence/reproduce_publish_collision.py` creates that final name from the
rename seam and reports:

```text
{'refused': None, 'foreign_target_survived': False, 'held_target_replaced_it': True}
```

This violates the approved rule that a task this composition did not write is
refused rather than replaced. Correct the final transition with an atomic
no-clobber operation. On collision, preserve the foreign target, remove only
this operation's staging name, raise a typed refusal that reaches the existing
preparation-failure journal, and do not start a runtime. Add a deterministic
regression in which the final target appears after the first absence check.

## P2 — the recorded negative matrix is incomplete

- The static cases exercise a directory but not a FIFO, leaving the intended
  `O_NONBLOCK` anti-hang boundary unexecuted.
