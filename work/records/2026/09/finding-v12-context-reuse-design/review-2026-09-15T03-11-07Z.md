## Why this is the smallest compatible composition

**Journal rather than migration.** Current ControlStore.open rejects a different
schema version; schema comments preserve the clean-initialization decision.
ControlStore.transact provides BEGIN IMMEDIATE, in-lock replay checking, atomic
result recording and durable refusal semantics. New bounded metadata can use
that existing mechanism without inventing schema19 migration. This is a
justified amendment to the original proposal, not a claim migration already
existed. No schema/store/documents rewrite is necessary merely for context IDs.

**Actual CLI profile rather than a borrowed transport label.** Frozen
agent-session-1.0.schema.json admits acp/codex-app-server profiles. Current
ClaudeAgent._provider uses --print/--output-format json and returns success
without retaining its structured identity. A dedicated CLI use owner is honest
about the executable and preserves the current exchange/attempt/session rules.
The design does not reinterpret a fake certified ACP session as a Claude CLI.
A fresh attempt/exchange/use can restore the same actual conversation UUID;
reviewer identity and private-line grants remain independently proved.

**Custody and delivery.** Immutable generations never mounted writable, private
per-use working copies, descriptor/object identity checks and a typed OCI delivery
fit the existing explicit mount model. The current generic input/workspace root
allowlist remains closed. The credential slot is volatile and excluded; the
positive state-layout allowlist avoids copying unknown HOME/configuration files.
The design correctly disclaims general isolation between same-UID children and
unknown secret detection. Preserve that qualification: a file allowlist is not
proof an arbitrary hostile provider cannot put secret bytes into allowed files.
Private context is deliberately retained; it is excluded from public artifacts,
not prohibited from secure custody as the earlier advisory incorrectly said.

**Ending composition fits current code.** stage_execution's implementation end
calls review_driver.end_implementation, then _finished. The driver already
quiesces, freezes/intakes/retains, publishes while assigned, freezes/fences the
checkpoint and authorizes cleanup. _cleaning_implementation and
_resumed_implementation preserve the fenced-cleanup and completed-cleanup cuts.
Inserting context finalization after the successful driver result and before
_finished keeps the existing ending obligation owed while context publication
is incomplete. No generic driver, scheduler, Authority or cleanup rewrite is
needed for that insertion. A retained receipt alone never proves runtime
exclusion, and a later stop cannot turn an unknown provider turn into success.

**Useful proof rather than labels.** The three scheduler tests cited by the
design do contain the claimed actual correction, fresh attempt and nonzero
engine/reopen evidence. Their bodies also show the stated limits: revised
preparation is not revised import, and absent/scripted AgentSession rows are
not provider counters. C's separate actual provider and engine observations,
positive pre-reopen baselines and independently rejecting duplicate evidence
extend those cases without rebuilding all18 predecessor schedules.

## Concrete selection clarifications — within the proposed paths

1. **Do not let a refused admission occupy the next transition identity.**
   ControlStore can durably record ContractRefusal at an operation ID. Specify
   action/use-qualified operation identities, fixed expected predecessor and
   immutable signed operands. For example, include action, context, use and
   expected revision in the owner-derived identity; never derive a new ID just
   to evade changed-operand collision. Derive the head only from validated
   committed context transitions, reread it inside the transaction, and allow
   at most one committed successor. A rejected competing admission must not
   prevent the incumbent's finalize/hold transition from committing. Exact
   failed requests retain their refusal, while a distinct authorized transition
   remains possible. Add this focused negative to A's already-selected competing
   admission/replay cases. This is a design hazard inferred from the existing
   store contract, not a reproduced new bug or a request for a new store owner.
2. **Make historical finalization independent of fresh admission and lost
   execution roots.** The suggested finalize_context_use API needs explicit
   access to the existing Job/receipt/checkpoint/runtime owner readers (direct
   arguments or a narrowly constructed owner capability). A receipt_body or
   saved ContextDelivery cannot supply those facts by itself. Recover the
   original admitted use and protected per-use root by their committed pins;
   do not call live admit_context_use to finish an already-fenced attempt or
   rebuild a launch after ordinary cleanup removed it. Scope the protected
   root's readable custody/normalization policy before first runtime use;
   after exclusion, inaccessible/replaced state holds instead of silently
   chmodding or relocating it. Crash-before-journal generation publication
   validates/rebuilds only its own deterministic staging operation from its
   excluded, pinned source. The ordinary ending stays owed throughout.
3. **Keep exports and observations bounded.** A's new modules can be imported
   directly as submodules; DESIGN does not select worker_manager/__init__.py
   or generic port/schema additions. Do not repeat W63255's unselected export
   expansion. Invocation witnesses belong to a fresh use and are excluded from
   restorable conversation state. Public metadata carries only declared opaque
   identifiers, bounded statuses and evidence digests; the generation manifest,
   file paths, transcript and credential slot contents stay private. Production
   profile qualification state must be an owner fact, never a caller's healthy
   boolean or an image label.

These clarify the selected mechanism and its acceptance cases; they introduce
no new Work dependencies, test-permission requests, source paths or cumulative
