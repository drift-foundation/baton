## Confirmed source facts and remaining design obligations

attempts.pin_boundary_identity records the observed root device/inode, and
v12/python/tools/single_worker.py:2002 pins it before request_runtime_start at2063.
That supports identification of the same observed directory object. It does not
alone prove every overlapping resource has one conflict domain, or that every
competing attempt consults the same durable token authority. Different nested
roots can have different inodes while sharing writable descendants. Replaced roots
and retained resource generations also need an explicit exclusion argument. Use
canonical resource ownership/overlap exclusion or prove the supported composition
rejects overlap; do not equate a same-object key with complete TOK-1 conformance.
Treat the device/inode selection as an implementation proposal until its connected
scope and evidence establish those properties, not a new accepted specification.

More immediately, the proposed sequence keeps adapter.start unchanged and binds
only from its returned runtime_id. oci.run_vector:1233 composes Docker run --detach,
oci.py:1388 mounts assignment roots with their writable flag, and OciAdapter.start
executes self.run(argv) around2526 BEFORE returning its runtime ID. That starts the
execution with resource mounts already present. A later effects_permitted call
cannot retroactively prevent pre-binding effects. This conflicts with TOK-4 even
if the normal worker waits for input; worker cooperation is not host exclusion.
Implement a genuine host-enforced create/bind/start or equivalently safe execution
boundary, with controlled-engine evidence at the moment effects become possible.
Include lost/delayed launch replies and expiry between reservation and activation.
Existing duplicate-start/reconcile safeguards must remain effective.

Likewise, acquisition ahead of runtime.start in a separate transaction must not
turn preliminary attempt eligibility into the authoritative check. Select a pure
same-store atomic eligibility decision with token reservation and preserve explicit
held/reconciliation state across subsequent journal boundaries. No external reads
or adapter calls under DB transactions. Basic expiry must revoke/stop/confirm/settle;
normal shutdown must positively confirm the exact container before return.

These are implementations of already-selected TOK/DB requirements, not new product
scope or an owner gate. Pin exact paths and choices in FINDING/PLAN before edits.
The next claim includes implementation AND focused verification. Needing tests is
not itself a blocker requiring review before beginning. Previous review accepted
narrow evidence, not repeated voluntary pre-implementation stops; the author's
