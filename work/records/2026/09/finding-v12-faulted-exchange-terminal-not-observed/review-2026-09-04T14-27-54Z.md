## Findings

### P1 — an observation failure can abort the whole sweep before projection

`manager._refresh` contains only `ContractRefusal`. The new deployment member
can propagate other operational failures from the engine runner, while the
manager also assumes without validation that every non-null return has mapping
shape. Consequently one stage's runtime observation can abort the whole sweep
before the first `projection.stage_states` call. That suppresses an independently
readable exchange terminal and prevents unrelated stages from progressing,
contradicting the accepted per-stage containment contract.

Two direct probes against the candidate demonstrate the open boundary:

- configuring one fake refresh with `RuntimeError("engine transport broke")`
  propagates that exception from `sweep()`;
- returning the invalid scalar `"wrong"` propagates `AttributeError` from
  `answer.get(...)`.

Required correction: own and validate the refresh-result contract at its seam.
Only `None` or the closed documented result shape/vocabulary may reach manager
state replacement; malformed output must become a contained typed refusal.
Operational engine-boundary exceptions also need a typed, per-stage uncertain
outcome so they cannot suppress exchange observation or another stage. Do not
blanket-catch arbitrary implementation defects. Add regressions for invalid
shape/vocabulary and a thrown engine-boundary failure, proving that the faulted
exchange is still projected and another live stage still advances.

### P1 — explicit `status --observe` is silently ignored without `--control`

`tools.job_manager._status` returns `Unobserved()` immediately when `--control`
is absent, before considering the explicitly supplied `--observe` operand. An
operator can therefore request deployment observation, receive success, and get
`exchange: null` without any indication that the request was not performed.

Required correction: refuse the invalid operand combination (or otherwise make
the observation request effective under a recorded contract); do not silently
downgrade an explicit observation request. Add the exact CLI regression.

### P1 — the no-durable-mutation acceptance boundary lacks a behavioral proof

The candidate tests capability absence and verifies that observation-only
`refresh_runtime` returns `None`, but they do not compare durable Job/Control
state before and after a real observation-enabled status invocation. The core
accepted distinction from serving operations is that operator observation has
no Authority acts **and no durable mutation**.

Required correction: add an integration-level regression that snapshots the
relevant durable owner rows/journals, invokes real `status --observe`, and proves
the durable state is byte-for-byte or structurally unchanged while the exchange
terminal is returned. Keep the existing surface-capability assertions as a
separate defense.
