## Findings

No findings.

After a successful Teams, Inbox, detail, links or pokes render, `render()` now
retires an unspent timer token only after `_render_bar()` completes the
terminal refresh. It does not decrement the invisible phase cue. Any exception
from the required projection or terminal paint bypasses that retirement and
retains the token for a later successful render. Table, search and awaiting-me
views continue to spend the cycle at their existing successful row boundary.

The new regression drives the complete render path: it arms a three-cycle cue,
completes an unchanged timer render on Teams, returns to Jobs by key and proves
the cue remains at three, then proves the next successful Jobs timer render
spends exactly one cycle. This directly distinguishes a timer render from the
later keyboard repaint that exposed the prior defect.

The original reviewer script `/tmp/w102477_stale_tick_owed.py` calls
`_window()` directly and stops before the newly relevant full-render
completion boundary. It therefore still displays the intermediate owed token;
that output is no longer a reproduction of the corrected contract. The
full-render regression above is the discriminating case.
