## P2 — argument evaluation can erase the current call's result provenance

Within `_origins`, `visit_Assign` visits the complete RHS before calling
`_source` on it. During that pass `_callable_members` reads the current bindings
when origins.evaluating is true. A named expression in an argument can therefore
replace the callable metadata before the enclosing call's result is attributed:

```python
performing = getattr(session, "release_token", None)
answer = performing((performing := other))
return answer["kind"]
```

Python selects the callable before evaluating its arguments. The current call
still invokes release_token. The candidate retains the bare crossing but drops
release_token.kind, whereas replacing the argument with `other` discovers both.
This defeats the approved expression-point provenance boundary; a successful
census can silently omit the consumed member.

Use the callable selected at the function-expression evaluation point for the
current invocation, while retaining the argument's rebinding for subsequent
uses. Add a positive current-result control and a negative subsequent-call
control. Keep ordinary alias overwrites and branch contexts correct; do not
solve it by retaining stale callable metadata globally.

## P2 — deleting an attribute/item is mistaken for deleting every referenced name

The new `visit_Delete` walks every Name below each deletion target and clears
its callable metadata regardless of context. These statements do not rebind
performing:

```python
del other[performing]
# or: del performing.cached
return performing({})["kind"]
```

The candidate reports no crossing and no injected members for either form.
The subscript form is a normal dictionary-key deletion; the attribute form can
apply to a session member implemented as a callable object. Actual
`del performing` correctly removes the binding and remains the negative control.

Clear only names actually rebound/deleted, including true destructuring targets,
and preserve receiver/index names evaluated as loads. Review the new tuple/list
target invalidation for the same recursive-walk mistake. Continue to visit
receiver/index expressions at their correct evaluation points so their own calls
or side effects remain visible. Add both nonbinding-deletion controls alongside
the existing actual-name deletion case; preserve all existing assertions.
