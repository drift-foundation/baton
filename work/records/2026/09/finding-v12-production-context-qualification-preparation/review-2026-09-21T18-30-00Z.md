## Qualification authorization must be concrete before guards change

Sections 1 and 3 name an "explicit one-run owner selection" without specifying
its durable representation, binding, consumption or replay rules. This is the
central missing design detail, not an executable escape from the bootstrap
problem. _context_preflight, provider_context._facts, invocation composition and
context materialization currently all require context_profile_of; relaxing the
OCI refusal alone cannot launch an uncertified candidate profile.

During the already-authorized implementation, pin the smallest coherent path:

- Distinguish an unqualified candidate admitted for the exact qualification run
  from a certified production profile. Never label live execution deterministic.
  Enumerate how every existing profile consumer resolves that candidate while
  retaining its unqualified status.
- Bind the one-run selection to exact candidate/profile configuration, deployment
  or authority/Job, open and correction attempt identities, shared-identity
  posture and execution bounds. Persist consumption/recovery semantics so a
  replay observes the original run and cannot authorize a second pair or another
  Job. Define failure/hold and explicit later certification as separate acts.
- Certification must bind the full qualified configuration: image, adapter,
  runtime/argv/environment policy, state layout/allowlist and bounds, as well as
  CLI/model. A matched model tuple is not transferable evidence for arbitrary
  images or state layouts. Prove both receipts' mode/order/same-conversation,
  generation/checkpoint lineage and prior-runtime exclusion, and the independent
  accepted outcome. Hashing caller-supplied JSON alone is not evidence provenance.
- Exercise the real admission guard with deterministic positive and negative
  cases. A fake engine can establish valid admission before any live run; keep
  missing/foreign/reused selection and mismatched evidence refusals. The proposal's
  claim that the unmocked positive is possible only in the live packet is too
  restrictive for the standing deterministic verification policy.

Pin concrete test filenames rather than "the context/oci suites", and any
additional required product path before editing it. Existing selection permits
bounded implementation; this is not a demand for another approval for each
routine design choice. Preserve live-execution and production-enabling exclusions.
