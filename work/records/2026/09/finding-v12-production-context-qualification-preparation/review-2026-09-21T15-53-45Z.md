## R1 [P2] — feedback FIFO blocks before the promised type refusal

`v12/worker/claude_agent.py:3340`, `_context_feedback`, opens `feedback` with
`O_RDONLY | O_NOFOLLOW` and only then calls fstat to require a regular file.
Opening a FIFO without a writer blocks before fstat. Consequently a substituted
non-regular feedback file hangs instead of reaching the named refusal, byte
limit or prompt/argv digest gate. This happens before `_ran_provider` installs
the provider-turn timeout. A surrounding attempt supervisor may eventually
terminate the attempt; the feedback reader itself is not bounded as claimed.

Independent reproduction: create a 0700 synthetic context root, put a 0600 FIFO
at `feedback`, invoke the actual `_context_feedback({"mode": "restore"})`
in a child. The child prints its entry marker, then remains blocked until the
2-second subprocess timeout kills and waits for it. It never starts a provider.
The final measured timeout was 2.0044122219551355s. The same opening precedes
the open-mode unexpected-feedback check, so that mode also needs the fix.

**Required correction:** add nonblocking open before the existing regular-file
check (as the manager-side report reader and existing bounded worker readers
already do). Preserve no-follow and the byte/digest gates. Add a bounded FIFO
regression proving prompt named refusal and no provider invocation, for restore
and open. Keep this inside claude_agent.py and the selected focused context
tests; do not relax any production guard or invent another transport.

The durable executable reproduction is review-probe-231132.py. Its FIFO test
asserts the current defect and is evidence, not a product regression whose
passing result signifies correctness. The implementer should invert that
expectation in the product regression when fixing the open.
