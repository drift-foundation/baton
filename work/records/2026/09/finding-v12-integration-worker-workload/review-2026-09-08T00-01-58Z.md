## P1 — whole-candidate test authority is still not established

`_authorized_scope` treats the Job's test_scope as the enumeration of tests and
only requires review material when the account already has an existing-test row.
`compose_prompt` then instructs semantic evaluation of “Every row below that
requires authority,” rendering only those rows. An actual existing test outside
the scheduled scope produces no row and no instruction to identify and refuse
the unscheduled change. This is also the residual behavior the author explicitly
records. Removing a filename heuristic did not authorize weakening the whole-path
authority requirement.

`scope_probe.py` derives a bundle changing an existing test assertion outside
`v12/python/tests/job_manager`, observes empty authority rows, takes one provider
turn and reads an integrated result over the changed test. `scope-prompt.txt`
retains the exact instruction gap. This is deliberately derived evidence and the
fixture provider performs imports without semantic evaluation. It is not a claim
that a real model would ignore policy, nor that the producer would originate
this altered evidence. It demonstrates that the joined fixture supplies no
missing semantic proof and confirms the empty-row consumer behavior.

The provider must evaluate the whole candidate: identify every changed existing
test, establish its accepted scheduled scope, and inspect the frozen review's
evaluation before importing. Empty authority rows are not permission. Make this
explicit in the instructions and prove the bounded semantic refusal behavior;
keep producer identity/custody validation in W114085. No keyword classifier or
generic approval is a replacement for that evaluation. The current claim of
completed semantic authority is not accepted.
