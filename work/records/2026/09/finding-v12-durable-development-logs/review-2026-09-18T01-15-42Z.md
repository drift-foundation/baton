## R1 — protect the status sidecar as part of the same attempt boundary

_status uses ordinary open on capture-status.json before any held-directory checks. A symlink to a sibling synthetic status file declaring finished causes a prefix log to be reported as captured. record_capture opens capture-status.json.staging with ordinary truncating open: a staging symlink to a sibling synthetic file overwrites that file. Both are reproduced, using only probe-created files. This is an actual write outside the attempt room, not merely an imprecise comment. Ordinary status opens also permit a FIFO to block the supposedly bounded reader; that consequence is static analysis, not an executed FIFO probe.

Apply the no-follow, descriptor-relative, regular-file and bounded-read rules to metadata as well as streams. Create staging entries exclusively without following preexisting entries, anchor replacement to the held directory, and preserve unrelated files on refusal. Add linked-status, linked-staging and special-status-file regressions. Raw development logs being accepted does not authorize attributing another attempt's status or overwriting its files.

## R2 — atomic replacement does not make a shared status update atomic
