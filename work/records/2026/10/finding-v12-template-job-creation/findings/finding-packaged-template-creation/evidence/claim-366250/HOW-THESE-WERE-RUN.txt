WHAT WAS NOT RUN, AND WHY

  Every install passed --no-repositories. No Job was served, no runtime or
  container was started, no provider, model or credential was reached, and
  no deployed instance was touched: every destination is a disposable root
  outside the checkout, created and discarded by the cases themselves.

  NO GIT MUTATION OF ANY KIND. The only version-control calls anywhere in
  this claim are `rev-parse`, `status`, `log`, `diff` and `archive` -- the
  first two performed by `build_stamp` at packaging time, which its own
  docstring describes as read-only, and the rest by me while reading state.

WHAT STANDS IN, NAMED, AND IT IS ONE THING

  The OPERATOR'S INPUT DOCUMENT for `bootstrap` is composed in the test
  process from `test_bootstrap`'s accepted worker fixtures and written to a
  file. The installer reads JSON and nothing else from it, so composing it
  there is the same act as an operator writing one; v12/STACK.md specifies
  its members. Nothing of the checkout reaches the command any other way:
  every invocation is a subprocess run from `/` under
  `env {HOME: <disposable>, PATH: /usr/bin:/bin}` -- no PYTHONPATH, no
  BATON_V12_*, no virtual environment.

  In particular NOTHING IS PATCHED. `test_connected_creation` must patch
  `bootstrap._identity_of` because its runtime is a stand-in directory; here
  `--distro` names the real bundle and `_identity_of` runs the real command.
