The correction
--------------

`custody` (which is asked twice, the second time holding the destination's
lock) now includes `install_inputs` and `install_inputs_temporary` in the
link/outside loop and refuses either name outright, exactly as it refuses the
justfile and the selector — before any effect.

The write itself no longer goes through `_publish`. It is the justfile's own
pattern: `os.open` with `O_CREAT | O_EXCL | O_NOFOLLOW`, the identity pinned
from `_identity_of_handle` the moment the file exists, the document written
through that handle, and no temporary and no rename anywhere. `install`'s
unwind removes it through `_remove_if_still_ours`, so a file somebody replaced
between the create and the failure is left alone and reported as such.

What the eight new cases assert
-------------------------------

  * a foreign REGULAR document at that name is refused with its bytes intact
    and nothing published;
  * a LINK at that name is refused, the link survives and so do its target's
    bytes;
  * a DANGLING link is refused (lexists, not exists);
  * a link at the TEMPORARY name is refused and not followed;
  * a stale `.tmp` link is inert: the install succeeds, the link and its
    target are untouched, and the creation over that instance still works;
  * a selector failure after the document is written removes ONLY what this
    attempt made, leaves no half install, and a RETRY installs and creates;
  * a document REPLACED during the failure is left alone, with the unwind
    saying it is "no longer the installer input document this attempt made";
  * a successful install owns a regular file at that name, leaves no
    temporary of either spelling, and a second install into the same
    destination is refused rather than replacing it.
