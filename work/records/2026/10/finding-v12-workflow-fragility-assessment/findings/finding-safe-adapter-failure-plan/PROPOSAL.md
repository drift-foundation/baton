## Narrow producer contract

Introduce a worker-owned AdapterDeclarationRefusal type in the shared worker boundary, used only at explicit pre-provider declaration checks. It is not a general TaskRefusal serializer. Construct it from built-in literals and validated role selection, never exception text, class name, repr, a provider record or inferred string matching. The adapter changes the selected shared-role declaration checks to raise it. All other TaskRefusal instances and exceptions retain generic agent behavior.

The exact payload has three members: component=`role-adapter`, code in the table below, role=`implementation` or `review`. No output name, path, free text, adapter name, provider identifier or arbitrary descriptor value travels in this payload. Thus even an unknown output name containing a credential cannot become an identifier in status. Role is selected from the trusted task dispatch; the manager checks it against the current stage role. A provider cannot supply an arbitrary safe-looking identifier through this interface.

| code | Exact producer condition at selected shared-role declaration check |
| --- | --- |
| declaration-set-invalid | outputs is not a nonempty list, or has duplicate names |
| declaration-name-unsupported | a name is outside the adapter's closed supported set |
| role-output-missing | a member of this role's built-in produce set is absent |
| other-role-output-required | a declared output outside this role's produce set is required |

Use existing check order: set shape, duplicates, unsupported names, missing role output, required nonproduced output. Malformed declaration member shapes that fail earlier/general validation keep their existing refusal; do not classify arbitrary KeyError as one of these codes. No provider-failure codes are added. No mapping from the proposed W371072 descriptor is required to emit these four current adapter checks. Future descriptor-specific causes require a separate reviewed version; the sibling's descriptor vocabulary remains symbolic pending approval.

The worker validates the exact payload again, catches this dedicated type before generic Exception, and emits typed information only for operation=work. An invalid payload, unexpected role or use during describe becomes the existing generic agent terminal. Do not invoke arbitrary __str__ or forward exception attributes. Existing WorkerFault codes retain their meanings. Tests must exercise imports used by the actual worker/adapter package so duplicate exception classes cannot silently defeat the catch.

terminal/2 adapter_failure is either null or exactly {component, code, role, operation, operation_id}. The first three fields are the payload above; operation is literal work; operation_id is copied from the commanded work entry, never from the adapter. Non-null is legal only with ending=faulted, fault_code=agent, disposition=null, manifest_digest=null and answered=[describe]. Require receipt, describe=answered, work=faulted and no impossible tail, as today. Non-adapter faults, lost endings and answered endings have adapter_failure=null. These rules do not widen fault_code or disposition. terminal/1 cannot carry the added member. The normalized exchange terminal includes this field only under the new reader contract; /1 maps to missing typed evidence, not to a clean adapter result.

Existing outer session, attempt_id, sequence_id and command_digest still come from the command. Manager recomputes sequence/operation identities using existing functions and compares against its delivery/launch, validates the complete history, then verifies role against the canonical Job stage. Matching a string grammar alone is insufficient. Identity values exposed downstream come from manager-owned expected identities, after equality validation, not arbitrary worker operands. Job/stage/episode/runtime identities remain supplied by the existing owner/projection, not repeated in the adapter payload. A foreign, stale or inconsistent terminal is untrusted, never a typed declaration refusal for this stage.

Retain the existing raw-byte SHA256 command_digest (including exact command file whitespace). Do not replace it with a canonical command digest. For evidence identity, add no field to the terminal: calculate terminal_digest as sha256 of the exact bounded terminal file bytes validated in the same read. Do not reopen a mutable file to compute its digest. JSON readers reject duplicates, trailing values, invalid UTF-8, NaN and Infinity; retain existing outer exchange limits and set the added object to at most 1024 UTF-8 bytes and depth 1. Exact keys, built-in strings only, each at most 512 UTF-8 bytes; allowlists/equality are the safety gate, lengths only a backstop. The terminal file remains subject to existing overall size limits. No digest authenticates a worker; it identifies bytes.

The synthetic terminal example and command bytes in evidence/claim-371189 use exact derived sequence/operation IDs and a real raw-byte command digest. They illustrate a proposed /2 document; they are not a real execution receipt or accepted attempt.

## Existing diagnostic and report composition

ManagerOperations.observe reads the validated exchange once and passes that same immutable observation into failure_cause composition. Extend that composition's API with an optional observation operand; omitted means not observed, preserving existing non-Job callers. Do not independently reread the terminal for diagnostics. Carry the actual status snapshot observed_at into composition as the observation coordinate; the report must never call a clock. All data acquisition remains in existing read-only owners. The runtime read remains independent even if exchange is malformed.

Diagnostic/2 adapter_failure is an object with exactly state and facts. state is one of known, absent, unavailable. known has facts containing exactly component, code, role, operation, operation_id, session, sequence_id, command_digest, terminal_digest, observed_at. Each uses the existing known leaf shape {known:true,value:...,source:...}; sources are fixed literals: worker-exchange.terminal for the first four, worker-exchange.command for operation_id/session/sequence_id/command_digest, worker-exchange.terminal-bytes for terminal_digest, job-status.observed_at for observed_at. observed_at is a validated UTC snapshot instant (existing status instant grammar), not worker occurrence or first durable observation time. The source status may later be stale. There is no invented cause.at and no inference from token expiry or file mtime.

absent has facts=null: no typed adapter refusal in the available /1 history, no terminal, or a valid /2 terminal with null. This means absence of typed evidence, not evidence no refusal occurred. unavailable has facts=null: the exchange was not read, unsupported, unreadable or failed identity/history/role validation. No unknown version or offending value is echoed. Known cessation/start/preparation and cleanup facts remain readable beside either state. Failure of this added projection alone must not collapse the whole existing diagnostic to unavailable.

Report/2 mirrors this closed state/facts object using its existing scalar sanitization, then checks code/component/role/operation allowlists, digest grammars, expected current attempt-derived operation and existing stage/runtime correlation again. Invalid new fields produce unavailable for the added branch without echoing any rejected content; retain valid neighboring diagnostic facts. Report/2 normalizes a /1 diagnostic to absent and preserves all prior fields. Unknown diagnostic version preserves the existing diagnostic-unavailable behavior. Job/version parsing accepts only the explicitly supported /7 and /8 shapes, not every older schema and never /6. A mismatched /7 envelope carrying /2 diagnostics is rejected; a /8 envelope may carry /1 historical diagnostics with adapter_failure=absent. Unknown top-level status schema refuses safely as today. Existing report readers remain strict; they do not silently read /2.

Use the existing report diagnostic locator and operator-supplied retained-output operand, unchanged. Do not publish exchange directories, host paths, provider transcripts or generated shell commands using worker input. The terminal digest identifies the source when it is still retained; it is not a promise the artifact can be recovered. Existing exchange retention owns the evidence lifetime. Cleanup may leave only a saved status snapshot or no typed evidence; the latter is honestly absent/unavailable. This proposal does not promise a new persistent post-cleanup history service.

All cessation answer_of behavior stays /1-equivalent. A known adapter failure can coexist with cessation unknown or positive cessation; it neither orders nor proves a stop, releases a token, allows retry, changes acceptance, fabricates output nor marks the Job successful. Likewise it does not fill the existing cessation unknown with an adapter cause. Stopped-failed settlement belongs to the sibling, with no writer/API changes hidden here.

## Compatibility and deployment boundary — R1 correction, E371367

This section supersedes the original E371189 paragraph delegating host compatibility to W371072. Owner E371253 approved that sibling's capability/1, deployment/3, derivation/1 and resolution/2; none binds a host-reader tuple. Preserve those exact approved shapes. The following separate installation contract and startup guard are **proposed**, requiring owner approval before code or DESIGN changes.

### Source-backed enforcement owners

Observed: tools.instance.manifest hashes the entire runtime folder, including internal resources, and rejects external symlinks. tools.bootstrap.admit uses it and queries the prospective runtime identity before install effects. bootstrap.held closes bootstrap/1 members/schema and prepare calls it before durable composition; main performs admit before prepare. tools.instance.verify checks installed runtime content against its recorded manifest. These owners presently establish bytes/identity, not protocol compatibility. A build stamp or matching source commit cannot substitute for a qualified executable folder.

Observed: worker_manager.launch.launch_document authors launch/1–/4; baton_worker.launched validates that closed version/member vocabulary before dispatch. terminal/1 readers reject /2. New readers can be implemented to read old terminals, but old hosts cannot be taught new qualification rules by supplying a new JSON field. An exploratory tools/install.py locator was absent; bootstrap.py and instance.py are the actual existing installation owners.

Recommend an explicit **fresh installed-instance transition**, not in-place mutation of existing instances. No old store or history is rewritten. The selected package and worker images are qualified together offline, installed through bootstrap/2, and rechecked before serving. Existing instances may continue their legacy pair. Moving selected execution to the new pair requires a later explicit operational selection and cessation/recovery prerequisites; this planning does not authorize it.

### Exact separate qualification document

Propose `baton.v12.exchange-qualification/1`, a detached closed JSON object with exactly:

- `schema`: that literal.
- `host_runtime_digest`: `sha256:` plus the existing instance.manifest folder digest. This names the exact full installed host package, including diagnostic/report readers; it is not the bootstrap launcher source revision.
- `workers`: nonempty list, at most 64 entries, sorted by `(image_digest, adapter_digest, runtime_profile_digest)` with no duplicate tuple. Each entry has exactly those three digest fields and `wire_profile`. Each digest is `sha256:[0-9a-f]{64}` and must equal the installed deployment tuple. Worker IDs, roles and credentials remain owned by existing deployment/3/capability/1; no arbitrary string is added here.
- `evidence_digest`: canonical digest of the independently reviewed qualification evidence document described below. Its bytes are retained as a separate evidence artifact, not copied into every Job.

`wire_profile` is exactly `legacy-file-exchange/1` or `typed-adapter-file-exchange/1`. The profile is a closed built-in mapping, not a reader-version negotiation language. Both profiles name a **new qualified host** publishing diagnostic/2, status/8 and report/2. Legacy workers use unchanged launch/2–/4 and publish terminal/1; typed workers use launch/5 and publish terminal/2. Both host profiles read terminals /1 and /2 for historical reporting but a current execution must match its selected publisher profile. A legacy-only old host is deliberately not eligible for this new qualification document; it continues the existing bootstrap/1 instance path.

Document limit 32768 UTF-8 bytes, maximum depth 4; duplicate keys, unknown members, non-JSON constants, non-built-in scalar values and malformed digest tokens refuse. Canonical identity uses baton_v12.contracts.canonical_bytes/digest over the full object, no embedded self-digest. Case and worker list ordering are exact, not normalized after acceptance.

Qualification evidence: propose `baton.v12.exchange-qualification-evidence/1` with exactly `schema`, `host_runtime_digest`, `workers` (identical ordered worker tuples/profile objects), and `checks`. `checks` is an ordered array of exactly the seven objects below, each with exactly `case`, `result`=`passed`, and `artifact_digest` (canonical SHA256 identifier of its retained measured test evidence). Case order: `matched-typed`, `new-host-legacy-worker`, `old-host-new-input`, `legacy-launch-new-worker`, `unsupported-tuple`, `historical-report`, `no-effect-refusal`. The independently reviewed artifacts must name actual host and image identities, test inputs/outcomes, simulation boundaries and measurements. The evidence document is bounded to 32768 bytes/depth 4 with the same closed parsing. Digests of fixtures or synthetic names do not qualify a real image/package. The seven required cases cover every worker tuple relevant to the case; an aggregate artifact explicitly enumerates covered tuples, including both selected roles. A missing tuple/test is incomplete qualification, even if all seven labels occur.

Qualification is not self-authorization: the owner explicitly selects the canonical qualification digest from independent review for the installation. The installer receives this expected digest separately from document bytes, verifies it before use, checks the bound evidence bytes/digest and exact repeated tuple, and compares actual prospective package/deployment identities. A syntactically valid self-authored `passed` document is insufficient. This is the existing trusted operator/review selection boundary, not a new signature or trust service. No runtime provider test is inferred; deterministic tests use exact selected executables/images and simulated provider boundaries. Any necessary real image preparation/execution needs separately selected authority.

The detached qualification/evidence files live outside the runtime folder. The runtime digest does not include them; they refer to the package, never vice versa. The instance stores their selected digest/content after validation. This avoids a package/evidence hash cycle. Changing any tuple/package requires new evidence, independent review and explicit selection; current-history read compatibility is not execution qualification.

### Closed installation carriers and pre-effect gate

Propose stack-bootstrap/2: the exact existing bootstrap/1 members and semantics, plus mandatory `exchange_qualification` (the complete qualification/1 object) and `exchange_qualification_digest` (the independently selected canonical digest). The separately supplied evidence document is an installer input selected by a proposed `--exchange-qualification-evidence` operand; it is read/validated, not interpreted as executable code. New bootstrap requires these fields for /2 and refuses them in /1. Existing /1 stays the legacy-only path. No per-Job manifest authorship is introduced.

The new check belongs in bootstrap.admit/prepare's shared preflight, before Authority mint/composition, destination writes, repository preparation, token acquisition or engine/provider effects. Inspect the candidate package manifest, verify the selected digest and evidence, compare all configured worker image/adapter/profile tuples, and confirm the selected package itself implements the exact wire profiles through a new pure packaged command `exchange-compatibility`. That command returns only its closed built-in supported profile literals and schema `baton.v12.exchange-reader-support/1`, object exactly `{schema, profiles}` with profiles in the fixed legacy-then-typed order. The command is not qualification: it is a feature-presence check on already digest-bound bytes. An old package has no such command; refusal is the correct outcome. Installer source supporting /2 with an old target package therefore refuses before installation effects. Direct install entrypoints perform the same preflight; a caller cannot bypass it with an unvalidated precomputed structure.

Propose stack-instance/2: retain the exact /1 instance document fields/meaning and add `exchange_qualification` plus `exchange_qualification_digest`, copied from the validated selection. Existing runtime folder digest remains independently checked. instance.verify revalidates selected digest, tuple mapping and runtime hash; the installed stack-command/manager serving entrypoint performs this verification before scheduler, dispatch, token or runtime actions. Source-development serving must explicitly supply the same validated context or refuse to emit launch/5. Read-only historical reporting can operate without a serving context and never turns it into execution authority. The qualification context is passed in memory through existing deployment/launch owners, not persisted as an unversioned addition to approved deployment/3.

The existing stack-bootstrap-record/1 remains unchanged: it records Job bindings, not qualification. On repeat installation the new instance/2 qualification must be compared before old record comparison, and a changed/missing qualification refuses the whole repeat. A legacy record/selector cannot be silently upgraded. Existing stage deployment/3 and capability/1 are not widened; qualification stays in the installed instance and validated in-memory launch context. Launch adoption must compare the entire /5 wrapper and payload exactly, preserving existing retry/context identity checks.

An old installer receives bootstrap/2 and rejects its schema/members using its existing closed checks; it need not understand the new qualification. An old installed launcher receives instance/2 and refuses the unknown schema. Those are source-backed existing fail-closed behaviors to verify against the packaged old binary. Rewriting a /2 document as /1 is not a migration path. However, an operator could still manually give an old /1 host the digest of a new image: no new installer check can retroactively protect that binary. The worker-side guard below closes **provider execution** on that mismatch. It cannot promise that an old engine never starts a container for manually forged/unsupported inputs; such a pre-engine guarantee would require an external admission controller, which is not proposed here.

### Worker guard without trusting old-host checks

Propose worker-launch/5 as a closed wrapper with exactly `schema`, `wire_profile`, `payload`. Schema is `baton.worker-launch/5`; wire_profile is literal `typed-adapter-file-exchange/1`; payload is one complete existing launch/2, /3 or /4 document validated under its own unchanged schema, including context when present. /1 framed launch is excluded. The outer object has no other fields, and nested /5 is forbidden. Apply the existing launch byte bound to the whole document and existing payload identity validation; the wrapper does not add arbitrary metadata. The new manager launch owner authors /5 only after the installed qualification tuple selects the typed profile. New strict worker validation unwraps it before using the existing session/attempt/Job/context fields.

A typed-publisher worker image refuses unwrapped file-exchange launch/2–/4 **before constructing the adapter, accepting commands, publishing a receipt or invoking any provider/tool**. Its legacy framed /1 behavior is outside this selected file-exchange feature and remains unchanged. The typed image must never silently downgrade to terminal/1. The old host can only author unwrapped launch/2–/4, so the new image exits with the existing bounded startup diagnostic and produces no invented correlated terminal. This is distinct from the typed adapter refusal path, which needs a valid launch/receipt. No exception prose or new diagnostic platform is introduced.

For new-host/old-worker, the qualified legacy tuple selects the existing unwrapped launch version, terminal/1 and generic agent failure, while the new host normalizes absent typed evidence. Sending /5 to an old worker is a negative test: its existing unsupported-launch check refuses before adapter dispatch. Thus the profile is pinned by exact worker tuple; it is not guessed by probing a running model or accepting a failed negotiation as progress. A worker receiving forged /5 from an arbitrary program is outside this cooperative package-selection trust boundary; this is compatibility enforcement, not authentication against a malicious host.
