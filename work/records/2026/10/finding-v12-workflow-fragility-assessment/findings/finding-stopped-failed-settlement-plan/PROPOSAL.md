# W371074 — settle a stopped failed execution, retaining its evidence

Proposed by baton.codxpc under E371444 and owner planning selection E370866. This is a proposal for independent review and owner decision, not implementation or operational authority. W370747 joins acceptance; W371076 consumes the accepted design. No retained instance is acted on here.

## Revalidated problem and reuse

**Observed:** W370560 CLEANUP-RESEARCH-370686.md and SETTLEMENT-COMMANDS-370686.md distinguish non-satisfying authority closure, runtime settlement and supervisor stop. W371320 PROCEDURE.md and its independent review-2026-10-28T03-39-14Z.md establish the concrete retained requirement: the review container was positively exited while the assignment remained active, token returned=false, cleanup pending and no independent verdict. Those timestamped observations are not a fresh observation by this Work. Neither its prepared close nor its stop is executed or duplicated here.

**Observed in current source:** single_worker.ending handles answered attempts and excludes faulted/lost exchange. It performs output freeze/intake/retention and authority pass before authorize_cleanup. single_worker.abandon_attempt composes intake.abandon_attempt: durable abandonment intent, exact authority fence and destroy_abandoned, then recordless cleanup. It requires destroy capability and couples authority disposition/removal. It is not the desired retain-and-release command. intake.settle_revoked_resource requires revoked entitlement and positively absent runtime; tokens.revoke accepts only an expired generation. Ordinary reclamation already offers exact-token return/replay but does not supply a supported explicit settlement of an unexpired, stopped failed container while retaining it. Current manager CLI exposes fresh-attempt, creation, status and serving, not this operation. Fresh-attempt is new execution admission and cannot stand in for settlement of the old one.

**Observed normative requirement:** DESIGN TOK-5–7 and TOK-10–12 require exact cessation and settled effects before handoff, but primary-path execution release does not require output acceptance, normalization or destruction. Storage inspection is later consumer work. workspaces.preparation_completed and standing_preparation own completed/open host preparation windows and must be consulted, not a synthetic no-writer assertion. The current absence/destruction/intake coupling is a concrete code/spec gap; do not weaken TOK-7 to match it.

**Observed residual:** W44342 PLAN and review-2026-10-28T00-44-30Z.md preserve unresolved late engine-operation/helper creation, with no generic durable provider selected. Its accepted restart/receipt/exact-stop evidence is useful, but does not establish no future late activation from an unsettled request. W44342 remains parked; W371320 and W370560 retain operational ownership. This proposal neither resolves nor adds a gate on them.

**Proposed:** add one explicit host-manager operation for an already stopped failed file-exchange attempt, with read-only preview/replay and no stop, destroy, normalization, reset, launch, result acceptance or authority mutation. Existing cancellation/expiry controllers remain responsible for making running/uncertain execution stop; this operation refuses or holds rather than becoming a second stop controller.

## Supported command and exact selection

Propose packaged `manager settle-stopped --instance INSTANCE --request REQUEST.json [--check]`. The installed manager resolves its Job/control/Authority/configuration through the existing instance binding/verification owner, not independent path operands. `--check` is read-only: report eligibility and exact expected identities, without intent, fence, runtime change or a promise the later action will succeed. It may make bounded read-only engine observations and reports their times; no engine command is run during this planning Work. It opens observation-only ports. Normal invocation composes the existing deployment's per-attempt adapter and governance through the same owner as serving, never reconstructs private adapter operands in a shell helper.

Request schema `baton.v12.stopped-execution-settlement-request/1`, closed members exactly:

- `schema`, `operation_id`, `instance_digest`, `deployment_digest`;
- `authority_uuid`, `job_id`, `stage_id`, `episode`, `attempt_id`;
- `assignment` exactly `{work_ref, participant, generation}`, where work_ref is the existing exact Authority/Work reference shape;
- `runtime_id`, `start_operation_id`, `token` exactly `{domain, generation, owner, launch}`;
- `failure_evidence_digest`, `reason`.

Identities use their existing owning grammar and maximum bounds (backstop 512 UTF-8 bytes); episode/generations are positive built-in integers, never Boolean. Digests are sha256 plus 64 lowercase hex; instance_digest is the canonical digest of the validated complete instance selector, deployment_digest the canonical installed execution deployment bytes as owned by its reader. operation_id is the existing bounded manager operation identity grammar. reason is the fixed literal `failed-execution-retain-evidence`, not user prose. failure_evidence_digest names a validated faulted exchange history captured by the exchange owner: canonical digest over its exact command/receipt/state/terminal raw-byte digest tuple, ordered by fixed document name. No adapter-text diagnosis is required. Reject unknown fields, duplicate keys, nonfinite numbers, invalid UTF-8 and documents over 16384 bytes/depth 8. No caller-supplied stopped, helpers, timestamps or verdict booleans exist in this request.

Initial selected eligibility is faulted file exchange with a valid exact receipt/history, no successful worker answer for this operation, and fully bound runtime. A valid generic agent fault is sufficient; W371073 typed codes are optional diagnostics and not a prerequisite. Unknown/lost exchange without a durable failure classification, preattachment/start failure, integration execution and already successful answered attempts are outside this first command. Keep their supported recovery paths; do not guess a failure from empty logs. Future cancellation/timeout request support may reuse this owner only when those existing durable owners establish the exact failed/stopped attempt; this first version refuses them as sole failure evidence. Cancellation/expiry racing a faulted eligible attempt is covered below.

The retained W371320 instance has not been checked here for complete primary-preparation/launch provenance or migration eligibility. If those facts cannot be read through the owning APIs, it remains held; no historical proof is backfilled from current configuration. Fresh-attempt continues its independent all-stage/exclusion checks and is neither invoked nor guaranteed eligible by this one release.

A preview emits exact expected operands for operator review, not a receipt. Operator selects one stable operation_id and the retained request. No fresh ID on lost response. A changed operand under the same ID is operation-collision. A different ID cannot create a second settlement for the same attempt/start/token generation: return the existing operation locator or refuse already-selected, rather than repeat fencing/effects. Replacing an episode requires its own recovery authority and new request, never editing an old expectation file.

The acting capability is the existing installed host-manager operational ownership boundary, not impersonation of the worker or approver. Acquire InstanceOwnership.held plus a per-attempt invocation exclusion patterned on the existing fresh-attempt invocation lock, with all stores bound to the same instance. A serving manager holding the cross-process guard causes a separate command to refuse busy; do not kill or bypass it. Same-process calls use counted ownership plus per-attempt exclusion. Future ordinary serving may resume an already selected intent through this same owner, but does not autonomously select settlement on silence. This operation creates no new Authority role or privilege.

## Preconditions and durable sequence

1. **Read/validate without effects.** Own request, package/instance/deployment identity, canonical Job/stage/episode, fixed assignment, token generation/owner/launch/start mapping and exact fault history. Reject a new request whose expected current assignment or episode no longer matches. Confirm primary-path provenance and absence of unresolved admission/engine effects. Perform a bounded fresh exact observation; running, restarting, missing attribution or inspection error yields held, no token fence or outcome yet. Do not interpret missing container output as absence unless the trusted adapter explicitly proves exact absence.
2. **Intent plus execution fence, atomic control transaction.** Through proposed `begin_stopped_settlement`, revalidate the fixed control identities, unreturned token, launch/activation state and expected resource-generation mapping under the same write lock as token acquisition/admission. Persist the immutable request signature/intent and a new exact-generation settlement fence together. All admission, activation, binding, renewal and effects_permitted/_owning paths must reject that fence; settlement return/reconciliation alone may proceed. Existing expired-token revoke semantics remain unchanged. No engine/Authority call or file inspection runs inside this transaction.
3. **Observe after fence.** Read exact runtime again outside transactions using the selected adapter. The first observation admitted the request, but only this post-fence observation may support the outcome. Verify current immutable runtime identity, settled activation and primary confinement facts, plus any explicit surviving-writer/uncertain-operation evidence. Positive quiescent and exact absence qualify; storage inaccessible alone does not defeat container cessation. A running/unknown/foreign outcome holds the fence and reports the precise reason. It does not order stop or destroy. Existing selected cancellation/expiry policy handles necessary termination; retry this same request after its evidence is resolved.
4. **Commit failed-stopped outcome.** In a short owner transaction, CAS the same intent signature, attempt/start/runtime/domain/generation/launch and unchanged activation state. Record the trusted observation's instant, source and cessation digest, authoritative execution outcome failed-stopped, resources-preserved and unresolved result-consumption status. Evidence says how cessation was established, not that a directory was read or normalized. A known outstanding helper or engine effect refuses this cut. On primary-path proof, no automatically launched helper or filesystem normalization receipt is required.
5. **Return this token.** Use Governance.release with exact execution and start operation, typed cessation from the committed outcome and manager-settlement mode. Existing tokens.returned checks domain/generation/owner/launch/container, Boolean stopped and unresolved activation under its lock. Extend its internal fence handling to allow only this matching settlement return. It must recheck current token state at commit; old evidence cannot return a newly bound/activated generation. No hand-built cessation from CLI and no default helpers=[] without the primary confinement proof. A primary-path zero-other-writer fact is derived from owned lifecycle provenance, not absence of a callback. Legacy uncertain helper paths remain held.
6. **Receipt.** After durable return, commit/finalize the command receipt. If response/receipt write fails after return, replay reads the generation's existing returned record and completes this receipt without engine call, new observation or another return. Failed-stopped recorded before token return means release-pending, not released; it must be surfaced as such and resumed. The command never triggers a successor attempt or repairs the workspace.

Authority and control stores are separate owners: this is **not** an atomic Authority assignment CAS or a new distributed transaction. The first request validates current assignment via the Authority read port and durably binds the original fixed assignment in control. After intent exists, an Authority close/pass/cancel racing or following it does not invalidate safe settlement of that exact old execution; replay is bound to its original identity and cannot operate on the new assignment. Record the observed assignment provenance, never claim it remained active throughout. A stale assignment supplied on a new request refuses; a later Authority transition does not strand a previously committed settlement intent. No Authority mutation needs rollback because this operation performs none. Manager ownership excludes concurrent local episode selection; external Authority transitions remain separately observable.

The execution fence is a new owner API/record, not a call to tokens.revoke before expiry and not a fake authority cancellation. An expired/revoked token can use the same exact settlement if its failure and cessation qualify; already-returned generation resumes/returns its own prior facts, not another token. Renewal, activation, cancellation and settlement race at the token owner: whichever fence/admission commits first determines eligibility. An already admitted unsettled activation always holds, even if the container currently appears exited or absent. This retains W44342's late-effect boundary.

## Closed record and receipt proposals

Use the existing manager store journal, signatures, replay lookup and atomic transaction owners. Propose these versioned documents plus the retained observation wrapper below, no parallel database:

| Document | Exact members and semantics |
| --- | --- |
| `baton.v12.stopped-execution-settlement-intent/1` | schema, request (full request/1), request_digest, selected_at (manager UTC), fence_operation_id. Committed with fence; immutable |
| `baton.v12.stopped-execution-settlement-fence/1` | schema, operation_id, request_digest, attempt_id, start_operation_id, token (same closed tuple), runtime_id. Journal kind `resource.settlement-fenced`; deterministic ID derived from domain/generation; blocks old acting capability without returning ownership |
| `baton.v12.stopped-execution-settlement-outcome/1` | schema, operation_id, request_digest, attempt_id, runtime_id, token, cessation (below), execution_outcome=`failed-stopped`, resources=`preserved`, result_acceptance=`not-performed`, authority_disposition=`not-performed` |

cessation is exactly `{state, observed_at, source, evidence_digest, writer_basis}`. state is quiescent or absent; source is literal trusted-runtime-adapter; writer_basis is literal primary-confined-execution. observation time uses existing validated UTC instant grammar. evidence_digest binds a retained owner observation document containing the exact attempt/runtime/launch/token and provenance; add no raw engine stderr or arbitrary exception text. Propose the retained wrapper `baton.v12.stopped-execution-observation/1`, exactly schema, attempt_id, runtime_id, start_operation_id, token (request tuple), state (quiescent/absent), observed_at, provenance_digest. The settlement owner creates it from the trusted existing runtime observation plus validated token/launch/preparation records, never request booleans. provenance_digest is the canonical digest of the ordered pair of exact committed host-preparation and launch-record digests; absence of either or an unresolved helper/activation record holds. No raw engine text travels. Commit outcome only after validating these retained bytes. This is a new bounded observation wrapper, not a claim that current adapter documents already have this schema. Legacy unknown provenance is ineligible, not normalized into this literal.

Command result schema `baton.v12.stopped-execution-settlement/1` has exactly schema, operation_id, request_digest, attempt_id, state, reason, outcome_digest, token_returned, resources, result_acceptance, authority_disposition. state is eligible (check only), held, release-pending or released. reason is null for eligible/released, otherwise one of busy, failure-unproved, identity-mismatch, runtime-not-stopped, observation-unavailable, activation-unsettled, effect-unsettled, storage-record-unavailable, token-return-pending. outcome_digest is null before outcome, otherwise its canonical digest; token_returned is a Boolean checked from the exact token owner, never inferred from state or exit code. resources is preserved; result_acceptance and authority_disposition are not-performed. Read-only preview reports actual existing token-returned state and cannot produce a newly released receipt. Schema/type/operation-collision refusals remain existing bounded CLI errors, not a fabricated held success.

Canonical document signatures use contracts.canonical_bytes/digest with closed parsing; journal operation IDs derive deterministically from `request_digest` plus fixed step literal, except the unique per-generation fence ID. No timestamp enters an operation identity, and replay retains selected_at. Journalling failures preserve holds and use the existing diagnostic degradation channel. No new token public wire is assumed: `token_of` is an internal API whose fence awareness must cover all its acting consumers. Its existing public diagnostic fields (returned, revoked, runtime etc.) keep their meanings: settlement-fenced is not falsely reported revoked-by-expiry. The standalone receipt conveys held/release-pending/released.

Job status remains on its existing version and semantics for this bounded operation: the stage stays exceptional; it does not become completed because release succeeded. Existing diagnostics report exact token return/runtime/cleanup facts; they do not pretend cleanup pending means an active writer. Proposed read-only `manager settlement-status --instance INSTANCE --operation-id ID` returns the same result schema using stored intent/outcome/token records only, with no engine call or state repair. It can show release-pending after a crash. No additional status/diagnostic/report schema widening is required here; W371073's separate /2-/8 proposals remain independent. No claim that old installed binaries expose these new commands or journal kinds.

A deployment containing new settlement fences cannot safely be served by old code that ignores them. Current worker_manager.schema.SCHEMA_VERSION is **18**, STORE_KIND is baton.v12.python.worker-manager; ControlStore validates exact metadata version on open. Propose control-store **19**, preserving store kind and tables, with the new journal kinds and mandatory fence checks. Version-18 binaries already reject a version-19 store on open; no old binary is assumed to understand a new fence. New version-19 normal open refuses /18 rather than silently migrating. New instances create /19. This is an explicit version proposal tied to the captured source, to revalidate if another selected change consumes 19 first.

The current schema source explicitly says there is no migration and its historical production boundary requires fresh stores. The following narrow 18-to-19 exception is therefore a **new owner decision**, not existing authority or an assumed API. If owner declines it, version-19 fresh instances can use settlement, and the retained version-18 instance remains blocked on a separately selected compatible operational solution. Do not silently broaden this to older schemas or cross-deployment conversion.

For retained instances, propose a store-owner `manager upgrade-control --instance INSTANCE --from-version 18 --to-version 19 --operation-id ID` maintenance operation. This is separately selected operational migration, not performed by settle-stopped. Acquire exclusive installed-manager ownership, prove every old serving/controller process is stopped, validate instance/store kind, exact version and journal integrity, then atomically record upgrade intent/result and change only schema-version metadata through the store owner. A committed marker/result replays; interruption rolls the transaction back or replays its complete result. All existing attempt/token/Authority/result evidence is byte-preserved. Unknown schema, active old manager, unverified integrity or mismatched identity refuses before writes. No force/open-raw-store fallback, downgrade or mixed writer versions. An old already-open process would not be protected by an open-time gate, so stopping/excluding all old owners is a required migration precondition, not an optional operational suggestion. Migration does not settle any token or authorize execution. Verify old-reader rejection and exact history preservation deterministically. No production migration or deployment is authorized here.

> The manager provides an explicit, replayable settlement operation for a failed execution whose exact confined runtime has positively ceased. It durably fences that execution's permission, records its outcome and returns only its bound resource generation, while preserving private storage and outstanding result-consumption evidence. Settlement does not require output inspection, a successful verdict, Authority assignment closure, normalization or resource destruction. Unknown launch, activation, writer or engine-effect state keeps ownership held. A committed settlement remains recoverable across independent Authority disposition without affecting a replacement assignment or generation.
