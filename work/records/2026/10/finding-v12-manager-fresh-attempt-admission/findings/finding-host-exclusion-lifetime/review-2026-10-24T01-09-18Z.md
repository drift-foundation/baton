## R19 [P1] Counted borrows do not compose with lifetime-owner acquisition

the guard and later releases on that stale fact. `hold_manager_instance` still
returns the cached object without joining or excluding that borrow chain.

Independent real API sequence: enter an admission borrow; acquire a serving
lifetime via hold_manager_instance; exit the admission. The serving handle is
the same object and now has descriptor None; a spawned process acquires the
instance despite that serving lifetime still being held. See
`serving_acquired_during_borrow`. No thread timing or altered state is required.

**Required:** make ordinary lifetime owners and temporary borrowers obey one
coherent ownership rule. A serving owner acquired during an admission must either
be safely refused or retain valid exclusion after admission exits. Also retain
the reciprocal guarantee: an active admission cannot silently lose exclusion
when an independently held serving lifetime ends. Preserve the existing API's

## R20 [P2] Fork inherits a mutex that its child cannot release

The new `_BORROWING` RLock is not reset or otherwise reconciled by
`workspaces._forget_inherited_guards`. A fork while another thread owns it
leaves the child blocked acquiring a borrow, even after the parent unlocks.

The bounded probe holds the actual mutex on a helper thread, calls real os.fork
on the main thread, releases the parent mutex, and asks the child to borrow an
otherwise unheld instance. Its two-second alarm exits77 with no acquisition
message. The child is reaped and the helper joined. Python emits its expected
multithreaded-fork warning; this is a controlled test of the explicitly required
guard fork contract, not a recommendation to fork arbitrarily in an application.
The existing direct fork-handler test cannot detect an inherited locked mutex.

**Required:** preserve safe child guard behavior with the new synchronization,
including fork during bookkeeping. The child must not inherit authority or hang
on a vanished thread's lock. Verify actual fork behavior with bounded cleanup.
