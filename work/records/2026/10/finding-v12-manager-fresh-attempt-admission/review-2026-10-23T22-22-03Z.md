calls with the same incarnation on separate real JobStore connections both
return admission and both invoke the shared binding effect. Independent probe
`same_incarnation` records two admissions and `same_incarnation_bind_effects`

updates, not the whole Work/binding/submission sequence or its other owner calls.

**Required:** distinguish exclusive execution from replay identity. Concurrent
same-incarnation requests must not both own external effects; a completed replay
and a safely resumed interrupted request must still work. Establish the property
at the supported direct-manager boundary as well as CLI composition. No blanket
database transaction around external calls.

## R10 [P1] Admission releases an existing manager's guard

Candidate `v12/python/tools/fresh_attempt_ports.py:91` always releases the
guard returned by `hold_manager_instance`. The existing API explicitly returns
the process's already-held lifetime descriptor (canonical workspaces.py:1054).
The adapter therefore borrows that descriptor and closes it on exit even when
another caller owns the manager lifetime.

Independent real-guard probe: hold the serving guard, confirm a spawned process
is refused, enter/exit `InstanceOwnership.held` in the holder process, then
try the spawned process again. The borrowed object is exactly the serving
object; the second process now acquires it while the original owner has not
released its lifetime. `borrowed_guard` records both results. This is an actual
loss of exclusion, not a test against a fake refusal port.

**Required:** preserve caller ownership and lifetime. Admission may not release
another composition's guard, and concurrent/nested admission must not imply
exclusive invocation ownership merely from process membership. Prove competing
processes stay excluded until the actual owner releases, including error exits.
Keep this coupled with R8's admission execution ownership correction.
