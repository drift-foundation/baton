How the runs in this directory were produced — claim362249, W361910
===================================================================

Same recipe as evidence/claim-361943/HOW-THESE-WERE-RUN.txt. The canonical tree
is not edited, so every run is on a disposable scratch root built from the
canonical bytes at 182c8f94 with the candidate overlaid; the base root is built
the same way with no overlay, so a base/candidate diff compares BYTES and not
environments.

  base root       /tmp/w361910-base        (retained from claim361943)
  candidate root  /tmp/w361910-r2          (candidate-362249 overlaid)

Each root is <root>/v12/python + <root>/v12/worker + <root>/v12/DESIGN.md and
the v12 JSON files + <root>/AGENTS.md + the one published result-manifest
vectors subtree under <root>/work/records/2026/08/... that
tests/manager/test_output.py and tests/job_manager/test_review_driver.py read
by `parents[4]`. Keeping the `v12` directory level matters: without it the
repository root resolves one directory too high and ~354 suites fail on a
missing vectors.json.

The 89 and the 259, stated the same way as last round
-----------------------------------------------------

They are PRE-EXISTING in this root and this candidate adds none: the base and
candidate lists are byte-identical, which is what makes them a baseline rather
than a claim. They are NOT asserted to be failures in the canonical checkout —
a scratch root is not a checkout, has no container engine, no installed
instance and no deployment state root, and much of tests/manager asks for one
of those. The whole tests/manager run was not required by the review ("no
broad suite required"); it is here because this round changes the package's
exported surface and an identical baseline is cheap insurance.

What was NOT run, and why
-------------------------

No provider, no container engine, no Authority, no installed instance, no
deployment. The Job stores these cases open are the disposable SQLite files
tests/job_manager/fixtures.JobManagerCase creates under a temporary directory.
The compatibility generation is moved with unittest.mock.patch in the test
process only — exactly as the reviewer's probe did — and no installed default,
configuration file or live instance is touched. No Git operation of any kind,
in the repository or in the scratch roots. tests/tools was not re-run this
round: nothing in these bytes reaches tools/, and claim361943's evidence
records that surface against the same base.
