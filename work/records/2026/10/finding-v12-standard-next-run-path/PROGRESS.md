### The correction

`v12/python/tools/next_run_confinement.py`, base
`317414e0246818f4507e5c3ab907e03b149151a9bb42acf2bf1b9ec9772b469e` →
`77037d51fd24848fdbe91a2888e13e08a4778a3136259acdf2351ecd7cb45e65`. The base
digest is the one the review states for the installed **and** checkout module,
so the "before" bytes in the evidence are exactly the installed ones.

**One additional Landlock rule and nothing more.** It is bound to the null
device's **own inode**, through an `O_PATH|O_NOFOLLOW` descriptor, and grants
**`WRITE_FILE` alone** — no truncate, no create, no remove, no directory right.
The device is fixed in the module and identified by **type** (`S_ISCHR`) and
**device number** `(1, 3)` rather than by its spelling, so a later path
substitution cannot redirect it — the same reason the root rule binds a
descriptor.

**And it fails closed.** The validation runs *before*
`landlock_restrict_self`, so a missing, wrong-type or wrong-number device
refuses with **no boundary applied** rather than a weaker one.

What it is not: no `/dev` grant, no writable-root expansion, no caller-selected
device or path, no `chmod`/`chown`, no disabling of Landlock, no installed
mutation. A null device cannot carry data, so a write right over that one inode
leaks nothing; the point is only that the `O_RDWR` open Git's launcher performs
succeeds.
