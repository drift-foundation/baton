## Findings

### [P1] The retained manager still provisions and requires Git metadata

The pinned ruling says the core manager does not understand Git and that
private ephemeral space is generic runtime capacity, not protocol vocabulary.
`assignment_workspace` (`workspaces.py:323-343`) still creates and returns
`inputs`, `workspace`, and `git`; its docstring explicitly assigns the third
root to Git metadata and mutable refs. The retained isolation tests likewise
iterate over and require `git` (`test_workspaces.py:246-271`).

The same acquisition vocabulary survives independently in the OCI adapter:
`ROOT_NAMES` is closed over `inputs`, `workspace`, and `git`
(`oci.py:107-127`), `_roots` therefore refuses an otherwise complete generic
root set, and the mount tests require a private Git-metadata root that no
posture is allowed to mount. The core adapter still understands Git even
though the acquisition operations that once consumed this root are gone.

This is not merely a stale name. It is acquisition-specific behavior still
performed by the core manager: every assignment gets a Git metadata area even
when its staged input is a directory, archive, database snapshot, media, or a
future format. The call-graph cut treated `assignment_workspace` as one generic
node and therefore did not separate the acquisition-specific work within it.

Correction boundary: return only generic manager-owned roots from
`assignment_workspace`, close the OCI adapter over the same generic roots, and
remove the `git` root from their contracts and tests. Preserve assignment
isolation, posture, the staged-input root, writable/private workspace
containment, and cleanup. A future source stager or Git-capable driver can
allocate its own private capacity under an explicit owner.

Regression:

- `TheCoreManagerDoesNotAcquireSources.test_no_git_metadata_root_survives_the_acquisition_cut`;
- `AMountIsCanonicalAndNeverTheHosts.test_the_assignment_root_contract_is_artifact_neutral`.

### [P2] The module contract still advertises the deleted acquisition component

The module docstring (`workspaces.py:1-45`) still says sources are rebuilt and
delivered here, that workspaces carry private Git metadata, and that `GitPort`
injects repository transport. The file also ends with the now-empty
`delivering a source` section at line 382. Introspection and generated
documentation therefore describe an API and owner that this Work deliberately
removed.

Correction boundary: rewrite the module contract around the retained generic
directory measurement, assignment-private roots, containment, and cleanup;
remove the empty acquisition section. Historical reasoning remains in the
dossier and does not need to survive as the live module contract.
