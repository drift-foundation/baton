## Findings

### [P1] A custody directory is mistaken for a committed result

`sealed_result` treats `os.path.isdir(held)` as sufficient replay evidence.
Creating custody and copying its entries are not atomic, so a process can stop
after only a prefix of the measured tree exists. On restart the adapter
measures that prefix and publishes it as the complete output without
consulting the two-file live output or any operation-bound commit record.

The additive
`test_a_partial_custody_directory_is_not_a_settled_replay` creates exactly
that state. The returned manifest has one entry instead of two.

### [P1] A settled missing-optional answer is not replayable

`missing-optional` deliberately has no artifact directory. Because replay is
inferred only from artifact-directory existence, the same freeze operation
consults today's workspace again. If the optional path appears later, the
answer changes from `missing-optional` to `present`.

The additive
`test_an_exact_retry_preserves_a_missing_optional_answer` reproduces this
identity change. A committed result record must represent the whole answer,
including absence, and sit above both partial custody and current workspace
reads. Directory existence alone is neither necessary nor sufficient.

### [P1] The approved credential lifecycle remains absent

The source and focused test contract still contain no approved credential
mechanism: no closed logical slots, trusted-profile provider mapping, provider
resolution, assignment-private volatile files, fixed read-only
`/run/baton/credentials` root, live-secret registry spanning output-content
leak checks and proved teardown, cancellation/failure cleanup, exact restart
adoption, or bounded orphan cleanup. The test module explicitly says
credential delivery is not present.

This remains the Work's largest deliverable and blocks sign-off independently
of the two retry defects.

## Accepted corrections and verification

The original 23 sealing cases pass, including construction-time canonical
path refusal and replay of a present artifact after the live workspace is
gone. Combined sealing, OCI and dependency modules run 118 cases successfully
with one skip before the two new regressions are added. With them, the sealing
module runs 25 cases: the original 23 pass and the two new cases fail as
described.

Five focused boundary-inventory assertions run. The stale-owner and witness
checks pass. Remaining failures are a shared 23-entry orphan set beginning in
intake, handshake missing probes, and an OCI destroy probe intercepted by its
command envelope. Neither `sealed_result` nor `collected_result` appears in
the owned-but-unprobed set that was W6634's prior defect.

No protocol or application implementation was changed by this review. It adds
two focused regressions and durable review evidence only.
