## Findings

### [P1] The final commit record can exist before it is complete

`_commit` opens the final `sealed.json` path directly and writes its bytes.
Opening creates or truncates the final name before the write completes, so a
process stop can leave an existing empty or partial record. Restart treats
existence as a settled answer and sends those bytes directly to `json.loads`.

The additive
`test_an_incomplete_committed_record_is_not_replay_evidence` creates an empty
interrupted record. Seal raises raw `JSONDecodeError` rather than restaging or
failing closed with a contract refusal. Publish complete bytes under a private
temporary name and make the final record visible atomically; replay must also
own and validate the adopted document and its digest before returning it.

### [P1] Replay does not prove the request is the settled operation

Custody is selected only by attempt id. `_committed_result` returns the stored
answer without comparing its `freeze_operation`, assignment, disposition,
input digest or policy binding against the incoming request and adapter
identity.

The additive `test_replay_requires_the_same_freeze_operation` seals once and
then asks under a different operation id and signature. The adapter returns
the first answer instead of refusing the non-exact retry. Bind and compare the
committed response before replay; "replay above state reads" does not mean
"replay before identity proof."

### [P1] The approved credential lifecycle remains absent

The latest progress explicitly says nothing about credential delivery has
been implemented. Source and focused tests still have no closed slots,
trusted-profile provider mapping, provider resolution, assignment-private
volatile files, fixed read-only `/run/baton/credentials` root, live-secret
registry spanning content leak checks and proved teardown, cancellation and
failure cleanup, exact restart adoption, or bounded orphan cleanup.

## Verification

`tests.manager.test_sealing` runs 28 cases. The 26 pre-existing cases pass; the
incomplete-record case errors with `JSONDecodeError`, and the non-exact replay
case fails because no `ContractRefusal` is raised. `git diff --check` is clean
for the reviewed source, tests and dossier.

No protocol or application implementation was changed by this review. It adds
two focused regressions and durable evidence only.
