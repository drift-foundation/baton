## Findings

1. **P1 — the approved credential lifecycle is entirely absent.** The current
   adapter has no logical credential slots, trusted-profile provider mapping,
   provider resolution, assignment-private volatile files, fixed read-only
   `/run/baton/credentials` mount, live-secret registration, output-content
   leak check, teardown proof, restart adoption or bounded orphan cleanup.
   `test_sealing.py` still explicitly says credential delivery is not present.
   Consequently the Work's credential and leakage/cancellation acceptance is
   unimplemented even though approver message 16691 settled the mechanism.

2. **P1 — an exact seal retry still depends on today's worker workspace.**
   `sealed_result` checks and measures the live declared path before consulting
   existing custody. After one successful seal, deleting the live output makes
   the exact same adapter request fail `precondition` instead of replaying the
   immutable artifact. This contradicts restart/retry idempotence by manager
   operation/artifact identity. The additive
   `test_an_exact_seal_retry_replays_custody_without_the_workspace` reproduces
   it.

3. **P1 — the prior construction-time path correction is incomplete.**
   `declared_outputs` owns paths only as nonempty text. Absolute, escaping and
   non-canonical paths are accepted at adapter construction and are rejected,
   if at all, only later during seal. The prior review required canonical
   relative-path validation before any worker execution or filesystem mutation.
   The additive `test_output_paths_are_validated_at_construction` demonstrates
   five accepted invalid forms.

4. **P1 — the new sealing receivers are not covered by the mandatory boundary
   inventory.** The broader gate reports owned-but-unprobed entries for
   `sealing.py:sealed_result`'s request, assignment, attempt, disposition,
   instant and operation, and for `sealing.py:collected_result`'s request,
   attempt, output names and result id. The implementation cannot claim the
   manager's exhaustive receiving-boundary proof until those entries have
   exact witnesses. Other boundary-inventory failures in the same dirty tree
   name neighbouring active Work and are not attributed to W6634 here.
