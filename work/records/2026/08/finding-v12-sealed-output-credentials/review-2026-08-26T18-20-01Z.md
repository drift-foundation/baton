## Findings

1. **P1 — a credential delivery can start under another attempt's runtime
   identity.** `OciAdapter.start` compares profile, policy and adapter labels,
   but never compares `credential_delivery.attempt_id` with the start label's
   `runtime_attempt_id`. Additive
   `test_a_delivery_cannot_start_under_another_attempts_labels` starts an
   attempt-2-labelled runtime mounting attempt-1's root, then records that
   container under attempt-1. Refuse before engine creation and do not tear
   down based on a candidate query for the wrong attempt.

2. **P1 — the promised all-refusal start settlement is not exhaustive.** A
   `ContractRefusal` raised while composing `run_vector` bypasses
   `_refused_start`. Additive
   `test_a_pre_engine_vector_refusal_settles_the_credential` first proves the
   candidate set empty, then drives a mount collision before engine creation;
   the root and registry entry remain. Route all pre-creation refusal/fault
   exits through a lifecycle decision, while preserving unresolved state for
   any path that cannot prove no runtime holds the mount.

3. **P1 — live-mount agreement still accepts shadowing and multiplicity.** The
   comparison checks unexpected descendants of `/run/baton/credentials` but
   not a bind directly on that root, so an engine-reported root bind can shadow
   every per-slot bind and still be adopted. It also converts observations to
   a dict keyed by target, silently collapsing duplicate binds. Additive
   `test_a_bind_shadowing_the_fixed_root_is_not_exact_agreement` and
   `test_two_live_binds_cannot_satisfy_one_recorded_slot` reproduce both.
   Exact agreement must include one-and-only-one expected bind and no bind at
   or below the fixed root beyond the recorded entries.

4. **P1 — recovery performs broad orphan deletion without a complete live
   set.** The no-record branch calls `discard_orphans(live=[])`, and the failed
   branch does the same once only the requested attempt's candidates are gone.
   `CredentialHome` is assignment-scoped and can contain sibling attempt
   roots. Additive
   `test_no_record_for_one_attempt_does_not_discard_another_attempt` shows
   recovery of attempt-1 deleting attempt-2's materialized root while its
   lifecycle record and live bearer remain. A per-attempt recovery may remove
   only what it has proved stale; a broad pass needs the complete proved live
   set.

5. **P1 / unresolved dependency — W14251 has not settled the output
   publication contract.** The pinned ruling says the worker publishes
   `/output/output.json`; the current W14251 schema makes that file a
   manager-authored result requiring later freeze/custody facts; W6634 still
   publishes atomic `sealed.json` in manager custody. W14251's active review
   explicitly requires W6634 revalidation. Do not close this Work as a sealed
   output contract until the exact writer, final name/location, completion
   signal and manager receipt are aligned with W14251's durable ruling.
