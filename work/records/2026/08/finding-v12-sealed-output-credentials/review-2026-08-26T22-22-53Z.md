## Findings

### [P1] Exact receipt replay still depends on the transient worker envelope

`sealed_result` calls `_completion_envelope` before `_committed_result`.
Consequently an exact retry after successful custody refuses if
`/output/output.json` has been removed with worker-owned output, even though
the committed manager receipt already contains and binds the digest of the
envelope this manager validated.

The additive
`test_an_exact_retry_does_not_need_the_worker_envelope_again` seals normally,
removes only `output.json`, and repeats the identical freeze request. It gets a
`refused/precondition` error instead of the byte-identical committed answer.

Replay must first prove the immutable request-to-receipt binding and then
return the settled receipt without consulting current worker state. The
existing changed-envelope test pins the same ordering defect: a changed file
is not an operand of the already committed operation. PLAN records explicit
authority to revise that assertion narrowly.

### [P1] The completion reader follows a worker-created link outside `/output`

`_completion_envelope` uses `os.path.isfile(place)` and then ordinary
`open(place, "rb")`. Both follow symlinks. The additive
`test_the_completion_signal_is_a_regular_file_in_the_output_root` moves a
valid completion document outside the writable root and places an
`output.json` symlink to it; sealing succeeds.

This turns a worker-controlled fixed path into a host-side read of a path the
worker selected and contradicts the Work's linked-output refusal boundary.
Open without following links, verify the opened descriptor is one admitted
regular file under the fixed root, and read that same descriptor under the
existing byte bound.

### [P1] A completion envelope for another assignment is accepted

Standalone validation proves that `assignment_ref` is well formed, but
`_answers_the_assignment` compares only output names, types, paths and required
status. The additive `test_the_envelope_answers_this_exact_assignment`
publishes a valid completion envelope for generation 2 while the freeze
request settles generation 1. The manager accepts it and binds its digest into
generation 1's receipt.

The worker document must be held against the exact input/freeze assignment,
not merely against declarations that happen to be identical. Compare the
owned `assignment_ref` before any custody mutation.

### [P1] Zero-runtime credential recovery can never converge

When the lifecycle record exists but the exact engine query returns no
runtime, `_recovery_failed` receives an empty list. It computes
`gone = bool(stopped) and all(stopped)`, which is false for that list, reports
`UNRESOLVED`, and retains both the stale root and record. Every later recovery
repeats that state.

The additive
`test_a_stale_record_with_no_runtime_converges_to_absence` reproduces the
loop. A successful exact query returning zero candidates is positive absence;
there is nothing to stop, and targeted cleanup may remove the stale root and
record before a second recovery reaches ordinary absence.
