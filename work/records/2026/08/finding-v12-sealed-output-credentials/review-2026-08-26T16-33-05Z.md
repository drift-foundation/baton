## Findings

1. **P1 — restart adoption does not prove the live runtime's mount/root
   identity and has no recovery integration.** `CredentialHome.adopt` compares
   a lifecycle record with caller-supplied attempt/runtime ids and locally
   derived paths, but it receives no engine observation. `OciAdapter.observe`
   owns only runtime identity and state, and no production path calls
   `read_state`, `adopt`, or `discard_orphans`. A self-authored record agreeing
   with its own local files is not proof that the live container has the same
   mount sources and targets. The approved disagreement path — fail closed,
   accept no output, stop the worker, then bounded orphan cleanup — is likewise
   absent. The current exact-adoption case therefore proves document
   consistency rather than the approved restart boundary.

2. **P1 — an engine-declined start strands the materialized credential.** On
   a non-zero start result `OciAdapter.start` raises immediately. The volatile
   root and live-secret registration remain, while no runtime id or lifecycle
   record exists for the claimed single destroy path. Additive
   `test_an_engine_declined_start_releases_the_undelivered_credential`
   reproduces both remnants after the engine has answered that it declined the
   launch. The failure path must settle the credential only after it proves no
   runtime can retain the mount; uncertainty must remain explicitly
   unresolved.

3. **P1 — a failed multi-slot adoption leaks earlier registry
   registrations.** `CredentialHome.adopt` validates, reads and registers each
   slot in one loop. If a later slot is missing or malformed, earlier bearers
   stay registered and no `Delivery` is returned to own or release them.
   Additive `test_a_partial_adoption_does_not_leave_an_unowned_live_bearer`
   demonstrates the leak. Adoption must prove the whole delivery before
   registering it, or unwind every registration on any refusal/fault.

4. **P1 — materialization treats a short write as complete delivery.** The
   credential writer calls `os.write` once and ignores its returned byte count.
   Additive `test_a_short_file_write_does_not_truncate_the_credential` makes
   the call accept one byte; materialization succeeds with a one-byte file
   instead of the registered bearer. Complete the write or refuse and execute
   the existing failed-materialization cleanup.
