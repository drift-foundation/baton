## Finding

### [P1] Structured range bounds are accepted but not required to be canonical

The approver ruled that range operands normalize to UTC, and `_export_scope`
does that before constructing the structured result. The new
`_export_scope_document` calls `_export_instant` to validate each direct
structured bound but discards the canonical return value. The renderer then
emits the caller's original spelling in DOT metadata.

Consequently one normalized scope instant can produce several different DOT
documents. Both `changed_from` and `changed_until` currently accept and emit:

- a numeric-offset spelling instead of its UTC instant;
- lower-case `t`/`z`; and
- a fraction with non-canonical trailing zeros.

For example, `2026-01-01T01:00:00+01:00` and
`2026-01-01T00:00:00Z` describe the same approved lower bound but produce
different `baton_scope_changed_from` bytes. That breaks the projection's
canonical scope contract and the DOT promise that an identical normalized
scope has one byte representation.

Keep the public operand path accepting and normalizing all legal RFC 3339
spellings. At the structured-result boundary, require each non-null bound to
equal `_export_instant`'s canonical value (UTC `Z`, upper-case separators,
minimal significant fraction), and raise `WorkError` naming the bound before
rendering if it does not. Apply the rule symmetrically to both bounds.

Additive regression:
`test_a_structured_scope_carries_the_canonical_utc_instant`.
