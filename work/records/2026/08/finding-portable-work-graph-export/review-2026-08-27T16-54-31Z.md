## Findings

### [P1] Individually valid values still form impossible node and edge states

The approved structured schema couples status to phase/outcome:

- open Work has one scheduler phase and `outcome=null`;
- closed Work has `phase=null` and one terminal outcome.

The validator instead treats all three members independently. It emits
complete-looking DOT for all four impossible combinations: an open node with
no phase, an open node with an outcome, a closed node with a phase, and a
closed node with no outcome. Each value is individually null or a member of
its closed vocabulary, so the new enum guards do not see the contradiction.

The same gap exists on edges. The fixed schema says `via_obligation` is
dependency provenance and is null for every other relation, but a containment
edge carrying `via_obligation=7` currently renders.

Validate these cross-member invariants in the shared graph validator before
DOT rendering. The existing
`test_null_is_accepted_exactly_where_the_contract_allows_it` currently asserts
that `phase=null` is valid on the helper's open node; that assertion contradicts
the confirmed schema and must be corrected to exercise the two valid paired
states rather than independent nullability.

Additive regressions:

- `test_node_state_members_are_valid_as_one_state_not_three_values`;
- `test_only_a_dependency_may_name_obligation_provenance`.

### [P1] “The whole input validated” still excludes scope and counts

`dot.render_work_graph_dot` requires `scope` and `counts`, and its module and
inline contracts say it validates the whole structured result. In practice it
validates only outer container shapes plus nodes/edges. Four malformed results
currently render without refusal:

- `scope.status="bogus"`;
- `scope.closure="recursive"` instead of the fixed `incident-endpoints`;
- the unpaired, non-RFC bound `scope.changed_from="yesterday"`; and
- `counts.nodes=2` beside a one-node array.

The first three become authoritative-looking graph attributes; the count is
silently ignored despite being a required structured member. Add one shared
result validator, used by both the projection and renderer, that owns the
fixed scope shape/value rules and proves all four counts from the node/edge
arrays. The pure renderer cannot validate a configured team against a store;
it can and should own the nullable text type while the projection retains the
snapshotted configured-team check.

Additive regression:
`test_the_renderer_owns_fixed_scope_and_count_semantics`.
