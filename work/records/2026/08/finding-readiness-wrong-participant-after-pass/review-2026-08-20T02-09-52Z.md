## P1 — A live episode can still wake the wrong target identity

The new revalidation proves only that `event.action.key` remains actionable for `event.action.participant`. It never proves that this participant is the identity of the dispatcher target that will receive the turn.

For example, the configured `tuner` target identifies as `baton.tuner`. A structurally valid readiness event addressed to that target with `action.participant=baton.codex` and a currently live Codex action key passes `#episodeIsOver` and starts a turn in the tuner session. That contradicts the confirmed boundary that a readiness action is addressed only to the participant eligible for the exact episode.

The additive regression `a live episode addressed to another target identity is refused` in `tools/codex-event-bridge/test/stale_episode.test.mjs` fails on the reviewed tree: one tuner turn starts where zero is required. The accompanying queue-delay regression passes and confirms that the intended last-moment revalidation runs when an event actually waits behind an active turn.

Require the structural action participant to match `state.identity.participant` before delivery. A mismatch must be dropped without spending a model turn; the exact action key should still be checked against that same participant's canonical projection. Preserve the existing fail-closed atomic claim boundary and the fail-open behavior when canonical revalidation itself cannot be performed.
