## Findings

### [P1] The worker-authored output manifest requires manager-only facts

The owning artifact-neutral ruling says the worker writes durable results
below `/output/` and publishes `output.json` last. Revised SPEC §8.4 identifies
that file with `baton.worker-manifest/result`, whose schema requires
`freeze_operation`, `manager_observed_at`, and artifact references containing
manager-custody facts. Those values are created by the manager only after the
worker is quiescent, so the worker cannot publish this document under the
pinned ordering.

The new conformance cases encode the opposite owner: publication is stimulated
by manager `output.freeze`, and the interrupted-publication case stops the
manager. The downstream W6633 revalidation then assigns publication back to
the worker while requiring the same manager-owned artifact answer. This is an
unimplementable cycle, not a prose ambiguity.

Separate the worker-authored `output.json` completion envelope from the
manager-authored frozen-result/custody receipt, or obtain and durably record an
explicit supersession of the pinned worker-publishes ruling. Whichever boundary
is approved must align the schema, SPEC, vectors, conformance cases, W6633
handoff and W6634 sealing contract.

### [P1] Input and output relative paths are still compared in one root

`manifest.py` and the canonical contract model concatenate source destinations
and output paths, then reject lexical overlap. SPEC §12 rule 3 repeats the old
rule. Under the revised fixed roots, `/input/repo` and `/output/repo` are
disjoint, so equal or nested relative spellings across the two roles cannot
alias.

Additive
`test_equal_relative_paths_in_the_two_fixed_roots_do_not_overlap` reproduces a
valid manifest being refused with `integrity.path`. Retain overlap refusal
within the source set and within the output set; stop comparing paths across
the two fixed roots. The pre-existing cross-root overlap regression and its
stale shared-workspace rationale will need explicit case-specific correction.

### Incomplete downstream revalidation

W6634 is directly affected. Its accepted sealing path publishes atomic
`sealed.json` in manager custody, not `/output/output.json`. Item 7's statement
that only W6633 is affected is therefore false. Revalidate W6634's exact
publisher/name/location contract once the ownership split above is resolved.
