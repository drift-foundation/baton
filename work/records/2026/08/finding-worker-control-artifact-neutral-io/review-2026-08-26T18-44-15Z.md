# Third independent implementation review — changes requested

Reviewer: `baton.codex`

Work: W14251

Date: 2026-08-26

## Result

**Changes requested.** The two-author publication split fixes the prior
cycle, and the cross-root overlap regression is green. The revision still
allows payloads to occupy the two fixed manifest filenames, leaves the
completion semantics in design evidence but not in the shipped validator, and
makes the only durable link from the manager receipt back to the worker
completion envelope optional without a version or negotiation boundary.

## Findings

### [P1] The fixed manifest filenames are valid payload destinations

The contract reserves `/input/input.json` for the manager-authored input
manifest and `/output/output.json` for the worker-authored completion envelope.
But `sourceDescriptor.destination` and `outputDescriptor.path` are unrestricted
`relativePath` values, and `_check_input_manifest` compares only declarations
within each role. Mutating the published input vector to stage a source at
`input.json` or declare an output at `output.json` passes both schema and the
shipped semantic validator.

Those are direct containment collisions: one payload replaces the protocol
document in the same root. Reserve each root's manifest name, including a path
nested below a name that must be a file, in the schema/model/shipped validator
and invalid vectors. The additive
`test_payload_paths_cannot_take_the_fixed_manifest_names` currently fails for
both roles.

### [P1] The shipped validator accepts completion envelopes the contract model rejects

The record's `_validate_completion_manifest` rejects duplicate output names,
overlapping paths, `present` without a content manifest and
`missing-optional` with one. The shipped
`check_manifest_structure`, however, dispatches semantic validation only for
`baton.worker-manifest/input`. Calling it with `completionManifest` accepts all
four malformed envelopes after schema, digest, secret and content-manifest
checks.

This is the validation boundary W6634 is expected to use when it begins reading
`/output/output.json`; leaving these rules only in design evidence makes the
downstream instruction incomplete. Add the standalone completion semantics to
the shipped validator and vectors. Separately, pin W6634's cross-document
comparison against the exact input manifest: exactly one completion answer per
declared output, no extras or omissions, exact `name`/`type`/`path`, and no
`missing-optional` answer for a required declaration. Conformance currently
tests publication order and the two-author split, but none of those identity
relations.

The two additive shipped-validator tests fail in four subcases.

### [P1] The manager receipt may permanently omit the completion it validated

`resultManifest.completion_manifest_digest` is optional. SPEC §8.4 explains
that as an implementation-sequencing accommodation: a receipt may omit it for
a worker that published no envelope. But the revised 1.0 contract makes the
worker envelope the completion signal and requires the manager to validate it
before freezing. There is no schema version, negotiated capability or other
durable marker that distinguishes a legacy no-envelope result.

As written, a conforming manager can forever publish a frozen-result receipt
that does not bind the exact worker claim it says it validated. Require the
digest for results under this superseded contract, or define an explicit
versioned/negotiated legacy boundary whose receipt cannot be mistaken for the
new path. A temporarily green implementation is not a stable shape rule.

### [P2] §7.1 still states the superseded cross-root overlap rule

SPEC §7.1 says staged-input destinations cannot overlap “any output”, while
§12 rule 3 correctly says input and output relative spellings are never
compared across the disjoint fixed roots. Replace the stale sentence with the
within-root rule and the two explicit reserved-name rules. The current prose
otherwise leaves two live normative answers after the code correction.
