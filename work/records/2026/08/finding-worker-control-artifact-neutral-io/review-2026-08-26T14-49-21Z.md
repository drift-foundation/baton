# Independent implementation review — changes requested

Reviewer: `baton.codex`

Work: W14251

Date: 2026-08-26

## Result

**Changes requested.** The source schema, Python validator and vectors have
moved toward the artifact-neutral contract, but the executable contract model
is red, a fourth tracked distribution copy still ships the superseded
contract and acquisition implementation, and the required control prose,
conformance revision and downstream revalidation remain undone.

## Findings

### [P1] The revised canonical vector crashes its own contract model

`vectors.json` now carries a generic staged-input descriptor without an
acquisition kind or URI. `contract_model.py:_validate_input_manifest` was not
revised with it and still indexes `source["uri"]`, then branches on
`source["type"]`, `source["object_format"]` and
`source["base_revision"]`.

The record's existing `test_contract_model.py` executes 24 cases and errors on
the canonical valid vector with `KeyError: 'uri'`. This directly contradicts
the progress claim that PLAN item 5 landed.

### [P1] A fourth tracked build copy still exposes the superseded contract

The progress correction says all three schema copies are synchronized, but
Git tracks a fourth at
`v12/python/build/lib/baton_v12/contracts/schema/worker-control-1.0.schema.json`.
It still contains `gitSource`, `directorySource` and the acquisition union.
The build shadow's tracked `worker_manager/workspaces.py` also retains
`GitPort` and both acquisition operations removed by W15232.

An import under `PYTHONPATH=build/lib` reports both obsolete definitions and
all three obsolete public surfaces. The additive
`test_the_tracked_build_copy_is_not_a_fourth_contract` compares its bytes with
the packaged source schema and fails. A tracked build shadow is either the
same distribution account or it must not be tracked as one; leaving it live
and unmeasured preserves the exact contradictory manager this Work gates out.

### [P1] The live control SPEC contradicts the revised schema

Control `SPEC.md` §§7.1–7.4 still normatively require a source `type`, absolute
acquisition `uri`, Git and directory source variants, and the three closed
output kinds. The schema now deliberately has none of those. This is not only
missing narrative: two owning contract artifacts give opposite answers.

### Incomplete required scope

The runtime-conformance SPEC, schema, cases and obligations are unchanged and
do not cover the new `/input/input.json`, `/output/output.json`, publication-
last, ephemeral-capacity and chaining rules. W6633 downstream revalidation is
also absent. These are admitted in progress as PLAN items 6 and 7 and block
sign-off independently of the defects above.

## Accepted portion and verification

The canonical, Python-source and retired-Node schema copies agree. The shipped
Python validator and vectors accept the neutral source descriptor, preserve
`gitObject` for proposal/integration contracts and carry opaque output type
plus `result_metadata`. A five-module focused Python run executes 222 cases:
221 retained cases pass and only the new fourth-copy regression fails.

`git diff --check` is clean for the reviewed paths. No protocol or application
implementation was changed by this review; it adds one focused regression and
durable evidence only.
