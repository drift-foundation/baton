# Review — 2026-08-29T13:43:10Z — `baton.codex`

Disposition: **changes requested**. The delivered unit suites are green and
the daemon probe supports the selected exec transport, but two deterministic
boundary failures contradict the implementation's own closed-session claims.

## Findings

### [P1] A scalar program is silently reinterpreted as argv characters

`v12/python/src/baton_v12/worker_manager/oci.py:951` applies
`list(program)` before validating each word. A caller passing the common
mistake `program="python3"` therefore receives:

```text
['docker', 'exec', '--interactive', 'runtime-1',
 'p', 'y', 't', 'h', 'o', 'n', '3']
```

That is a successfully composed closed engine vector, not a typed refusal.
The image-owned program operand is an external container boundary and must
accept one explicitly supported sequence shape or refuse before composing an
argv; Python iteration must not invent its shape.

Reproduction:
`evidence/repro-review-boundaries.py` (first result).

### [P1] Surplus worker stdout can be accepted as a clean answer

`v12/python/src/baton_v12/worker_manager/worker_entry.py:352` checks only
bytes already buffered by `_Reader.trailing()`. It does not read once more or
establish EOF. `_finished(channel)` at line 358 returns only status and stderr,
so the interface provides no later place to observe unread stdout. A peer can
return the one expected correlated frame, make an unsolicited second frame
available on the next read, exit 0, and receive `ending: answered` while the
surplus frame remains unread.

This contradicts the module's explicit rule that a worker writing more than
asked makes the conversation `lost`. It is also a false-clean-session path at
an untrusted worker boundary. The transport/channel contract must close the
send side, consume stdout to EOF under the same bound, and reject any bytes
after the final expected frame (or return the equivalent evidence from
`finish`).

Reproduction:
`evidence/repro-review-boundaries.py` (second result).

### [P2] The new start operands are not directly held at their security boundary

The 45-case transport suite never exercises `run_vector`'s new explicit
network or interactive operands. In addition,
`OciAdapter.__init__` uses `interactive not in (True, False)` at
`oci.py:1299`, which accepts integers `0` and `1` by equality even though the
later vector requires exact booleans. The module introduction at `oci.py:23`
still states every restriction is unconditional, while network is now the one
documented explicit substitution. Add direct default/explicit/refusal cases,
use exact boolean validation at construction, and update the public contract
text. Decide whether the currently unused `EXEC_SECONDS` and absent public
export of `exec_vector` are part of this child or remove/defer them explicitly.
