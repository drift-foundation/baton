## Findings

### [P1] A provider-created candidate link is followed into the proposal

The staged source is checked for links only before Claude runs. After the
provider controls the candidate, `claude_agent.py:487` walks it in `_diff()`
and `_lines()` opens each apparent file; `_publish()` at line 547 then applies
`shutil.copyfile()` to the same unchecked entry. Both operations follow a file
symlink.

The provider has the fixed credential at
`/run/baton/credentials/claude`. It can create
`candidate/credential-copy -> /run/baton/credentials/claude`; the adapter then
reads the bearer into `change.patch` and copies the target bytes as a regular
file into `proposal/candidate/credential-copy`. This directly contradicts the
pinned rule that the credential is never copied into the workspace or result.
The worker's later no-link measurement cannot repair it: by then the adapter
has already dereferenced the link into a host-writable output.

The additive regression
`v12/python/tests/manager/test_claude_agent.py:309` uses only the fixture's
literal `not-a-credential`. It currently fails because the copied output file
exists. Revalidate the entire provider-authored tree before diff or
publication: regular files/directories only, no followed top-level or nested
links, and bounded entries/bytes. Hold the same checked objects through copy so
the proof is not separated from the use by another path lookup.

### [P1] `MAX_DIAGNOSTIC` and `MAX_VERIFICATION` are post-allocation truncations

The provider call at `claude_agent.py:267` and verification call at line 324
both use `subprocess.run(..., capture_output=True)`. Python collects complete
stdout and stderr in memory before returning. `_text(...)[-MAX_DIAGNOSTIC:]`
and the `[:MAX_VERIFICATION]` slice happen only afterwards.

A noisy or wedged provider/verification command can therefore exhaust the
container's memory and turn the worker into transport loss instead of the
typed bounded failure the acceptance requires. Provider stdout is not used at
all, so it need not be accumulated. Capture each required diagnostic through a
genuinely bounded stream/file strategy and regression-hold output beyond each
ceiling.

### [P2] The fixed `/input/source` boundary is implemented as an unused constant

The confirmed boundary says the adapter copies exactly `/input/source`, and
the module defines `SOURCE_ROOT = "source"` at line 70. That constant is never
read. `_task()` accepts any syntactically contained `source_root`, and `work()`
joins that caller-selected value below `/input`.

If `source_root` remains in the frozen task document, hold it by equality to
the fixed workload value just as `schema` is held. Otherwise the adapter's
effective source is selected by the task payload while its dossier and module
claim the path is a constant.
