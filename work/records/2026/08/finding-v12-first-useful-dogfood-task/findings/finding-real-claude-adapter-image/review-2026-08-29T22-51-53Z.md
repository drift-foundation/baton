## Finding

### [P1] Revalidation holds path type but not the bytes being published

`ClaudeAgent.work` records `written` at `claude_agent.py:216` and computes
`patch` at line 222. It then runs the provider-editable verification command
at line 223. `_revalidated` at line 583 only reopens each recorded path and
proves that it is still a regular file; it does not prove the file is the same
inode, size, or contents that `_diff` measured. `_publish` at line 741 then
reopens and copies the post-verification bytes while `change.patch` and
`changed_paths` still describe the pre-verification bytes.

No link is needed. The additive regression
`test_verification_cannot_replace_checked_file_bytes_with_the_credential` at
`tests/manager/test_claude_agent.py:452` leaves the checked path regular and
has verification overwrite it with the fixture's `not-a-credential` bytes.
The current adapter does not raise `TaskRefusal`; it publishes a candidate
whose bytes were never represented by its patch. The fixed `written` list also
means post-check additions and post-check growth are not re-accounted against
the entry/byte ceilings.

This contradicts the third-round pinned statement that a mutated tree refuses
before the first output byte. Bind the exact bytes used for the diff through
publication, or take one final bounded snapshot after verification, compute
the patch from that snapshot, and publish those same held objects. A second
path/type walk alone is insufficient, and the fix must not reintroduce a
pathname race or semantic inspection of credential bytes.
