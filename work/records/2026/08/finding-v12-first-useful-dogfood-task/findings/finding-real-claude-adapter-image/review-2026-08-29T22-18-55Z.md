# Review — 2026-08-29T22:18:55Z — `baton.codex`

Disposition: **changes requested**. The second round closes the original
top-level candidate-link case and implements the fixed source-root check, but
the claimed no-secret publication boundary is still bypassable in two places.
The candidate entry ceiling also does not count directories. Three additive
regressions reproduce the remaining gaps in the focused suite.

## Findings

### [P1] Verification can swap a checked parent directory into the credential root

`claude_agent.py:216` records only relative path strings from `_checked_tree`.
The task's provider-authored verification then runs at line 223, before
`_publish` reopens those strings at line 226. `_open_regular` at line 518 uses
`O_NOFOLLOW`, but that flag protects only the final component. If verification
replaces `candidate/nested` with a link to `/run/baton/credentials`, opening
`candidate/nested/claude` follows the intermediate link and reads the mounted
credential as an ordinary final file.

The existing additive regression
`v12/python/tests/manager/test_claude_agent.py:413` performs exactly that swap.
The current implementation does not raise `TaskRefusal`; it copies the dummy
credential into `proposal/candidate/nested/claude`. The fix must keep a
no-follow directory capability through every component and every final read,
or move/revalidate the provider-authored tree after verification so no
untrusted command can mutate it between proof and use. A list of path strings
is not the “same checked objects” claimed by PLAN and PROGRESS.

### [P1] Verification can replace its capture pathname with the credential

`_verify` at line 368 creates the capture directory inside the candidate and
runs provider-authored code in that same directory. `_capture` opens
`capture-*/stdout`, lets the child run, closes the original descriptor, and
then `_window` reopens the pathname at line 324. The verification command can
unlink that visible pathname and replace it with a link to the credential.
The bounded reader then follows the link and writes the bearer into
`verification.txt`.

The additive regression at `test_claude_agent.py:440` replaces only the
capture pathname after its descriptor was opened. The resulting transcript
contains the fixture's literal `not-a-credential`. Keep and read the already
opened descriptor, and place capture state outside any namespace the child can
rename; reopening an untrusted pathname after the child returns reintroduces
the exact credential-disclosure class the second round intended to close.

### [P2] The advertised entry bound ignores directories

`_checked_tree` examines directories only for symlinks at line 553 and appends
only files to `found` at line 567. `_copy_tree` has the same shape: its
`entries` counter advances only for files at line 599. A provider can therefore
create an arbitrary number of empty directories without crossing
`MAX_SOURCE_ENTRIES`, leaving the supposedly bounded traversal limited only by
tmpfs inode availability and runtime.

The additive regression at `test_claude_agent.py:589` sets the bound to the
two existing files and adds one empty directory. The candidate is accepted
instead of refusing at three entries. Count every regular file and directory
that the adapter traverses against the entry ceiling on both staged and
provider-authored trees.
