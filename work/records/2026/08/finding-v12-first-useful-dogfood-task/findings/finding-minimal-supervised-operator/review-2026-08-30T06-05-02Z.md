## [P1] The task can change after its first hold

`frozen_task` answers an ordinary mutable `dict`. `preflight` then checks only
that it is a dict with the expected `schema`; `_copied_task` later serializes
the dict it receives. Thus the future arc can read a valid task, mutate its
task ID, instructions, verification vector or source root, pass preflight,
stage source and copy the changed task into `/input/task.json`.

The additive
`test_a_held_task_cannot_be_mutated_between_its_two_reads` drives all four
changes through the public preflight and fails. Factor one pure task-document
hold and apply it in `frozen_task`, `preflight` and immediately before copying,
or answer a recursively immutable held value whose later consumer cannot
change. Checking the schema a second time is not the same hold.

## [P1] Preflight holds record-binding keys and network presence, not values

Four correctly named `record_binding` members pass even when either digest is
malformed, the root is empty or the path is absolute. These are refused by the
frozen input-manifest schema only after staging. Likewise, any non-empty string
passes as `network`, including `--network=host`, `../bridge` and `two words`;
`oci._network` rejects those only when the runtime vector is composed.

The additive `test_record_binding_values_are_held_before_staging` and
`test_the_network_is_held_to_the_engine_grammar_before_staging` fail. Hold the
two digests, opaque root, canonical relative path and the existing engine
network grammar here. Reuse one grammar owner rather than letting the operator
and OCI adapter drift.

## [P1] A malformed policy container is not a typed preflight refusal

`policies=None` leaks `TypeError`, a string leaks `ValueError`, and an empty
list happens to behave like an empty mapping. The public preflight promises
one collected `OperatorRefusal` over explicit grants, so it must first hold
`policies` as the exact document shape it iterates. The additive
`test_a_non_document_policy_set_is_a_typed_preflight_refusal` records all
three cases.

## [P2] Narrow source ceilings need a value contract too

`stage_source` now prevents widening, but it accepts booleans and zero as
ceilings and leaks `TypeError` for text. One boolean reaches
`copied_manifest` and appears in a manager refusal as a limit of `True` files.
The additive `test_a_narrower_ceiling_is_a_positive_whole_number` requires the
operator's optional narrowed bounds to be positive exact integers before
copying.

## [P2 follow-up] The sender/receiver agreement test proves constants, not the predicate

`TheOperatorAndTheWorkerHoldOneTaskContract` compares the member tuple,
schema, source name and regex text. It does not compare the actual acceptance
predicate. The operator requires `task_id` to be an exact string; the worker's
`claude_agent._task` applies the regex to `str(document["task_id"])`, so JSON
number `7` is accepted by the receiver. The operator is safely stricter for
this pilot, so this does not reopen the corrected W39358 sender boundary, but
the record's claim that both ends hold one whole contract is false. File the
receiver correction against W39357 rather than editing that closed child's
owned file through W39358.
