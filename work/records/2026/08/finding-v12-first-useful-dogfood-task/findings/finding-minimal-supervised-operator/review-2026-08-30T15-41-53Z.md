## [P0] Editable `review_pass` cannot suppress the authority replay

`retry_handoff` calls `_passed` only when `evidence["review_pass"] is None`.
The retained file is explicitly editable and untrusted, while the pass is an
effectively-once authority operation that is safe and necessary to replay.
A plausible non-null pass projection in the file currently skips the authority
call entirely.

The additive
`test_editable_review_pass_cannot_suppress_the_authority_replay` supplies the
ordinary recorded pass shape while all manager facts agree. Settlement runs,
but `PassingSession.pass_work` is called zero times. An editable evidence
member has therefore become an alternate authority fact.

Always replay the exact authority pass identity on the narrow retry. If a
recorded pass projection remains in evidence, hold it whole against the
authority's replay answer; otherwise remove it from the trusted input. The
file may identify what to replay but cannot prove the pass happened.

## [P1] The nested hold still omits retry-owned history

The prior review explicitly required the trusted result, manager projections
and retry-owned history to be held. `_held_record` does not validate
`unresolved`; `historical = list(evidence["unresolved"])` therefore leaks a
raw `TypeError` for an editable boolean.

The existing malformed-record table now includes `unresolved=True`. The five
projection subcases pass, while this sixth subcase errors. Hold `unresolved`
as the bounded list of durable text this retry consumes, and hold every other
nested member used to decide or report the retry rather than stopping at the
members named by the first witness.

## [P1] Manager ownership did not close the proof/use interval

`adopted_assignment_workspace` applies the right read-only no-link checks and
returns `AllocatedRoots` containing ordinary path strings. `_for_retry` hands
those strings to `OciAdapter`, which later reopens them and derives the
credential home from the workspace pathname. Moving the check to its grammar
owner removes the duplicate rule; it does not make a check and later open one
identity hold.

This is the same class now independently reproduced at W43975's destructive
root seam: a path replaced after proof is followed at use. Finish this
boundary with a manager-owned adopted-root capability whose use preserves the
proved identity, or an equivalent no-follow use immediately at each consumer.
Do not claim the check-then-open race closed merely because the checking
function moved modules.
