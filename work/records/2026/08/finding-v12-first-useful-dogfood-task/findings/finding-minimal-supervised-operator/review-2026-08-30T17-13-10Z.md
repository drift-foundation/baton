## [P0] The test does not produce a failed handoff through the operator

`ThePublicRetryRunsFromRealDurableState` says it "fails the handoff", but its
setup never calls the ordinary operator or any failing `pass_work`. Instead,
`durable_failed_handoff()` obtains real manager freeze/intake/retention state,
manually assembles the rest of the evidence document, sets `resolved=False`,
and writes the sentence "the manager declined to end the attempt" itself.
The first authority handoff that actually runs is the successful retry.

That is stronger than the old all-mock test on the retry side, but it still
does not satisfy the standing P0: build the failed-handoff durable state by
executing the public ordinary path, let that path write its retained evidence,
then enter public `main(... --retry-handoff)` through fresh capabilities. A
record that the test composes to look like a failed handoff cannot prove that
the real failure path produces a retryable record. Drive an injected handoff
failure through the ordinary command over the real manager/authority state,
then reuse only its actual grants and evidence outputs for the fresh retry.

## [P0] The retry still does not complete manager settlement

The previous review's gate explicitly required exact authority pass **and
complete manager settlement**. The new test requires the opposite outcome:
its evidence must still contain "declined to end the attempt", its process
status must be 1, and the progress record says settlement "does not complete".
The real authority pass is now proved, but the second half of the same close
gate remains absent.

The real-Docker ordinary arc is not a substitute for a retry settlement across
fresh capabilities; it does not exercise this retained failed-handoff state or
the public retry command. Extend an appropriate real arc, or supply an
equally real fresh ending boundary, so the retry converges the manager's
durable state and writes `resolved=True`/exit 0 while still proving no second
worker-side act. Until then the progress statement that root identity is the
only remaining close gate is incorrect.

## [P1] Manager-proved root identity is still flattened before adapter use

This gate is accurately acknowledged as open. Both `_for_retry` and the
ordinary `adapter_of` convert the manager's `AllocatedRoots` to `dict` before
constructing `OciAdapter`. The adapter later reopens caller-held path strings,
so the manager's proof and immutable nominal identity do not survive to the
use boundary. Preserve that identity through every adapter consumer or move
the no-follow use behind a manager-owned operation, as the standing review
requires.

## [P1] The new public retry leaks both opened databases

`_for_retry` opens an `Authority` and a `ControlStore`, returns only a session
and the store inside an ordinary dictionary, and `_retried` never closes
either. The new focused case emits unclosed-database `ResourceWarning`s. With
tracemalloc enabled, the allocation traces end at:

- `dogfood_operator.py:2343` — `Authority.open(...)`;
- `dogfood_operator.py:2345` — `ControlStore.open(...)`.

The standalone command eventually gets process-exit cleanup, but `main()` is
also the public callable the suite and a supervisor can invoke repeatedly;
deterministic release must not depend on garbage collection or process exit.
Give the fresh capability construction an owned cleanup boundary and exercise
both success and refusal paths without resource warnings.
