## [P0] A committed intake receipt is hidden until after fallible work

In `_custody`, `receipt = request_intake(...)` is followed by all of these
before `evidence["intake_receipt"] = True`:

1. converting `receipt["artifacts"]` to a list;
2. rejecting an empty artifact set;
3. recomputing the independent diff and launching verification;
4. calling `decide_retention`.

The empty-artifact branch raises `_Lost`; verification can time out or fail to
launch; and retention can refuse. Each reaches `_ended_however`, but that
function selects cleanup from the late evidence boolean rather than from the
already committed receipt. It therefore appends the false statement that no
intake receipt exists and never calls `authorize_cleanup`.

This is not merely an evidence-field ordering issue. The receipt is the
manager's durable authorization and was committed before any of those later
steps. Record its presence immediately after `request_intake` returns, before
reading its artifacts. Then every later `_Lost`, typed refusal or unexpected
failure reaches the receipt-authorized cleanup in `finally`. Add the same
coverage for verification failure/timeout and a retention refusal so moving
the flag past another fallible step cannot recreate the interval.

The additive
`test_an_empty_intake_receipt_still_authorizes_cleanup` drives a successful
work disposition, quiescence, freeze and an empty committed intake receipt.
It fails because `authorize_cleanup` is called zero times.

## [P0] The W44716 ending must fence before stopping an unanswered worker

The prior review required the lost/no-disposition branches to enter an ending
and measured that with a stop call. W44716 research supersedes that incomplete
expectation: `request_cancellation` establishes the invariant in its own
public contract that the exact authority generation is fenced before the
agent and runtime are ordered to stop. A lost worker-entry conversation says
explicitly that the manager cannot know what the worker did; it does not make
the still-live assignment safe to stop.

`_ended_however` currently calls `adapter.stop` directly while M44657's normal
authority transition is still pending and before any cancellation/abandonment
fence. That is acceptable on the successful-disposition path only as the
quiescence step needed for freeze; it is not an honest failure ending for an
unanswered worker. W44716 is now blocked on an approver ruling for an explicit
abandonment record/fence/receiptless-destroy operation versus widened
cancellation. W39358 must depend on and consume that public operation for
these branches, not keep a direct stop-before-fence workaround.

The prior stop-count regression should be revised when W44716 lands to assert
the authority fence and manager-owned retained cleanup ordering. Until then,
an unresolved named runtime is honest; reporting a safe ending is not.

## [P2] The no-disposition fixture is not a possible `converse` answer

The second existing subcase mocks `converse` as `ending="answered"` with only
a `describe` answer even though the caller requested `describe` and `work`.
The real transport returns `answered` only after every requested operation
answered successfully. Its work-answer member set requires `disposition`, but
does not type the value, so the reachable defensive case is a `work` answer
whose disposition is `None` (or another value `_disposition_of` cannot use).
Drive that shape rather than a transport document the real component cannot
produce.
