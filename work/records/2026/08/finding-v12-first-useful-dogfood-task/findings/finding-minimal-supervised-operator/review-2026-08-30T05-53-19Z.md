## [P1] The manifest records paths below a retired `workspace/` prefix

`input_manifest` records source destination `workspace/source` and output path
`workspace/proposal`. The current manifest contract interprets source
destinations relative to the fixed `/input` root and output paths relative to
the fixed `/output` root; `contracts/manifest.py` states that relationship
explicitly when checking overlap. The delivered worker independently reads
`/input/source`, and `ClaudeAgent.work` joins the declared output path directly
below `/output`.

The current document therefore says `/input/workspace/source` while the actual
delivery is `/input/source`, and asks the worker to write
`/output/workspace/proposal` instead of the parent record's accepted
`/output/proposal`. The claim that `sources[].destination` is consumed by
nothing also needs a recorded supersession: it is not a materialization
instruction in this build, but it is read by the manifest rules and retained
as the durable description of the staged delivery.

The additive `test_manifest_paths_are_relative_to_the_two_fixed_roots` fails
for both source and output. Use `source` and `proposal` respectively, then
re-run the real input-root composer.

## [P1] `frozen_task` does not hold the worker's task contract

The operator promises to find a malformed task before a container starts, but
`frozen_task` validates only the member set, schema and `source_root`. It
accepts an integer `task_id`, list or empty `instructions`, and a scalar or
empty `verification`. W39357's `_task` rejects all of those inside the
container, so this foundation moves the promised refusal to the failed
provider attempt it was meant to avoid.

The additive `test_every_task_member_is_held_before_the_container_starts`
reproduces all five shapes. Hold the task id grammar, non-empty instruction
text and non-empty list-of-text verification at this first read, and keep the
operator/worker copies regression-held against one another.

## [P1] The claimed preflight happens after staging and validates only keys

`input_manifest` requires the already-produced `staged` manifest, so its
policy check cannot establish the recorded claim that incomplete policy
identity is found "while nothing has been staged." The existing incomplete-
policy test itself calls `stage_source` first. The check also validates only
the seven key names: `policy_digest="not-a-digest"` is accepted here and left
for the manager to refuse later.

The additive `test_a_policy_value_that_is_not_a_digest_is_refused_here` proves
the value gap. Before the arc is built, give it one pure preflight that holds
all explicit task, policy, image, toolchain, record and network operands before
`stage_source` writes anything; then compose the manifest from those held
values and the staged result. Supersede the current stronger-than-code ruling
rather than leaving both accounts live.

The exported `stage_source` surface also takes caller-selected
`max_entries`/`max_bytes` and forwards them unchanged, so callers can widen
the module's stated ceilings. Retain lower test bounds if useful, but clamp or
refuse any value above the operator constants before the real command depends
on this helper.
