## [P1] Record-binding locators do not use the frozen manifest grammar

The input manifest types `record_binding.root` as `opaqueId` (1–160 characters,
closed character grammar) and `record_binding.path` as `relativePath` (1–512
characters, with absolute, empty/dot/dotdot segments, doubled separators,
backslash and NUL forbidden). `_held_identities` instead accepts any non-empty
string as the root and applies `posixpath.normpath` plus only a few exclusions
to the path.

Consequently preflight accepts roots containing spaces or 161 characters, and
paths equal to `.`, containing a backslash or NUL, or containing 513
characters. `_sealed` later drives the assembled input manifest through the
frozen schema and refuses those values, but by then `stage_source` has already
created the delivery. That preserves exactly the interval preflight exists to
remove, and the third-round record's statement that both locators are now held
by value is stronger than the code.

The additive
`test_record_binding_locators_use_the_frozen_manifest_grammar` fails in all six
subcases. Use the public frozen-contract owner — `validate_fragment(value,
"opaqueId")` and `validate_fragment(value, "relativePath")`, translating its
`ContractRefusal` to the deployment's collected fault — rather than maintaining
a second approximation in this tool. Apply the same `_held_identities` result
at preflight and at `input_manifest`, as the current composition already does.
