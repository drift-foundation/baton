## P0 — the named acceptance test still does not prove settlement

`ThePublicRetryRunsFromRealDurableState.test_the_documented_retry_recovers_a_handoff_the_command_failed`
calls the public retry and discards its return status. It then proves only the
authority pass and the absence of a second worker-side act. It never reads or
asserts the retry's `resolved`, `cleanup`, or `unresolved` result.

The implementation record confirms the omitted fact: the fresh retry reaches
the ending but does not complete manager settlement because this fixture has
no real engine/runtime for the custody helper. An exit-1 retry with unresolved
cleanup therefore satisfies the test currently named as the last acceptance
gate.

Required: drive the public retry through fresh real capabilities to exact pass
AND complete manager settlement, assert exit 0, `resolved == true`, empty
current unresolved reasons, complete cleanup and positive runtime absence,
while retaining the no-worker-side-act assertions. A fixture that merely
ignores the unfinished ending is not this acceptance boundary.

## P1 — adopted-root proof is still discarded before use

Both adapter constructions still flatten manager-provided roots:

- retry: `assignment_roots=dict(_proved_roots(given))`
- ordinary launch: `assignment_roots=dict(roots)`

`AllocatedRoots` carries provenance/behaviour, but these calls retain only
mutable path strings which `OciAdapter` later reopens. The manager-owned
adoption check is therefore still separated from use by pathname
re-resolution. This is the unchanged identity-through-use gate; do not close
it by adding another path check.

Required: define and consume a manager-owned capability that preserves the
proved root identity through every adapter use, for ordinary launch and
restart, without flattening to names and reopening them.

## P1 — the ordinary launcher leaks its durable handles

The focused 122-test run emits an unclosed SQLite `ResourceWarning`.
Tracemalloc identifies the allocation exactly:

`test_dogfood_operator.py:749 -> dogfood_operator._launched -> Authority.open`

`_launched` opens an `Authority` and a `ControlStore`, returns neither owner
nor a closure bundle, and `main` has no `finally` for the ordinary path. The
positive launcher test manually closes only the store through `open_store`,
which is why the authority warning remains; the real command closes neither.

Required: make ordinary capability ownership explicit and close every handle
on success, unresolved return, and exception. Add a resource-lifetime
regression over the public ordinary command rather than teaching only the test
to clean up production-owned objects.
