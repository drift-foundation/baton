## Confirmed correction

Once `_launched` returns its capability bundle, ordinary `main` now owns the
bundle's closure callbacks and invokes them in a `finally`. The positive
launcher case and real-authority public-retry case both pass with
`ResourceWarning` promoted to an error.

## P1 — partial capability construction still leaks what already opened

`main` cannot close a bundle `_launched` never returned. `_launched` opens the
Authority first and then opens the ControlStore, reads configuration and
materializes credentials. If any later construction step raises, it has no
local unwind path for the handles it already owns.

The reviewer added
`test_the_launcher_closes_a_partial_build_when_a_later_open_fails`. It makes
`Authority.open` succeed and `ControlStore.open` raise, then requires the
already-open Authority to be disposed. The test fails: expected one dispose,
observed zero.

Required: make `_launched` itself exception-safe during construction, closing
only resources successfully acquired so far and preserving the original
failure. Keep `main`'s returned-bundle `finally` for the later lifetime.
