not a Claude-specific protocol member. A test-owned Docker build context can
provide that same path and call the unchanged
`baton_worker.main(agent=<deterministic fixture agent>)`. The fixture agent can
write the declared proposal tree deterministically; it need not impersonate a
provider or stand in for W39364's live acceptance.

- the documented ordinary and `--retry-handoff` public commands;
- fresh authority and control-store capability construction;
- the real Docker daemon, `EnginePort`, `OciAdapter`, exec transport and
  `/opt/baton/dogfood_entry.py` binding;

- real freeze, intake receipt, retention decision, custody-helper settlement,
  destroy and positive absence.

Only the provider agent is deterministic, which is the correct test boundary:
this gate is about lifecycle settlement and retry, while W39364 exclusively
owns a live Claude turn and its human credential/network grants.

test-owned deterministic agent/entry into a temporary Docker build context.

to the declared proposal and writes the expected metadata files. Cause the

the command; trusted completed worker result; exact authority pass; complete
manager settlement; resolved evidence; retry exit zero; runtime, launch and
credential cleanup with positive absence; and no second worker act.
