## Findings

### [P1] The provider timeout is no longer a bound when a descendant inherits stdout

`ClaudeAgent._ran_provider` closes only the adapter's write descriptor and then
waits without a deadline in `reader.join()` (`v12/worker/claude_agent.py:449-462`).
If the direct provider starts a descendant that inherits stdout and then exits,
that descendant still owns the pipe's write end. The direct provider has
completed, but the reader never sees EOF until the descendant exits; an
arbitrarily long-lived descendant therefore wedges the worker after `_run`
returns and bypasses `PROVIDER_SECONDS` entirely. The same mechanism can hold
after `subprocess.run` times out and kills only its direct child.

**Observed reproduction.** A direct Python child spawned a five-second
grandchild inheriting stdout and then exited immediately. Calling
`_ran_provider(..., seconds=10)` under an independent two-second process bound
was killed by that outer bound (`exit 124`) without returning. The existing
real-child flood case proves continuous draining while the direct child owns
the descriptor, but it does not exercise an inherited writer.

**Required correction.** Make completion of the drain bounded independently
of EOF from provider descendants while still draining bytes already available
through direct-child completion and retaining at most 64 KiB. Add a real-child
regression whose leader exits while a longer-lived descendant inherits stdout;
the adapter must return promptly, publish only the closed fallback when the
record cannot be proved complete, and not leave an unbounded reader wait.

### [P1] The parser does not implement the approved malformed-JSON fallback

`_failure_reason` calls Python's permissive `json.loads` and catches only
`UnicodeDecodeError` and `ValueError` (`v12/worker/claude_agent.py:678-684`).
Two provider-controlled records escape the approved rule that every malformed
or unusable document becomes `unclassified`:

- `{"terminal_reason":"api_error","x":NaN}` is not JSON, but Python accepts
  the non-standard constant and the adapter publishes `api-error`.
- A bounded 60,001-byte record made from 30,000 nested arrays raises
  `RecursionError`, which escapes `_failure_reason` and faults the worker
  instead of publishing `unclassified`.

This is not raw-byte disclosure, but it makes the supposedly strict parser a
false-classification and availability surface controlled by the provider. The
current malformed cases cover syntax errors and trailing data but not Python's
accepted extensions or parser resource exceptions.

**Required correction.** Reject non-standard JSON constants explicitly and
turn bounded parser depth/resource failures into the same fixed
`unclassified` result without interpolating an exception. Add focused cases
for `NaN`, positive/negative infinity, and a maximally nested record below the
retention ceiling.
