## P2: finally joins return states into paths that continue to a later read

`Assignments.visit_Try` merges continuing, ended and escaping states before
visiting finally. It then assigns the resulting combined map to each pending
loop exit (`exit[1] = dict(origins)`). When a normal path also exists it keeps
that same combined map for fallthrough. Different exit destinations therefore
borrow each other's origins even when finally is only `pass`.

With `_view(row)` returning row["identity"], independent fragment:

```python
def public(connection, supplied, condition):
    row = None
    for item in supplied:
        try:
            row = connection.execute("SELECT * FROM first").fetchone()
            if condition:
                break
            row = connection.execute("SELECT * FROM second").fetchone()
            return None
        finally:
            pass
    return _view(row)
```

Only first.identity can be read after this loop. A path holding the second row
returns None from public and cannot reach _view. The candidate nevertheless
reports both first.identity and second.identity and includes both in public's
return summary. Zero iterations leaves None and cannot justify the second
origin. This is a false attribution caused by the new pending-exit rewrite;
the predecessor lost the break read entirely rather than reporting it correctly.

A second fragment isolates the same defect without a loop:

```python

    row = None
    try:

            return None

    finally:
        pass

```

Here only second.identity reaches _view; both versions report first.identity
as well. This part remains from the prior finally-state join. The two examples
are one defect: origins reaching finally must not be indiscriminately transferred
to every destination after finally. The inventory promises actual-origin and
unrelated-origin controls, not invented member reads from terminal paths.

Requested correction: retain the pending destination alongside each state

actually execute there; after finally, return/raise states must not become
break or ordinary continuation states. Add both fragments as negative controls,
