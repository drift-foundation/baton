The bridge now enforces a wall-clock turn deadline, rotates the agent process

## [P0] The designated launcher verifier accepts a mount-only launcher

`successor/verify.mjs` tests `launcher.includes(flag)` for
`--unshare-pid` and `--die-with-parent`. Both strings also appear repeatedly
in comments in `launch-agent-sandboxed.sh`. Removing both flags from the
executable `ARGS` line therefore leaves both verifier predicates true:

```text
launcher with ARGS=(--dev-bind / /)
[ true, true ]
```

This is the one enforcer the implementation clarification assigns, because the
ACP-generic bridge deliberately does not inspect `agent.command`. Its false
positive therefore admits the exact mount-only launcher that lets `setsid`
tools survive. Parse or execute a closed launcher contract rather than search
free text, and add a negative verifier regression that removes the functional
flags while retaining the explanatory comments.

## [P0] The operator procedure cannot install or preflight this staged set

`successor/INSTALL.md` was not updated. Its policy installation commands do
not install `preflight-process-domain.sh`, although the template now lists the
installed path as a required policy resource. Its preflight section also never
runs the service-context process-domain probe. Following the documented
cutover therefore produces a configuration that refuses startup as missing or
unreadable, without ever testing the approved kernel boundary. Independent
validation of the staged template against the current installed paths refused
exactly this missing resource.

Add the reviewed script to install, byte-comparison, rollback/reconciliation,
and service-context preflight steps. The process-domain preflight must run
before the changed launcher/template can be activated, and a nonzero result
must keep dispatch paused.

## [P1] The preflight and green suite do not prove descendant teardown

The preflight runs `echo $$` inside bubblewrap and accepts PID 1 or 2. That
proves namespace creation, but it does not prove the acceptance invariant:
that terminating the bridge-owned outer process removes a detached/session-
leader descendant and that exit of the outer owner positively implies the
domain is empty.

The only real descendant case in the 87-test suite deliberately observes the
`setsid` descendant survive, kills it from the test, emits a diagnostic, and
still passes. Thus the handoff's “real-descendant case” is a diagnostic of the
unexercised boundary, not positive acceptance evidence.

Strengthen the service-context preflight or add an operator trial that launches
the exact staged wrapper, creates at least one detached/session-leader and one
busy descendant, terminates the bridge-owned domain owner, awaits its exit,
and proves both descendants absent while an unrelated process remains. Record
that result before acceptance; this managed sandbox's exit-3 namespace refusal
cannot substitute for it.

## [P1] Large valid timeout operands collapse to a 1ms deadline

Validation accepts every positive safe integer. Node's timer range is only a
signed 32-bit millisecond interval: `2147483648` passes `validateConfig`, then
`setTimeout` emits `TimeoutOverflowWarning` and uses 1ms. An explicit operator
choice can therefore become the opposite deadline without refusal.

Reject values above the runtime timer ceiling (and document the maximum), or
implement a bounded long-duration timer without narrowing. Add the exact
`2147483647`/`2147483648` boundary cases.

## [P1] The “chatty infinite turn” case emits invalid ACP updates

The fake agent's `tool_call_update` lacks required ACP members. During the
independent run, the SDK repeatedly reported `Invalid params`; the update never
reached `clientHandler`. The case still reaches the wall-clock timeout, but it
does not prove that valid streamed activity cannot extend it. Emit a valid ACP
tool update, assert that the bridge observed at least one update, and then
assert the same deadline outcome.
