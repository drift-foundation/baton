`pgrep -f` tokens. Those tokens occur inside the shell program passed as an
argument to `bwrap`, so the outer `bwrap` process itself satisfies both
"descendant started" checks. Once that outer process exits, both tokens are
absent and the script calls that absence successful reaping.

Independent reachability proof used a PATH-local stand-in named `bwrap` whose
entire body is:

```sh
#!/bin/sh
while :; do sleep 1; done
```

It creates no PID namespace and no child processes. Nevertheless the
unchanged staged preflight exits 0 and reports:

```text

both an escaped (setsid) and a busy descendant when the domain owner exits,
and leaves an unrelated process untouched
```

`/tmp/w28681-preflight-false-positive/`. This is the mandatory service-context
acceptance gate, so a green operator run cannot currently prove the boundary.
Have the inner processes publish exact host-visible identities through files
or another channel that cannot be satisfied by the owner's argv, then prove
those exact identities alive before owner termination and absent afterwards.
Add this no-descendants/owner-argv negative case to the gate's reachability
proof.
