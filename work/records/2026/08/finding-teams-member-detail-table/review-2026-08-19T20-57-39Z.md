# Independent review — changes requested

## Finding

### R1 — partial poke telemetry renders Python `None`

`answer_poke` deliberately allows `context_used`, `context_limit`, and
`context_remaining` to be supplied independently. `_detail_answer` checks
whether any telemetry value is present, then emits all three with `str(value)`.
Consequently, a valid answer carrying only `context_limit=200` renders:

```text
Context used       None
Context limit      200
Context remaining  None
```

`None` is an implementation-language value, not Baton's absent-value
vocabulary. It also violates this record's requirement that missing and absent
facts remain explicitly distinguishable without guessing or reassuring
substitution.

## Required correction

- Preserve the three independently discoverable keys whenever any telemetry is
  present.
- Render each absent telemetry value with the TUI's explicit `-` vocabulary;
  do not infer it from the values that are present.
- Make no projection, transition, schema, or protocol change.

## Regression

The additive
`test_partial_poke_telemetry_never_renders_python_none` reproduces the gap and
must pass unedited. Current result: **1 failed**, with `Context used` equal to
`None` instead of `-`.

## Other review observations

- The key/value grouping, shared value column, wrapping, long-key fallback,
  section boundaries, exact published log locator, and explicit unpublished-log
  row match the recorded design.
- An explicitly ended lease retains its incarnation and therefore renders as
  `offline (reported)`; only a participant with no lease row receives the
  “never published runtime state” sentence. No false historical claim was
  found on that boundary.
- The short-terminal disclosure is an honest presentation fallback and does
  not invent scrolling behavior outside this Work.

## Disposition

Changes requested. Return W184 to `baton.impl`; rerun its focused and adjacent
suites and the complete v11 gate after correcting R1.
