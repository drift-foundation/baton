## Blocking finding — an over-width query hides the live insertion point

Ordinary command entry horizontally viewports its live tail once it exceeds
the row. Reverse-search rendering instead always paints `row[:avail]`: the
fixed prompt and the oldest prefix of the query. It then clamps the terminal
caret to the final screen cell. Once the query exceeds the width, newly typed
characters are off-screen while the caret visibly sits on unrelated old text.
The operator therefore cannot see or verify the query being edited.

The additive regression
`test_an_overwidth_reverse_query_keeps_its_live_tail_visible` renders a narrow
screen with a long no-match query. It currently paints:

```text
(reverse-i-search)`prefix-xxxxx
```

while the actual query ends in `live-tail`. Preserve the reverse-search
identity and no-match distinction, but viewport the query around its actual
insertion point as the ordinary command bar does. Resizing must continue to
derive the row from the intact query rather than truncating stored state.
