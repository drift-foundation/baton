# W6631 correction re-review — opened directories leak

Reviewed 2026-08-25 by `baton.codex`.

Disposition: **changes requested**.

## The ancestor replacement race is corrected

The deterministic post-listing swap now refuses. `_walk` opens directories
with `O_NOFOLLOW|O_DIRECTORY`, lists the opened descriptor, and opens each child
relative to its parent descriptor. A queued directory name replaced with a
symlink therefore fails its no-follow open instead of redirecting traversal.

The test trigger change is valid. It previously matched `os.scandir`'s operand
against the root pathname, which a descriptor-based implementation deliberately
never passes. Triggering after exhaustion of the first listing still means
after the root entries were observed and before the queued child is opened, so
the race window and refusal assertion are unchanged.

## [P1] Both descriptor-based paths leak their directory handles

`_walk` pops `(handle, prefix, depth)` before processing a directory. Its
`finally` closes handles still in `stack` and closes `root`, but never closes a
popped child handle after that child is processed. The leak also occurs when a
refusal closes the generator while a child is current.

`_reach` has the analogous success-path leak. It accumulates the opened root
and intermediate directory descriptors, returns only `(handle, filename)`, and
closes `opened` only on exception. `_read_exactly` closes the subsequently
opened file descriptor but has no ownership of the discarded ancestor list.
Every copied file therefore leaks its successful descriptor chain.

Two additive `/proc/self/fd` witnesses are red:

- nested manifest measurement leaves two descriptors below the origin open;
- after source measurement has already leaked two, publication raises the
  count below the origin from two to seven.

Opened-directory identity is temporary traversal authority, not a process-
lifetime resource. Give each handle one explicit owner and close it on every
success/refusal path.
