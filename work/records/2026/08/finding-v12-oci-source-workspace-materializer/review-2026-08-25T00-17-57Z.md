## [P1] A child replaced after listing is followed outside the source

The required follow-up is not implemented. `_walk` stores `entry.path` after
the parent listing and later calls `os.scandir` on that pathname. Its
final-component file open uses `O_NOFOLLOW`, but the raced symlink is an
ancestor, so opening `origin/deep/secret.txt` follows it before the final
component is reached.

The additive
`test_a_directory_swapped_after_listing_is_not_followed` deterministically
plants the link after the root listing has yielded all entries and before the
queued child is descended into. The current code accepts and measures the
outside tree; no refusal is raised.

The existing `test_an_ancestor_directory_swapped_for_a_link_is_refused` moves
the directory before `directory_manifest` starts. It proves visible links are
refused, not the required replacement window, and its docstring's statement
that traversal uses opened directory identity is not true of `_walk` yet.

Bind descent to opened directory descriptors with no-follow semantics, or an
equivalent mechanism that prevents a queued name from becoming authority.
