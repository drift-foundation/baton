## Findings

### [P1] A post-listing FIFO replacement still blocks the manager

`workspaces._read_exactly` opens a worker-controlled entry with
`O_RDONLY | O_NOFOLLOW` at `workspaces.py:395`, then checks the descriptor's
kind. `O_NOFOLLOW` protects only against a final symbolic link. If the entry
was regular when `_walk` listed it and becomes a FIFO before this open, the
open blocks waiting for a writer and the `fstat` refusal is unreachable.

The two new FIFO cases do not establish this interval. Both create the FIFO
before `_walk` lists it, so `entry.is_file(follow_symlinks=False)` refuses it
without opening it. The mutation harness likewise has no mutation removing a
nonblocking source-file open because that guard is absent.

Reviewer evidence:

```text
$ python3 evidence/w26283-review-fifo-race.py
BLOCKED: the post-listing FIFO replacement hung os.open
exit 1 (child bounded at three seconds)
```

Required correction: add `O_NONBLOCK` to the source-file descriptor open,
retain the descriptor-level regular-file proof, add a bounded regression that
replaces the entry after listing, and add a mutation that removes the flag.
The focused finding explicitly requires a nonblocking regular-file read and
race coverage, so this blocks sign-off.
