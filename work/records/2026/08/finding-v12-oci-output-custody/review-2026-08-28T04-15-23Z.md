## [P1] Byte and entry limits do not bound the source read

`workspaces._read_exactly` checks `fstat().st_size` once and then calls
`_read_all`, which loops until EOF with no byte operand or ceiling. A worker
can grow the already-open regular file after the size check. The manager then
keeps allocating and reading beyond both `MAX_BYTES` and the output's declared
`max_bytes`; `copied_manifest` checks `len(content)` only after the whole read
returns. A continuously growing file can prevent that refusal from being
reached at all. This is the regular-file analogue of the just-fixed blocking
FIFO: a guard after an unbounded operation does not bound that operation.

The entry limit is ordered the same way. `copied_manifest` calls
`_read_exactly` and only then checks whether this file crosses `MAX_ENTRIES`
or declared `max_entries`. The over-limit file is therefore read before the
manager refuses it.

Deterministic evidence is
`evidence/w26283-review-read-bounds.py`. With `MAX_BYTES=8`, a size initially
observed as one byte supplied 64 bytes and EOF through the open descriptor;
the manager consumed all 64 before refusing. With declared `max_entries=1`,
both files `a` and `b` were read before the second was refused:

```text
byte ceiling 8: source returned 64 bytes across 65 reads before refusal
entry ceiling 1: source files read before refusal: ['a', 'b']
exit 1
```

Required correction:

- check global and declared entry ceilings before opening/reading the next
  file;
- give the descriptor reader the smaller remaining global/declared byte
  allowance and read at most allowance plus one byte, so growth after `fstat`
  cannot widen work or memory;
- retain the existing taxonomy and precedence: a global ceiling is
  `policy/denied`, a delivery's declared ceiling is `integrity/limit`, and an
  equal crossing preserves the current global-first decision;
- add bounded regressions for growth after `fstat` and for no read of the
  over-entry file; and
- extend the mutation harness to remove each pre-read/limited-read guard. The
  current 13 mutations cover the FIFO flag but not these two bounds.

This is within the dossier's existing acceptance: source reads are bounded,
and staging occurs under explicit size and entry limits. It does not import
quiescence, credential, or lifecycle-settlement ownership.
