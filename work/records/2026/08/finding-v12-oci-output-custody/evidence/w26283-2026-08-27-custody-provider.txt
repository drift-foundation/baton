=== 2. [P1] THE SEVENTH DID NOT HOLD, AND I PROVED IT RATHER THAN READ IT

  Staging measured with W6631's race-safe walker -- which descends by
  OPENED DIRECTORY IDENTITY and opens every file O_NOFOLLOW relative to
  that descriptor -- and then copied by REOPENING each path with a plain
  open(), resolving every component a second time.

  Two harms, both driven against the real code. The reproduction is kept
  beside this file as evidence/w26283-pre-fix-reproduction.py and still
  demonstrates both against the pattern:

    measured entries: [('deep/a.txt', 11)]
    custody now holds: 'HOST FILE THE WORKER MUST NOT REACH\n'
    >>> the manager read and copied a file from OUTSIDE the workspace
    >>> TIMED OUT: one mkfifo stalls the copy indefinitely

  The second one is the sharper harm: one mkfifo stalls the manager
  indefinitely. It is the SAME failure _read_without_following added
  O_NONBLOCK to prevent for output.json, reintroduced one function away.

  This is the third appearance of one defect class in this module. Its
  own walker records having fixed it once -- 'a no-follow open of the
  FINAL file does not stop a raced ANCESTOR from becoming a symbolic
  link' -- and the completion envelope was corrected for it separately.
  Staging is where it survived, and it is the place the acceptance names
  directly: the sealed manifest must describe the manager-custodied
  bytes, 'not a path later reopened from worker storage.'
