=== C. THE [P1] RACE: A LISTED FILE THAT BECOMES A PIPE

  The review is right and the finding's own obligation list said so from the
  start. `O_NOFOLLOW` refuses a final symbolic link; it says nothing about a
  name that was a regular file when the walk LISTED it and is a FIFO by the
  time `_read_exactly` opens it. That open blocks waiting for a writer, so the
  descriptor-level `fstat` refusal below it -- the one guard a racing
  replacement cannot defeat -- is never reached. One `mkfifo` in
  worker-owned storage stalls the manager indefinitely.

  THE FIX, at the open:

    descriptor = os.open(name,
                         os.O_RDONLY | os.O_NOFOLLOW | os.O_NONBLOCK,
                         dir_fd=parent)

  The regular-file proof on the descriptor is unchanged and is what refuses.
  On a regular file the flag costs nothing: regular files are always ready,
  and the kind is proved before a byte is read either way.

  WHY MY OWN REVALIDATION MISSED IT, stated plainly. Section 1 of the handoff
  evidence lists "bounded no-follow nonblocking read -- O_RDONLY|O_NOFOLLOW|
  O_NONBLOCK, and S_ISREG on the DESCRIPTOR" among the six obligations the
  provisional code met. That was true of ONE of the two places this manager
  reads worker-controlled bytes: `sealing._read_without_following`, for
  output.json, which carries the flag and a comment recording that without it
  "the case covering this rule does not terminate". The walker's file read
  never had it. I checked the obligation, found it established, and did not
  ask whether it was established at BOTH sites -- so a rule this module had
  already learned once, and written down, was absent one function away. The
  evidence even says of the copy defect that it was "the SAME failure
  _read_without_following added O_NONBLOCK to prevent for output.json,
  reintroduced one function away", and I wrote that sentence about the copy
  without turning it on the read.

  THE REGRESSION, and why the existing FIFO cases did not establish this.
  Both existing cases create the FIFO BEFORE the walk lists it, so
  `entry.is_file(follow_symlinks=False)` refuses it without ever opening it --
  they establish that the walk refuses what it SEES. The new case interposes
  on the REAL walk at the yield boundary, so the entry really was accepted as
  a regular file by the code under test, and the parent directory descriptor
  is unchanged by the replacement, which is what puts the FIFO exactly where
  the open will land.

    tests.manager.test_workspaces
      TheCopyIsTheMeasurement.test_a_file_replaced_by_a_pipe_after_listing_does_not_block

  It is BOUNDED with SIGALRM. A regression here is a HANG rather than a
  failure, and a hanging case takes the whole gate with it; the alarm raises
  out of the blocked syscall so the case fails in three seconds instead of
  never. That bound is also what makes the mutation below measurable rather
  than a 900-second stall.
