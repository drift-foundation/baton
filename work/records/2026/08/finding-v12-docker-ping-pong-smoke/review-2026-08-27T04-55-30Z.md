## Findings

### P1 — a JSON value outside the expected provider type raises instead of refusing the shape

`FACT_RULES["provider"]` evaluates `value in CREDENTIAL_TARGET` without first
holding `value` to a string. A valid JSON array therefore raises `TypeError:
unhashable type: 'list'` from `_closed_shape()` instead of returning `False`.
Because the output is worker-authored, the closed-shape validator must be total
over every JSON value, not only over the values the current wrapper emits.

Require an exact string type before dictionary membership and keep a regression
that malformed-but-valid JSON is refused without losing the structured host
report.

### P1 — successful tag removal is still treated as proof that the image identity is absent

Cleanup records an immutable `image_id`, removes only the unique tag, and then
queries `docker image ls` only by that now-removed tag. It adds the recorded id
to survivors only when the removal command itself fails. If Docker successfully
untags an image that remains under another reference, the tag query is empty,
`image_removed` is true, and the trial reports `clean: true` and satisfying
while the recorded image identity still exists.

Query the recorded image identity after every removal attempt. A surviving id
must appear in `images_surviving` and prevent clean success, even when tag
removal returned zero. This also resolves the stale source comment claiming an
immutable-id query that the implementation does not perform.
