## Findings

### P1 — the closed result validates names, not the facts or success/failure branch

`_closed_shape()` proves only required/extra member names. It does not validate
the members' value types. A document with textual `result_bytes: "four"` is
allowlisted to `null`, retains `closed_result_shape: true`, and can satisfy the
trial because byte counts are not otherwise part of the verdict.

The two supposed shapes are also not disjoint: any recognized
`failure_category` is accepted regardless of the document's exit/digest facts.
A zero-exit exact-pong document carrying `failure_category: authentication`
therefore returns satisfying success, despite being neither the success shape
nor a truthful failure shape.

Hold every required fact to its bounded type/grammar and make the branches
exclusive. The success shape has zero provider exit, exact pong digest and no
failure category. The failure shape has a recognized category and at least one
failed provider-exit or answer condition. Preserve the host's separate
container-exit and correlation checks.

### P1 — provider-specific readability is collected but still not in READY

Preflight now builds `nominated_per_provider` for the exact `claude` and
`codex` paths beneath a nominated directory, but `ready` still consults only
the root's presence/readability. A readable empty nominated root prints READY
and exits zero while both exact provider entries are absent.

Require both paths each trial will actually mount to be present and readable
by uid 65532. If a different layout is allowed, accept explicit provider-
specific operands rather than treating one readable generic root—or one file
that cannot represent both formats—as proof for both trials.
