## Finding

### P1 — a failed immutable-identity query is accepted as proof of absence

The new `docker image inspect <recorded-id>` call treats every nonzero result as
“the image is absent.” It then hard-codes `image_identity_query_ok = True`, and
`clean` does not consult that member. A query execution failure therefore has
the same meaning as a successful observation of absence. With the tag query
and every other operation succeeding, an identity-query status of 125 still
returns `clean: true`, `satisfying: true`, and process status zero.

This is the same fail-open observation boundary already corrected for
`docker ps` and the tag query. Use an identity/inventory query whose successful
empty result can be distinguished from query failure, record the real query
status, and require that status in `clean`. A failed identity query cannot
establish absence.
