## Findings

### P1 — allowlisting output is not validating the closed result

`allowlisted()` silently drops every unknown member. A document with all valid
facts plus raw `result`/`pong` members therefore remains satisfying. That keeps
unknown provider-chosen material out of the printed host report, but it does
not establish the first review's required closed result shape and it allows a
result file carrying forbidden provider text to be accepted as this harness's
own document.

The additive case supplies a valid exact-pong digest and zero exits beside the
two old unexpected members. The trial returns success. Refuse missing, unknown
or extra members against the one exact success/failure shape before deriving
the verdict; filtering is the durable-report boundary, not document validity.

### P1 — failed cleanup observations are treated as empty observations

The image-removal answer is now enforced, but the commands intended to prove
container and image absence are not. A failed `docker ps` or `docker image ls`
returns empty stdout, which becomes an empty survivor list; both additive cases
still report `clean: true` and satisfying success.

Include each cleanup query's zero status in `clean`. On timeout, the recorded
kill/removal statuses must participate too; merely recording them is not the
fail-closed treatment the review requested. Treating a failed image removal as
a surviving immutable id is safe, but the dossier/evidence must not call that
an actual immutable-id query unless one is performed.

### P1 — preflight reports readability but does not gate readiness on it

`ready` requires only Docker and nominated-path presence. A nominated provider
that `_described()` correctly reports as unreadable by uid 65532 still prints
`READY` and exits zero. The additive metadata-only case reproduces this without
opening the file.

For a directory provider, `_readable_by_container()` checks its read bit but
not its own execute/traversal bit; a mode `0444` directory is reported usable.
Require readability in the readiness predicate and require both read and
execute on a directory provider, plus execute on every ancestor. A generic
root such as `/run/baton/credentials` also cannot prove the provider-specific
files beneath it are readable; the operator preflight should assess the exact
path each trial will mount.
