=== 4. WHAT THE TWO RUNTIMES DO DIFFERENTLY AT THE WRAPPER BOUNDARY
  which is what the ruling asks this experiment to compare.

  CLAUDE reads a read-only credential provider and makes an
  AUTHENTICATION decision: 'Not logged in'. A read-only mount at
  $HOME/.claude is sufficient for it to get that far.

  CODEX will not start with its state directory mounted read-only:
    'failed to initialize in-process app-server client:
     Read-only file system (os error 30)'
  It writes beside its credential while running. The provider therefore
  has to be mounted as a FILE over auth.json, leaving the state
  directory writable -- which is why --credentials accepts both shapes.

  CODEX also refuses a HOME under /tmp outright:
    'Refusing to create helper binaries under temporary dir'
  The first version of the trial gave each runtime a fresh mkdtemp home.
  Claude accepted it; Codex would not run at all.

  AND BOTH need their state directory pre-created and owned in the
  IMAGE. Docker creates a missing bind-mount parent as ROOT, so a
  container running as an unprivileged uid got 'Permission denied'
  beside its own credential before reaching any provider.

  THAT IS DIRECTLY USEFUL TO W6634. Its approved credential delivery
  materializes assignment-private files at 0600 and mounts them
  READ-ONLY at a fixed root. On this evidence that shape works for a
  Claude-like runtime and does NOT work for a Codex-like one, and the
  file mode has to admit the container's uid rather than the host user's.

=== 5. TWO DEFECTS IN THIS HARNESS THAT ONLY A REAL RUNTIME FOUND
  A scripted echo worker would have found neither, which is the ruling's
  own argument for superseding it.

  (a) THE FIRST CODEX RUN HUNG PAST ITS OWN DEADLINE. The in-container
  timer fired and killed 'codex', but its child held the stdio pipes
  open, so Node's 'close' never arrived and nothing was published. The
  container was still up ten minutes later. Now: its own process group,
  killed as a group; settle on 'exit' rather than only 'close'; a grace
  timer that settles anyway; and a HOST-side bound that ends the
  container and records a 'timeout' category.

  (b) A trial that cannot end is worse than one that fails -- the
  operator has nothing to read either way and no reason to stop waiting.

=== 8. WHAT IS NOT PROVED, said plainly
  NEITHER TRIAL RETURNED A PONG. The ruling closes this Work satisfying
  only when both real agents return the correlated pong from inside
  their containers. They did not, because no credential provider has
  been nominated: /run/baton/credentials does not exist, and the
  operator's own runtime credentials are theirs to offer rather than
  mine to take. Choosing one would be exactly the 'weakening isolation'
  the ruling forbids, in the one direction it did not have to spell out.

  This is a PARTIAL RESULT and the ruling anticipates one: 'a partial
  result remains valuable experiment evidence but is not a satisfying
  two-provider proof'. It is recorded as exactly that.
