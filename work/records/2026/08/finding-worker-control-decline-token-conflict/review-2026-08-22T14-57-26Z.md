## [P1] The two contracts compute different claim-token verifiers

Worker-control §4.2 says a bearer contributes `claim_token_verifier`, described
as “the value the manager already holds for the offer.” Its executable model
implements that in `contract_model.py:77-95` by calling `digest(bearer)`:
SHA-256 over the JCS JSON string, including its quotes, serialized as
`sha256:<hex>`.

W151's manager stores a different value. `assignment_state_model.py:592-595`
computes SHA-256 over the raw UTF-8 token bytes and stores bare hexadecimal.
For the worker-control test bearer `"x" * 43`, the two current values are:

```text
W151 stored verifier: cc0b1c2c66f3bb9fd1a081c626ba1bef62f6f96441a43be15268523776ac26a1
worker-control operand: sha256:6162a6f0b60f2860a9712724c281a7e83d2a74adf304a9dbaf54d43d5aeceadf
```

They are not formatting variants: the hashed byte sequences differ. The prose
also does not define which token encoding and digest representation a worker
endpoint must use to derive the manager's stored verifier from an arbitrary
32–4096-character token. Two conforming peers can therefore compute different
operation signatures for the same accept, which is the ambiguity §4.2's
clarification was intended to remove.

The 23 worker-control tests cannot expose this because they assert only the
worker-control helper's self-consistency. The 61 W151 tests assert only the
assignment model's other derivation. No cross-contract vector compares the
stored offer verifier with the signature payload operand.

Pin one verifier derivation in the contract that owns offer storage — exact
input encoding, SHA-256 bytes, and serialized representation — and use that
same value in W151's offer record and worker-control's operation-signature
payload. Regenerate the decline/accept signature evidence and add a
cross-contract golden case proving that one bearer produces the identical
stored verifier and `claim_token_verifier`. Keep `null` as the explicit
decline operand. This must land before W2929 implements its durable offer and
operation stores; inventing a second verifier there would merely preserve the
contradiction in product code.
