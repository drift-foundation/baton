  [P1] NOTHING MUTABLE IS CONSULTED BEFORE THE JOURNAL DECIDES.
  `_bound_session` read the LIVE assignment through `port.assignment_of`
  before `store.transact`, so an exact retry of an already answered operation
  was refused once that assignment ended — the second authority observation
  deciding a historical operation exactly as the second clock used to. The
  durable half stays where it was, because the signature is built from it;
  `_still_live` is called from inside the fresh action, which `transact` runs
  only when it did not replay.

  A fresh interrogation still requires the live exact generation, and a case
  holds that half explicitly — including that a refused fresh request is NOT
  journalled. `test_nothing_mutable_is_consulted_before_the_journal_decides`
  counts BOTH mutable inputs, the clock and the authority, and requires zero
  reads of each on the replay path; it is the two corrections stated as one
  property so a third mutable input added later has somewhere to fail.

  answer is walked in `_observation`, which is the one owner both the fresh
  adapter path and the exported settlement reach, and the walk runs BEFORE the
  members are composed because the walk's named half is about member names.
