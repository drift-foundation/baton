## [P1] Replay still performs fresh deadline arithmetic before consulting the journal

Moving `deadline_at` out of the signature removes the ordinary collision, but
`_ask` still calls `store._now()` and `boundaries.deadline(...)` before
`store.transact` can decide replay. A later valid clock near the representable
limit therefore refuses an exact retry because a newly derived deadline would
overflow, even though the durable first request and its deadline already
exist. The correction's claim that the second clock decides nothing is still
false at this boundary.

The additive
`test_an_exact_retry_does_not_recompute_an_impossible_later_deadline` commits a
normal probe, moves only the injected clock to the last representable instant,
and retries the same caller operands. It errors in `boundaries.deadline`
instead of replaying the first document.

Compute `requested_at` and the absolute deadline only inside the transaction's
fresh `act`, after the journal has decided this is not a replay. The stable
signature must remain available before that act and continue to include the
caller's duration.

The additive `test_public_settlement_cannot_bypass_observation_ownership`

door before the row is changed. Re-audit idempotent same-outcome settlement so
a second, different reading cannot be silently treated as the first.
