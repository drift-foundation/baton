=== 2. WHY THE PERMISSION RULES WERE THE SHARPEST

  test_one_private_file_per_slot asserts the observed mode against
  credentials.VOLATILE_FILE — THE CONSTANT THAT PRODUCED IT. That proves
  internal consistency and nothing about the required permission:
  0o644 and 0o755 both pass the entire suite.
    201-        self.assertEqual(sorted(os.listdir(delivered.root)),
    202-                         ["api", "signing"])
    203-        self.assertEqual(stat.S_IMODE(os.stat(delivered.root).st_mode),
    204:                         credentials.VOLATILE_DIR)

  The acceptance says fresh-run files and roots have the REQUIRED
  permissions, and a required value is a literal somewhere or it is not
  required. They are asserted as literals now, UNDER A ZERO UMASK —
  os.open's mode is masked by the umask, so a case run under 0o077 would
  observe 0o600 for a file created 0o666 and pass for exactly the defect
  it exists to catch.

=== 3. WHAT CHANGED: NOTHING, DELIBERATELY

  The code already did all seven. What it lacked was anything holding it
  to them:
    the two permission literals, the mode given AT the open, and O_EXCL
    MAX_SLOTS at BOTH owners — the assignment's authorized set and the
      adapter's mount composition are separate rules and needed separate cases
    the failure path's order: the root gone BEFORE the bearer is forgotten,
      driven by failing the provider on the second slot so the first is
      already written and live when the discard runs

  Two of my own new cases were wrong before they were right. The
  provider capability is handed (provider, reference) rather than the
  slot name, so my first failure injection never raised at all; and
  refused/unavailable is not a pairing the taxonomy has, which the closed
  pairing refused — the check doing its job on me.

=== 4. THE REAL-ENGINE SUITE, AND MAKING ITS CLAIM FALSIFIABLE

  The acceptance asks for real-engine coverage and for proof that secrets
  are absent from argv, environment, labels and durable documents.
  test_credentials_engine.py starts real containers carrying a delivered
  credential and asks the DAEMON what it recorded — the whole inspect
  document searched as text, then the four members individually so a
  failure says which.

  THAT ASSERTION HAD TO BE MADE FALSIFIABLE. Nothing in the ordinary path
  puts a bearer where the daemon could store it — the credential is a
  file, not an argument — so asserting its absence proves only that the
  ordinary path is ordinary. A caller-supplied LABEL is the one member
  that would be spelled into the command line, so the case plants one and
  then asks the daemon whether anything was created.

  Driving that raised a question worth answering: start reaches the engine
  BEFORE the sweep, for its duplicate probe. I checked whether that
  probe's argv carries the bearer. It does not — participant is not one
  of the candidate label filters — and the case now asserts it so it
  stays true. Verified rather than assumed; it could as easily have gone
  the other way.
