## Findings

### [P1] Failed materialization forgets a bearer without proving absence

At `credentials.py:384-391`, the failed-materialization handler calls
`_discard(root)`, ignores its boolean answer, and then unconditionally invokes
`forget_secret` for every bearer already written. `_discard` deliberately
answers false when the root remains. Consequently a filesystem refusal leaves
the credential file present while every later §13 scan is disarmed.

The new ordering test watches a successful `_discard`; the harness mutation
either removes that call or swaps successful removal and forgetting. Neither
drives the operation's explicit false answer, so all 19 mutations can be
caught while this required failure boundary remains unsafe.

Reviewer reproduction:

```text
materialization cleanup: root_present=True bearer_live=False
```

Required correction: branch on the absence proof. If the root cannot be proved
gone, keep the affected bearers live and surface an unresolved
`policy/credential-lifetime` ending. Add failure injection and mutation
coverage for the false result, not only successful deletion.

### [P1] The duplicate probe can receive a live bearer before the sweep

`OciAdapter.start` calls `self.list({"labels": labels})` for duplicate
detection before `run_vector` executes `check_no_durable_secret(argv)`. The
list vector places candidate `runtime_attempt_id` in an engine `--filter`
argument. A provider answer is explicitly treated as untrusted; if that live
bearer equals the attempt identity, the mounted delivery and labels agree, and
the engine receives the secret before the later run-vector sweep can refuse.

The new real-engine falsifiability case chooses `participant` specifically
because it is not a candidate filter. It therefore proves that the later sweep
works while leaving the earlier candidate-vector leak untested.

Reviewer reproduction:

```text
pre-sweep engine calls: 2 calls containing bearer: 2
```

Required correction: sweep every engine-bound candidate vector before the
first engine invocation while the registry is armed, then add a case using the
candidate attempt label and a mutation removing this earlier guard.

### [P1 test gap] The real-engine cleanup case deletes before runtime absence

`test_teardown_forgets_only_after_the_bytes_are_proved_gone` starts a real
container, then calls `CredentialHome.tear_down(delivery)` directly. It never
removes the container or asks the adapter to establish positive runtime
absence. Removing the host pathname is not proof that a bind-mounted runtime
cannot still hold the inode, and the finding explicitly keeps the shared
quiescence/removal/settlement crossing outside this provider.

The real-engine gate therefore does not establish the claimed lifecycle
ordering. Exercise cleanup through the authorized adapter crossing after
positive absence, or leave that cross-provider proof to W6636 and keep this
suite within fresh-run delivery/failure scope.
