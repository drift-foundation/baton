## [P1] The credential-to-launch restart boundary is still untested

The production boundary exists inside `OciAdapter._removed`: after positive
runtime absence it calls credential teardown, then `launch.discard`. A process
can fail between those acts even though the adapter exposes one composite
answer. The test does not need to call private `_removed`: inject the failure
at the public manager act `launch.discard`, after the real orphan teardown has
made the credential absent. Assert the first command writes a partial record
with the runtime absent and credential torn down but launch unresolved, then
invoke the documented command afresh and prove convergence.

object; a freshly constructed same-path `CredentialHome` would still pass.
