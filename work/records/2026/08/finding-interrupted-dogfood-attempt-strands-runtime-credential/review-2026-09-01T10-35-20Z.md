## [P1] The zombie report identifies the wrong runtimes and misstates the act

`_reported_zombies` receives only `record["runtime"]`, whose `runtime_id` is
the manager row's expected target. `OciAdapter.observe` reduces a mismatched
inspection to prose and discards the returned ID; it similarly reduces an
ambiguous list to a count. The new report therefore cannot name every runtime
left alone as claimed.

The retained `/tmp/w55758-zombie-report-probe.py` drives mismatched and
two-runtime inspection answers. In both cases the command first issues:

```text
docker rm --force --volumes runtime-1
```

It then reports only `runtime-1` with action `left untouched`. For the
mismatched answer it omits `some-other-runtime`; for the ambiguous answer it
omits both `runtime-a` and `runtime-b`. Thus the locator is not the runtime the
engine actually reported, and the action is false for the runtime it does
name.

Carry structured observed candidate identities and per-runtime action/outcome
instead of reconstructing zombies from the expected target and diagnostic
prose. An exactly identified target whose removal was attempted but remains
running is not “left untouched”; mismatched or ambiguous candidates that were
not targeted are. Add the duplicate case to the zombie-specific assertions.

calls `stop` for every ambiguous or mismatched candidate at
`worker_manager/oci.py:1852-1856`, while M60437 says unknown, ambiguous, and
mismatched old-incarnation runtimes remain untouched for initial v12. Record
the supersession where this older recovery rule is owned, then cover the
