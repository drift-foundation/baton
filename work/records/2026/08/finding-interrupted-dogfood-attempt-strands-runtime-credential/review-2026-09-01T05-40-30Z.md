## [P1] The approved temporal assertion is not load-bearing across the arc

The two new launcher tests drive `_launched` and then call `adapter_of`
directly. They do not drive `run_dogfood_task`, and therefore do not prove that
assignment activation happened before credential materialization or that
runtime creation had not begun. The production source is ordered correctly
today, but a mutation moving the factory call before `activate_assignment`
would not be caught by these temporal tests. That is the exact bearer-without-
selector window M59057 was issued to close.

The same test compares `adapter.credential_home.place` with the granted path
and then proves `_credential_home()` returns `adapter.credential_home`. A
fresh `CredentialHome` object constructed over the same path would satisfy
both assertions. It does not prove the adapter received the exact home object
whose `materialize` call produced the delivery, which is the third assertion
approved in M59057.

Add one arc-level ordering case whose materializer records that
`activate_assignment` has completed and `request_runtime_start` has not begun,
then prove runtime start follows it. Capture the receiver of the materialize
call and assert the adapter owns that exact object by identity. The case should
fail if either ordering edge moves or if the adapter is handed a newly
constructed same-path home.

## [P1] The required public-command recovery matrix remains incomplete

Plan item 7 is an acceptance boundary, not optional follow-up coverage. The
handoff explicitly leaves these rows without a case:

- interruption between runtime creation and lifecycle publication;
- running, wrong-label, duplicate, absent, and uncertain runtime outcomes
  through the recovery command;
- command-level restart after declaration, fence, runtime removal, credential
  teardown, launch teardown, directory custody, and before terminal commit;
- exact retry, conflicting declaration/policy, and a newer generation/runtime
  through `--abandon`;
- damaged lifecycle state and a mismatched recorded root while proving no
  record-derived path is followed;
- documented `main --abandon` over an attached attempt; and
- the existing `--retry-handoff` path proving it adopts through the shared
  granted credential owner.

Lower-level `abandon_attempt` coverage is not a substitute for these
composition cases. Earlier rounds in this same Work found false credential
endings, cross-attempt deletion, and lost partial records only at the crossing
between otherwise tested components. Complete the declared matrix and return
for final security review.
