## Verified corrections

### Cross-attempt teardown is bound before destruction

Every public destroy command now passes its `runtime_attempt_id` into
`OciAdapter._removed`, and `_bound_orphan` compares that identity with the
held `OrphanTeardown` before `destroy_vector` reaches the engine. A mismatch
or absent attempt refuses `refused/precondition`; the refused-start path, which
has no destroy command to bind, refuses an orphan ending entirely.

The new public-seam regressions prove a mismatched attempt leaves both the
engine and credential material untouched, the exact match still reaches a
`torn-down` ending, and the unnamed case is refused by this rule rather than a
later schema check. This satisfies the second P1 from the prior review.

### A started recovery carries a bounded account through faults

`recover_abandoned` now owns the recovery document before entering either
branch. Expected pre-attach credential and launch refusals become named
`unresolved` facts. An unexpected fault carries that bounded document to
`_abandoned`, which attempts the durable write before re-raising; only the
exception type is retained, never its text.

The added regressions cover the carried unexpected record and an expected
cleanup refusal. Independent `/tmp/w55758-partial-retry-probe.py` uses two real
`CredentialHome` instances: the first home is proved absent before the second
refuses, and an exact retry converges to `torn-down` with both homes absent.
The implementation behavior is sound, but the repository still lacks the
prior review's required real two-home partial-failure plus retry regression;
that case must be promoted from the temporary probe into the suite.

The old `/tmp/w55758-review-probe.py` deliberately replaces
`recover_abandoned` with a function that cannot carry the new record and calls
the private `_torn_down` seam directly, bypassing `_removed`'s new identity
gate. Its original outputs no longer test either corrected public contract.

## Open P1 and decision recommendation

The earliest post-materialization/pre-attempt crash remains open. Renaming its
test as a reproduction is accurate, but the bearer still exists before any
durable attempt/activation selector can authorize cleanup.

**Proposed ruling:** approve option (i), using lazy materialization inside the
ordinary launcher's `adapter_of` closure after `activate_assignment`, and keep
the existing `run_dogfood_task` parameter list rather than moving the arc's
roughly ten injected/test call sites.

This order is the narrow correction:

1. `record_attempt`, claim, and `activate_assignment` commit the manager-owned
   attempt and label context;
2. only then does `adapter_of` materialize the credential through the already
   validated operator-granted `CredentialHome` and construct `OciAdapter` with
   that same home and delivery; and
3. runtime creation remains later under `request_runtime_start`.

A crash before activation then leaves no bearer. A crash after materialization
has the durable `label_context` needed to prove runtime absence and clean the
exact orphan without inventing a terminal attempt. This neither treats raw
grants as deletion authority nor moves the accepted credential-home grant.

The ruling must explicitly authorize replacing the existing assertion in
`tests.tools.test_dogfood_operator.TheDocumentedLauncher...` that `_launched`
returns a materialized `credentials.Delivery` at bundle-build time. Replace it
with stronger temporal assertions: launcher construction leaves no volatile
credential root or lifecycle record; invoking the launcher's adapter factory
after activation materializes exactly once; and the resulting adapter holds
that `Delivery` and the same granted `CredentialHome`. This is a case-specific
change to an existing assertion, so repository policy requires confirmation
before implementation.
