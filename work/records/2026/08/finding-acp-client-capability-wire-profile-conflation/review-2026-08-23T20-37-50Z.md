## P1: an expected JSON member must be enumerable

`recordFault()` proves exact own names and data descriptors but checks only
that each descriptor has a `value`. It does not check `enumerable`. This
envelope therefore passes `validateClientCapabilities()`:

```js
const offered = {};
Object.defineProperties(offered, {
  fs: { value: {}, enumerable: false },
  terminal: { value: false, enumerable: false },
});
```

Both required values can be read directly, but `JSON.stringify(offered)` is
`{}`. The validator consequently answers a property-access question rather
than the contract's JSON-document question—the same distinction the Date
correction established.

Require every expected member descriptor to be enumerable as well as a data
descriptor. This must remain an inert descriptor check: do not read the value,
run behavior, or alter Proxy handling. Empty records, ordinary/null-prototype
records, insertion-order independence, hidden extra-member refusal, and both
caller taxonomies remain unchanged.

Two additive regressions preserve the primitive and actual ACP boundary:

- `v12/test/worker_manager_records.test.mjs`: a hidden expected member is not
  part of the JSON document.
- `v12/test/worker_manager_agent_handshake.test.mjs`: an envelope whose two
  required fields are hidden must be `policy.denied`.
