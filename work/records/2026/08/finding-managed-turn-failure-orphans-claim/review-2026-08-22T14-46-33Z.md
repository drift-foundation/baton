## [P1] Resume-discovered failed turns clear without reconciliation

`EventBridge.#reconcileTarget` in
`tools/codex-event-bridge/src/event_bridge.mjs` handles a persisted active turn
whose status is no longer `inProgress` by logging it and clearing
`state.activeTurn`. It does not call the new shared `#settleTurn`, publish
`failed(internal)`, create the durable fence, or file the incident. It then
drains the target.

This path is reached whenever the transport disconnects before the dispatcher
receives `turn/completed` and the resume snapshot is the first observation of
the terminal failure. That is not an exotic status: reconnect reconciliation
already exists specifically because notifications can be missed.

The reviewer-added regression delivers W2907, disconnects without a completion
notification, and resumes an idle thread whose persisted `turn-1` is `failed`
while canonical readiness still reports W2907 claimed at the delivered
episode. The current result is `deliverable=true`, `orphan=null`, and zero
incidents. The expected result is a non-deliverable target fenced on W2907 with
one incident.

Route every terminal persisted managed turn through the same settlement before
clearing the attempt or draining. Preserve the success case, the absent-turn
ambiguity boundary, and idempotence if a late `turn/completed` notification
arrives after resume settlement.

`evidence/review-reconnect-terminal-gap-2026-08-22.txt`.
