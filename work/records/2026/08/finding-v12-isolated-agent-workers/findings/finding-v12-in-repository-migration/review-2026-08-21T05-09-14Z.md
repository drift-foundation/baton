# Independent review — round 1

## Verdict

entry points do not fail closed before destructive cleanup.

## Findings

### [P1] Validate and bound every destructive target before cleanup

`scripts/run-proof.sh` reads raw strings from `poc.json`, derives
`EV="$STATE/evidence/$LABEL"`, and recursively removes it before any call
through `bin/v12-poc` validates the configuration. It later invokes
`new-authority.sh`, whose first setup operation recursively removes its
authority operand, and recursively removes `record_base` and `state_dir` while
still relying only on those raw strings. The evidence label is unconstrained,
so parent-directory components can also make `EV` escape the declared state
root. `just state-clean` repeats the same pattern: it reads raw `state_root`
and recursively removes it after excluding only `/`, `$HOME`, and the current
prototype directory.

This is not a theoretical invalid-config branch. The exported placement check
currently accepts `/tmp` and `/var` as state roots; either would be offered
directly to `state-clean`, and `new-authority.sh` accepts similarly broad
authority operands. A typo or crafted proof label/configuration can therefore
delete data outside the disposable PoC root before the runtime's later
validation or container fence has a chance to refuse the run.

Required correction: establish one fail-closed, non-destructive placement
validation that every state-creating and state-deleting entry point uses
before its first `chmod`, `mkdir` over a configured target, or recursive
remove. Reject filesystem-wide/broad roots, prove each destructive operand is
a strict descendant of the validated state root, and constrain the evidence
label to one safe path component. Add negative tests for traversal labels,
broad roots, and out-of-root authority/record/attempt paths without executing
the dangerous deletion.

### [P1] Enforce externality against the whole Baton checkout

`src/config.mjs:43` compares `state_root` only with `POC_ROOT` (`v12/`). A
direct reproduction shows that it accepts
`/home/sl/src/baton/v12-state-sibling`, which is outside `v12/` but still
inside the Baton checkout. `scripts/new-authority.sh:23-31` makes the same
subtree-only comparison, and the post-proof stray-state walk inspects only
`v12/`. The later container fence still rejects a checkout mount, but that is
too late: proof setup may already have created or recursively removed state in
the checkout before a container is considered.

This contradicts the recorded migration rule that the single state root is
external and that the entire checkout remains state-free. Derive or explicitly
name the checkout root, reject overlap with it in either direction at every
entry point, and add a regression for a sibling of `v12/` inside the checkout.
The container fence should remain unchanged as the canonicalized launch-time
defense; it is not a substitute for safe setup and cleanup.
