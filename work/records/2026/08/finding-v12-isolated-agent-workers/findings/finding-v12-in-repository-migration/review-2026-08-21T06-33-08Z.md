## Finding

### [P1] Do not recursively delete a fixed shared path to make it absent

`v12/test/placement.test.mjs:157-159` chooses the fixed path
`/tmp/v12poc-guaranteed-absent-8f61c2` and immediately calls
`rmSync(..., { recursive: true, force: true })` before asserting absence. The
name does not make the path guaranteed absent: another test process, another
checkout, or an earlier interrupted run can own data there. Running this gate
then deletes that directory without the marker or exact-plan validation the
test exists to enforce.

This also contradicts the round-one regression boundary requiring dangerous
negative paths to be tested without performing the dangerous deletion. A test
of “absent paths are never offered to recursive cleanup” cannot establish its
precondition by recursively cleaning an unowned shared path.

Create a unique test-owned temporary parent with `mkdtempSync`, select a child
that has never been created, and assert that child is absent. Run the direct and
CLI checks against that child, then clean only the parent the test created.
There must be no pre-test recursive removal of the absent candidate. Preserve
the current assertions that deletion emits no path, setup still reports
`fresh`, and neither operation creates the child.
