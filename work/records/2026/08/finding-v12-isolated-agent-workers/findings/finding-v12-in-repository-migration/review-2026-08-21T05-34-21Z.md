## Findings

### [P1] Bind authority recreation to the configured plan, not any descendant

`scripts/new-authority.sh:19-20` still takes raw authority and record-base
operands. Its gate at lines 35-36 calls `placement.mjs check`, but `check`
only proves that each operand is some strict descendant of `state_root` and
prints no validated values. The script then uses the raw operands for
`mkdir -p`, `rm -rf`, and the generated authority. This contradicts the
recorded correction that every entry point uses the paths returned by the one
placement plan.

A direct non-destructive reproduction passes both
`/tmp/baton-v12-poc/evidence` and `/tmp/baton-v12-poc/attempts` through
`placement.mjs check`, even though the configured plan names
`/tmp/baton-v12-poc/authority` and `/tmp/baton-v12-poc/records`. Invoking the
script with those legal-but-wrong descendants would recursively remove the
retained external evidence directory and construct an authority over the
attempt directory. Swapping the two configured operands passes for the same
reason.

Required correction: eliminate these free-form operands or compare them to
the exact authority and record-base values produced by `planPlacement`, then
use only those returned values. Add non-mutating regressions for swapped
configured paths and for other in-root descendants (especially evidence and
attempt state); each must refuse before any filesystem change.

### [P1] Path depth does not prove that `state-clean` owns the root

`assertStateRoot` rejects a fixed top-level denylist and paths shallower than
two components, but that does not establish the comment's claimed invariant
that the directory exists for this prototype and nothing else. Direct calls
accept `/var/log`, `/usr/local`, and `/home/sl/Documents`. `just state-clean`
then consumes the accepted string at `justfile:49-51`, recursively makes the
tree writable, and removes it in full.

This leaves the original data-loss class open one component lower: a typo can
still offer an existing system or user directory to recursive deletion. No
finite broad-root denylist or depth threshold can prove exclusive ownership.

Required correction: root deletion must require positive, durable ownership
evidence for this exact PoC and canonical root, not path shape alone. A root
that already exists without that evidence must refuse unchanged; creation of
a fresh dedicated root may establish it deliberately. Add non-destructive
regressions showing that existing unrelated roots—including depth-two system
paths and a user directory—cannot reach `chmod -R` or `rm -rf`, while the
sample's initialized disposable root can still be cleaned.
