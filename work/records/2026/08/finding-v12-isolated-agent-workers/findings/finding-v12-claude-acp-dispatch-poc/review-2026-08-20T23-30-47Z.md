# Independent review — round 3

## Verdict

Changes requested. The four round-2 findings are materially corrected and the
44-test focused suite is green. The two fresh proof packs establish the happy
path and corrected ordering, but the harness retains long-lived credentials,
does not reliably refuse the production authority, and can misreport an
ambiguous committed Baton mutation.

## Findings

### P1 — every attempt leaves a full Claude OAuth credential copy on disk

`stageCredentials()` copies the operator's complete `.credentials.json`,
including the refresh token, into
`run/attempts/<attempt>/claude-config/.credentials.json`. Container reaping
removes only the containers. Neither the successful path nor any failure path
removes the staged credential directory after the relevant containers are
proven gone.

This is observable in the returned tree now: all four round-3 attempts still
contain mode-0600, 509-byte credential copies. The evidence-pack grep passes
only because it scans `evidence/<label>`, not the retained runtime attempt
directory. Calling this a runtime copy does not make it ephemeral; it remains
a long-lived operator credential after the attempt is over.

Dispose of staged credentials on every path once all containers that mount
them are positively absent. If absence cannot be proved, report the retained
secret as part of the stranded condition and do not claim cleanup. Add
success, pre-claim failure, compensated failure, and unprovable-reap
regressions. The proof runner must assert the runtime state as well as the
sanitized evidence pack.

### P1 — the production-authority guard misses the live symlink and aliases

`BatonClient` rejects configuration paths matching
`/^\/home\/sl\/baton-v11\./`, but the live deployment is conventionally
addressed as `/home/sl/baton-v11/baton.json`. That exact path passes the guard.
A symlink under `/tmp` or the prototype root that resolves into a production
home passes too because the check is lexical.

The finding makes production coordination state a stop condition, not a
best-effort naming convention. Resolve and compare the real authority path
against the configured forbidden production roots (including the live
symlink), and add exact-live-path plus alias regressions. A disposable
authority must still pass.

### P1 — an ambiguous committed claim or pass is reported under the wrong state

The manager supplies an `op-id` to `claim`, but `BatonClient.run()` makes one
attempt and throws on timeout/lost output. If the authority committed the
claim and the result was lost, `attempt.claimCommitted` remains false, so the
catch path reaps the worker and performs no reconciliation or release. The
canonical Handler can be left held while the attempt reports only `error`.

The mirror exists at return: `pass` has no operation id and
`attempt.handedOff` flips only after its response arrives. A committed pass
whose output is lost enters compensation; release then refuses because the
Handler is already gone, and the attempt reports `stranded` although the Job
was successfully handed to review.

Use effectively-once identities for manager mutations and reconcile an
ambiguous result through the public projection before deciding whether the
claim is held, released, or handed off. Add commit-then-lose-result tests for
claim and pass. This is the exact boundary where a trusted manager must know
whether it owns a live assignment before it starts or advertises another one.

### P2 — canonical mount comparison still uses the mutable alias for launch

`assertNoBatonCapability()` resolves each mount source for comparison, but
returns the original spec unchanged. A symlink source that points somewhere
safe during the check is still handed to Docker by its alias and may be
retargeted between the check and `docker run`. The implementation comment
explicitly claims to cover later-retargeted links, but canonical comparison
alone does not do that.

Launch with the already-validated canonical source, or refuse symlinked mount
components. Add a regression proving the runtime argv no longer contains the
mutable alias accepted during validation.
