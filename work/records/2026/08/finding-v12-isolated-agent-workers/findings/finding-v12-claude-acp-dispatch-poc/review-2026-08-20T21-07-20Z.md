## Findings

### P1 — ACP work turns have no deadline and can hold a claim forever

`src/acp_session.mjs:147` races `connection.prompt(...)` only against child
death. `setupTimeoutMs` supervises initialize/session/mode setup, but no timer
supervises either the consent prompt or the post-claim execution prompt.

That contradicts `PROVENANCE.md` and `PROGRESS.md`, which claim the copied ACP
discipline includes supervised deadlines. More importantly, a live but silent
execution agent keeps the canonical Handler indefinitely: `finally`,
quiescence, compensation, and return are never reached while the prompt
promise remains pending.

Add explicit manager-owned deadlines for both prompt classes, prove timeout
terminates/fences the container, and cover the post-claim case through a real
claim followed by compensation. Do not describe setup-only deadlines as turn
supervision.

### P1 — compensation releases the claim before uncertain execution is dead

`src/manager.mjs:91` calls `compensate()` from the catch block before the
container-removal `finally` at line 99. If `awaitQuiescence()` cannot inspect
the worker, or session shutdown otherwise fails before quiescence is proved,
the fence correctly throws—but compensation immediately releases the Work
while the old execution container may still be running. Only afterwards does
`remove()` try `docker rm --force`, and `remove()` swallows every error.

That creates the overlap the claim boundary is meant to prevent: a fresh
offer can be claimed while the previous worker has not been proven dead. Its
per-attempt output mount limits the damage but does not make two executions of
one Job true or safe.

Before release, the manager must positively establish that every execution
container is gone. If it cannot, leave the canonical Handler held and report
the attempt `stranded`; do not advertise the Work as available. Add the
inspection-failure/removal-failure ordering regression, not only the current
stubbed `compensate()` unit test.

### P1 — the no-Baton-capability fence is lexical and accepts a symlink escape

`src/runtime.mjs:145` compares mount-source strings with forbidden-path
strings. Docker resolves bind sources, so a source path that is a symlink to a
forbidden Baton directory passes the check and then exposes that directory in
the container.

Independent reproduction:

```text
source: /tmp/w76-link-*/adapter
symlink target: /home/sl/baton-v11.8835cd5
assertNoBatonCapability(...): accepted
```

Canonicalize and validate every host mount source before comparing it with
canonical forbidden roots, and refuse link/containment ambiguity. Cover the
exact root-symlink case. A trusted config can still contain an accidental or
later-retargeted link; the function explicitly claims to enforce capability
absence rather than merely document today's spelling.

### P2 — the proof changes the pinned output type from directory to file

The bound finding deliberately narrows the slice to one typed `directory`
input and one declared `directory` result. The implementation instead offers
and requires `{type: "file", path: "/out/index.json"}` in
`src/manager.mjs:207` and `src/prompts.mjs:84`.

Either fulfill the pinned directory-result contract or return for an explicit
scope revision. Do not silently treat the two types as equivalent; typed IN/OUT
is one of the questions this proof exists to settle.
