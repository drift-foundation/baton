## P1 — retirement does not preserve its terminal disposition across a crash

Authority retirement and the control-store offer CAS are separate durable
boundaries. `settle_operation` records the signature and free-form reason but
returns only generic `retired`. `_terminalize` then applies whichever local
state its current caller requested: `settlement-expired` for the timeout path
or `claim-refused` for the claim path.

The additive trace crashes the manager after a settlement timeout retires the
fixed claim operation but before it changes the still-`accepted` offer row. A
later claim request observes the retirement through `Authority.claim`, enters
the claim-refusal terminalization path, and changes the offer to
`claim-refused`. The authority outcome intended `settlement-expired`, but the
retry path relabels it.

This is the same ambiguity the authority-side settlement was introduced to
remove. Retirement must durably bind its terminal disposition, not just that
the identity is dead. Every manager entry path that finds the retirement must
replay that disposition into the offer CAS. A timeout retirement must remain
`settlement-expired`; a positively submitted-and-refused retirement must
remain `claim-refused`. The exact representation is an implementation choice,
but a crash between the two stores cannot make the retrying caller choose a
new outcome.
