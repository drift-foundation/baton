P1 — SESSION REFUSALS RENDER UNBOUNDED CALLER TEXT

`errors.py` states the authority-wide rule directly: caller-controlled text in
a Refusal is bounded by the RULE and never by the operand. The new session
wrapper bypasses `name_of` at two sites:

  session.py:183  joins every unknown operand key into the message
  session.py:213  interpolates the supplied assignment participant directly

Independent probes with one 1,000,000-character string produced:

  foreign assignment participant:  Refusal, 1,000,056 characters
  unknown operand key:              Refusal, 1,000,089 characters

Both verdicts are correct and both diagnostics violate the package's explicit
bounded-output rule. The extra-key path also performs an avoidable full
sort/join for diagnostic prose. Preserve useful small names, but bound each
caller-controlled rendering and the complete message; for multiple unexpected
keys report a bounded sample/count rather than the whole rejected set.

P2 — THE “ONE EXACT BUILT-IN DICT” BOUNDARY IS NOT EXACTLY ONE DICT

The implementation boundary says every runtime-session mutation takes one
exact built-in operand dict. Current `session.py` instead:

  line 161: converts explicit `None` to `{}`
  line 256: declares `given=None`, conflating omission with explicit null
  Python arity: a second document escapes as raw TypeError

Independent answers:

  claim()        -> Refusal “claim needs operation_id, work_id”
  claim(None)    -> the same Refusal; explicit null was silently replaced
  claim({}, {})  -> TypeError, not the authority's Refusal outcome

An explicit value must not be dropped, especially in the wrapper whose stated
purpose is to refuse supplied-but-ignored operands. Require exactly one
positional operand document at the public transition boundary; zero, explicit
null, or more than one must be typed Refusals naming the one-document rule.
