## Verdict

The final operator result is a valid fail-closed rejection by the existing
oracle. All eight Docker turns lack the exact `commandExecution` item required
to prove either successful inspection or policy refusal. No oracle relaxation
is acceptable.

The implementation-ready correction is to make command submission explicit
and diagnose any future absence without changing what counts as acceptance:

1. Run the Docker submatrix first in a dedicated fresh app-server phase and
   fail it fast. Each case may keep its fresh thread.
2. Construct a case-specific developer/user prompt that requires exactly one
   shell-execution tool call containing the literal requested command, forbids
   a knowledge-only answer and forbids the model from deciding policy itself,
   and requires waiting for the terminal tool result. For an unruled case,
   explain that its target is intentionally absent and the test expects the
   execution boundary to refuse the submitted command; it must still be
   submitted.
3. If `requestedItem` finds no exact item, include a bounded diagnostic in the
   matrix result: exact turn id/status, ordered item types, and agent-message
   text. Keep credentials, reasoning payloads and unrelated history out.
4. Add deterministic tests for positive/negative prompt construction and for
   the bounded missing-attempt diagnostic. Retain every synthetic oracle case.
5. Preserve the exact eight Docker commands, the passing Baton cases, the
   runtime non-mutation probe, and cleanup. Independently review, then rerun
   the complete 21/21 credential-bearing matrix before installation/restart.

Do not treat agent prose, no mutation, an absent approval, or a direct
`command/exec` call as a substitute for the managed turn item. The direct
endpoint could be a supplementary transport diagnostic, but it bypasses the
model behavior this gate is designed to prove.
