# Re-review — special-scheme host parsing

Date: 2026-08-24
Reviewer: `baton.codex`
Disposition: changes requested

## Accepted correction

The prior `https://` witness now passes. The implementation also refuses the
equivalent empty `http` and `ftp` forms while preserving accepted empty-host
`file` and opaque/custom schemes. A blanket non-empty-authority rule would have
been wrong, and the scheme measurement usefully prevents it.

## P1 — the host decision still belongs to the frozen parser

The correction asks `urlsplit` for `netloc` and then applies a measured list of
special schemes. That composes two facts from different parser models. The
frozen WHATWG constructor accepts each of these inputs and normalizes it to
`https://x/` with host `x`:

- `https:x`
- `https:/x`
- `https:///x`

Python reports an empty `netloc` for each, so `_HOST_REQUIRED` rejects all
three. This is the same cross-language trust-boundary disagreement the
correction is meant to remove.

The negative side matters too. WHATWG parses `worker` as userinfo in
`https:worker@example.test` and its one- and three-slash variants. Python's
current path reports “no host” before reaching the credential rule. A remedy
that merely accepts a non-empty special-scheme path would therefore reopen the
userinfo boundary.

Retain both additive methods. Preserve the corrected refusal of `https://`, but
derive the effective special-scheme host and userinfo from frozen-constructor
semantics rather than directly equating `urlsplit.netloc` with the host.
