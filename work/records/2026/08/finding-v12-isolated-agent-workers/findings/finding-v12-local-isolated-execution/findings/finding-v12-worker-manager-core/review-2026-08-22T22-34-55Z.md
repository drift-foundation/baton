## P1 — activation is not bound to this attempt's claim or full identity

`activateAssignment` accepts any free-standing attempt plus any currently live
assignment (`attempts.mjs:104-145`); it never proves this attempt's accepted
offer committed that claim. It also ignores the session's participant, stores
no assignment participant, compares only Work/generation on the fixed path,
and omits participant from runtime labels (`schema.mjs:101-129`,
`attempts.mjs:106-162`). A foreign session can activate the attempt, later
activation can replay under another participant/authority, and runtime labels
do not carry the required four-part assignment.

Bind attempt activation to item 3a's exact durable claim result, require the
injected session participant, persist and compare all four assignment fields,
and label the runtime with all four. Drive it through a real `V12Session`.

Regressions: `reactivation compares the FULL assignment`, `runtime labels
carry the full assignment`, `activation uses the participant-bound session`,
and `activation requires this attempt's recorded claim`.

## P1 — attempt replay omits durable operands

`recordAttempt` writes adapter name plus input, policy, image and toolchain
digests, but signs only attempt id, adapter digest and profile digest
(`attempts.mjs:76-95`). Changed durable operands replay instead of colliding.
Include every durable operand in the effective signature.

Regression: `attempt replay signs every durable operand`.

## P1 — runtime start has no durable manager operation identity

`requestRuntimeStart` records `start-requested` through a raw axis update and
calls `adapter.start({labels})` (`attempts.mjs:176-192`). No `runtime.start`
journal operation exists and the adapter receives no stable operation id. A
state label is not the effectively-once act a restart and adapter must settle.
Commit one fixed fully signed start operation before the call, pass its identity
to the adapter, and reconcile/replay that same operation after result loss.

Regression: `the runtime-start operation is durable before start`.

## P1 — positive absence is a caller-authored boolean

`reconcileRuntime(..., {absenceProven: true})` treats an ordinary caller value
as proof and resets to `not-started` (`attempts.mjs:207-251`). Any caller can
authorize a second start after ambiguity. This repeats the rejected
`schemaProven: true` shape: a proof the caller can write is not proof. Derive
absence through validated certified-adapter evidence, or keep retry disabled
until item 4 provides that path.

Regression: `a caller cannot self-attest runtime absence`.

## P1 — attachment is mutable and minted label mismatch is ignored

The attach operation unconditionally overwrites `runtime_id`
(`attempts.mjs:221-245`), so a later inspection silently replaces the fixed
runtime. Conversely, the exact id just returned by `start` with wrong labels is
filtered out and reported as uncertainty rather than the pinned mismatch
cancellation (`attempts.mjs:207-212`). The first positive attachment must CAS
null-or-identical; only the same id/full labels replay. A different attached id
or minted id with different labels enters cancellation without rewriting it.

Regressions: `a runtime identity is fixed after attachment` and `the minted
runtime with wrong labels cancels`.

## P1 — enum order and public reset do not define monotonic axes

`observe` treats vocabulary array order as one transition order and exports
`allowReset` (`attempts.mjs:260-297`). The vocabularies contain alternatives:
`worker_disposition=completed` currently advances to the different terminal
answer `unable`, while `allowReset` changes positive `destroyed` evidence back
to `running`. Define transitions per axis, keep terminal alternatives immutable,
and make the narrow proven-absence retry private.

Regressions: `allowReset is not a public monotonicity bypass` and `terminal
alternatives are not an enum walk`.

## P1 — monotonicity is a read/check/write race

`observe` reads current state, checks it in JavaScript, then performs an
unconditional update outside a transaction/CAS (`attempts.mjs:277-296`). A
deterministic two-connection interleaving advances `running` to `quiescent`,
then lets a stale observer overwrite it with `cancel-requested`. Decide/write
atomically against expected current state. Use the existing observation journal
with adapter incarnation, source sequence/digest and manager sequence so exact
duplicates replay and conflicting or regressing duplicates refuse.

Regression: `a stale observer cannot regress a newer axis value`.
