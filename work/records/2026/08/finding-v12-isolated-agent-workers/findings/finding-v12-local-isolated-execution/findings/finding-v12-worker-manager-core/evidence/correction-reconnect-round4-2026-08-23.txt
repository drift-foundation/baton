2. THE RULE WAS RIGHT AND I APPLIED IT AT ONE OF TWO SITES

Last round I wrote that a refusal must never run the value it is refusing,
and that "translating an unavoidable reflection failure is cheaper than
proving no host or Proxy object can make `getPrototypeOf` throw". Then I
wrapped the reflection in `describe` and left the one in `isPlainRecord` bare
— and `isPlainRecord` runs FIRST. So a Proxy with a `getPrototypeOf` trap
leaked an arbitrary Error before the guard I had just written was reached.

A rule applied at the second of two sites is not applied. The correction is
ONE translated prototype snapshot, taken once and shared by the record test
and the description, so there is a single place the reflection happens.

The second part is the same rule at a place I had not thought of as
reflection at all. `hasOwnProperty` runs nothing, so I treated the ownership
check as inert — but the property READ that followed it executes an own
ACCESSOR. An ACCEPTED plain record could therefore still run the caller's code
at a boundary whose entire rule is that it does not.

`ownTurnInFlight` reads one guarded own-property DESCRIPTOR and accepts
absence or a data descriptor. An options document carries data; a getter is a
program, and a program is not an operand.

Y4 is MEASURED AS MASKED and the distinction is worth stating: an accessor's
descriptor has no `value`, so the boolean proof downstream refuses it with the
same closed pair. What the accessor branch adds is the MESSAGE. What actually
keeps the getter from RUNNING is reading the descriptor instead of the
property — Y3 — and that fails six cases. The guard is the descriptor read;
the accessor branch is its explanation and is not counted as one.
