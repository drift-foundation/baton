2. THE FINDING

[P2] `null` WAS BOTH A LEGAL FAILURE AND THE NO-FAILURE SENTINEL.
`agentFailure = null` meant two things at once, and JavaScript lets a boundary
throw any value. An agent that threw `null` had its failure silently dropped:
the runtime stop was still ordered, but the caller received an ordinary
`ordered: true` answer, and a simultaneous runtime failure lost its partner in
the aggregate. Both of last round's claims — "re-thrown unchanged" and
"neither hides the other" — were false for exactly that value.

PRESENCE IS ITS OWN FACT. A boolean carries it and the variable carries only
the thrown value.

THIS CODEBASE ALREADY KNEW THIS. `ControlStore.replay` carries a review note
from an earlier round saying the same thing in the same words — it answered
`null` for both "no row" and "the committed result was JSON null", and the
correction was that presence is its own fact and is returned as one. I wrote
the identical defect three modules later. The lesson had been recorded and not
generalized, which is the part worth keeping.


3. ONE MORE OF THE SAME SHAPE, FOUND BY SWEEPING RATHER THAN BY REVIEW

`agentSettlement = agent.cancel(...) ?? null` collapsed "the boundary returned
nothing" into "the boundary returned null". That is the same mistake one size
smaller, and it CONTRADICTED THE COMMENT DIRECTLY ABOVE IT claiming the
settlements are passed through un-summarized. Both settlements are verbatim
now.

It is recorded as my own sweep, not as a review finding, because it is not one.
