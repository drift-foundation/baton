## P2 — caller input and remaining strings can still remove the bound

The exported helper still is not bounded in every dimension as its contract
claims.

At `command_oracle.mjs:331-334`, `Math.min(limit, hardMaximum)` turns
`limit: NaN` into a `NaN` cap. `clip` then evaluates
`value.length > NaN` as false and returns the entire string. A one-million
character message and command produce a one-million-character diagnostic even
though the caller is only supposed to be able to tighten the bound.

Separately, `allTypes` at line 342 retains every item-type string verbatim.
The count is capped, but the string is not. One item with a one-million-
character `type` produces a one-million-character summary. The same structural
problem exists for the unbounded turn id/status and command status copied into
the returned object and summary. Protocol-conforming values are small, but the
helper's stated hard-output property currently depends on that external
conformance and therefore is not a hard property of the helper.

Exact reproduction:

```json
{"nanMessage":1000000,"nanCommand":1000009,"nanSummary":1000088,
 "longType":1000000,"longTypeSummary":1000051}
```

Required correction:

- normalize the optional limit before using it; a non-finite or otherwise
  invalid value must fall back to the private hard maximum, never disable it;
- length-cap every externally supplied string retained in the structured
  result or summary, including type/status/id fields, or enforce an equivalent
  hard whole-result bound;
- add regressions for `NaN` and oversized metadata, asserting a fixed maximum
  for the complete serialized diagnostic;
- retain true counts, omission markers, reasoning-payload exclusion, and the
  diagnostic-only boundary.
