## P1 — adopted entries are still derived from existing validators

`receiving_entries()` calls something an adopted entry only when the AST already
contains `boundaries.adopted`. That is the same circularity PLAN 4ca rejected:
a persistent value with no validator produces no inventory row.

The omission is live. `_offer_row` validates the caller's lookup identity, then
returns every SQLite column as trusted internal data. If an accepted row's
`settle_by` is changed to `not-an-instant`, `settle_claim` compares it and
continues without refusal. The claimed 2-entry adopted inventory stays green
because this crossing contains no `boundaries.adopted` call to discover.

Enumerate persistent reads independently of validators and give each adopted
row/document one exact owner before its fields reach comparisons, branches or
effects. Preserve lexical source/class/function/call-site identity; function
name alone can collapse distinct methods.

## P1 — document and alternative owners are not closed

`boundaries.document` rejects missing required members but accepts every extra
member, contradicting its exact-document contract. A Work projection with an
unexpected member is accepted and reaches offer issuance.

`boundaries.alternative` closes only the discriminator vocabulary, not the
variant shapes. A settlement answer containing only `{"kind":"committed"}` is
accepted and durably advances the offer to `claimed` with a null assignment.
Each variant needs its own exact required/optional member contract and nested
ownership before branching. This is the inbound half of 4bz's same closed
contract model, not a request for local checks in `settle_claim`.

## P1 — the inventory does not require a probe per entry

The receiving inventory is keyed by `(domain, owner, entry)`, but the probe gate
still iterates the old global `(kind, label)` table. There is no assertion that
each of the 55 receiving entries maps to one probe that reaches that entry. This
lets the missing adopted offer-row crossing coexist with a green inventory and
means a repeated label can stand in for multiple entries.

Make the same lexical entry key govern universe, owner and non-vacuous probe.
Validator calls may satisfy an independently discovered row; neither validators
nor the old global label table may define or cover the universe by implication.
