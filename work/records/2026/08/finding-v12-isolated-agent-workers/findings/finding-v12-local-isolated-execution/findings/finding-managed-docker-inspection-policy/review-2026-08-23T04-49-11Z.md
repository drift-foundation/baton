## P2 — the new diagnostic has no total bound

`missingAttemptDiagnostic` truncates each agent message, but it emits every
message, every item type, every command, and each full command string. Its
`summary` concatenates all commands. A synthetic turn with 1,000 commands of
1,000 characters produces:

```json
{"itemTypes":1000,"commands":1000,"summaryLength":1029041}
```

That contradicts the stated bounded-output contract and can flood the manual
operator log precisely when a model goes off-script.

Required correction:

- enforce hard maximum counts for reported item types, agent messages, and
  commands;
- enforce a hard per-command string cap and a hard per-message cap;
- report the true total counts and explicit omitted/truncated markers;
- make caller-supplied limits clamp to hard maxima or keep the hard limits
  private, so the exported helper cannot be made unbounded accidentally;
- add deterministic regressions for many messages, many commands, and one
  long command;
- continue excluding reasoning payloads and keep the helper diagnostic-only.

The matrix integration is otherwise sound: it prints the diagnostic only for
failed Docker verdicts, while the strict oracle remains the sole decision.
