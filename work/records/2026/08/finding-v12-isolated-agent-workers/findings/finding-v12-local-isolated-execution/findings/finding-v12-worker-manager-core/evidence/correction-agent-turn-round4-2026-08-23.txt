2. P1 — THE SUPERVISION BOUNDARY NOW MINTS THE IDENTITY

Schema 11 -> 12 adds `turn_allocations`:

  turn_token   PRIMARY KEY
  (runtime_attempt_id, posture, session_epoch, turn_ordinal) UNIQUE
  FOREIGN KEY (attempt, posture, epoch) -> agent_sessions
  turns.turn_id -> turn_allocations(turn_token)

`allocateTurn(store, sessionRef)` claims the next per-epoch ordinal under
BEGIN IMMEDIATE and derives `turn:<digest(attempt, posture, epoch, ordinal)>`.
The UNIQUE constraint is what makes epoch-local uniqueness a fact rather than
an intention — the same reasoning the one-open-session-per-posture index
already carries: two managers racing on separate connections both pass any
read, and only the database can refuse the second.

`recordTurn` takes `turnToken`, uses it AS the identity (nothing is derived
any more), and binds it inside the write transaction: the token must name an
allocation, and that allocation must belong to the epoch this turn claims.

WHAT THE IDENTITY NOW CARRIES: the attempt, the posture, the epoch and an
ordinal. No prompt, no timestamp, no outcome — nothing the agent said and
nothing the manager later observed.

PROMPT BYTES MOVED TO THE SIGNATURE, where the review put them. The signature
is digest(kind, {turnId, sealed}) and `sealed` is the document digest, which
covers prompt_digest. So a changed prompt under one allocated turn is changed
operands for one act and COLLIDES; it can no longer become a quiet second
turn. There is a case asserting exactly that.

Preserved, and each still has its case: same-prompt later turns separate
(they are separate allocations), exact replay, changed-operand collision, and
the deliberate exclusion of the observed `endedAt` — which is now automatic,
because no operand reaches the identity at all.

TWO DELIBERATE CHOICES, RAISED RATHER THAN BURIED.

First, allocation is NOT journalled. An operation journal replays an act by
its identity, and allocating is how an identity comes to exist; keying it
under an invented id would be inventing the thing allocation produces. A
retried allocation mints a fresh ordinal and the abandoned one is a GAP —
visible, harmless, and honest about a turn the relay opened and did not
finish. What must survive a retry is the RECORD, and it does, because the
relay holds the token it was given.

Second, allocation does NOT check the settle-admitting state or the provider
reference. Opening a turn asks whether the epoch exists; whether a turn may
still SETTLE there is a question about the moment it settles, and `recordTurn`
asks it then against the state that holds then. Allocating into an epoch that
later refuses the record costs one gap and no durable turn. This also keeps
every record-time boundary the third review installed genuinely exercised at
the record call rather than pre-empted at allocation.


3. P2 — TWO MALFORMED SHAPES

`recordTurn` proves each policy-failure element is a plain object BEFORE
`structuredClone`, and translates any residual clone failure to the same
closed pair. The clone exists to stop a caller mutating what was validated,
not to discover what kind of value it was handed.

`turnRecordOf` parses the retained record inside an integrity wrapper.
Retained bytes that cannot be parsed have failed the seal as surely as bytes
that parse and disagree with it, and the SUMMARY in the same safety path
already reported the closed pair.
