2. [P1] AN EXACT STRING IS INERT BUT IT IS NOT NECESSARILY TEXT

`label_of` proved the label was an exact `str` -- which makes it safe to READ --
and then returned it. Python strings may hold lone surrogates, so the refusal
carried one out to whatever logged it, and the ordinary refusal the boundary had
already decided on became a `UnicodeEncodeError`.

That is the same failure `name_of` uses `ascii` to prevent for a rejected VALUE,
and I did not carry it across when I wrote the parallel boundary for a rejected
LABEL. Two rules that are the same rule, applied in one of the two places.

Ordinary prose is returned exactly as written; only text that cannot round-trip
is rendered, and `ascii` runs nothing and cannot fail. Slicing cannot create the
problem: Python strings are code points, so a bound never cuts a character in
half.

AND "ORDINARY PROSE IS RETURNED AS WRITTEN" IS NOW A CASE. Rendering every label
through `ascii` bounds and encodes just as well and NOTHING IN THE SUITE
NOTICED -- so preserving prose was an intention, not a property. Found by a
mutation with no witness.


3. [P2] THE ANALYZER PROVED FOUR THINGS THE AST DOES NOT SAY

  constants     were one package-global set of bare names. A package-global name
                set is a package-global SPELLING, which is the thing this
                analyzer exists not to trust. Constants are per module now: what
                the module binds ONCE to a literal, plus what it imports from a
                module in this package that owns it. Shadowing is decided by
                COUNTING bindings rather than by inspecting one of them -- a name
                bound twice is nobody's constant, because the analyzer cannot say
                which binding ran last.
  scopes        `ast.walk(function)` descends into nested functions, so a closure
                proved its enclosing function's parameter. A scope is a scope.
  control flow  a name was proved if ANY safe assignment existed. Reaching
                definitions would be the real answer; the honest answer for a
                test is CONSERVATIVE, so a name is proved only when every binding
                of it in its own scope is a plain assignment from a bounding
                call, at the function's top level where it dominates, and the use
                is after it. A loop target, a `with` target, a walrus, an
                augmented assignment or a `global` is a binding this analyzer
                does not model, and one of those makes the name unproven.
  site identity each site carries its DOTTED LEXICAL PATH, and an exception
                covers the number of sites it declares rather than a spelling. A
                spelling has no count, which is exactly how one entry excused ten
                exported helpers.

The dotted path of every excused site is also pinned in a case, so moving an
exception between two `body` siblings changes a list somebody has to edit.
