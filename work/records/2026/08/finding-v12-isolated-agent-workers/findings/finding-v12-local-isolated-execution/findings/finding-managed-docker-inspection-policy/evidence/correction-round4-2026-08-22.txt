3. THE DECISION DOMAIN, MEASURED

Each spelling appended to the exact four as
`prefix_rule(pattern=["not-docker"], decision="<D>")`:

  LOADS     allow, prompt, forbidden
  REFUSED   deny, forbid, ask, bogus, reject, warn, allowed,
            Allow, ALLOW, prompt_user, "" (empty string)

The domain is case-sensitive. Only `allow` is coverage and only `allow` is
what this generator emits; `prompt` and `forbidden` are accepted because
they LOAD, and refusing an operator's valid restriction would be
fail-blind in the direction round 1 warned about. Anything outside the
measured three is UNACCOUNTED, including a spelling a later Codex might
add — the same stated limitation this module already carries for CRLF.


4. A NEIGHBOURING CASE THAT IS NOT A DEFECT

  empty string pattern ELEMENT
    prefix_rule(pattern=[""], decision="allow")
    evaluator: exit 0 — LOADS
    audit after the fix: satisfied=true  unaccounted=0

The evaluator's complaint is about an empty PATTERN, not an empty element.
An empty element covers nothing, because no argv element equals "". It
stays accounted; refusing it would be fail-blind.
