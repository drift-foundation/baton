2. [P1 1] A COMPARE-AND-SWAP THAT COMPARES ONE OBJECT AND MUTATES ANOTHER

An assignment for Y satisfied `_expect` -- correctly, it WAS Y's live
assignment -- and then X was gated. On the live path it was worse: Y was ENDED
and X stayed untouched, so a gate arrival for X terminated somebody else's
assignment on another Work.

The identity must belong to the Work being acted on, and that is checked before
either branch. I had treated `_expect` as "is this identity current", and the
question at this boundary is "is this identity current FOR THIS WORK" -- the
second is not implied by the first, and the operand carries the Work id right
there in it.


3. [P1 2] THE GENERATION SPACE IS FINITE AND ITS END IS A REFUSAL

The counter was incremented and returned as an assignment identity without ever
being held to the frozen range, so a Work at the boundary minted
9007199254740992 -- a generation no consumer of these documents can read back.

I bounded integers in `own` and in `check_generation` in cut 1 and then MINTED
one without going through either. The bound was on what a caller may send; the
authority is also a producer.

§10.1 says the counter is never decremented or reused, which means the space is
finite, and running out is an ORDINARY refusal rather than a number nobody can
use. The last generation the range allows is still minted; the one after it
refuses and moves nothing.


4. [P1 3] ONE TEXT RULE, NOT TWO

`_text` required exact nonempty `str` and stopped there. `own` -- for
documents -- also required the text to be ENCODABLE. So the scalars had a
weaker rule sitting beside the stronger one, and a lone surrogate reached
SQLite from a route, an ending's prose, a plan digest, and out of `gate_token`
as an invalid durable token.

A rule that exists twice holds in one of the two places. There is one now,
`check_text` in `identity`, beside the other frozen grammars, and every cut-2
text operand uses it -- optional prose included, because prose is durable too.

AND ORDINARY NON-ASCII TEXT IS DATA. A route named `révision-plan` and a reason
carrying an emoji are asserted to work, because a rule that refused them would
be a bug wearing a fix.


5. [P1 4] A GATE IS DISCHARGED BY PROOF, NOT BY TRUTHINESS

Every evidence check used truthiness, so a list stood for an exact runtime
identity, a dict stood for a pinned clause, and a list satisfied a
plan-revision gate. `[1]` is not a proof of anything; it is a value that
happens not to be empty. Each kind now names the shape it requires, through the
one durable-text rule.

AND THE PROOF IS BOUND TO THE CONFIGURED FACT:

  contract-runtime   the evidence must name the profile, and it must be the one
                     certified for this contract. Recording only "a certified
                     profile exists" leaves the evidence unable to say WHICH one
                     was relied on, which is the whole point of keeping it.

  certified-isolation  THE ONE REPRESENTATION DECISION THIS CORRECTION TAKES,
                       raised here rather than left implicit. A boolean
                       `isolation_certified` made "pinned" mean "somebody once
                       said yes", and the evidence then only had to be truthy,
                       so neither side named anything. The policy now holds the
                       CLAUSE IDENTITY and the evidence must name that clause;
                       `True` is no longer a pinned clause. I took the strict
                       reading because it is the safe direction and because
                       "pinned clause" reads as an identity in the frozen
                       prose -- but it is a representation choice and the
                       reviewer invited it to be raised, so: raised. Rule it
                       otherwise and I will change it.


6. [P1 5] THE HISTORY IS THE WHOLE LIFE, IN WHOLE IDENTITIES

Claim wrote no event, so the journal said who LOST the Work and never who took
it. W151's transition table requires the claim event; the frozen Node host
omits it, and the frozen host is executable-reference evidence rather than the
contract. It is written in the SAME transaction as the Handler, because an
event that can exist without its state is not a record of anything.

And the events answered in separate columns -- work id, participant and
generation -- which is three quarters of an identity in the one place a reader
reconstructs history from. §4 says an identity is never a participant alone or
a local selector, and a journal that answers in parts invites exactly the
comparison §4 forbids. The columns stay, because they are what is indexed; the
ANSWER is an `assignment_ref`.

The existing one-event-after-end case was UPDATED rather than kept: it pinned
the reference's omission, and the review is explicit that it should not.


7. [P2 6] ONE MISSING-ASSIGNMENT REFUSAL FOR EVERY TRANSITION

`cancel` subscripted the normalized ABSENCE before reaching the
compare-and-swap, so `cancel(None)` raised `TypeError` where every other
transition gives an ordinary refusal. The COMMON precondition comes before the
transition-specific one: "you gave me no assignment" is true of every act and
is answered the same way by all of them. The case drives all four.


8. [P2 7] A BACKSTOP FOR BOTH DIRECTIONS

It checked gate-implies-block and nothing else, so an open Work in `block` with
NO gate, and one in an INVENTED phase, both returned True. A backstop that
checks one direction of a cross-product is a backstop for one of its two
failures. It now checks membership in the closed axis, both directions of the
pairing, and the gate's kind and detail -- and the coherent pairings still pass,
so it has not simply become a refusal.
