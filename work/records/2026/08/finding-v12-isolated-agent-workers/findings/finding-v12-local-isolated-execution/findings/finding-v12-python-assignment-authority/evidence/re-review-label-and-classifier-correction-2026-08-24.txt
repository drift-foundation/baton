Finding 1: an exact string label may still be unencodable
=========================================================

`label_of` proves an exact `str` inert and bounds its length, but unlike
`name_of` it returns the text itself. Python exact strings may contain lone
surrogates. Calling the exported `check_work_id(None, what="\\ud800")` returns
a Refusal whose first character is that raw surrogate; encoding the message as
UTF-8 raises `UnicodeEncodeError` at position zero.

That is not merely display polish. The package already treats a diagnostic as
text likely to cross a log or wire, and its value renderer deliberately uses
`ascii` so a lone surrogate cannot replace an ordinary refusal with an encoding
fault. The new label boundary needs the same round-trip property without
running caller behavior or changing ordinary labels.

Finding 2: the origin analysis still has false positives
=========================================================

The rewritten analyzer proves more than the AST establishes in four ways:

1. `owned_constants` is one package-global set of bare names. A literal `LIMIT`
   in one module therefore proves a caller-supplied parameter named `LIMIT` in
   another module.
2. `proven_locals(function)` uses `ast.walk(function)`, descending into nested
   functions. An assignment `what = label_of(...)` inside `nested` therefore
   proves the caller-supplied `what` in `outer`.
3. A local is called proven if ANY safe assignment exists. A later raw
   reassignment, or a branch in which the reaching assignment is raw, still
   leaves the interpolation classified safe.
4. A named-site key uses module + short function name + expression. Core
   deliberately has many nested functions named `body`; one exception for a
   `body` therefore excuses a same-spelled interpolation in a distinct sibling
   `body` in the same module.

These are not hypothetical parser curiosities: each was reproduced with a
minimal fabricated package driven through the audit's own `interpolations` and
`offenders` entry points. The analyzer returned no offenders for all of them.
The checker therefore still matches spelling beyond the origin it claims to
prove, just at more specific spellings than the prior version.

Required correction
===================

1. Make `label_of` return encodable bounded diagnostic text even for an exact
   string containing a lone surrogate, while preserving normal short labels and
   the measured useful ending.
2. Prove constants with module/import and lexical-shadowing context rather than
   a package-global bare-name set.
3. Keep local proofs inside their lexical scope and accept them only when safe
   reaching definitions dominate the interpolation with no unsafe reassignment
   or branch. A deliberately conservative rule or direct rendering at the site
   is preferable to an unsound data-flow claim.
4. Give named sites a unique lexical identity so an exception cannot travel
   between same-named nested functions.
5. Mutation-check these families, make all three reviewer methods green, and
   rerun the complete source and locked installed-wheel gate.
