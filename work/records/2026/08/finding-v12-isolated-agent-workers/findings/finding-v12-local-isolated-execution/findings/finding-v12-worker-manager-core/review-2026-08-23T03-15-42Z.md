## P1 — the Codex terminal mapping contradicts the frozen table

The frozen boundary's §10.3 maps `turn/completed` status `failed` to
`agent-failed`, refined by §10.6. `CODEX_TURN_STATUSES` instead contains only
`completed` and `interrupted`, and the existing test asserts that `failed`
must be rejected. That test expectation must be corrected to the already
recorded provider table.

The refinement branch also collapses every `codex-error-info` string to
`agent-failed`. Section 10.6 maps `ContextWindowExceeded` to `truncated`; the
remaining certified values map to `agent-failed` with different error pairs.
An unknown value is not a certified provider fact and must refuse rather than
silently becoming an agent failure. Retain both additive Codex regressions.

## P1 — the durable turn bypasses its frozen shape and seal

`recordTurn` checks only that its three time strings are nonempty. It accepts
and persists `deadlineAt: "not-a-timestamp"` and
`promptDigest: "not-a-digest"`, even though the frozen turn record requires
the reproduced timestamp and digest definitions. This repeats the foundation
lesson: later semantic code cannot stand in for shape proof.

The current input and row cannot represent a complete frozen `turnRecord`:
among the required members absent from the durable surface are
`dropped_event_bytes`, `policy_failures`, evidence, adapter diagnostics and
the document seal. Construct the complete owned document, run the placed
agent-session schema before reading semantic members, verify its seal, and
retain enough exact bytes to reproduce what was accepted. Retain the malformed
record regression and add representative negative count/failure-shape cases.

## P1 — the policy fact selecting the outcome is discarded

Any array-like value with nonzero `length` selects `policy-failed`; no failure
document is validated. After selection, the entire `policyFailures` input is
discarded: the turns table has no corresponding member and the returned value
does not carry it. A durable outcome whose deciding evidence vanished is not
the frozen turn record.

Validate every policy failure against the frozen definition and retain the
exact owned list with the turn. The additive unexpected-approval case currently
finds no durable `policy_failures` value.

## P1 — recording a turn is neither replay-safe nor collision-safe

`turnId` provides a deterministic act identity, but `recordTurn` performs a
plain insert outside the manager operation journal. Repeating the exact same
call therefore exposes SQLite's UNIQUE constraint instead of replaying the
committed result. Changing the terminal fact under that same identity also
cannot produce the manager's closed `refused.operation-collision` result.

Record this durable act through the existing transaction/replay boundary with
a signature covering every effective durable operand. Resolve exact replay
before mutable session state can hide it; collide changed operands; and retain
the additive replay/collision case.

## P1 — the first answer aliases the caller's terminal fact

The dossier pins durable rows and returned values as owned copies.
`recordTurn` instead returns `terminalFact` directly. Mutating the caller's
object after the call rewrites the already-returned answer from
`acp-stop-reason/end_turn` to `relay-policy/unexpected-approval`, while the
durable row says something else.

Return the same owned result the journal commits and later replays. Retain the
additive alias regression; the replay correction can naturally enforce this
boundary if it canonicalizes the one answer for first call and retries.
