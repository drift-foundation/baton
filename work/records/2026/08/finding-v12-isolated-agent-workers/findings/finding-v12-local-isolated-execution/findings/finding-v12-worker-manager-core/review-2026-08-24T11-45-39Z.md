## P1 — fixed-width digits do not establish a calendar instant

`_durable_instant` accepts `2026-99-99T99:99:99.999Z`. During issue, `_later`
calls `datetime.strptime` before its `try`, so the value escapes as raw
`ValueError`. During expiry it is never parsed, sorts after a real deadline,
and silently expires a live offer.

Make the shared instant rule establish both the frozen textual shape and a
representable calendar instant before any arithmetic or lexicographic
comparison. Merely moving `strptime` inside `_later`'s exception handler closes
the raw error but leaves comparison-only paths accepting a value that is not an
instant.

## P2 — the derived settlement-clock sweep is precondition-vacuous

The sweep describes each row as a minimal valid call and treats any
`ContractRefusal` as proof of the spoiled operand. Its `settle_claim` row has no
accepted offer. With only `now` spoiled, `_require_accepted` refuses the absent
offer before clock validation; deleting `_durable_instant(now)` would leave the
case green.

Supply the accepted-offer state needed to reach the clock boundary, or require
the exact integrity/schema refusal attributable to the spoiled operand. The
export-name completeness check is useful, but it does not establish per-
operand reachability.
