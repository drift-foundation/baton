## Accepted correction

`issueOffer` now obtains replay provenance from the transaction boundary:
the closure marker is set only when `ControlStore.transact` executes this
call's action. A replay returns without executing that action, so the losing
issuer refuses even when winner and loser receive the same injected bearer.
The verifier comparison runs only after a first commit and is correctly
classified as an integrity invariant rather than evidence of provenance.

The retained deterministic interleaving at
`v12/test/worker_manager_offers.test.mjs:1070` now passes. A genuine first
issue and a different Work both return normally, so the correction does not
collapse every issue into the replay refusal.

## Non-blocking test-description precision

The case titled “a SEQUENTIAL exact reissue is refused by the same marker” is
intercepted by the optimistic `store.replay` precheck in the current code; it
does not itself execute the closure-marker branch. This is not a remaining
coverage gap: the same-bearer concurrent case deterministically exercises the
replay marker, while the first-issue case exercises the commit outcome. The
sequential case pins the public refusal but should not be cited as independent
branch evidence.
