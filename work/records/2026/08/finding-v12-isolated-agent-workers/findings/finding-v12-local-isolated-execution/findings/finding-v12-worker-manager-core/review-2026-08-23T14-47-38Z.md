## P1 — content-derived turn identity conflates distinct supervised turns

`turnId` derives the operation identity only from `(attempt, posture, epoch,
prompt_digest)`. The frozen contract permits more than one supervised turn in
an epoch and requires one turn document per supervised turn; equal prompt
bytes do not make two prompts the same act. A second legitimate turn using
the same prompt digest but later timestamps therefore reaches the first turn's
operation id and refuses as `operation-collision`. The store cannot represent
both turns.

Introduce one stable manager/relay-owned per-turn identity component that is
independent of prompt content while remaining stable across retry. Allocate or
validate it atomically within the session epoch, and retain both the distinct
same-prompt case and exact-retry case.

## P1 — turn admission proves row presence, not the session it names

The initial session query selects `state` and then ignores it. A session row
already marked `closed` accepts a new turn and writes a durable record, even
though closed means every turn the epoch started already has a terminal fact.
The same query does not load or compare `provider_session_id`; a caller can
name `provider-session-b` while the durable session row names
`provider-session-a`, and the mismatched reference is sealed as accepted
evidence.

Bind a new turn to the full durable session reference and a state in which a
turn may legitimately settle. A terminal or ambiguous epoch must admit no new
turn. Preserve exact replay of a turn committed before the session later
closed: immutable operation identity must be resolved before today's session
state, while a genuinely new turn checks the current state and stored
reference.

## P1 — current secret liveness hides an exact committed replay

The complete document secret scan runs before `ControlStore.transact` can
resolve the operation journal. If ordinary diagnostic text is durably accepted
and that same value is later registered as an ephemeral bearer, an exact retry
of the already committed turn now refuses `integrity.secret-leak`. It writes
nothing new and returns no bearer-bearing field; the mutable registry merely
hides the immutable answer, while the original durable bytes necessarily
remain unchanged.

Resolve exact replay/collision from the fixed turn identity and signature
before applying current-state checks to a genuinely new record. Keep the
new-write secret refusal intact and retain a changed-retry collision case.

## P2 — malformed input and summary bypass the closed error taxonomy

`recordTurn` calls `policyFailures.map` before it has proved the list shape, so
`policyFailures: null` throws a raw `TypeError`. `permitsDisposition` parses
the unsealed summary outside an integrity wrapper, so malformed retained JSON
throws a raw `SyntaxError`. Both contradict the frozen rule that every
reported failure is one closed category/code pair, and the latter fails the
prior review's explicit requirement that any summary divergence refuse as an
integrity failure.

Prove the collection shape before iteration and translate malformed retained
summary bytes to the intended `integrity` pair. Retain both negative cases.
