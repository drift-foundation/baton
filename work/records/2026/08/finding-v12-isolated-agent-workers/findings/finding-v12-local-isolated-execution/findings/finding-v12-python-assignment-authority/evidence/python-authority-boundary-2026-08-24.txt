3. PYTHON DATA AND IDENTITY BOUNDARY

Durable/public documents use the frozen snake-case conceptual shapes, not the
Node implementation's camel-case objects:

  work_ref       {authority_uuid, work_id}
  assignment_ref {work_ref, participant, generation}

For v12, `authority_uuid` is 32 lowercase hexadecimal characters, `work_id`
is the full canonical `<8hex>-W<positive>` id, participant matches the frozen
`team.member` grammar, and generation is a positive safe integer. V11 may
carry no live generation internally, but a worker-control assignment document
is always v12 and never serializes a null generation.

Every runtime-session mutation takes one exact built-in operand `dict`. The
boundary first copies recursively from exact built-in dict/list and JSON
primitives, then validates. Dict/list subclasses, arbitrary mappings, objects,
booleans where an integer is required, unsafe integers, floats, invalid
Unicode, non-string keys, extra fields and excessive depth/members refuse
without calling caller hooks. Supplying `actor` or `participant` refuses;
authenticated identity comes only from the bound session. Returned documents
are fresh owned built-ins, never aliases of inputs or retained store objects.

This is the Python translation of the reviewed snapshot/TOCTOU correction. It
does not transliterate JavaScript Proxy/getter mechanics. Hostile Python
objects and container subclasses prove the portable property: validating one
view and executing another is impossible because behavior-bearing containers
never enter the authority.

Operation signatures are authority-owned canonical operand bytes/text, not
worker-control's SHA-256 `signature_digest`. `claim_signature(work_id,
participant)` is exported by the authority package and used by W4; the manager
does not recreate its encoding. Missing and explicit null operands remain
distinct through an internal sentinel/tag where the transition distinguishes
them. Timestamps cross the boundary as validated UTC text, not Python datetime
objects.


4. STORE CREATION AND ADOPTION

The Python authority store has its own store-kind marker, schema version and
durable authority UUID. It must not open the frozen Node authority merely
because both call their first schema version `1`.

  * `Authority.create(path, authority_uuid=...)` requires an absent exact file
    and wins creation exclusively. It initializes the store-kind, version and
    UUID in the creating transaction.
  * `Authority.open(path, expected_authority_uuid=...)` requires an existing
    recognized Python-authority store. It performs a read-only compatibility
    probe before any schema/PRAGMA write and rechecks inside the first write
    transaction. An unowned, empty, foreign, newer/older or UUID-mismatched
    database refuses without modification.
  * The authority creates no directory and receives no state-root authority.
    Placement supplies the one explicit external file. Symlinks and non-regular
    targets refuse.
  * Every process opens its own `sqlite3` connection in autocommit mode,
    enables foreign keys and a bounded busy timeout, and wraps mutations in
    explicit `BEGIN IMMEDIATE` transactions. No connection crosses a process.

The schema carries only authority facts: meta, certified contracts, permitted
contract transitions, policy, Work, route handlers, capabilities, fenced
generations, the deployment-wide participant claim slot, authority operation
journal, assignment/contract/gate/activity events, proposal, immutable
receipts and integration attempts. It carries no offer, attempt, runtime,
output, intake, cleanup, token/verifier, artifact or credential fact.


5. TRANSACTION AND REPLAY BOUNDARY

One private assignment-ending helper serves cancellation, ordinary end,
pass, close, gate arrival, plan rejection and contract advancement. It clears
Handler/live generation and claim-slot state in the same authority transaction
and never changes the generation counter. Cancellation additionally inserts
the fence and derives the runtime-quiescence gate in that same commit.

The operation journal preserves the four W151 states: no row is UNSUBMITTED;
rows are COMMITTED, REFUSED only when the refusal itself retained evidence, or
RETIRED. Action execution occurs inside a savepoint within the surrounding
`BEGIN IMMEDIATE` transaction:

  * ordinary Refusal -> rollback savepoint, no operation row;
  * private durable Refusal -> retain its prior evidence and record refusal;
  * any other exception -> rollback the entire transaction;
  * success -> mutation and canonical result record commit together.

Replay checks RETIRED before operand comparison, because retirement kills the
identity for every submitter. Committed/refused records compare the complete
canonical signature first. Retirement binds expected signature, reason and
terminal disposition. Settlement without explicit `may_retire` observes only;
an unavailable lookup settles nothing; a committed claim always wins the
settlement race.

Clock and UUID sources are injected at trusted bootstrap for deterministic
tests. Production defaults use aware UTC and `uuid4().hex`. SQLite time and
process-local counters are not authority.


6. TWO PUBLIC FACES, WITH AN HONEST PYTHON TRUST CLAIM

`Authority` is trusted bootstrap/configuration. It creates/opens/disposes the
store, certifies/withdraws contracts, permits transitions, configures policy,
routes and capabilities, creates Work, reads projections, and mints sessions.
It performs no runtime transition itself.

The minted runtime object exposes exactly:

  transitions: claim, activity, advance_contract, approve, cancel, close,
               end, install_gate, integrate, pass_work, publish, reject_plan,
               review, satisfy_gate, settle_operation, verify
  reads:       assignment_of, assignment_events, activities, canonical_target,
               contract_events, fenced_generations, gate_evidence,
               integration_attempts, operation_record, operation_result,
               project_work, proposal, receipt, receipts, slot_holder,
               assert_invariants

Attributable receipt/close actors and claim participant come from the binding.
Assignment-owned transitions compare the normalized expected participant with
that binding before core execution. `close` is the deliberate exception: its
configured close capability authorizes the actor, while exact `expect` is the
compare-and-swap operand when it ends somebody else's live assignment.

Python reflection is not a sandbox. A determined trusted in-process module can
inspect private attributes/closures or import private package modules. The
reviewed guarantee is therefore exact and honest: the SUPPORTED/EXPORTED API
hands W4 neither bootstrap nor store/path/SQL/session-mint authority, and the
deployment/filesystem/process boundary does not give W4 those objects or
paths. Tests inspect the exported/reachable public surface and deployment
wiring; they do not claim underscore names are cryptographic capability
isolation. Untrusted workers remain process/container isolated behind W5.
