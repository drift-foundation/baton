## P1 — allocation opens a turn without admitting the session that will run it

`allocateTurn` is now the supervision boundary: its own contract says it opens
one turn before the relay issues the prompt. But it calls `sessionRow` only for
existence and deliberately ignores both the session state and the stored
`provider_session_id`. It therefore durably opens a turn in `not-started`,
`initializing`, `prompting`, `turn-ended`, `cancel-requested`,
`agent-quiescent`, `unknown`, or `closed`, and it can return the caller's
mismatched provider-session label as though that were the durable reference.

That is not a harmless abandoned allocation. Frozen §7.3 has exactly one edge
that starts a prompt: `ready -> prompting`; `agent-quiescent` says the
conversation is over, while §3.3 makes `unknown` and `closed` terminal.
Moreover, `closed` means a terminal fact was observed for EVERY turn the epoch
started. Opening another turn after that state immediately makes the durable
session assertion false. Frozen §3.1 also says the full reference labels
evidence. Deferring both checks to `recordTurn` is too late: the allocation
boundary precedes the external prompt, whereas recording follows its terminal
fact.

Admit allocation under the existing write lock against a positive START set
(`ready` in the frozen state graph) and the full durable provider-session
identity, before inserting anything. Keep `recordTurn`'s separate positive
SETTLE-state and provider checks: an allocation may legitimately open while
ready and settle after the state advances, and an exact committed record must
still replay after later closure. The existing exhaustive settlement test can
allocate while ready and then move to each tested settlement state before
calling `recordTurn`; that preserves the boundary it was designed to prove.

One additive regression, without changing an existing assertion, drives every
non-`ready` frozen state and a mismatched provider id, requires the closed
`refused.precondition` pair, requires zero refused allocations, and accepts the
exact ready reference at ordinal one. It currently fails at the first state,
`not-started`.
