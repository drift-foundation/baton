## P1 — a no-change observation does not consume its source identity

`observe` now resolves a prior durable identity before consulting the axis,
but when no prior row exists and today's value already equals the observation,
it returns success without inserting the identity (`attempts.mjs:545-568`). A
sourced `consent_runtime=not-started` observation therefore leaves its
`(attempt, incarnation, source_seq)` reusable; a different
`execution_runtime=running` observation under the same identity then commits.
The earlier correction covers a conflict only when the first observation
changed state and consequently wrote a row.

Every accepted adapter-sourced observation must durably consume its source
identity, even when it changes no axis. Preserve the existing inert behavior
for manager-internal repeats if desired, but do not return success for an
external source identity that remains reusable.

Regression: `an inert observation still consumes its source id`.

## P1 — `stopping` still disables later mismatch cancellation

The transition-map comment and correction record say cancellation is reachable
from every nonterminal execution state, but `stopping` is the sole nonterminal
state without a cancellation response (`attempts.mjs:58-78`). When a later
inspection discovers two matching runtimes, `reconcileRuntime` calls `cancel`
and receives `runtime-observation.state-regression` instead of returning the
pinned cancellation decision.

Do not regress a runtime already stopping merely to rewrite it as
`cancel-requested`; make the cancellation response idempotent for an in-flight
stop, or otherwise represent the safety response without refusing it. The
test pins the decision, not a backward axis transition.

Regression: `multiplicity discovered while stopping still cancels`.

## P2 — contention classification matches arbitrary error prose

`isContention` concatenates structured SQLite fields with the free-form error
message and accepts any `text.includes("busy")` (`attempts.mjs:601-605`). A
trigger abort saying `busy provider invariant` is consequently assigned the
portable meaning and retry policy for a database lock. This remains the wrong
diagnosis the correction intended to remove.

Use SQLite's structured BUSY/LOCKED result codes, or exact canonical lock
indicators; do not infer storage contention from an unrestricted substring in
application-controlled prose.

Regression: `the word busy is not SQLite contention`.
