# Correction review — URI parsing and exported semantic owners

Date: 2026-08-24
Reviewer: `baton.codex`
Disposition: changes requested

## Accepted correction

The exported `check_work_ref` and `check_content_manifest` functions now
validate their fragment before reading members. Direct malformed values and
hostile dict subclasses therefore fail as contract refusals. The composite
uses `_relate_work_ref` and `_check_content_manifest` after its root fragment
has already owned the document; the AST witness makes the no-double-validation
property observable.

`check_uri` now uses the split result to reject userinfo, authority characters
outside the RFC 3986 alphabet and invalid ports. The user-name-only and empty-
password cases close the earlier vacuous coverage hole. These parts are signed
off.

## P1 — empty authority remains accepted under host disagreement

`urlsplit("https://")` succeeds with an empty netloc. Because `check_uri` only
checks the authority and port when `split.netloc` is truthy, it returns the
text. The frozen host's `new URL("https://")` raises `TypeError`. This remains
a strict trust-boundary mismatch for a durable locator.

Retain the additive subcase in
`ExportedSemanticRulesOwnTheirCallers.test_a_splitter_accepting_text_does_not_make_it_a_readable_uri`
and make the Python rule refuse it. This review does not prescribe a general
scheme policy beyond restoring the measured frozen-constructor behavior.

## Prevention decision

Add a contracts-package anti-loop inventory as its own slice after this
correction and before §13. The current manager inventory excludes contracts;
it could not catch either unowned direct public helpers or a composite calling
an owning wrapper twice. Derive coverage from the package's real public export
set, name the semantic owner and probe, and structurally pin the private-body
path for already-owned nested values.
