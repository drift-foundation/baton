# Independent signoff — named manifest fragments and digest identity

PLAN 4ct is accepted with no correction finding.

Both requested design decisions are approved. Public fragment validation takes
one name from the frozen schema's `$defs`, never caller-supplied schema data;
every validator the boundary can run is therefore package-built and
identity-owned. Each fragment validator contains only the frozen `$schema`,
`$id`, `$defs` and the selected `$ref`. Root envelope constraints, especially
`oneOf`, do not apply to a definition validating as itself.

The definition operand types before membership, the document is exact-POD owned
before validation, and fragment validators come from the same private parse as
the whole-document validator. Digest verification owns the manifest, requires
the declared member, recomputes over every other member and returns the computed
identity rather than merely forwarding the claim.

The narrower scope is accepted because it is named narrowly: these two helpers
do not present themselves as the full manifest trust entry. All remaining §12
semantics, retention, tables and freeze/record stay explicitly queued.
