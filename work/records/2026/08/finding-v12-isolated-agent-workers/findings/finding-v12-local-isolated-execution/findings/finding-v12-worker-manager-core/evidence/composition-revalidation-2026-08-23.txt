2. ITEM 4aj — THE CLOSED TAXONOMY, SWEPT

Six review rounds established that a refusal must never serialize the value it
is refusing, and each round fixed the ONE site the reviewer had found. Nobody
swept. I swept.

MEASURED, by driving every boundary with a BigInt, a circular object, a
throwing `toJSON` and a trapping Proxy:

  ELEVEN diagnostic sites lost the closed pair.

  agent_session_axis   normalizeAgentSessionRef, the state check
  agent_events         tool-call status, sourceKind, sealEvent kind,
                       the observed turn id
  agent_turn           turnSessionRef, the turn token
  posture_slots        evidence, posture, attemptId, epoch, runtimeIdentity
  agent_handshake      wire version, observed build id, and all THREE method
                       surfaces
  attempts             the claimed and expected assignments

Every one was `JSON.stringify(x ?? null)` inside a message. They are one
helper now, `nameValue` in `contracts.mjs`, beside the `ContractError` it
exists to build. It calls `records.mjs` for shapes rather than duplicating it.

AND THE DIAGNOSTIC IS STILL WORTH READING, which matters: a string primitive
interpolates without running anything and cannot fail, so a method name is
SHOWN. "The agent called session/prompt" is the whole diagnostic and losing it
to "a string value" would be paying for safety twice. It is bounded at 60
characters, because an unbounded caller value in a message that may become
durable is a different problem. Numbers, booleans, bigints and symbols have a
`String` form that runs nothing. Everything else is named by SHAPE.


3. ITEM 4ak — OPERANDS THAT REACHED SQLITE UNPROVED

A second, different class, found by the same sweep and reported separately
because it is not a diagnostic defect:

  turnRecordOf(store, id)              id bound straight into the statement
  eventRecordOf(store, ref, seq)       four members read off an unproved
                                       reference and bound
  attempts.attemptRow(store, id)       id bound straight into the statement

An object operand produced SQLite's own "Unknown named parameter 'toJSON'"; a
trapping Proxy produced an arbitrary Error of the caller's choosing. Three
READ boundaries that never validated their one operand.

Each proves its operand first. `eventRecordOf` proves the reference through
section 3.1's own normalizer and uses THE ONE OWNED COPY for both the query
and the retained-document binding, because reading the members twice is how a
check and an answer come to disagree.

ABSENCE AND REFUSAL STAY DIFFERENT ANSWERS. A well-formed id naming nothing
still answers null; an id that is not an id refuses. Conflating them would
tell a caller "no such turn" about a question that was never asked, and there
is a case for it.


4. TWO COPIES OF SECTION 3.1 THAT HAD DIVERGED, NOT MERELY DUPLICATED

`turnSessionRef` in `agent_turn.mjs` and `normalizeAgentSessionRef` in
`agent_session_axis.mjs` are both section 3.1. Measured:

  providerSessionId: ""    axis REFUSES        turn ACCEPTED

The same reference was valid at the turn boundary and invalid at the axis.

THIS NEEDED NO RULING: the frozen schema decides it. `$defs.providerSessionId`
is `{"type": "string", "minLength": 1, "maxLength": 512}`, and an empty opaque
id is not an id. The axis was right. The turn copy had dropped the word
"nonempty" from its check AND from its own message.

Fixed, and the case that owns it drives BOTH copies through one table --
because the defect was not either check on its own, it was that nothing
compared them.

STILL LOOSER THAN THE FROZEN SCHEMA, MEASURED AND NOT FIXED HERE: neither copy
enforces `maxLength` (512 for a provider session id, 160 for an opaque id) or
`opaqueId`'s `^[A-Za-z0-9][A-Za-z0-9._:-]*$` pattern. That changes what is
ACCEPTED across every W4 boundary and belongs in the composition ruling beside
4ah, not in a correction round.


5. ITEM 4ah — THE RULING, WITH THE MEASUREMENTS IT NEEDS

I did not decide this. Here is what is true, so the decision is about
evidence:

  a) ORDINARY ACCESSORS RUN. A plain object whose four members are getters is
     accepted and all four run. Refusing Proxies alone would not establish an
     inert-data rule, exactly as the review says.

  b) ITEM 4aa's PROTECTION HOLDS. A shifting getter is read ONCE -- measured,
     one read -- so the check and the answer cannot disagree. Whatever is
     ruled, that property is already there and must survive.

  c) ANY CONTAINER IS ACCEPTED. A class instance carrying the four members is
     accepted. AN ARRAY with the four members attached is accepted.

  d) EXTRA MEMBERS ARE IGNORED. A reference carrying `extra` and `state`
     alongside the four is accepted and the extras are dropped.

  e) THE FROZEN SCHEMA IS ALREADY EXACT. `$defs.agentSessionRef` is
     `additionalProperties: false` over exactly those four members. That is
     direct contract evidence for the inert-record reading -- though it
     governs the DOCUMENT form, and whether the in-process API operand must
     match it is precisely the open question.

  f) THE BLAST RADIUS IS NOW ONE LARGER. This pass routed `eventRecordOf`
     through the axis normalizer, so a ruling reaches the event reader too.
     Three call sites in `src` plus the turn module's own copy.

If (a) is ruled inert, `recordFault(ref, [the four])` from `records.mjs` does
it exactly, and BOTH copies must change -- which is the argument for the turn
module consuming the axis normalizer rather than reimplementing it.
