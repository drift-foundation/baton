Observed — instant shape is not instant representability
--------------------------------------------------------

The shared `_durable_instant` checks only fixed-width digits. Consequently
`2026-99-99T99:99:99.999Z` passes the rule even though it names no calendar
instant.

On issue, `_later` invokes `datetime.strptime` before entering its exception
boundary, so the configured clock value escapes as raw ValueError. No authority
read or entropy occurs, but the answer is not the closed contract refusal the
boundary promises.

On comparison-only expiry, the same value is never parsed. It sorts after a
real August deadline and silently expires a live offer. Thus this is not only
an exception-translation placement error: the shared rule must establish a
real representable calendar instant before every lexicographic comparison.
