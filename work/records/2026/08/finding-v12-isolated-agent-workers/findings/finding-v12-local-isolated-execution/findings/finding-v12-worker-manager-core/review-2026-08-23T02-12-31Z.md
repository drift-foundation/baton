# Independent review: agent-profile certification first slice

Date: 2026-08-23T02:12:31Z
Reviewer: `baton.codex`
Disposition: **changes requested**

Scope: `v12/src/worker_manager/agent_profile.mjs`, its product schema asset,
the shared `profiles` table and the existing profile consumer in
`offers.mjs`. This review remains bounded to item 4's first slice; sessions,
turns, normalized events and adapter contracts remain unimplemented.

## Result

The new composing entry point does validate shape, then document seal, then
policy in the recorded order. The two frozen design profiles certify under
the product canonicalizer, the schema asset is currently byte-identical to
the frozen design asset, and the original eight focused cases remain green.

Two public paths nevertheless make that entry point avoidable or confuse the
independent profile axes.

## P1 — the generic profile writer bypasses the one certification route

`offers.mjs` still exports `certifyProfile(store, { kind, name, digest })`.
It accepts `kind: "agent-session"` and inserts an arbitrary caller-authored
digest directly into the same `profiles` table. No agent-session schema,
document seal, posture policy or secret check runs. The new
`isAgentSessionProfileCertified` lookup then reports that digest certified.

This contradicts the frozen requirement that every profile use one composing
entry point. The new entry point is correct when called, but the older public
writer permits callers not to call it.

The additive regression `W2929 review: no generic writer can forge
agent-session certification` fails on the product path. Restrict or replace
the generic writer so it cannot create an `agent-session` row; only the
shape/seal/policy entry point may establish that kind. Retain the regression.

## P1 — an agent-session profile certifies the runtime-profile offer axis

`offers.mjs::certifiedProfile` queries only `digest` and `withdrawn_at`; it
does not require `kind = 'runtime'`. A valid agent-session profile therefore
satisfies `issueOffer`'s runtime-profile certification check. The test
certifies the frozen ACP agent profile through the new correct entry point,
then issues an offer using that agent digest as `profileDigest`; the offer is
accepted.

Agent-session and runtime profiles are separate contract axes. A digest
certified under one kind is not certification under the other even when the
bytes are genuine. Make every consumer name the required profile kind and
fail closed on a cross-kind row. The additive regression `W2929 review:
agent-session certification cannot satisfy runtime offer` currently fails;
retain it.

The inverse focused check already passes: a runtime row does not satisfy
`isAgentSessionProfileCertified`, because that new query is correctly scoped
to `kind = 'agent-session'`.

## P2 — retain the missing schema byte-identity regression

The product schema bytes currently match the frozen ACP-boundary asset
exactly, but this new suite did not guard that acceptance requirement. The
review adds `W2929 review: the product schema is byte-identical to the frozen
asset`; it passes. Retain it so the placed copy cannot drift silently.
