2. P1 — THE ANSWER RE-READ THE CALLER'S REFERENCE

`handleTransportLoss` passed the caller's object to the axis, which validated
and bound its own normalized copy — and then the ANSWER spread the caller's
object again and read `providerSessionId` a second time. So a getter could
answer provider A to the check that committed the epoch and provider B to the
record of it, and members the closed §3.1 shape does not have rode along into
something that looks like a session reference.

Two reads of one untrusted value, one of which decides and one of which
reports. This Work has the same shape recorded in `store.mjs` — "a `toJSON`
method can return `{diagnostic: <bearer>}` while `Object.entries` shows only
the method" — and I wrote it again at a new boundary.

Corrected: `normalizeAgentSessionRef` is exported from the axis module, the
reference is proved ONCE here, and the SAME object goes to the axis and into
the answer. The answer carries exactly the four members and is a fresh copy.

The proof also moved BEFORE the durable observation, so a malformed reference
cannot commit an epoch and then be refused on the way out.


3. P1 — THE OPTIONS ENVELOPE WAS UNPROVED

`{ turnInFlight = false } = {}` defaults only for `undefined`. An explicit
`null` reached a property read and left as a raw `TypeError`; a boolean, a
string or an array destructured to `undefined`, silently took the `false`
default, and COMMITTED the epoch to `unknown` on operands nobody proved.

A DEFAULT IS FOR AN ARGUMENT NOBODY GAVE, not for one somebody gave wrongly.
The envelope is proved before anything durable happens.

AND MY FIRST FIX MADE THE SAME MISTAKE ONE LEVEL DOWN. I wrote
`options?.turnInFlight ?? false`, which turns an explicit `null` member into
the default — and my own earlier case, the one asserting that whether a turn
was in flight is stated rather than inferred, failed immediately and caught
it. The member is now read only when the KEY is present.
