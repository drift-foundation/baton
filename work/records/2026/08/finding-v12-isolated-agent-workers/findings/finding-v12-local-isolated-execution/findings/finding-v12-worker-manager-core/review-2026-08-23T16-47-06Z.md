## P1 — two ACP mappings do not accept the frozen evidence

`normalizeAcpUpdate` makes only `other` contentless, so
`agent_thought_chunk` text becomes portable event content. Frozen §6.2 says
that reasoning content is diagnostics and **never portable evidence**. Count
it, but do not place it in the normalized event's portable `content`.

The tool-call path reads `update.toolCall.toolCallId` and `.status`. The frozen
captured trace instead carries `toolCallId` and `status` at the ACP update
root, for both `tool_call` and `tool_call_update`; the delivered normalizer
therefore refuses the provider shape it was built to normalize. Consume the
captured root shape and retain the provider's id and permitted status.

Case-specific existing-test migration is authorized by the frozen evidence:
replace the nested `toolCall` fixtures in the existing mapping/tool-call cases
with the captured root-level fields while preserving their id/status
assertions. This is a fixture correction, not a weakening.

**Open contract inconsistency:** the §6.2 prose says `tool_call` also carries
ACP `kind`, but frozen schema `$defs.toolCallView` permits only
`tool_call_id`, optional `title`, and `status` with
`additionalProperties:false`. Do not invent a portable `kind` member in this
slice. The contract owner should reconcile the prose and schema before a
future implementation relies on that field.

## P1 — observation does not answer from the authenticated durable frame

Frozen §6.4 requires the consumer to answer with the same sealed bytes and to
return owned copies. `observeEvent` instead returns only summary metadata on
both first observation and replay. On replay it reads only the indexed digest,
never parses or authenticates the retained body, and can consequently report
success after that body has become unparsable.

Return the sealed document beside observation metadata. The first answer must
not alias the caller's object; replay must load, validate, authenticate and
return a fresh owned copy of the retained body. A changed or unreadable body
must fail closed rather than being hidden by a matching summary digest.

Case-specific existing-test migration is authorized by §6.4: extend the
existing exact expected observation answer to include the returned document,
and preserve every existing observation-metadata assertion. This updates an
expectation that contradicts the frozen ruling; it does not remove coverage.

## P1 — the sealed turn identity can disappear during observation

`observeEvent` defaults a separate `turnId` operand to null, validates the
sealed `owned.turn_id` only when that operand is non-null, and writes the
operand to the row. Thus a frame sealed for a non-null turn is accepted with
no allocation check and persisted as an unbound event whenever the caller
omits the option. That loses an authenticated identity member at the durable
boundary and also gives lateness the wrong subject.

Use the sealed `owned.turn_id` as the durable turn identity. If a redundant
operand remains, require exact equality in both null and non-null directions;
for a non-null effective turn, validate its allocation in the same session,
derive lateness from it, and persist it. Refusal must write nothing.

## P1 — the event bound trusts an attacker-controlled accounting member

The implementation compares `owned.byte_count` with the profile limit.
`byte_count` describes source/update accounting; it is itself inside the
untrusted sealed document and can claim `1` while the canonical event is far
over the limit. The frozen model's `enforce_event_limit` measures
`canonical_bytes(event)`, and SPEC §6.3 bounds every normalized event.

Enforce the pinned event bound against the canonical bytes of the complete
authenticated event. Preserve `byte_count` for its distinct source-accounting
purpose. An over-limit document must refuse without a row.
