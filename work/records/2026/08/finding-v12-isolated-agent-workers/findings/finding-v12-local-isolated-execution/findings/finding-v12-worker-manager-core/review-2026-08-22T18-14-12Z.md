## [P1] The operation journal can durably store the claim bearer

`assertNoDurableSecret` correctly walks nested durable objects, but
`ControlStore.transact` does not call it. A successful action returning
`{nested: {claim_token: GOLDEN_BEARER}}` is JSON-serialized directly into
`operations.result` and committed. The existing file-wide bearer sweep proves
only that its one safe action was safe; it does not enforce the stated property
at the journal boundary.

Apply the durable-secret check to every committed journal result before the
operation record is written, inside the transaction so refusal rolls back the
action. Apply the same durable-surface discipline to sealed refusal data. The
retained regression requires `integrity.secret-leak` and no operation row.

## [P2] A database without Baton metadata is silently adopted

The incompatible-version correction checks only whether a table named `meta`
exists. If it does not, the constructor treats the database as fresh and runs
the complete manager schema. A pre-existing WAL database containing
`foreign_state` is therefore accepted and comes back containing both the
foreign table and every Baton manager table.

Absence of Baton's metadata is not evidence that an existing database belongs
to Baton. Initialize only a genuinely empty schema; if any application object
already exists without the manager's exact metadata, refuse without changing
bytes and close the handle. The retained regression fixes journal mode at WAL
before opening so it exercises ownership rather than failing incidentally on
SQLite's in-transaction journal-mode restriction.
