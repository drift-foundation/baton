3. THE ONE PLACE I DID NOT PORT THE NODE HOST, AND WHY

The frozen `Store.open` creates when absent, adopts when present, and writes
the schema BEFORE establishing whose store it is. For a disposable single-host
authority that was tolerable.

It is not tolerable here, and the boundary says so: this distribution now sits
beside three other SQLite files whose first schema version is also `1` -- the
Node authority, v11, and the manager's control store. A create-or-adopt `open`
against any of them writes tables into somebody else's database before anyone
has asked whose it is, AND THE FAILURE MODE IS SILENT SUCCESS.

So the two operations are separate and the order of the checks is deliberate:

  create   reserves the path with O_CREAT | O_EXCL BEFORE SQLite is involved,
           so two racing creators produce one winner and one refusal rather
           than two half-built stores. It fails on a file, a directory and a
           DANGLING SYMLINK alike -- the last being exactly the case a
           "does it exist?" check answers wrongly.
  open     probes READ-ONLY, checks KIND before VERSION before UUID, and only
           then connects. Kind first because "version 1" is true of three other
           products and telling a caller their store is the wrong VERSION when
           it is the wrong PRODUCT sends them to fix the wrong thing.

AND A REFUSAL LEAVES THE FILE AS IT WAS FOUND -- not "after we fixed the
PRAGMAs". The journal mode is the only PERSISTENT sqlite setting involved, so
`open` withholds it until the recheck under `BEGIN IMMEDIATE` has passed;
`busy_timeout` and `foreign_keys` are per-connection and write nothing.


4. THE PYTHON TRANSLATION OF THE SNAPSHOT CORRECTION

The Node defect was a getter answering one participant to the binding check and
another to the execution. Python's version of that hazard is not `Proxy` and
not getters: it is `dict`/`list` SUBCLASSES, `__getitem__` overrides, arbitrary
mappings and objects with hooks of their own.

So `own()` does not defend against those; it makes them unreachable. Types are
tested with `type(x) is T` -- never `isinstance` -- so a subclass is REFUSED
rather than admitted with its overrides intact, and only exact `dict`, `list`,
`str`, `int`, `bool` and `None` are data. A behaviour-bearing container never
enters the authority, so validating one view and executing another is
impossible rather than guarded against.

The test carries a `LyingDict` whose reads answer `baton.claude` once and
`baton.gemini` afterwards -- the exact Node defect, in Python -- and it is
refused for being a subclass, before either answer matters.

AND THE REFUSAL NEVER RUNS THE VALUE. A `Hostile` fixture raises from
`__repr__`, `__str__`, `__eq__`, `__hash__`, `__iter__`, `__len__`,
`__getitem__` and `keys`, and is offered as the operand, as a member, as a list
entry and nested; nothing runs in any position. This is the rule six W2929
review rounds established, applied at the first boundary of a new host rather
than after somebody finds it here too.

7. THE TRUST CLAIM IS THE NARROW ONE

`tests/authority/test_boundary.py` proves the exported names are exactly the
sixteen promised, that none of them contains store/path/SQL/mint/bootstrap,
that the bootstrap face exposes `authority_uuid`, `close`, `create`, `open` and
nothing else, that every module imports only the standard library and this
package, that no literal reaches for v11/the Node host/a dossier, and that the
schema's table set is exactly the authority's and disjoint from the control
store's.

It does NOT claim that underscores are a sandbox. A determined trusted
in-process module can import `baton_v12.authority.store` or read a private
attribute, and saying otherwise would be a false guarantee dressed as a test.
Untrusted workers are isolated by process and container, which is a mechanism
that enforces something.

`test_a_later_cut_adds_methods_rather_than_stubs` asserts that `claim`, `end`,
`cancel`, `session` and the rest are ABSENT: a stub raising
`NotImplementedError` is a method the exported surface claims to have.
