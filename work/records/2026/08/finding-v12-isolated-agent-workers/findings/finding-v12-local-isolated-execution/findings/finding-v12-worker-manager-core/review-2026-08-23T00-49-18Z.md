## Findings

### P1 — a retained non-input document is accepted as the input declaration

`loadManifest` returns `JSON.parse(found.body)` without validating the loaded
document, its stored schema, or the relationship between its body and key.
`recordFrozenResult` then passes that object directly to
`compareDeclaredOutputs`, which assumes that any object with an `outputs`
array is an input manifest. The public retention API can validly retain a
result manifest, and an attempt can name that result digest as its
`input_digest`; freeze accepts the result manifest's similarly shaped output
rows as trusted declarations and records a result.

The earlier review required a **trusted, digest-verified input declaration**,
not merely a row at the named key. Validate the loaded body specifically as
`inputManifest`, recompute its digest against the key, and fail closed before
using any declaration member. Preserve `W2929 review: the attempt input digest
must name an INPUT manifest`.

### P1 — declared output constraints are ignored

`compareDeclaredOutputs` checks name and type, plus required status for a
completed disposition, but never reads `expect.constraints`. A result whose
content manifest exceeds the declaration's `max_bytes` freezes successfully.
The same omission covers declared entry limits and allowed media types.

The frozen worker-control contract says output descriptors carry these limits
and that freezing rejects limit violations. Artifact-byte verification can
remain W2930's, but the counts, totals and media type already present in the
validated sealed observation are decidable here. Enforce every constraint the
result manifest can prove and preserve `W2929 review: a result must satisfy its
declared output limits`.

### P1 — result retention silently accepts a digest/body collision

`retainManifest` correctly refuses an existing key with different bytes, but
the result path bypasses it with `INSERT OR IGNORE INTO manifests`. If the
result digest already names different stored bytes, the insert is ignored and
the new `outputs` row commits a foreign-key reference to those wrong bytes.
The operation then reports the requested result as frozen even though reload
returns a document its digest does not identify.

This contradicts the correction's own invariant that one digest cannot name
two documents and that a collision refuses rather than overwrites. Apply the
same compare-before-reference behavior inside the result transaction and
preserve `W2929 review: result retention refuses an existing digest
collision`.

### P1 — exact result replay still depends on current declaration retention

The correction moved only the output-axis check behind `store.replay`.
`recordFrozenResult` still loads and compares the input declaration before it
computes the record signature and consults the committed operation. Removing
that old input row after the result commits makes an exact retry refuse, even
though the journal still holds the settled fixed result identity.

Replay is a fact about the already settled identity; later retention state is
not a precondition for reproducing that answer. Compute the immutable result
identity/signature, resolve replay or collision, and apply declaration/current
state checks only to a genuinely new record. Preserve `W2929 review: an exact
result replay does not require its old input row`.
