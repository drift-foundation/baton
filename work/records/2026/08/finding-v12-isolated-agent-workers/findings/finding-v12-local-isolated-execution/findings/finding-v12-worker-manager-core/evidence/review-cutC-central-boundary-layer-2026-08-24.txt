Structural finding — the inventory derives validators, not trust entries
--------------------------------------------------------------------------

PLAN 4bz requires each receiving trust-domain entry and its owner. The AST walk
starts from calls to `boundaries.<kind>` instead. A missing validator therefore
produces no node for the inventory to discover.

The implementation then drops exported callables whose reached set is empty,
collapses every method of a class into one class entry, represents call sites as
only `(kind, label)`, and finally checks the global union. Repeated labels and
distinct receiving entries disappear into one pair. AuthorityPort,
claim_operation_id and revive_refusal are already absent from the resulting
ten-operation map, while the test's `> 5` threshold remains green.

This is the anti-loop failure mode in structural form: the inventory can prove
that visible validator calls are probed, but cannot prove that every receiver
input has a validator. The redesigned inventory must derive trust entries
independently -- public entry parameters, adopted persistent decodes and
injected/callback returns -- key them by owning entry/call site, and then require
one owner and one reachable probe for each. Validator calls may satisfy that
inventory; they cannot be its source of truth.

Observed persistent-input gaps
------------------------------

ControlStore.replay trusts adopted row payloads after SQL. A malformed committed
`result` escapes from json.loads as JSONDecodeError. A refusal replaced with
`{}` reaches revive_refusal and escapes as KeyError. Both are adopted persistent
data under PLAN 4bz and must be owned as exact closed documents before replay or
revival. The boundary-call-derived inventory cannot see either missing owner.

Observed injected-result gaps
-----------------------------

Only the claim-signature result has an injected owner. Other session results
are processed directly:

* integer project_work output reaches `.get` as raw AttributeError;
* integer claim output is durably recorded as assignment 7 and advances the
  offer to `claimed`;
* integer settle_operation output is silently interpreted as `live` and leaves
  the offer accepted.

These are receiver inputs at the capability return boundary. Own their exact
document/result alternatives before branching or persistence. A generic
`injected = text` alias cannot express those result shapes.

Outcome
-------

Changes requested under the anti-loop gate; Cut D remains unstarted. This is not
a request for six named-site patches. Correct the centralized model so the
inventory is derived from trust entries independently of validators and the
layer owns persistent and injected document shapes once at entry.
