## P1 — the inventory cannot discover a missing validator

PLAN 4bz requires an inventory of each receiving trust-domain entry and its
owning validator. `derived_inventory()` begins with existing
`boundaries.<kind>` calls. If an entry has no validator, there is nothing for
the walk to collect.

It also drops exported callables with empty reached sets, collapses all public
methods into one class node, reduces distinct call sites to `(kind, label)`, and
checks only the global union. `AuthorityPort`, `claim_operation_id`, and
`revive_refusal` are absent now, yet all existing inventory tests pass. Reused
labels erase still more per-entry identity.

Derive receiving entries independently from implementation structure -- public
parameters, persistent-data adoption/decodes and injected/callback returns --
and key them by owning operation and source entry. Then require exactly one
owning validator/closed constructor and a probe that reaches each entry.
Validator calls can satisfy this inventory but cannot define its universe.

## P1 — adopted journal payloads bypass the layer

Malformed persisted committed JSON escapes `ControlStore.replay` as
`JSONDecodeError`; a persisted refusal `{}` escapes `revive_refusal` as
`KeyError`. Both are adopted persistent receiver inputs under PLAN 4bz. Own the
exact closed result/refusal documents before trusted replay processing.

## P1 — session callback documents bypass the layer

An integer `project_work` answer faults at `.get`. An integer `claim` answer is
accepted, persisted as assignment `7`, and advances the offer to `claimed`. An
integer `settle_operation` answer is silently treated as `live`. These are
injected result entries and need exact document/alternative owners before
branching or effects; the current `injected = text` helper covers only the
signature string and cannot represent them.
