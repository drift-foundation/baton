1. CALLING A LENIENT PARSER AND DISCARDING ITS ANSWER IS NOT PARSING

  `check_uri` called `urlsplit` inside a `try` and threw the result away, so
  the only thing it proved was that the splitter did not raise. `urlsplit` is
  deliberately permissive: it hands back a hostname containing a space and a
  port that is not a number, and the frozen host's URL constructor refuses
  both. It also parses userinfo without objecting to it, so
  `worker:secret@host` -- a credential in a durable locator, which is the exact
  thing §12 rule 4 exists to keep out -- was accepted.

  The split's ANSWER is now read. Userinfo first, because a credential-bearing
  locator has a reason and the reason is the part a reader acts on; then the
  authority against RFC 3986's own alphabet, which a space is not in; then the
  port, whose accessor is where `urlsplit` finally does raise.

  `@` IS IN THE ALPHABET, deliberately: RFC 3986's authority is
  `[userinfo "@"] host [":" port]`, so leaving it out would refuse a
  credential-bearing locator for the wrong reason.

2. AN EXPORTED RULE OWNS ITS OWN OPERAND

  `check_work_ref` and `check_content_manifest` are on the package's public
  surface and indexed their arguments as though the composite had already
  schema-owned them. A direct caller's malformed value escaped as a TypeError
  or a KeyError, and a dict SUBCLASS executed hostile `__getitem__` inside the
  trusted contracts layer -- the one thing this cut exists to keep out.

  One public wrapper that validates the fragment, one private body the
  composite calls with values it has already owned. A public entry owns its
  input; an already-owned value is not owned twice.
