P1 witness 1 — a committed attachment replay never repairs the axis
--------------------------------------------------------------------
`_attach` commits `runtime_id` and the journal result in `store.transact`, then
calls `observe(... execution_runtime=running)` outside that transaction only
when its local `attached` list says the action ran. A fault in that gap leaves
the attachment and journal committed but the axis at `start-requested`. After a
store close/reopen, the exact retry replays the journal without running the
action, leaves `attached` empty and permanently skips the observation while
returning `decision=attached`.

Additive regression:
`TheRuntimeIsStartedOnceAndReconciled.test_a_committed_attachment_replay_repairs_the_running_observation`

Expected: the reopened manager's exact reconciliation retry leaves the fixed
runtime attached and the durable execution axis at `running`.

Observed:

    AssertionError: 'start-requested' != 'running'

The existing `observe` implementation explicitly uses a savepoint because it
is meant to run inside a journalled action. The correction should make the
attachment update, running observation and committed result one atomic act, or
provide equivalently atomic replay repair. A second unjournalled gap is not a
durable correction.

P1 witness 2 — the fence answer is not related to the expected generation
----------------------------------------------------------------------------
`AuthorityPort.cancel` owns the fence document and passes its assignment to
`_assignment`. That shared owner relates authority UUID, Work id and participant
but only shapes `generation`. Consequently a well-formed fence answer naming
generation 2 is accepted while `expect` names generation 1; provider-agent
cancel and runtime stop are then both ordered even though this attempt's exact
generation was not shown fenced.

Additive regression:
`CancellationFencesBeforeItStops.test_a_fence_for_another_generation_orders_nothing`

Expected: a different returned generation is a ContractRefusal and neither
downstream cancellation boundary is called.

Observed:

    AssertionError: ContractRefusal not raised

The correction should relate the owned fence assignment to all four members of
the exact `expect` passed to the authority before anything below the fence runs.
