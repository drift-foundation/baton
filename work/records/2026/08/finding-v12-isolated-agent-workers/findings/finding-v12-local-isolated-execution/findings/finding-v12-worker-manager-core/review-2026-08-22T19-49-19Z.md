## [P2] Releasing a pinned registration reports that the secret is gone

explicitly says a pinned value never is. When a caller dynamically registers
`GOLDEN_BEARER` and releases that last dynamic registration, the function
deletes `_live` and returns `true` without consulting `_PINNED`. The actual
durable-secret guard correctly continues to reject the value, so this is not
a leak; the exported lifecycle answer nevertheless says the opposite of the
state the guard enforces.

value is no longer live while the build still pins it. After removing the
last dynamic owner, report “gone” only when the value is not pinned. Preserve
the existing nested-count, unbalanced-release and permanent pinned-protection
behavior. Retain the additive regression, which observes both the false
return and the still-active guard.
