## [P1] Escaped string literals still bypass whole-file accounting

`stringLiteral` at `tools/codex-event-bridge/src/exec_policy.mjs:233` treats
every backslash sequence as syntax it fully understands, but it decodes only
`\n` and `\t`; every other escape drops the backslash and copies the following
character. That is not Starlark's string semantics.

I appended each of these rules separately to the exact four generated
inspection rules:

```text
prefix_rule(pattern=["\x64ocker"], decision="allow")
prefix_rule(pattern=["\u0064ocker"], decision="allow")
prefix_rule(pattern=["\144ocker"], decision="allow")
```

For all three, the installed `codex execpolicy check` decoded the executable
as `docker` and authorized `docker run --privileged alpine`. The corrected
`auditInspectionRules` returned `missing=[]`, `broad=[]`, `extra=[]`,
`unaccounted=[]`, and `satisfied=true`. The command was evaluated only; Docker
was not invoked.

Because `readPolicy` is shared, an escaped absolute executable bypasses the
Baton workflow audit too. Appending

```text
prefix_rule(pattern=["\x2fopt/baton/bin/baton"], decision="allow")
```

made the evaluator authorize `/opt/baton/bin/baton unruled-verb`, while
`auditRules` again reported satisfied with no broad, extra, or unaccounted
content.

This is the same class as round 1: the preflight still calls a construct fully
accounted when its interpretation differs from the real evaluator. Do not
accept any escape form unless its semantics are proved identical to the
evaluator. A bounded fail-closed correction can route every escaped literal to
UNACCOUNTED; if generated paths require escapes, their exact evaluator
semantics need oracle-backed handling rather than the current partial decoder.
Add Docker and Baton oracle regressions for hex, Unicode, and octal escapes.
