2. THE P2 IS THE FINDING, AND THE P1 IS ITS CONSEQUENCE

The audit I wrote to stop this defect is the reason it survived. It classified an
interpolation by UNPARSING it and matching a string prefix, so:

  it read `name_of(value) + value` as bounded because the TEXT began with
  `name_of`, which is a bounded call inside an unbounded expression;
  it accepted any `join` of anything, with no proof the iterable was ours;
  and it accepted `what` BECAUSE OF HOW THE VARIABLE WAS SPELLED.

`what` is package prose at every internal call site and caller text at every
exported one. Trusting the spelling meant one entry, written for the internal
sites, silently covered the ten exported ones -- so a check whose stated purpose
was "no site is trusted because somebody looked at it once" trusted thirty sites
because of a variable name.

I wrote in the last evidence that a rule nothing checks holds wherever somebody
happened to look. The sharper version is the one I have now been shown: A CHECK
THAT MATCHES SPELLING INSTEAD OF ORIGIN IS ANOTHER PLACE FOR SOMEBODY TO HAVE
LOOKED ONCE.


3. THE LABEL, BOUND ONCE AT THE BOUNDARY

`label_of` bounds a caller-supplied label, applied at the entry of every function
that accepts one -- ten in `identity`, one in `store`, four in `core`. A label is
not QUOTED the way a rejected value is, because it is prose naming the operand a
rule is about and quoting it would make every message read like a citation. The
LENGTH rule is the same rule, so it applies.

AND THE BOUND IS MEASURED, NOT CHOSEN. Binding the label at the sixty-character
VALUE limit truncated this package's own longest label mid-word and took the
member name with it, so twelve publication cases went from "policy_digest is
nonempty text" to a sentence that no longer said which digest was missing. That
is the settlement-signature lesson in a second place: A BOUND BELOW WHAT THE
AUTHORITY ITSELF LEGITIMATELY PRODUCES BREAKS THE AUTHORITY RATHER THAN THE
CALLER. The limit is 160, and a case measures the package's longest label plus
one rendered member and fails if that ever exceeds it -- so the number is checked
rather than remembered.

A THIRD THING, FOUND BY A MUTATION WITH NO WITNESS: a label that is not text was
returned raw and then interpolated, and `f"{what}"` CALLS `__str__`. A caller
supplying a hostile label could therefore replace the refusal the boundary had
already decided on with an exception of its own choosing -- the exact rule
`name_of` exists to enforce, in the one place nobody had checked it. A non-text
label is named by its type now, and a case offers a label that raises from
`__str__`, `__repr__` and `__format__` and asserts none of them ran.


4. THE CLASSIFIER, PROVING SHAPES AND ORIGINS

  a bounding call     the WHOLE interpolation is one call to a named bounding
                      helper. A `BinOp` with a bounded operand is not bounded,
                      and neither is a conditional, a subscript, a slice, a
                      `%`-format, an f-string of both, or a generator inside a
                      join.
  a proven join       `"...".join(X)` only when X is proved package-owned.
  a package constant  proved BY FIXPOINT over the whole package: a name is owned
                      when the module assigns it an expression that reaches
                      outside nothing, and `GATE_KINDS = frozenset({...})` is
                      owned on the second pass because the names it mentions are
                      owned on the first. Origin all the way down.
  a proven local      a bare name assigned IN SCOPE from a bounding call, with
                      the scope chain unioned because a closure reads its
                      enclosing function. This is how `what` earns its place now
                      -- by where its value came from, not by its name.
  a named site        keyed by MODULE, FUNCTION and expression.

The named-site table is eleven entries and each states its reason. It is keyed by
SITE, and the property is enforced rather than described: fabricated findings
prove that an entry excuses the one site it names and neither the same expression
in another function nor in another module.

Two other things the rewrite fixed, both found while doing it:

  the walker attributed each closure's refusals TWICE, once to `body` and once to
  the transition around it, so a named entry could have been written for the
  wrong one. It descends with a scope stack now and the site belongs to the
  innermost function.
  116 interpolations, 22 unproven, 11 named. The old classifier reported ZERO
  unproven -- which is what a prefix match looks like when it agrees with you.
