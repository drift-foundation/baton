# Independent first-slice review — 2026-08-22T16:37:37Z

**Verdict:** changes requested. The slice preserves the authority/manager
ownership split, the sealed product schema is byte-identical, the W4487
signature and verifier shapes are correct for valid documents, and the
database enforces one live offer per Work. Five foundation boundaries need
correction before orchestration is built on them.

## [P1] The trust entry accepts an invalid command without recomputing its signature

`validateEnvelope` never runs the frozen Draft 2020-12 schema. Its signature
helper exempts every `message_type` other than the exact string `command`, not
only a schema-proven reply. A valid `offer.decide` body with a stale operation
signature and `message_type: "commmand"` therefore passes. This directly
reopens the W4487 integrity hole: one misspelled discriminator turns a
mutating command into the reply exemption before anything has proved it is a
reply.

The same gap is broader than unknown extra fields. Required fields, closed
enums, limits and command/reply correlations are not established before the
semantic helpers read them. The previously non-blocking *choice of library*
may remain an implementation choice, but schema validation itself is now a
blocking prerequisite for this foundation. Validate a sealed copy against
the frozen schema before semantic dispatch, and make the reply exemption
reachable only from a schema-proven reply. Retain the misspelled-command/stale-
signature case plus missing, extra and mistyped-field negatives.

## [P1] “Exact” negotiation selects an unsupported extension and cannot form a welcome

`negotiate` accepts a hello with neither required `limits` nor
`runtime_profile_digest`. It copies every peer extension into the result even
though the caller supplies no supported-extension set, and it returns no
`effective_limits`. The reproduced result therefore claims
`org.example.not-implemented/1` was selected and cannot itself validate as the
frozen `control.welcome` body.

Schema validation will close the missing-field half but cannot choose local
support or effective limits. Make negotiation take both peers' exact
extension support and the manager limits/profile policy, select only an exact
intersection, and return the complete frozen welcome shape. Regress missing
required fields, unsupported and malformed extensions, duplicate values,
limit intersection, and the byte-valid welcome.

## [P1] Runtime observation identity loses the adapter incarnation

The frozen contract scopes `source_seq` to one runtime incarnation, and this
dossier specifies observation identity as adapter incarnation, runtime and
source sequence. The table stores `incarnation` and `runtime_id`, but its
primary key is only `(runtime_attempt_id, source_seq)`. After an adapter
restart, a valid new incarnation beginning again at source sequence 1 collides
with the prior incarnation's sequence 1.

That makes the required restart path indistinguishable from a conflicting
duplicate before monotonic observation logic even runs. Key the source
identity by its full scope and separately enforce the per-attempt manager
sequence/axis monotonicity. Add a restart case that accepts the new
incarnation's first observation while still replaying an exact same-
incarnation duplicate and refusing a conflicting one.

## [P1] Durable refusal replay changes the committed outcome

The operation journal persists only a refusal message. On replay it constructs
every durable refusal as `refused.precondition`, regardless of the original
closed category/code. A durable `policy.retention` refusal reproduces as
`refused.precondition`. The decision action runs only once, but its exact
retry has a different portable meaning and potentially a different retry
policy, so this is not replay of the same refusal.

Persist and restore the complete sealed refusal outcome needed to reproduce
the first answer, including its closed category/code and retry/operation-state
facts where those are part of the returned control error. The regression must
use a pair other than `refused.precondition`; the current case hides the loss
by choosing the fabricated pair as its original. The same journal currently
records every `settled_at` as `1970-01-01T00:00:00.000Z`; inject the manager
clock and retain the real/injected settlement evidence.

## [P2] Refusing an incompatible store mutates it first

`ControlStore` executes all schema DDL and changes journal mode before it
reads `meta.schema_version`. Opening a database whose recorded version is 99
does refuse, but the reproduction shows the full six-table version-1 set was
present afterward, five tables added by the refused open. The throwing
constructor also leaves its private database handle unclosed.

An incompatible binary must inspect and refuse an existing store without
changing it. Separate atomic fresh-store initialization from existing-store
validation, put the busy policy in force before lock-taking initialization,
and close on every constructor failure. Assert that `sqlite_master` and the
store bytes/state remain unchanged after the refused open.

## [P1] Canonicalization accepts values the frozen contract forbids

The hand canonicalizer checks `Number.isSafeInteger` but not non-negativity or
`Object.is(value, -0)`. It serializes `-1` as `-1` and negative zero as `0`,
despite section 3.2 forbidding both. It also accepts a lone UTF-16 surrogate as
an escaped string, whereas RFC 8785 requires invalid Unicode data to fail.
Those values can consequently acquire body and operation digests under a
function presented as the frozen canonical trust boundary.

Use a conforming RFC 8785 implementation or close the local implementation
exhaustively for the schema's restricted value space. Add at least negative
integer, negative zero, lone-surrogate, sparse-array and non-JSON-object
negatives alongside the existing positive vectors.
