### P1 — settlement can mint an invalid durable operation identity

The new frozen opaque-ID grammar is enforced only by `Store.replay`.
`Core.settle_operation` uses the weaker text check and writes the retirement
directly, so a one-million-character operation ID is still accepted as a
durable primary key. Spaces, a leading dash and the other rejected opaque-ID
shapes are likewise accepted by settlement and both public journal reads.

This is not only a size problem. After settlement records `"bad id"` as
retired, a claim under `"bad id"` rejects its shape before seeing the
retirement, so two authority paths disagree on whether the durable identity
exists and the claim does not replay the bound retirement reason. Apply one
opaque-ID validator to replay, settlement, `operation_result` and
`operation_record`; cover every path with the same invalid/valid table and pin
retirement precedence for a valid identity.

### P2 — installed-layout race children import the source package

Both spawned child scripts prepend the repository `src/` path unconditionally.
Consequently the installed-wheel gate's five inherited/concrete subprocess
race cases execute source code in their children even though the parent uses
the venv package. A packaging skew in claim, replay or settlement can therefore
pass the gate that claims to exercise the whole installed layout.

Let subprocesses inherit the source gate's `PYTHONPATH=src` or the installed
gate's empty `PYTHONPATH` plus venv interpreter, and assert/report that child
and parent package origins agree.
