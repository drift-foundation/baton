## Findings

### P1 — the accepted operation cannot settle against the real authority

`acceptOffer` writes `claim_signature = NULL` (`offers.mjs:180-186`) and
`settleClaim` consequently passes `undefined` (`offers.mjs:289-293`). A real
committed claim has `V12Authority.claimSignature(workId, participant)`, so
settlement treats it as an operation collision. Retirement of an uncommitted
identity likewise cannot store an undefined signature in the authority's
`NOT NULL` operation column. Persist the fixed authority signature in the
acceptance transaction and use that exact value for every settlement.

The same real-boundary case exposes a second shape mismatch: `V12Session.claim`
returns the assignment directly, but both immediate and late recording read
`result.assignment` (`offers.mjs:232-235`, `294-298`). The authority therefore
holds a live generation while the manager durably answers `assignment: null`.
Record and replay the exact four-part assignment returned by the authority.

Additive regressions:
`W2929 review: the real authority assignment is recorded exactly` and
`W2929 review: lost-result settlement uses the fixed claim signature`.

### P1 — offer identity is not bound to the participant-bound session

`issueOffer` accepts an independent `participant` operand and never compares
it with `session.participant` (`offers.mjs:70-99`). The offer, verifier and
intent can therefore name participant B while `submitClaim` necessarily acts
as participant A through the bound session. Refuse this mismatch before
entropy, or remove the independent choice and derive it from the binding.

Additive regression: `W2929 review: an offer participant is the session
binding`.

### P1 — expiry leaves a permanent live offer and an unspent verifier

The expiry branch only throws (`offers.mjs:156-159`). It leaves state
`issued`, `verifier_spent = 0`, and the partial unique index occupied. There
is no other expiry operation in this slice, so the Work cannot receive a new
offer and the verifier remains replayable despite the pinned single-use rule.
Settle expiry by CAS, consume the verifier, retain the visible `expired` row,
and release the per-Work nonterminal slot.

Additive regression: `W2929 review: expiry consumes the verifier and releases
the Work`.

### P1 — stale terminalization can overwrite an accepted offer

`settleTerminal` updates both `issued` and `accepted` rows
(`offers.mjs:200-209`). Both its callers act from an earlier `issued` read: a
decline in `acceptOffer`, and restart abandonment in `recoverOnRestart`.
Another manager can accept between that read and this update; the stale
decline/abandonment then destroys the durable authorization and fixed claim
identity. Each issued-only transition must CAS only from `issued`; losing the
CAS adopts or refuses from the winner's current state without rewriting it.

### P1 — certification is optional at the enforcement boundary

The profile comparison is conditional on `certifiedProfileDigest !==
undefined` (`offers.mjs:84-92`). Omitting the argument therefore issues an
offer without any certification check, and the existing happy-path fixture
does this throughout. Make certification an unavoidable local fact (ideally
looked up from the control store by the Work contract), and reject absence
before entropy.

Additive regression: `W2929 review: profile certification cannot be omitted`.

### P1 — offer issue replay can return an unusable secret

`issueOffer` mints a new bearer before `ControlStore.transact`, while the
operation signature covers only `(offerId, workId, participant)`
(`offers.mjs:100-123`). An exact operation replay therefore returns the first
durable verifier beside a newly minted bearer that does not derive it. A
changed policy digest also replays as though it were the first request rather
than colliding. Make the operation signature cover every effective durable
operand, and ensure replay either reproduces a matching bearer through a safe
explicit contract or refuses without returning a mismatched secret. The raw
bearer must remain off durable storage.

Additive regressions: `W2929 review: an issue replay never returns a bearer
for another verifier` and `W2929 review: issue replay signs every durable
operand`.
