THE FINDING

  `check_uri` ran its authority and port rules only when the split found a
  NON-EMPTY netloc, so `https://` returned unexamined. The frozen host's
  constructor throws for it, and a locator this build cannot resolve is never
  durable state.

  The correction guards the whole authority clause, not the netloc: a scheme
  that requires a host must have one.

MEASURED RATHER THAN REASONED ABOUT

  The obvious rule -- "an empty authority is invalid" -- is wrong, and I checked
  before writing it. Run against the frozen host's own constructor:

    new URL("https://")        THROWS TypeError
    new URL("http://")         THROWS TypeError
    new URL("file://")         ok, host ""
    new URL("file:///x")       ok, host ""
    new URL("artifact://")     ok, host ""
    new URL("artifact://id")   ok, host "id"
    new URL("foo://")          ok, host ""
    new URL("urn:x:y")         ok, host ""
    new URL("mailto:a@b")      ok, host ""

  So the rule is that the schemes which REQUIRE a host must have one, and
  `_HOST_REQUIRED` is that measurement rather than a policy this build invented.
  The review asked for the frozen constructor's behaviour restored and said it
  was not prescribing a general scheme policy; measuring is how I kept to that
  rather than substituting my own.

  `file://` staying valid matters: it is the form the contract uses, and a rule
  that refused every empty authority would have refused it while looking
  stricter.

MUTATIONS, ROUND 16 (3 run against the 574-test suite)

  Q1  a declared authority may be empty     2 failing
