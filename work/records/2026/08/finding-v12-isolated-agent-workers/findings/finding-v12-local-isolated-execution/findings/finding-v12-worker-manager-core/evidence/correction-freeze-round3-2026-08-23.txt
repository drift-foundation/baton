CORRECTED, and to the contract rather than to the minimum that passes the

can choose which half to supply.


3. ONE INERT BRANCH THE CORRECTION EXPOSED, AND CLOSED

With both representations required, the size computation's fallback — "the
tree's total, or else the artifact's declared size" — became unreachable, and
`size !== null` became always true. That is the inert-guard shape I recorded
last round.

So it is a decision now rather than a deletion: BOTH sizes are bounded by the
declaration. Measuring only the tree would leave the transported
representation unbounded, and the constraint says "maximum bytes" about the
output, not about whichever representation happened to be there. The media
type check lost its now-impossible null guard for the same reason.
