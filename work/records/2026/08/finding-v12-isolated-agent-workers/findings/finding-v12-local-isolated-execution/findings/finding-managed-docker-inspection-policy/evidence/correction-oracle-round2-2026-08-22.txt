2. [P1] CORRELATION STOPPED ONE BOUNDARY SHORT

Two faults with one shape: I checked that an approval was ABOUT this item and
never that it was the right KIND of approval or that the client actually
ANSWERED it.

IDENTITY IS NOT SUFFICIENT. Read out of the installed schema rather than
assumed — and this time I checked all three:

  item/commandExecution/requestApproval   threadId turnId itemId  command …
  item/fileChange/requestApproval         threadId turnId itemId  grantRoot …
  item/permissions/requestApproval        threadId turnId itemId  permissions …

All three carry the same identity triple. So a file-change or permission
prompt in the same turn was being read as command-execpolicy evidence, and
that can ACCEPT an unruled case whose command merely `failed` — the exact
state the correction otherwise refuses. The whole point of refusing a bare
`failed` was that a command can fail on its own; an unrelated approval let it
back in through the other door.

AN OBSERVED REQUEST IS NOT AN ANSWERED ONE. `CodexClient.respondError`
returns false when it cannot send — a closed socket, a missing id — and
`runCase` discarded the return value. The matrix's claim is that it denies
exactly as the dispatcher denies; an unanswered prompt does not support that
claim, it only shows the boundary ASKED.

CORRECTED:
  - `COMMAND_APPROVAL_METHOD` is the schema's exact spelling and
    `approvalsFor` matches method AND identity.
  - `runCase` records `denied` from `respondError`'s own result.
  - `deniedApprovals` is what the unruled approval path requires, on top of
    the already-required terminal non-completed item.
  - A RULED inspection still fails on the mere REQUEST, answered or not: the
    reason those four are ruled is that nothing asks about them at all.
  - A direct `declined` is still a refusal with nothing to correlate, and a
    bare `failed` is still insufficient.


3. THE FIXTURE SPELLING, AND WHY IT MATTERED

My synthetic approvals said `commandExecution/requestApproval`. The installed
schema defines `item/commandExecution/requestApproval`. Method-blind
correlation hid it exactly: A NAME NOTHING COMPARES CANNOT BE WRONG. The
fixtures now build from the exported constant, so the product and the cases
cannot drift apart again, and the review is right that the wrong spelling was
a symptom rather than a separate slip.
