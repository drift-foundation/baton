## P1 — Python does not enforce its claimed canonical IPv6 text

Node restricts the literal to IPv6 characters and requires the constructor's
hostname to equal the original bracketed text. Python checks only lowercase and
whether `IPv6Address` can parse the input. It never compares `str(parsed)` with
the original and does not exclude scope syntax.

Consequently Python accepts all three while Node refuses them:

- `https://[2001:0db8::1]/x` — leading-zero normalization;
- `https://[2001:db8:0:0:0:0:0:1]/x` — compression normalization;
- `https://[fe80::1%eth0]/x` — a scoped address outside the recorded literal
  alphabet.

Restrict Python to the same `[0-9a-f:.]+` literal alphabet and require
`str(ipaddress.IPv6Address(literal)) == literal`.

## P1 — the claimed DNS grammar omits DNS bounds

Both host regexes validate label characters and hyphen placement but not DNS
length. They accept a 64-character label, although a DNS label is bounded to 63
bytes. Enforce 1..63 ASCII bytes per label and the complete DNS textual bound in
both runtimes. The shared corpus now carries the overlong-label witness.
