2. THE SEVEN

[P1] ACTIVATION WAS NOT BOUND TO THIS ATTEMPT'S CLAIM OR TO ITS SESSION. It
accepted any free-standing attempt beside any currently live assignment,
ignored the session's participant, stored no assignment participant, compared
only Work and generation on the fixed path, and left the participant out of
the runtime labels.

Three separate things must now agree: the session's binding, THIS attempt's
own committed claim, and the authority's live assignment. Any two agreeing is
not enough — that is exactly how a foreign session or a replayed activation
gets in. All four assignment fields are persisted, compared, and labelled.
The offer records the generation its claim COMMITTED (schema 1 -> 2), because
without that the attempt has nothing to compare against.

[P1] ATTEMPT REPLAY SIGNED THREE OF EIGHT OPERANDS. A changed adapter name or
input digest replayed instead of colliding. Every durable operand now rides
the signature.

[P1] RUNTIME START HAD NO DURABLE OPERATION IDENTITY. A state label is not an
effectively-once act: a journalled operation is what a restart replays and
what the adapter can be asked about. One fixed, fully signed `runtime.start`
operation commits before the call, and its identity goes to the adapter so
both sides settle the same act rather than two adjacent ones.

[P1] POSITIVE ABSENCE WAS A CALLER-AUTHORED BOOLEAN. This is the rejected
`schemaProven: true` shape a third time, and the review is right to name it
as such: a proof the caller writes is not a proof. Certified evidence of
absence is item 4's to define, so THE RETRY PATH IS CLOSED and the refusal
says which slice owns it.

[P1] ATTACHMENT WAS MUTABLE, AND A MINTED MISMATCH WAS FILTERED AWAY. The
first positive attachment now compare-and-swaps null-or-identical; a
different id cancels without rewriting what is recorded. And a runtime THIS
CALL started, carrying labels for another assignment, is checked BEFORE the
label filter — it is not absent, it is wrong, and this call caused it.

[P1] ENUM ORDER IS NOT A TRANSITION ORDER. Treating the vocabulary's array
order as a sequence let `worker_disposition=completed` advance to `unable` —
a different terminal ANSWER, not a later stage of the same one. There is an
explicit per-axis transition map now, terminal alternatives are immutable,
and the exported `allowReset` bypass is gone: a monotonicity a caller can
switch off is not one.

[P1] MONOTONICITY WAS A READ/CHECK/WRITE RACE. The transition is decided
INSIDE the write now, against the exact value the UPDATE compares, within a
savepoint — a savepoint rather than a transaction because `observe` is also
called from inside a journalled operation, and a nested BEGIN would refuse.
Observations are journalled with adapter incarnation, source sequence and
observed digest, so an exact duplicate replays and a conflicting one refuses.

A concurrent writer surfaced as a raw `ERR_SQLITE_ERROR`; it is translated to
a typed `runtime-observation` refusal. A caller that must handle a raw SQLite
error beside contract refusals will eventually handle neither, and the
meaning here is exactly one thing: this observation did not land.


3. TWO MODEL CHANGES THE REVIEW'S OWN CASES REQUIRED

A COLD START CAN DISCOVER ANYTHING. My first transition map allowed only
`not-started -> start-requested`, and the retained cases observe `running`
and `destroyed` directly. They are right: at restart the local axis is
`not-started` while a runtime may already exist, so reconciliation must record
what it FINDS rather than inventing an intermediate state nobody observed.

RECONCILIATION IS LEGITIMATE FROM A COLD START too, so the precondition I
added refusing it was wrong and is gone.

rather than counted as covered.
