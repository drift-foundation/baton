Independent reproduction: caller-supplied diagnostic labels
===========================================================

The AST audit globally allow-lists the expression `what` on the premise that it
is package-owned prose. That premise is false at the exported identity-helper
boundary. `identity.py.__all__` exports helpers whose public signatures accept a
caller-supplied `what`, and the existing `ExportedHelpersAreBoundaries` suite
already treats these module exports as boundaries.

One-million-character `what` labels produced these Refusal lengths through the
current source:

  own                    1,000,139
  check_authority_uuid   1,000,072
  check_work_id          1,000,108
  check_participant      1,000,044
  check_generation       1,000,051
  check_opaque_id        1,000,014
  check_text             1,000,037
  check_timestamp        1,000,082
  assignment_key         1,000,056
  normalize_assignment   1,000,139

These are messages the authority constructs after deciding to reject an
operand. The caller could construct its own `Refusal`, but that is a different
fact: these exported helpers are producing the unbounded authority diagnostic.

Independent reproduction: audit-classifier false positives
===========================================================

`EveryDiagnosticIsBoundedByTheRule._is_bounded` accepts an interpolation when
the unparsed expression merely STARTS with a bounded helper name, and accepts
every textual `join` with the same prefix shape. It therefore classifies each
of these unsafe forms as bounded:

  name_of(value) + value
  ', '.join(caller_values)
  what

The first contains raw caller text beside a bounded rendering. The second has
no proof that its iterable is package-owned. The third trusts variable spelling
rather than origin and is the exact false-negative behind the live helper
defect above. A future raw interpolation in any of these shapes would leave the
standing source audit green.

Required correction
