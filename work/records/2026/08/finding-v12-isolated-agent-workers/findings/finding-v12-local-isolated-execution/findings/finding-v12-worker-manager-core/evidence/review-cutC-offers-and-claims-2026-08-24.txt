Observed defects
----------------

1. AuthorityPort checks that its five session names exist, but checks only the
   injected claim_signature for callability. None of project_work,
   slot_holder, claim or settle_operation is required callable. A non-callable
   claim therefore passes construction and is discovered only after offer
   acceptance, as a raw TypeError with durable state already frozen. Validate
   every operation at construction; the participant member remains the bound
   value rather than an operation. authority_port.py:36,49-63.

2. offers._text checks only exact str and nonempty. A lone surrogate in an
   offer id reaches the accept read as a raw SQLite UnicodeEncodeError, and the
   same defect occurs for expire_overdue's now operand. Reuse the established
   durable-text rule before SQL. offers.py:78-83.

3. Time operands are compared as unrestricted strings. The value
   "not-an-instant" is accepted as now and lexicographically expires a valid
   offer. Validate the exact canonical instant grammar before any ordering
   comparison; encodability alone does not establish time meaning.

4. issue_offer exposes ttl_seconds as a caller operand but does not validate
   it before _later or entropy. A negative TTL mints a bearer and commits an
   already-expired authorization. Require the exact positive-integer policy
   before SQL/entropy, or remove the operand if the duration is fixed policy.
   offers.py:185,258.

5. The schema comment says acceptance freezes all five fields or none, but the
   CHECK constrains only three fields and only while state is issued. SQLite
   accepts an accepted row with all five absent and an issued row with
   accepted_at/settle_by populated. Enforce the whole cross-product: the five
   fields intent_digest, accepted_at, settle_by, claim_operation_id and
   claim_signature are all absent for issued/declined/expired/
   abandoned-after-restart and all present for accepted/claimed/
   claim-refused/settlement-expired. This is a durable-shape correction and
   requires an explicit schema-version transition. schema.py:126-131.
