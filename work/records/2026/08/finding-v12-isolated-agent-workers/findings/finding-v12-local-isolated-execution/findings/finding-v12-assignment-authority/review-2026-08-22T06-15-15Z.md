# Independent review — 2026-08-22T06:15:15Z

**Verdict:** changes requested. The durable claim/fence transaction and exact
assignment comparisons are promising, but the advertised public boundary can
bypass the authority outright, the workflow receipts omit required identity
and authorization, and two operation/state paths violate the ruled contract.

## [P1] The public authority exposes its raw writable store

`v12/src/authority/authority.mjs:83` returns the private `Store` from a public
`store` getter. Since `V12Authority` is exported by
`v12/src/authority/index.mjs`, W2929 can call arbitrary SQL through
`authority.store.run(...)`. This directly contradicts both W2928's confirmed
boundary and the index module's own statement that reaching into the store
would create non-conforming manager-local authority.

Using only the public index, I set one Work's `generation_counter` to 41 and
then claimed normally; the authority returned generation 42. The consumer had
therefore chosen the supposedly authority-minted generation. It can likewise
rewrite Handler, fences, operations, gates, proposals, and receipts.

Remove every public route to `Store`/`DatabaseSync`. Extend the boundary test
to assert that the authority instance exposes no store, database, SQL runner,
or mutable state handle, then prove a consumer can reach authority mutations
only through the reviewed transition methods.

## [P1] Proposal and workflow receipts omit ruled bindings and actors

W151 §10.11 requires a proposal receipt to bind the exact assignment plus
input, policy, output, candidate-tree, and target digests. W151 §10.12 requires
verification, technical review, approval, and integration to be separately
attributable immutable receipts. Instead:

- `publish` at `authority.mjs:606` accepts only assignment, proposal id, one
  undifferentiated digest, and target;
- the proposal schema at `schema.mjs:166-177` has no input, policy, output,
  result, receipt identity, actor, or approval-policy-generation fields; and
- `verify`, `review`, `approve`, and `integrate` at
  `authority.mjs:663-717` accept no actor at all and store only disposition
  strings.

The same authorization hole appears in `close` at line 732: W151 permits an
unclaimed close only to an actor holding the configured close capability, but
the method has neither actor nor capability input or check. As written, one
consumer can publish a candidate, self-verify, self-review, self-approve,
integrate it into the canonical target, and close the Work. Immutable strings
do not establish the separately attributable workflow the contract requires.

Implement the exact proposal digest tuple and typed receipt identities from
W151, include every durable field in operation signatures, and enforce the
configured actor/role/capability at each receipt, integration, and unclaimed
close transition. Add negative tests showing that the publisher cannot write
the verifier/reviewer/approver/integrator receipts merely by calling another
method on the same authority object.

## [P1] No-write refusals and settlement authority fail open

`integrate` passes `{ durableRefusal: true }` unconditionally at
`authority.mjs:717`. Consequently every integration refusal is recorded as
durable, not only the stale-target refusal that actually writes an
`integration_attempt`. I invoked integration before approval: it wrote zero
attempt rows, yet `operationRecord("integrate:early")` was permanently
`refused`. This violates W151's explicit rule that an ordinary refusal writes
nothing and remains retryable; REFUSED exists only when the refusal itself
wrote durable state.

Separately, `settleOperation` at line 285 defaults `mayRetire` to `true`.
Omitting the positive settlement-authority operand on an unsubmitted claim
therefore retires it immediately. The safe public default is the opposite:
without explicit authority to retire, settlement may only observe.

Make durable refusal depend on whether the transition actually committed its
durable refusal evidence, and make retirement authority explicit and
fail-closed. Add regressions that a pre-approval integration refusal leaves no
operation row and that omitted/false retirement authority returns `live`
without retiring the fixed claim.

## [P1] Public state transitions can commit impossible scheduler states

`createWork` at `authority.mjs:134` accepts `phase="active"` while creating no
Handler. `end` at line 387 accepts arbitrary caller-supplied phase/gate values,
including `phase="active"` while clearing Handler. Both calls commit
Handler-null/active rows; `assertInvariants` notices only after corruption is
durable. The same open-ended inputs permit unknown phases and malformed or
phase-inconsistent gates.

Restrict public operations to the transition table's derived scheduler
outcomes, validate typed gate/phase cross-products before writing, and make
invalid inputs refuse with no state or operation record. Invariants are a
backstop, not post-commit validation.

## [P2] The real-process race proof is nondeterministic and loses diagnostics

The first full run passed all W2928 race cases. The authority-only rerun then
failed `authority_race.test.mjs`, and running the file directly failed both
four-process cases while parsing an empty child stdout at lines 77 and 114.
The harness discards the child exit/signal/stderr context, so the failure does
not establish whether the authority, child launch, or test transport failed.

Make every racer outcome explicit and diagnostic, including spawn failure,
exit status/signal, stderr, empty output, and malformed output. Remove the
nondeterminism and demonstrate repeated green isolated runs before treating
this as the required competing-claim/replay race proof.
