Structural evidence
-------------------

* boundaries.document (boundaries.py:167-187) owns a dict and checks missing
  required members, but never rejects extra members. Its "exactly these
  members" contract is therefore false.
* boundaries.alternative (boundaries.py:190-208) checks only that `kind` belongs
  to a closed vocabulary. It has no variant-specific member contracts, so a
  committed answer need not carry `result`.
* _offer_row (offers.py:58-67) validates the lookup identity but returns the SQL
  row without adopting its fields. settle_claim (offers.py:592-609) compares
  `settle_by` and can persist `answer.get("result")` without a complete variant
  contract.
* receiving_entries (test_boundary_inventory.py:71-119) discovers an adopted
  entry only when it sees an existing `boundaries.adopted` call. An adopted SQL
  row with no validator is consequently invisible: the universe is still
  validator-derived for this domain.
* EveryProbeProvesItArrived iterates the old `(kind, label)` probe table, not
  the `(domain, owner, entry)` receiving-entry universe. No test requires one
  reachable probe per receiving entry. Owner identity is only a function name,
  without module/class/call-site identity, so same-named methods may collapse.
