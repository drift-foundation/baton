2. TWO DECISIONS I MADE RATHER THAN INHERITED, BOTH WRITTEN INTO THE CODE

THE PORT NAMES ONLY WHAT W4 USES. The delivered session carries sixteen
transitions and sixteen reads. A port naming all thirty-two would be a capability
nobody granted -- the manager would type, and a fake would have to implement,
authority the manager never exercises. Five members is what cut C needs; a later
cut widens the port deliberately rather than inheriting the width.

THE CLAIM SIGNATURE ARRIVES BY INJECTION RATHER THAN BY IMPORT. The frozen host
imports the authority's own derivation, and it is right that the manager must not
recompute it: a manager with its own spelling would be a second authority on
whether two claims are the same claim. But IMPORTING the sibling package would
make the manager depend on the authority's module graph to do arithmetic on a
string -- while the deployment that mints the session already holds the authority
and can hand the derivation over with it. One injected capability, one trusted
supplier, and the manager's import boundary stays where its own cases say it is.


3. THE OBLIGATIONS PORTED WITH THEIR CORRECTIONS INTACT

  the participant       is the session's BINDING. The frozen host took one
                        independently and never compared it, so the offer, the
                        verifier and the intent could name B while the claim was
                        necessarily taken as A -- an authorization recorded for
                        one identity and spent by another.
  certification         is UNAVOIDABLE. Its comparison was conditional on an
                        operand being supplied, so omitting it issued an offer
                        with no check at all, and the happy-path fixtures omitted
                        it throughout. There is no operand here: the control
                        store's own record is the only fact.
  expiry                is manager-owned time processing and runs BEFORE
                        entropy. It was reachable only from a late decision, so
                        an offer nobody answered held the per-Work slot forever.
  the replay check      runs BEFORE minting. Minting first meant an exact replay
                        answered with the first offer's verifier beside a new
                        bearer that does not derive it -- a secret the holder
                        cannot use and cannot tell is unusable.
  provenance            comes from the JOURNAL. It was inferred from bearer
                        inequality, and inequality proves a loss while equality
                        proves nothing.
  every durable operand rides the signature, INCLUDING THE AUTHORITY. The
                        signature carried the local Work id alone, so reusing an
                        issue identity against another authority read as an exact
                        replay rather than a collision.
  expiry                is a SETTLEMENT, not only a refusal.
  the verifier          is single-use across acceptance, decline and expiry
                        alike, so a decline cannot be replayed into an
                        acceptance.
  terminal transitions  CAS only from `issued`. Both callers act from an earlier
                        read and another manager can accept in between; a stale
                        expiry then destroyed the authorization and the fixed
                        claim identity acceptance had just frozen.
  the claim record      is WHAT THE AUTHORITY RETURNED, not a member of it. The
                        host read `result.assignment` while the session returns
                        the assignment directly, so the authority held a live
                        generation while the manager durably recorded null.
  settlement            may only OBSERVE before the deadline, and adopts an
                        existing retirement's bound disposition -- a second
                        manager inventing its own answer would give one operation
                        two meanings.


4. ITEM 4bd'S OWN SENTENCE, AS A CASE

"No adapter write occurs while claim outcome is ambiguous." That is why the
`live` answer writes nothing and says so: a control row written there would claim
knowledge this manager does not have. Two mutations witness it -- retiring early,
and writing a row on the ambiguous path.


5. A DEFECT MY OWN FIXTURE FOUND

The one-live-offer-per-Work rule is enforced by a partial unique index, and an
index violation is a raw `sqlite3.IntegrityError`. My fixture asked for a second
offer on one Work and got the driver's error rather than this manager's refusal.

A manager that loses that race is having an ORDINARY PRECONDITION refused, and
telling it so in SQLite's vocabulary would make a caller learn our taxonomy from
a driver. It lands in the closed pair now.

AND THE CASE THAT SHOULD HAVE CAUGHT IT WAS MINE, WRITTEN WEAKLY:
`assertRaises(Exception)` -- the weak assertion I have criticised in other
people's cases. It names the closed pair now, and naming it is what found the
defect.

THE TWO EQUIVALENCES, with reasons:

  X10 comparing the verifier with `!=` instead of `compare_digest` changes no
      verdict. The property is about INFORMATION, not outcome: an early return
      tells the holder of a wrong bearer how much of it was right, and no
      assertion in a suite can see that. Kept because the leak is real even
      though the test cannot be.
  X12 refusing a spent verifier is subsumed by the state check today, because
      nothing this module writes leaves `spent` set on an `issued` row. It
      states single-use independently of state, and it is the guard that stays
      correct if a later cut adds a state where both are possible.

8. THE OPERAND SWEEP CAUGHT ITS OWN PROXY

Cut C's public surface added twenty operand names, and my declared-operand check
required the list to stay SMALLER than the surface it permits -- a proxy for "the
list must not become the answer". Cut C made that proxy wrong rather than strict:
a package can legitimately have more distinct operand names than functions, and
the ratio then fails for growth instead of for laxity.

Measuring the wrong thing strictly is not rigour. The proxy is gone and the
property it stood for is stated directly: a declared operand may not be
bookkeeping BY NATURE -- `depth`, `seen`, `budget`, `stack`, `cursor` -- and no
declared operand may be stale.
