## [P1] Valid alternate rule syntax bypasses the unrestricted-Docker refusal

`tools/codex-event-bridge/src/exec_policy.mjs:202-214` parses only a
`prefix_rule` whose `pattern` keyword precedes `decision`, whose decision is
double-quoted, and whose pattern elements form JSON. The Docker audit at line
383 sees only that parser's results. Two valid unrestricted rules therefore
become invisible:

```text
prefix_rule(decision="allow", pattern=["docker"])
prefix_rule(pattern=['docker'], decision='allow')
```

I appended each form separately to the four generated inspection rules and
checked `docker run --privileged alpine` with the installed
`codex execpolicy check`. Both policies returned `decision: allow` with the
matched prefix `docker`. `auditInspectionRules` nevertheless returned
`missing=[]`, `broad=[]`, `extra=[]`, and `satisfied=true` for both. The
commands were evaluated only; Docker was not invoked. Full output is retained
in `evidence/review-alternate-rule-syntax-2026-08-22.txt`.

This violates the acceptance boundary that the auditor distinguish the exact
set from **any** unrestricted Docker rule. It is release-blocking because the
missed rule authorizes the host-impacting operations this Work exists to keep
behind the Worker Manager.

Make the preflight fail closed over every valid policy spelling, rather than
treating an unparsed construct as absent. Add regressions for at least reversed
keyword order and single-quoted strings, and prove with the real evaluator that
each fixture grants unrestricted Docker while the audit refuses it. Preserve
the current exact four-rule acceptance.
