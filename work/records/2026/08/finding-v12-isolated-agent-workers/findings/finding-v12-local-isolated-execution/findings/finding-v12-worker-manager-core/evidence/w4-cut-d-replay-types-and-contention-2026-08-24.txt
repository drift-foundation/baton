1. AN EXACT RETRY MUST REPRODUCE THE RECORDED ANSWER

  `activate_assignment` returned from the already-fixed branch before it reached
  the journal. So the FIRST call committed `already_fixed=False`, a later exact
  retry synthesized `already_fixed=True` from the row, and a contender that had
  read before the commit replayed the journalled False. One act, three arrival
  times, two answers.

  The manager's journal exists so an exact retry reproduces the recorded bytes,
  and a branch that steps around it is not a replay however reasonable its
  answer looks. The signature is derived before the branch and
  `store.replay` answers first.

  THE ORDER OF THE THREE CHECKS IS DELIBERATE:

    - the fixed-assignment MISMATCH is decided first, because it is a
      precondition about the ATTEMPT rather than about this operation's
      identity. An activation naming another assignment is refused with what
      actually differs, rather than with an operation collision that says only
      that the operands changed.
    - then the journal, which reproduces this operation's recorded answer and
      still collides on a full-signature disagreement.
    - then the already-fixed fallback, which now means what it always should
      have: an attempt this build finds fixed with NO act of its own to
      reproduce. The retained delivered case covers it by deleting the journal
      row, which is the shape that produces it.

3. ONLY CONTENTION IS TRANSLATED

  The savepoint handler rolled back and rethrew everything, so a stale writer's
  conditional UPDATE surfaced `sqlite3.OperationalError('database is locked')`
  and never reached the row-count refusal that means the same thing.

  Classification is by SQLite's own RESULT CODE and never by prose. The low byte
  is the primary code and the high bits are the extended reason, so a trigger
  abort's 1811 is compared as SQLITE_CONSTRAINT rather than as itself. A locked
  database at this boundary means exactly one thing -- another writer is
  deciding this attempt, so the observation did not land -- and everything else
  keeps its own identity, because giving a disk fault or a constraint a portable
  meaning it does not have hands a caller the wrong retry policy with full
  confidence.
