2. P1 — THE READ PATH BOUND THREE QUARTERS OF THE REFERENCE

`eventRecordOf` takes the full session reference and selected the row on
attempt, posture and epoch. `authenticateRetained` then bound the seal and the
sequence and never compared the retained `agent_session_ref` with the
reference the caller asked for. So a caller asking for provider session B
received a frame sealed for provider session A whenever the other three
components agreed — the SAME identity mismatch the write path refuses,
reached through the read path instead.

§3.1 makes the provider session id part of the reference, so binding three
quarters of it is not binding it. The requested reference is now a fifth
witness beside the shape, the declared digest, the recomputed digest and the
sequence.

ABSENCE AND DISAGREEMENT ARE DIFFERENT ANSWERS, and an added case holds both
directions. A genuinely absent `(attempt, posture, epoch, source_seq)` is
still null. A PRESENT row whose sealed reference disagrees REFUSES: answering
null there would tell a caller no such frame exists while the epoch holds one,
which is a worse lie than the one being fixed.

MEASURED: from the REPLAY path the same comparison is INERT, because the
retained and incoming digests are already equal there and equal digests mean
equal references. It is one function because the rule is one rule, and the
reader is where it has teeth. Said in the code rather than left for a reader
to work out.


3. P2 — SEALING NON-DURABLE INPUT LEAKED AN INTERPRETER ERROR

`sealEvent` called `structuredClone` directly on content, tool-call data and
diagnostics, so a non-cloneable member escaped as raw `DataCloneError`. The
outer taxonomy is closed and unnormalizable event content belongs to
`integrity.schema`; a provider-facing caller cannot map an interpreter
exception onto that wire contract without re-deriving policy it was never
given.

`ownDurable` covers all three members. The SEAL is wrapped separately, because
`canonicalBytes` is the other place a caller's value becomes durable.

AN EXISTING ContractError PASSES THROUGH UNCHANGED, which is the half worth a
case of its own: `Infinity` clones perfectly well and fails at the canonical
boundary, whose refusal names the rule exactly. A general "cannot own this"
would have reported the same pair while telling the caller less. The case
asserts both that the message names the rule AND that it was not wrapped —
because interpolating the precise text into the general refusal would satisfy
a naive pattern while losing exactly what the precision was for.

TWO OF MY OWN INSTRUMENTS WERE WRONG ON THE FIRST PASS, and the fix is worth
recording because both were silent.

D2 first read `if (false && a || b || c || d)`. `&&` binds tighter than `||`,
so that disabled only the FIRST clause — which no case drives, because a
differing attempt id makes the row absent rather than mismatched. It reported
zero witnesses and meant nothing. Rewritten as `if (false)`, it fails two.

D6 reported zero against an assertion that only required `/infinity/` to
appear in the message. Flattening INTERPOLATES the precise text into the
general refusal, so the pattern still matched. The case now also requires that
the general wrapper is absent, and the mutation fails.

A mutation that reports zero is a claim about the code; twice here it was a
defect in the instrument. Both are now measured rather than assumed.

D8 is MEASURED AS UNREACHABLE: nothing inside `structuredClone` raises a
`ContractError`, so removing that line changes no case. It is kept for
symmetry with the seal wrapper, where the same line is load-bearing, and it is
not counted as a guard.
