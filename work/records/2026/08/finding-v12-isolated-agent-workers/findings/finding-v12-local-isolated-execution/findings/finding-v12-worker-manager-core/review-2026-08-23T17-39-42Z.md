## P1 — the outbound allow list still contains the agent-origin method

The correction correctly states that direction answers two different
questions and introduces `AGENT_ORIGIN_METHODS = ["session/update"]` plus
`routeAgentOriginCall`. But `KNOWN_AGENT_SURFACE`, which
`checkOutboundMethod` uses as the relay-to-agent allow list, is still built as
all five `REQUIRED_AGENT_METHODS` plus the three optional methods. It
therefore still admits `session/update` in the reverse direction.

The pinned ACP SDK 1.3.0 makes the direction explicit: `session/update` is in
`CLIENT_METHODS`, while `initialize`, `session/new`, `session/prompt` and
`session/cancel` are in `AGENT_METHODS`. Frozen §2.3's five-member baseline
says what an endpoint must present across both directions; it is not an
eight-member relay-outbound allow list. Once this slice separated the inbound
route, leaving that same name in the outbound set makes the two claimed closed
directional surfaces overlap.

Keep `REQUIRED_AGENT_METHODS` at five for handshake capability validation.
Build the relay-outbound allow list from the four relay-origin required names
plus the three optional names, and prove it is disjoint from
`AGENT_ORIGIN_METHODS`. `checkOutboundMethod("session/update")` must refuse as
`refused.capability`; `routeAgentOriginCall("session/update")` must continue
to return it. Preserve every accepted first-review correction and the new
directional regression.

Case-specific authorization: migrate the existing focused assertion that
defines `KNOWN_AGENT_SURFACE` as all required plus optional methods and passes
all eight through `checkOutboundMethod`. Preserve the five-member handshake
requirement, the three optional members, and exhaustive pass-through for the
correct seven relay-outbound names. Rename the constant if that makes its
direction explicit; do not drop or deny the separate agent-origin route.
