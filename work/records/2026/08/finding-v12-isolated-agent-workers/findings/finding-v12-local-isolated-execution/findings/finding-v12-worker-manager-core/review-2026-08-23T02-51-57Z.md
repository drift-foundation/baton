## P1 — a foreign participant's authority session opens execution

`openAgentSession` receives the manager's participant-bound `V12Session`, but
checks only that it has `assignmentOf`. The projection itself is Work-scoped:
calling `assignmentOf(WORK)` through a session minted for `poc.gemini` still
returns the live assignment whose participant is `poc.claude`. The subsequent
four-part comparison proves that the projection and attempt agree; it does not
prove that the supplied authority handle is bound to that participant.

The additive regression creates a real authority, claims the Work through the
`poc.claude` session, activates the manager attempt, then calls
`openAgentSession` with a genuinely minted `poc.gemini` session. The call does
not refuse and writes the execution row.

Snapshot the authority session's participant binding once and require it to
equal the attempt's fixed assignment participant before an execution session
can open. A foreign or missing binding should fail closed without inserting;
the proposed frozen pair for this caller/session precondition is
`refused.precondition`. Retain `W2929 review: execution uses the assignment
participant's session` against the real authority.

This is distinct from provider isolation. The trusted manager may hold and
read its own participant-bound authority session; the provider and relay must
still receive neither that handle nor any capability. The existing answer and
durable-row absence case remains green.
