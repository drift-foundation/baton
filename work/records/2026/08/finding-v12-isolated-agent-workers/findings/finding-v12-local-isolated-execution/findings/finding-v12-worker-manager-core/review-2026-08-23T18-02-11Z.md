## P1 — a state observation does not bind the full session identity

Frozen §3.1 makes `provider_session_id` the fourth component of the session
reference that labels evidence. It authorizes nothing, but a label that names
provider session B cannot move or affirm the axis durably held for provider
session A. The turn and event boundaries already enforce that same distinction.

`observeAgentSessionState` discards `sessionRef.providerSessionId`, selects
only attempt/posture/epoch, and reads only `state`. A wrong or absent provider
id therefore moves the durable row, and a wrong id on a self-observation is
accepted as `{ moved: false }`. The no-op is still an observation and must
bind before it answers.

Normalize and prove the complete incoming reference before opening the write
transaction: nonempty attempt id, one of the two postures, positive integer
epoch, and a nonempty provider id or null. Malformed references are
`integrity.schema`, not raw SQLite binding errors or missing-session
preconditions. Select the stored `provider_session_id` with the state and,
inside the same transaction, compare it with the normalized reference before
either the self-observation answer or successor decision. A disagreement is
`runtime-observation.identity-mismatch` and changes nothing. Retain both
additive regressions and all exhaustive transition coverage.
