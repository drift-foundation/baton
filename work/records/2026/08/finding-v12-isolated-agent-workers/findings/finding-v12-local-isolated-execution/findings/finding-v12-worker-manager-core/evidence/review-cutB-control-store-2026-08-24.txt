DIRECT PROBES

1. Sixteen concurrent first opens of one absent path:

     one       -> ok
     fifteen   -> OperationalError: table meta already exists

   Each opener observed the empty schema before the first initializer committed.
   `_initialize` acquires a write lock but does not re-read after acquiring it.

2. A foreign database containing `CREATE TABLE meta (id INTEGER)`:

     OperationalError: no such column: key

   The file bytes remain unchanged, but the closed ContractRefusal boundary is
   bypassed by the generic table-name collision.

3. Journal one `offer.issue` result, then call the same operation id and exact
   signature argument with kind `cleanup.destroy`:

     {'a': 1}

   The first result is replayed. The stored kind is selected but never compared.

4. Direct inserts of each impossible outcome cross-product all succeeded:

     committed + SQL-null result + null refusal
     committed + JSON result + refusal
     refused   + null result + null refusal
     refused   + JSON result + refusal

   The schema checks the state vocabulary but not the payload implied by state.
