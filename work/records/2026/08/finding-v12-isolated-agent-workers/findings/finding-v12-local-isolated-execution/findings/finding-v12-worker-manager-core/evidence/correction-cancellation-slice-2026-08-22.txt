2. THE ONE I LEFT OUT

[P1] THE SLICE OMITTED AGENT CANCELLATION. The owning acceptance says "only
then does the manager order AGENT CANCELLATION AND RUNTIME STOP", and I built
the runtime half and called item 3k done. `session.cancel` is the
assignment-authority FENCE; it is not the provider agent's cancellation, and
nothing in the slice touched an agent at all.

I did not read the acceptance carelessly so much as let the item-4 boundary
swallow more than it owns. Item 4 owns what a conforming agent must BE. Where
its cancellation sits in the order is item 3's, and that is the whole subject
of this slice — so deferring it deferred the thing being built.

CORRECTED by injecting the agent as a boundary, exactly as the runtime adapter
already is, and ordering it BETWEEN the fence and the runtime stop. The order
is now `authority.cancel -> agent.cancel -> adapter.stop`, driven through one
shared trace.

The agent goes first for a reason worth stating: an agent told to stop after
its runtime is already going away never hears the order, and the cooperative
shutdown is the only thing asking it buys over a kill.

THE PARAMETER ORDER IS THE ACT ORDER, and two adjacent injected objects are
easy to swap, so both shapes are checked. A swap refuses `integrity.schema`
rather than cancelling the wrong boundary first.


3. THE OTHER TWO

[P1] CALLING `stop` MANUFACTURED A POSITIVE STOPPED FACT. `orderStop`
discarded the adapter's answer and reported `stopped: true` whenever the call
RETURNED. An adapter answering `{ stopped: false }` left the manager
announcing a stopped runtime while its own axis said only `cancel-requested`.

REACHING A BOUNDARY IS NOT EVIDENCE OF ITS EFFECT — and this is the same
mistake as the caller-authored `absenceProven` boolean, arriving from the
manager's own side instead of the caller's. The word `stopped` is gone from
the answer. The manager reports `ordered: true`, which is what it knows, and
passes each settlement through UNINTERPRETED so a caller can see what the
boundary said without the manager turning it into a fact about the world.
Positive quiescence arrives as an OBSERVATION or not at all.

[P2] THE PLAN CONTRADICTED THE IMPLEMENTATION ON RETRY. Plan item 3k said the
stop order is not repeated for a runtime already `stopping`, while the code
repeats it and a regression of mine requires the repeat.

THE DRAFTING WAS MINE AND THE CODE IS RIGHT. The AXIS is not rewound; the
ORDER is re-issued under the same operation identity, because an order that
may have been lost must be repeatable and the identity is what keeps the
repeat one act rather than two. Plan item 3k now states that rule and carries
a dated correction note naming the review, so the chronology shows the
contradiction and its resolution rather than hiding it.
