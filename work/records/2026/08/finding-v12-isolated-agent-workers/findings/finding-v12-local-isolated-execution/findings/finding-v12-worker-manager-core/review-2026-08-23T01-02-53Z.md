## Finding

### P1 — `present` with no material freezes as a successful required output

The correction now refuses an output that says `missing-optional` while
carrying a content manifest or artifact. The converse is not enforced.
`checkDeclaredLimits` enters the `present` branch, computes `size = null` when
both `content_manifest` and `artifact` are null, skips every limit, and returns
success. Because required-output handling tests only `status !== "present"`,
a required output with no tree and no artifact is frozen under a `completed`
disposition.

The schema deliberately allows the nullable members and leaves their
correlation to semantic validation. The frozen contract says a missing or
invalid required output prevents a successful result and that a frozen result
binds each declared output's content/tree digest and artifact reference. A
status word alone cannot prove material exists. Refuse `present` when it
carries no material (and enforce any type-specific minimum if the contract
requires more than one representation). Preserve `W2929 review: an output
that says it is PRESENT must carry material`.
