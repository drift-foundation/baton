## P1 — an attempt's claimed offer is not unique

`claimOf` asks SQLite for one claimed offer by `runtime_attempt_id` and uses
`.get()` (`attempts.mjs:159-162`), but `offers.runtime_attempt_id` has no
uniqueness constraint (`schema.mjs:56-104`). Two different Works can therefore
reach `claimed` under the same attempt identity, after which activation chooses
one by unspecified row order. The correction's statement that this is
"unwitnessable by construction" is disproved by the retained store itself.

Make the offer-to-attempt identity one-to-one at the database boundary (or
fail closed unless exactly one claimed row exists); allocation already treats
the attempt identity as belonging to one offer. Preserve that invariant across
schema-version handling.

Regression: `one attempt cannot have two claimed offers`.

## P1 — durable observation identity is consulted too late

`observe` returns immediately when today's axis already equals the supplied
value, and checks today's transition before querying the durable
`(attempt, incarnation, source_seq)` identity (`attempts.mjs:477-503`). Thus an
exact old observation is refused after the axis advances, while a different
observation reusing that source identity is silently accepted when its target
axis is already at the requested value. Both contradict the pinned rule:
exact duplicates replay; conflicting duplicates refuse; replay never regresses
a stronger observation.

Resolve the durable source identity and compare its immutable digest before
either the current-value shortcut or transition decision. An exact replay
returns the recorded answer without changing today's axis; a conflicting
digest refuses regardless of today's value.

Regressions: `an exact observation replays after the axis advances` and `a
conflicting duplicate refuses even at an inert value`.

## P1 — later multiplicity cannot enter cancellation from uncertainty

The zero-runtime path records `uncertain`, but the transition map omits
`uncertain -> cancel-requested`. If a later inspection discovers two matching
runtimes, `reconcileRuntime` calls `cancel` as promised and `observe` refuses
it (`attempts.mjs:357-361,389-393`). An ambiguous first inspection therefore
disables the safety response to stronger later evidence.

Permit the cancellation intent from every nonterminal runtime state in which
mismatch or multiplicity can be discovered, while retaining the rule that
uncertainty alone never proves destruction.

Regression: `multiplicity discovered after uncertainty still cancels`.

## P1 — the attachment CAS does not preserve mismatch semantics under a race

The JavaScript pre-check sees `runtime_id=null`; another manager attaches a
different runtime; then the stale manager reaches `store.transact` under the
same `attempt.attach:<attempt>` operation id with a different signature
(`attempts.mjs:402-423`). Journal collision fires before the SQL CAS, surfacing
`refused.operation-collision` instead of the pinned mismatch cancellation.
The existing raw-SQL CAS case bypasses this product path and therefore cannot
prove the claimed behavior.

After losing the race, re-read the fixed identity and preserve it, then enter
cancellation for the different observed runtime. Do not rewrite the first
attachment and do not report the second observation as another invocation of
the first attachment act.

Regression: `a concurrent different attachment enters cancellation`.

## P2 — every SQLite failure is mislabeled as observer contention

The `observe` catch translates every non-`ContractError` into
`runtime-observation.state-regression`, although only lock/busy failures mean
another writer is deciding the attempt (`attempts.mjs:461-474`). A deterministic
abort trigger is consequently reported as another writer's newer observation.
Disk, schema, constraint and corruption failures would receive the same false
portable meaning and retry policy.

Translate only the SQLite lock/busy condition this boundary intends to close;
preserve or accurately classify other storage failures.

Regression: `a storage failure is not reported as a stale observation`.
