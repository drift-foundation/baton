## [P1] Parser-invalid absolute URIs enter the trusted manifest

`validateUri` recognizes a textual scheme, calls `new URL(uri)`, then catches
and ignores every parse failure under the comment “opaque scheme, no
authority.” `https://[` is not an opaque URI; it is a malformed hierarchical
URI. Because AJV format assertions are deliberately disabled, a resealed
manifest carrying that source passes the schema and semantic trust entry.

Section 3.3 requires an absolute normalized URI and section 12 makes URI
validity part of semantic admission. Treat a parser failure as refusal. Valid
opaque forms such as `urn:` and `mailto:` already parse with the chosen URL
implementation and still need the original-text query/fragment rules. Retain
the additive manifest regression so malformed locators cannot reach a future
adapter as trusted state.

## [P1] Content manifests use UTF-16 order instead of byte order

`validateContentManifest` checks adjacent paths with JavaScript `<`. That is
UTF-16 code-unit order, not the contract's bytewise order. The resealed list
`["\u{10000}.txt", "\uE000.txt"]` is increasing under JavaScript `<` but
decreasing under UTF-8 byte comparison, and the product accepts it.

Use an explicit bytewise comparison of the normalized UTF-8 path bytes. This
is a cross-language seal boundary: accepting a different order from the
frozen contract and its model makes two conforming readers disagree about the
canonical tree. Retain the BMP/astral regression with correctly recomputed
aggregates and tree digest.

## [P1] The journal checks secret field names, not the bearer value

The store correctly calls `assertNoDurableSecret` before recording both a
committed result and a sealed durable refusal. The helper, however, only
rejects member names in `SECRET_FIELDS`; it never examines a string value. A
raw golden bearer under `diagnostic` commits, and the same bearer embedded in
a durable refusal `message` is recorded before the original refusal is
replayed. Both are surfaces section 13 names explicitly.

Bind the journal check to the actual ephemeral bearer value(s) known for the
operation, or establish an equivalent manager boundary that can detect and
redact/refuse those values in results, errors and diagnostics. Rejecting a
generic token-shaped string is not an adequate substitute: the bearer schema
allows arbitrary strings from 32 through 4096 characters, so shape alone
cannot identify the secret safely. Retain both regressions and require
`integrity.secret-leak` with no operation row on either path.
