## Result

The positive posture bindings are correct: consent carries no assignment,
workspace or declared output; execution carries the durable exact assignment;
the two policies remain distinct; and the profile bytes are retained rather
than replaced by an unreadable digest. Three P1 boundaries remain open.

## P1 — the retained document's own declared seal is not rebound

`certifiedAgentSessionProfile` validates shape and recomputes the body with
`document_digest` omitted against the row key, but it discards the document's
declared `document_digest` without comparing it. A retained profile whose
policy and all other bytes still match the key, but whose own seal is changed
to another well-formed digest, opens a session.

The loader must establish one equality among all three witnesses: declared
document digest, recomputed canonical digest and the digest key under which
the row was found. Retain the additive regression `W2929 review: retained
profile must declare the digest it is filed under`; it currently fails.

## P1 — a posture may have several concurrent open sessions

The frozen contract permits at most one open session per posture and maps a
second concurrent session to `runtime-observation.duplicate-runtime`.
`openAgentSession` instead takes `MAX(session_epoch) + 1` and inserts another
`not-started` row unconditionally. The existing freshness case consequently
creates three simultaneously open consent epochs; freshness and concurrency
were tested as though they were the same rule.

Refuse a second nonterminal session for the posture, with the frozen error
pair, and allocate/check the next epoch atomically across manager connections.
A later epoch becomes eligible only after the previous one reaches the
contract's terminal boundary and, after transport ambiguity, the §8.4
re-identification gate. Retain `W2929 review: one posture cannot have two
concurrent sessions`; it currently fails and observes two rows.

The prior interleaved freshness test must drive legitimate terminal
transitions between same-posture epochs rather than opening concurrent rows.
Add a two-connection race once that transition surface exists; a read of
`MAX` followed by a separate insert is not an atomic allocator.

## P1 — execution opens after the authority assignment ended

The slice says an execution session has the exact live assignment, but
`openAgentSession` consults only the assignment cached in the manager attempt.
The reviewer regression activates against a real v12 authority, cancels that
exact assignment, then opens an execution session successfully from the stale
control row.

The structural "no Baton capability" test conflates two roles. The trusted
Worker Manager is the one Baton authority client and must project/revalidate
the assignment immediately before creating an execution session. The
untrusted agent endpoint and Session Relay must not receive that session or
capability. Preventing the manager-side function from receiving its
participant-bound `V12Session` does not prove provider isolation; it prevents
the liveness check the contract requires.

Reproject and compare the full four-part assignment before the insert, while
keeping the authority handle out of every provider/relay call and durable
record. Retain `W2929 review: execution cannot open after its assignment
ended`; it currently fails against the real authority with the session row
created.
