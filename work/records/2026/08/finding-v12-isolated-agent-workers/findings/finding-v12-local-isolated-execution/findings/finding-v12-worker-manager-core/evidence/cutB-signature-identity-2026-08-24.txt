2. [P1] CHECKING THAT TWO ACCOUNTS AGREE IS NOT CHECKING THAT EITHER IS TRUE

The previous round bound the kind to the signature, because the journal stored
one and the signature contained the other and nothing compared them. That was
the right fix for the finding and the wrong depth for the rule.

`_agreeing` then asked: does this parse, and does its `kind` match? Both
questions are about AGREEMENT. Neither asks whether the thing agreeing is a
signature this manager could have written -- so an indented spelling, a document
missing `operands`, and one carrying an extra member all passed, and each became
a durable identity in the journal.

The consequences are the two the review names. Equivalent operations can acquire
DIFFERENT byte identities, so the journal cannot tell one act from another. And
data outside the defined operand set can enter collision and replay identity, so
an operation is compared on things it was never defined by.

The test is not "does this parse and agree" now but "is this exactly what we
would have written": own it as exact POD, require exactly `kind` and `operands`,
and compare the SUPPLIED BYTES against the canonical serialization of that owned
document. Anything else is not this manager's identity for anything, whatever it
parses as.

All of it before the journal transaction, so a refusal leaves no row -- asserted
by both retained methods.
