2. THE ONE I GOT MOST WRONG, FIRST

[P1] AN ATTEMPT'S CLAIMED OFFER WAS NOT UNIQUE. `claimOf` asked for one
claimed offer with `.get()`, and `offers.runtime_attempt_id` carried no
uniqueness constraint — so two Works could reach `claimed` under one attempt
identity and activation would pick between them by unspecified row order.

Last round I called this branch "unwitnessable by construction". THE
CONSTRUCTION WAS A PROPERTY OF THE ALLOCATOR, NOT OF THE STORE, and the store
is what activation reads. An invariant only the writer maintains is not an
invariant — and my claim was disproved by the retained store itself.

CORRECTED both ways the review asks for: a unique index on
`offers(runtime_attempt_id)` at the database boundary (schema 2 -> 3), AND a
reader that fails closed unless exactly one claimed row exists, for a store
written before the index. Choosing between two claims by row order would be
inventing an answer.

That fail-closed branch is now WITNESSED rather than argued about: a case
drops the index, writes the second row, and drives activation. Building the
damaged store the reader defends against is the only honest way to assert a
defence against damaged stores.


3. THE OTHER FOUR

[P1] DURABLE OBSERVATION IDENTITY WAS CONSULTED TOO LATE. The current-value
shortcut and the transition check ran before the `(attempt, incarnation,
source_seq)` lookup — so an EXACT old observation was refused once the axis
advanced, while a DIFFERENT observation reusing one source identity slipped
through whenever its axis already held the requested value. Both invert the
pinned rule. What a source identity already said is a fact about that
identity; today's axis has no bearing on it, so it is resolved first.

[P1] LATER MULTIPLICITY COULD NOT CANCEL FROM UNCERTAINTY. The zero-runtime
path records `uncertain`, and the map had no `uncertain -> cancel-requested`
— so one ambiguous inspection disabled the safety response to stronger later
evidence, and `reconcileRuntime` promised a cancellation `observe` refused.
The cancellation INTENT is now reachable from every nonterminal runtime
state, which is separate from the rule about destruction that uncertainty
still never proves.

[P1] THE ATTACHMENT CAS LOST ITS MISMATCH SEMANTICS UNDER A RACE. With the
operation keyed on the attempt alone, a stale manager reached the journal
under the same id with a different signature and surfaced
`refused.operation-collision` instead of the pinned mismatch cancellation.
Attaching runtime A and attaching runtime B are two acts; one identity made
the second read as a botched retry of the first. The identity carries the
runtime now, and a lost race re-reads the fixed identity, PRESERVES it, and
enters cancellation for the different runtime it saw.

[P2] EVERY SQLITE FAILURE WAS MISLABELLED AS CONTENTION. Only a busy or
locked database means another writer is deciding this attempt; a constraint,
a trigger abort, a disk or schema fault would have carried a portable meaning
and a retry policy belonging to a completely different fact. A wrong
diagnosis is worse than a raw error, because a caller can at least see that a
raw error is unclassified. Only the lock condition is translated; everything
else keeps its own identity.
