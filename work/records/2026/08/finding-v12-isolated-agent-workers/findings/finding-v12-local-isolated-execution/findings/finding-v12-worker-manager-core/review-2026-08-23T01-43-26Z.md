## Findings

### [P1] Exact intake replay and collision are hidden by current output state

`recordIntake` reads the current `outputs` row and refuses its absence before
it reaches the operation journal (`intake.mjs:115-141`). After a decision has
committed, however, the intake row owns the exact result digest and keeps the
retained manifest alive. Removing the now-redundant output index leaves the
committed intake operation and its material intact, yet an exact retry is
reported as a new precondition failure; a changed retry is likewise hidden
instead of returning `operation-collision`.

This contradicts the dossier's pinned intake idempotence and the same
immutable-identity-before-current-state rule already corrected in the output
slice. Resolve an existing intake identity from its committed durable binding
before consulting current output state. Preserve the sealed-output
precondition for a genuinely new decision.

Regression: `W2929 re-review: intake replay precedes current output state`.

### [P1] The intake loader does not re-bind its row to the committed operation

`intakeOf` validates only the assignment fields and returns every other column
as trusted (`intake.mjs:156-174`). The new foreign key proves that *some*
manifest exists; it does not prove this is the result digest the intake
operation committed. Pointing the row at a second, individually valid retained
result manifest passes the foreign key and is accepted by cleanup and operation
identity derivation.

Reconstruct and compare the intake row's immutable operation binding on read,
including its result digest and all decision operands, and validate the named
manifest as a digest-keyed result. The operation journal is the independent
durable witness available even when the current `outputs` index is absent.
Do not make the replay fix trust an intake row that its own committed signature
does not authenticate.

Regression: `W2929 re-review: the stored decision stays bound to its exact
result`.
