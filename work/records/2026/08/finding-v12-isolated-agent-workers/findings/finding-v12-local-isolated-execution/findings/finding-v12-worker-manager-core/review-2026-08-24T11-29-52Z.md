# Independent review — Cut C offers and claims — 2026-08-24

## Outcome

Changes requested. The delivered offer/claim flow is structurally complete and
its 393 methods remain green, but five additive review methods expose four
contract boundaries that must close before Cut C can be signed off.

## Accepted

The review accepts the narrow injected authority port and injected authority
signature as Cut C's two recorded decisions. It also accepts the presence and
positive-path structure of issue, accept, decline, submit, settlement, late
commit and asymmetric recovery: participant binding, certification before
entropy, capacity, complete issue identity, replay marker, constant-time
bearer verification, accepted-state CAS, fixed claim identity/signature,
observe-only ambiguity, adopted retirement and restart abandonment.

## P1 — the injected session capability is not typed at construction

`AuthorityPort` checks that all five named members exist, but verifies only the
separate `claim_signature` injection is callable. `project_work`, `slot_holder`,
`claim`, and `settle_operation` each accept `None` at construction. A broken
`claim` capability is consequently discovered only after the offer has become
accepted and its claim identity has been frozen, as a raw `TypeError`.

Require every named operation to be callable at port construction. Keep
`participant` as the bound value. The retained additive method exercises each
of the four operations independently.

## P1 — SQL text and time operands are weaker than the accepted Cut B rule

Cut C's local `_text` accepts lone surrogates. A surrogate offer id on the
accept read and a surrogate clock value on expiry both escape as raw
`UnicodeEncodeError` from SQLite. The same boundary also treats any nonempty
string as an instant: `"not-an-instant"` silently expires a valid offer by
lexicographic comparison.

Apply the shared durable-text rule before every SQL boundary and validate the
exact canonical instant grammar before any time comparison. These are separate
properties: encodable text is not necessarily an instant.

## P1 — a nonpositive TTL spends entropy and commits unusable authority

`issue_offer` exposes `ttl_seconds` but passes it directly to `timedelta`. A
negative duration causes a bearer to be minted and an already-expired offer to
be committed. Require an exact positive integer before reads or entropy, or
remove the operand and use the fixed policy constant.

## P2 — the offers schema does not enforce its all-five-or-none invariant

The schema documents that acceptance freezes all five identity fields or none,
but its CHECK mentions only `intent_digest`, `claim_operation_id`, and
`claim_signature`, and constrains only `issued`. SQLite accepts both an
`accepted` row with the five fields absent and an `issued` row with
`accepted_at`/`settle_by` populated.

Enforce all five absent for pre-acceptance/terminal-without-acceptance states
and all five present for accepted-derived states. Because this changes the
durable row shape, advance and validate the schema version explicitly.

## Verification

Five additive methods produce eight assertion failures and two raw errors;
the subtests independently cover four operations, two text sites, two invalid
row shapes, TTL, and time grammar. The delivered 393-method baseline remains
green; the source inventory is now 398 methods plus one explicit ambient-
version skip.
