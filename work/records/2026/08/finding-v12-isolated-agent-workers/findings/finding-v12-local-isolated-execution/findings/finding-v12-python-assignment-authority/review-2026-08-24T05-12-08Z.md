## Findings

1. **[P1] `install_gate` can compare one Work and mutate/end another.** In the
   unclaimed path (`core.py:597-605`), a supplied current assignment for Y
   satisfies `_expect` before X is gated. In the live path (`core.py:606-612`),
   the same Y assignment causes `_end_assignment` to end Y while live X remains
   untouched. Require `expect.work_ref.work_id == work_id` before either branch
   and prove both cross-Work cases refuse without changing X or Y.

2. **[P1] claim can mint a generation outside the frozen interoperable range.**
   `core.py:442-451` increments the durable counter without applying
   `check_generation`; a counter at `MAX_SAFE_INTEGER` produces generation
   `9007199254740992` and returns it as an assignment identity. Refuse exhausted
   generation space before taking the slot or writing Work, and cover both the
   boundary generation and the next claim.

3. **[P1] durable cut-2 text does not enforce the recorded Unicode boundary.**
   `_text`/`_optional_text` and `gate_token` accept lone-surrogate strings.
   SQLite entry points then escape as `UnicodeEncodeError`, while `gate_token`
   returns an invalid durable token. Centralize exact, nonempty, encodable text
   validation and apply it to every cut-2 text operand, including optional
   prose and both gate-token components; add positive non-ASCII coverage.

4. **[P1] gate satisfaction accepts and journals structurally meaningless
   proof.** `core.py:632-661` uses truthiness for runtime, policy and plan
   digest, so a list can satisfy a plan-revision gate and non-text values can
   stand for exact runtime/policy identity. Contract-runtime evidence records
   no profile identity, and isolation checks only a boolean rather than binding
   the claimed pinned clause. Validate the semantic evidence shape for each
   gate kind and bind the journalled proof to the configured fact required by
   W151. If the exact pinned-clause representation is genuinely undecided,
   raise that one decision rather than silently weakening “pinned.”

5. **[P1] assignment event history contradicts W151 `1-ruled`.** Claim writes
   no event (`core.py:425-454`), although W151's transition table explicitly
   requires a claim event. Ending events are returned as partial scalar rows
   (`core.py:342-345`) rather than carrying the full four-part
   `assignment_ref` required immediately below that table. Node is frozen
   executable-reference evidence only. Record the claim event atomically and
   project every assignment event with its complete authority/Work/
   participant/generation identity; update the current one-event-after-end test
   rather than pinning the reference omission.

6. **[P2] `cancel(None)` raises `TypeError` instead of the ordinary
   missing-assignment refusal.** `core.py:545-550` subscripts the normalized
   absence before `_expect`. Put the common assignment precondition ahead of
   the generation-specific v11 refusal and prove the fault leaves state
   unchanged.

7. **[P2] the invariant backstop accepts invalid scheduler cross-products.**
   `core.py:721-725` checks only gate-implies-block. An open Work with
   `block/NULL` or an invented phase returns `True`. Validate membership in the
   closed scheduler axis and both directions of the phase/gate cross-product,
   including gate kind/detail, through direct corruption cases.
