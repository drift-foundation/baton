# Independent review: output-freeze slice

Date: 2026-08-23T00:30:49Z
Reviewer: `baton.codex`
Disposition: **changes requested**

Scope: plan item 3p, `v12/src/worker_manager/output.mjs`, schema version 4,
and `v12/test/worker_manager_output.test.mjs`. The already signed-off
cancellation slice, future intake/cleanup, and item 4 are outside this pass.

The positive-quiescence and recorded-disposition gates are sound. `uncertain`
and `destroyed` do not masquerade as writer quiescence; the authority liveness
read is correctly described as a cross-store precondition rather than atomic
proof; fixed per-attempt operation identities prevent changed bytes from
becoming a second result; and the shared manifest validator closes the
portable shape/digest/path/credential rules it actually owns.

## Findings

### P1 — the sealed result's freeze signature is ignored

A result manifest binds a complete `freeze_operation`: operation ID and
`signature_digest`. `requestFreeze` computes the exact manager operation
signature and journals it, but passes only `operationId` to `adapter.seal`.
`recordFrozenResult` then checks only
`owned.freeze_operation.operation_id`; any schema-shaped digest is accepted.
The original successful fixture used `digest("freeze")`, unrelated to the
journalled operation, and every test remained green.

The operation signature is the binding over kind and effective operands; the
ID alone is only the retry key. Pass the complete operation identity to the
sealing boundary and compare the returned signature against the exact
journalled freeze signature before recording. Preserve `W2929 review: a
sealed result must echo the freeze signature`.

### P1 — exact replay is hidden by later output state

`recordFrozenResult` checks that the current output axis is
`freeze-requested` or `frozen` before consulting the fixed record operation.
After the output advances to `sealed`, an exact retry of the already committed
result refuses as a precondition instead of replaying the immutable journal
result. This repeats the earlier observation-ordering defect: today's stronger
state is consulted before the durable identity that says whether this is the
same act.

The acceptance states that the same digest replays, and the store model says
replay may never regress a stronger observation. Resolve replay/collision at
the fixed record identity without rewinding the later axis. Preserve `W2929
review: an exact result replays after the output axis advances`.

### P1 — “declared outputs only” is not enforceable from the stored state

The frozen contract makes declared outputs a freeze precondition and requires
a missing required output to prevent a successful result. The manager stores
only `attempt.input_digest`; neither `requestFreeze` nor
`recordFrozenResult` receives or resolves the validated input manifest whose
output descriptors that digest names. `validateManifest(resultManifest)` can
prove that the result is internally well formed, but it cannot prove that its
output names/types/statuses match a different document it never sees.

Consequently, a schema-valid result can substitute an undeclared output or
omit a required one while echoing the expected input digest. Carry a trusted,
digest-verified input declaration into this comparison and add positive,
undeclared, missing-required, missing-optional and type/status mismatch cases.
There is no honest additive regression yet because the current API/store has
no surface on which a test can establish the declaration being compared.

### P1 — schema 4 does not retain the immutable result manifest

The store surface requires an immutable freeze/result record, and the worker
contract defines that record as the full result manifest: assignment/input/
policy bindings, every output content/tree digest and artifact reference,
explicit missing optional outputs, evidence/log references, freeze operation,
and manager observation. Schema 4 retains only a summary row plus artifact
rows. `outputs` stores result ID, disposition, top manifest digest, freeze ID
and time; `output_artifacts` stores only outputs with non-null artifacts.
The operation journal stores another summary. The validated manifest bytes,
content-tree facts, missing outputs and evidence disappear when the call
returns.

That leaves restart, intake and proposal publication with a digest but no
durable record whose bytes it can replay or inspect. Persist a canonical owned
copy (or an equivalent lossless normalized representation) and prove after
reopen that the full manifest, including explicit missing output and evidence,
is byte-stable and caller-alias-free. Artifact byte verification may remain
with W2930; retaining the manager's sealed observation may not.
