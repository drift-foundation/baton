## Finding

### P1 — parseable JSON is accepted as the manager's canonical signature

`ControlStore._agreeing` checks that the supplied signature is non-empty text,
parses as a JSON object, and has a `kind` equal to the separate kind argument.
It does not establish either property promised by the refusal and helper:

- the bytes are exactly the canonical serialization; or
- the document has exactly the manager-owned `{kind, operands}` shape.

Consequently an indented spelling, a canonical document without `operands`, and
a canonical document with an extra member are all accepted and journalled.
These are durable identities `manager_signature` cannot produce. Equivalent
operations can acquire different byte identities, while added or omitted data
can enter collision/replay identity without belonging to the defined operand
set.

Parse as exact POD, require the exact two-member shape, then compare the input
bytes with the canonical serialization of that owned document before opening
the journal transaction. A refusal must leave no operation row. Retain:

- `test_a_noncanonical_json_spelling_is_not_a_durable_identity`;
- `test_a_signature_has_exactly_the_manager_owned_shape`.
