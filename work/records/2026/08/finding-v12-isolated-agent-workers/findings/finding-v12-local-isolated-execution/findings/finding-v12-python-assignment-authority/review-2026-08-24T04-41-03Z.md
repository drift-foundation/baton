## Findings

1. **[P1] `open` can expose a stale authority UUID over a different live
   database.** `store.py:168-195` validates the read-only `recorded` snapshot,
   validates `live` under `BEGIN IMMEDIATE`, then constructs the Store with
   `recorded[META_AUTHORITY_UUID]`. If another valid Python-authority file is
   selected in the recheck window and no expected UUID was supplied, both
   validations pass but the public `authority_uuid` names A while the live
   connection governs B. The recheck must make one live identity authoritative
   (or refuse the replacement), and a regression must assert the face and live
   meta can never disagree.

2. **[P1] a malformed durable UUID is treated as a recognized authority and
   populated.** `_check_compatibility` at `store.py:357-366` checks only that
   `authority_uuid` exists unless a caller supplied an expected UUID. A
marker-only SQLite file with `authority_uuid = not-a-uuid` opens and grows the
   full authority schema. Validate the recorded UUID with the same frozen
   grammar on both probe and live recheck, and cover malformed text plus wrong
   SQLite scalar types without modifying the file.

3. **[P1] failed schema application commits partial writes.** The
   `try/finally` at `store.py:182-188` always executes `COMMIT`, including when
   `_apply_schema` faults after earlier statements have changed the database.
   The reproduction leaves a newly created `policy` table behind after
   `Store.open` raises `OperationalError`. Commit only the success path;
   explicitly roll back every failure and prove both bytes/schema and
   connection usability afterward.

4. **[P1] exported identity/gate helpers bypass the exact-data boundary and
   execute caller code.** `same_assignment` compares an unowned caller dict,
   `is_v12_contract` invokes caller `__ne__`, and `gate_token` invokes caller
   formatting (`identity.py:327-345`). The probes escape as `RuntimeError` and
   record the hostile hook. Every exported boundary helper must either accept
   only validated exact built-ins or operate only on an owned snapshot; add
   hostile/subclass cases at the actual exported entry points, not only at
   `own`.

5. **[P1] large rejected integers escape as `ValueError` instead of bounded
   `Refusal`.** `check_generation` interpolates the rejected integer at
   `identity.py:247-250`, while `name_of` stringifies every exact int at
   `errors.py:81-82`. Python 3.13 refuses conversion of a 5,001-digit integer,
   so both `check_generation(10 ** 5000)` and an unrelated identity check with
   that value fail outside the authority outcome taxonomy. Name invalid values
   by the violated rule/bounded inert facts and add huge positive/negative
   integer regressions.

6. **[P2] the claimed locked build is neither consumed nor tested.** The
   `justfile` gate runs only the interpreter check and source-tree tests;
   `pyproject.toml` declares a lower-bounded build backend, and no command uses
   `requirements.lock` to create a hash-enforced environment or build/install
   the distribution. The lock-shape test proves only that text resembling pins
   exists. Add an offline, hash-enforced build/install/import gate derived from
   the lock, or narrow the recorded cut-1 packaging claim until that mechanism
   exists.
