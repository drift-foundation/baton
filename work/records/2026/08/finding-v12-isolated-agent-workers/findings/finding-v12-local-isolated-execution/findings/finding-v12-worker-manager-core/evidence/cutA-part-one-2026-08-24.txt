2. THE ONE PLACE A FAITHFUL PORT WOULD HAVE BEEN SILENTLY WRONG

RFC 8785 orders member names by their UTF-16 CODE UNITS.
`Array.prototype.sort` on JavaScript strings already is that ordering, so the
frozen host gets it for free and says so in a comment. PYTHON'S `sorted()`
ORDERS BY CODE POINTS.

The two disagree for every document with an astral member name beside one in
U+E000..U+FFFF, because UTF-16 encodes astral characters as surrogate pairs in
U+D800..U+DFFF, which sort BELOW U+E000. Measured:

  this implementation   {"<U+1F600>":1,"<U+E000>":2,"<U+FFFF>":3}
  a code-point sort     {"<U+E000>":2,"<U+FFFF>":3,"<U+1F600>":1}

Same document, two canonical forms, two digests. A transliteration would have
produced a manager that disagrees with the frozen reference about what a
document IS -- and it would have passed every test written from the Python side.
The ordering is done on the UTF-16 encoding, and a case pins the two orders side
by side rather than comparing one hash.

THIS IS WHY THE VECTORS ARE GENERATED FROM THE FROZEN HOST rather than written
here. 21 documents, chosen to distinguish the two hosts rather than to agree
with them -- escapes, control characters, DEL, combining marks, astral values,
astral member names, deep nesting, and a 40-member set whose order separates
lexicographic from numeric sorting. The frozen host is the oracle; a vector
written by the port would only prove the port agrees with itself.

All 21 match byte for byte, and every digest matches.

4. TWO THINGS I CHOSE NOT TO SHARE, AND SAID SO IN THE CODE

`baton_v12.authority` already has `Refusal`, `name_of` and `own`. A rule that
exists twice is a rule that holds in one of the two places, and I have been shown
that four times this campaign, so this is not a comfortable decision.

  the refusal TYPE   a caller has to be able to tell WHICH boundary refused. The
                     authority's is an ordinary outcome of an assignment
                     transition; this one is §9's wire-shaped pair.
  `own` and `name_of` these are not on the authority package's EXPORTED SURFACE,
                     and the authority's own boundary cases exist to refuse
                     reaching past it. Importing them would break the boundary
                     the two-package split is for. The bounds differ too: the
                     authority's are its contract's and these are the frozen
                     schema's.

PROMOTING A SHARED PRIMITIVE IS RAISED RATHER THAN TAKEN. It would change the
authority's exported promise, which is closed Work and not mine to reopen.


5. ONE CHANGE OUTSIDE MY OWN FILES, AND WHY

The build stage asserted the INSTALLED origin of `baton_v12.authority` only. The
distribution now carries two slices, so an origin check naming one of them would
report a green import while the other came from wherever it liked. It now checks
both AND asserts the frozen schema assets TRAVELLED INTO THE WHEEL -- package
data that never entered the wheel would otherwise fail nowhere, because a
source-tree run reads it from the checkout.

I also hit an existing authority case: its isolation test parses every module in
the distribution and refuses an import outside the standard library, and
`importlib.resources` is not on its list. I CHANGED MY MODULE RATHER THAN THEIR
TEST -- the asset is read relative to `__file__`, which is correct in both
layouts and needs no new import. Reporting it because a reviewer should know a
closed Work's case fired, and how I answered it.

FOUR STARTED AS ZEROS AND ALL FOUR WERE MY TESTS, not equivalences:

  A5   removing the float branch still REFUSES -- a float falls through to "no
       representation". The branch exists to give §3.2's REASON, so the case now
       checks the reason. A branch whose only job is the message needs a case
       that reads the message.
  C1   every raising site in this cut uses a valid pair, so the guard against a
       WRONG pair had nothing to fire on. The answer is a case that makes the
       future mistake on purpose -- and it asserts `AssertionError` rather than
       `ContractRefusal`, because a caller sending a bad document is an ordinary
       refusal and this package spelling its own vocabulary wrong is a defect.
  D1   `OPAQUE_ID_LIMIT = 160` agrees with the schema, so hardcoding it passes.
       Re-expressed as retyping it WRONG, the case fires -- which is what it can
       actually prove.
  D2   the agreement test compared a PRODUCTION HELPER to the schema, and a
       helper that returned the schema's own codes made it agree with itself.
       Both sides are derived in the CASE now, from `ERROR_CODES` and from the
       parsed schema. That was the sharpest of the four: a test that trusts a
       helper living next to one of its two sources is not comparing two things.
