# Independent review — Cut D runtime and cancellation durability

Verdict: changes requested. The slice preserves the principal ordering and
identity rules, but two P1 boundaries are not yet durable or exact.

## [P1] Attachment and its running observation are not one committed act

`_attach` commits the runtime identity and operation result before it calls
`observe(... running)`. If that call faults, an exact retry after reopening the
store replays the committed attachment result, does not run the action, and
therefore never calls `observe`; it returns `attached` forever while durable
state remains `start-requested`.

Retain
`test_a_committed_attachment_replay_repairs_the_running_observation`. Put the
running observation inside the same journalled transaction as the attachment
update and result (the observation savepoint was explicitly designed for that
nested use), or establish equivalent atomic semantics. Acceptance requires the
test to pass across its actual store close/reopen.

## [P1] A fence for another generation authorizes downstream shutdown

`AuthorityPort.cancel` says it fences the exact generation, but `_assignment`
only validates the returned generation's shape. It relates authority, Work and
participant, then accepts generation 2 for an `expect` naming generation 1.
`request_cancellation` consequently orders both provider-agent cancellation and
runtime stop without evidence that this attempt's generation was fenced.

Retain `test_a_fence_for_another_generation_orders_nothing`. Relate the owned
fence assignment to all four members of the exact expected assignment before
either downstream boundary can run.

The review accepts journal-before-start, the full seven runtime labels,
minted-runtime checking before filtering, fixed runtime identity, cancellation
ordering (authority, agent, runtime), both failure retention, the nested

remains deliberately unavailable and is not a finding in this pass.
