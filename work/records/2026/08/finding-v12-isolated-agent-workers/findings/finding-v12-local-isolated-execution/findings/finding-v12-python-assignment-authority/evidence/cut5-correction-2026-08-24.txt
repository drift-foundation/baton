2. [P1] I STATED THE RULE AND THEN WROTE THE SITES THAT BREAK IT

`errors.py` says it two files away: caller-controlled text in a refusal is
bounded by the RULE and never by the operand. Section 4 of my own cut-5 evidence
went further and asserted the bound HELD in the session, because `name_of` caps
a shown string at sixty characters -- while two sites in the file I was writing
interpolated caller text directly.

That is cut 4's projection defect one cut later, and the same reason: I checked
the helper I was calling instead of the message I was writing.

Every caller-controlled rendering now goes through `name_of`:

  the assignment's named participant   the caller's text
  the session's own participant        has a grammar, has NO LENGTH -- so it is
                                      bounded too, not assumed short
  unknown operand names                a bounded sample plus a count

AND THE MULTI-NAME HALF IS THE WORSE HALF, which the review's single-key probe
does not show. `own` admits up to 512 members, so 510 unexpected names of
100,000 characters each was a ~51,000,000-character refusal -- from a boundary
that had already decided to refuse. A sample of three plus a count is bounded by
CONSTRUCTION: the rule text is fixed, the transition name comes from the table,
and nothing else is interpolated.

The count is what makes the sample honest. "does not take three things" would
understate a 400-name mistake, so the message says three names and 397 more.

The full sort is gone as the review asked. The sample is now the first
unexpected names in the order the caller wrote them, which is also the more
useful answer: sorting a rejected set is work done for prose.

3. [P2] "EXACTLY ONE" WAS NOT EXACTLY ONE

`None` became the same empty dict -- IN THE ONE PLACE whose stated purpose is to
refuse an operand supplied and then ignored. And a second document left as a raw

The arity is checked HERE now rather than by Python. The generated method takes
`*documents`, and zero, null and several are each the one-document rule saying
so. `None` is no longer coalesced with absence anywhere on the path.

The superseded case is updated as specifically authorized: it used to call
explicit `None` "a legitimate operand document for nothing" and expect the
missing-member refusal. That sentence was the defect written down as a rule.
