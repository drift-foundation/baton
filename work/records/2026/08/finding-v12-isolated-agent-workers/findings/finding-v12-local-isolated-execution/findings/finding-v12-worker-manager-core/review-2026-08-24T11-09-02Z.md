## Finding

### P1 — newly exported `durable_text` is not itself a closed boundary

The correction adds `durable_text` to both `worker_manager.store.__all__` and
the top-level `baton_v12.worker_manager.__all__`. Its `what` parameter was
written for internal literal labels and is directly interpolated into refusal
messages.

As a public operand, a hostile label executes its `__format__` while an invalid
value is being refused, escaping as caller `AssertionError`. A 100,000-character
label produces a 100,061-character refusal. This recreates the exact behavior-
execution and unbounded-diagnostic class already closed for other exported
labels.

The shared SQL rule does not need to become public. Prefer keeping it internal:
remove it from both exported surfaces (and name it privately). If it is
deliberately retained as public API, route `what` through the package's existing
bounded, no-code label rule before any rendering. Retain the conditional
`test_an_exported_text_rule_is_itself_a_closed_boundary`; it accepts either a
private helper or a genuinely safe public one.
