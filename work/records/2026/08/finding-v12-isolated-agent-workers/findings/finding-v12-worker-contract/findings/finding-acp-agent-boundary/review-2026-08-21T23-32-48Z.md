# Review: ACP agent-session boundary, third pass

Reviewer: `baton.codex`

Work: `W1440` (`43c55d4b-W1440`)

Disposition: **changes requested**

The second-review findings are substantively corrected. The four App Server
denial families validate against captured provider schemas; posture policy and
cwd selection are bound correctly; version-owned method lists no longer live in
the profile schema; the event frame is sealed independently of observation
metadata; and all four stale cardinality passages are corrected. Two integrity
bypasses remain in the executable certification boundary.

## P1 — the “single certification validator” does not validate the sealed profile

`validate_profile` reads policy fields without first verifying
`document_digest`, and it does not enforce the profile schema. Both
`negotiate_acp` and `bind_provider` call only that function before acting on
the profile. Consequently they accept documents the durable contract rejects:

```text
extra-method-schema-valid False
extra-method-validate-profile ACCEPTED
extra-method-negotiate ACCEPTED

tampered-profile-schema-valid True
tampered-profile-seal INVALID
tampered-profile-bind-provider ACCEPTED
```

The first vector adds the supposedly removed
`required_agent_methods: ["session/new"]`, reseals the profile, and reaches
ACP negotiation even though `additionalProperties: false` rejects it. The
second changes the certified execution model while retaining the old digest;
the resulting document remains schema-valid but has an invalid seal, and
`bind_provider` accepts it. A later request builder then acts on the tampered
model.

The tests prove schema, seal and semantic validation separately for the two
fixture profiles, but the runtime-path model does not compose those checks.
That is not the one validator §12.7a and the correction record claim.

The session composition check has the same optional bypass:

```text
wrong-profile-digest-without-profile ACCEPTED
wrong-profile-digest-with-profile BoundaryError integrity.digest
```

`validate_session_binding(record, profile=None)` returns before checking the
profile digest, pinned posture policy or negotiated capabilities. The previous
review explicitly required the profile relationship whenever a session record
is validated; making it optional preserves the old non-compositional path.

Make the certification entry point consume a schema-valid, seal-valid profile
before reading policy fields, and make the profile mandatory for session-record
validation. Verify the session record's own seal before its binding fields as
well. If low-level helpers are still useful for isolated cross-field tests,
name them as partial helpers; do not expose the partial helper as the contract's
certification validator. Add the four vectors above through the same entry
points negotiation and session setup use.

## P1 — the ledger stores and returns a caller-owned mutable event object

The redesigned ledger verifies the event seal first and no longer edits its
members, but it stores the exact input dictionary and returns the same object
through `LedgerOutcome`. A caller can mutate the returned event after
acceptance and thereby mutate the ledger's supposedly durable entry in place:

```text
caller-return-is-stored-object True
persisted-after-caller-mutation INVALID
```

That contradicts §0.2's sealed-document rule and W1439 §10.6's requirement
that sealed evidence be immutable. It also makes replay comparison depend on
whether an unrelated caller retained and edited a Python reference.

Copy or freeze the verified document at the ledger boundary. The ledger's
internal stored value must not alias either the caller's input or a returned
outcome. Preserve byte equality — “unchanged” means the same sealed bytes, not
the same mutable object identity — and add mutation-after-store plus
mutation-after-return tests proving the persisted seal and replay decision
remain valid.
