All four first-review findings are substantively corrected. Observations now

## P1 — the admitted local profile cannot certify without a fault it is allowed to omit

SPEC §4 says fixture validation refuses a fixture that cannot inject every
fault the portable core needs, and §8.3 says both profiles run the same
portable core. `E-remote-host-restart` is one of those 107 portable-core cases
and requires `host-restart`.

But SPEC §8.1 and `MANDATORY_FAULTS_BY_PROFILE` explicitly exempt
`local-oci` from `host-restart`. The resulting fixture is accepted and then
necessarily fails certification as `unable`:

```text
local-without-host-restart-valid local-oci
local-verdict not-certified
local-unable ['E-remote-host-restart']
```

This is not an ordinary runtime failure: it is a contradiction in the suite's
admission rules. Resolve whether host restart is in the common portable core,
a remote-profile admission proof, or a profile-specific case. Make fixture
validation, the assessed core and the “same normative vectors” requirement
agree, and add the admitted minimal local fixture as a certification test.
Also correct §8.3's stale “101 portable core cases” count.

## P1 — a derived certified report can contradict the facts it certified

`build_report` derives assessments, verdict and profile signal, but accepts
`residual_risk` as unrelated caller input and seals it without comparing it to
the accepted observations. A fully certified run whose
`F-canary-each-surface` facts say all ten surfaces were scanned can therefore
produce this schema-valid certified report:

```text
contradictory-report certified {
  'surfaces_scanned': [],
  'surfaces_not_scanned': [],
  'unproven': ['nothing above the canaries is proved']
}
```

That contradicts SPEC §6.2's claim that the report is derived, §10's evidence
boundary, and the F-02/F-04 observations the same report says passed. It also
lets `surfaces_scanned` and `surfaces_not_scanned` omit or overlap surfaces.

Derive the residual-risk surface sets and unproven statement from accepted
case facts, or require and validate exact agreement with them before sealing
the report. Prove the two surface sets are disjoint and partition the closed
surface vocabulary. Add missing, overlapping and run/report-contradiction
vectors through `build_report`.

## P1 — runtime-supplemental cases are valid documents that no run can assess

SPEC §9 and the `scope` schema allow `runtime-supplemental` cases and say they
are reported separately without entering the verdict. The assessor has no
input for such case definitions, however. `CASE_BY_ID` contains only the 107
fixed core cases; `certify` rejects any observation whose case is not in that
map. `validate_case` would also reject an extension because the fixed
obligation register has no backlink to it.

A schema-valid sealed supplemental case and bound observation therefore fail
at the advertised entry point:

```text
supplemental-run ConformanceError run observes unknown case 'G-vendor-extra'
```

The existing `test_a_supplemental_pass_cannot_offset_a_core_failure` contains
no supplemental case; it only reasserts that a core failure remains a failure.

Define how a fixture/run binds supplemental case definitions and their
digests, accept and assess those definitions under the same shape/seal/fact
rules, report their assessments separately, and exclude them from the portable
verdict. Add positive supplemental assessment, failed supplemental with clean
core, and supplemental-pass/core-failure vectors.
