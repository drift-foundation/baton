# Review: ACP agent-session boundary

Reviewer: `baton.codex`

Work: `W1440` (`43c55d4b-W1440`)

Disposition: **changes requested**

The architectural separation between an agent turn, a runtime and Baton
authority is sound, and the cancellation/quiescence acceptance boundary is
stated unusually clearly. The dossier is not ready to freeze because the
machine contract currently accepts identities and lifecycle combinations the
normative text forbids, while the Codex profile cannot yet issue valid
provider-specific policy and denial messages.

## P1 — the session schema does not preserve W1439 identity and artifact types

`schema/agent-session-1.0.schema.json` locally redefines `workRef`,
`assignmentRef`, `participant`, `artifactRef` and integer bounds instead of
reproducing the frozen W1439 definitions exactly:

- child Work IDs admit `W0`, which W1439 refuses;
- child participants admit a digit-leading address and reject underscores,
  while W1439 does the opposite;
- child artifact references use `byte_length` and a relaxed media type,
  whereas the outer contract owns `bytes` and its stricter media type; and
- child integers omit W1439's JSON-safe maximum.

This is not merely duplicated spelling. A document valid under this child can
be invalid under the contract it claims takes precedence. Evidence refs must
reuse W1439's exact artifact shape, and copied identity/value definitions must
remain byte-for-byte semantically equivalent or be referenced through a
shared schema.

The same schema permits all three forbidden session bindings:

```text
execution-null-assignment True
consent-live-assignment True
cross-work-assignment True
```

An execution session must carry an exact assignment; a consent session must
carry none; and a non-null assignment's `work_ref` must equal the session's
`work_ref`. Add schema conditionals where local shape permits and semantic
checks/tests for the cross-field equality and full W1439 prefix rule.

## P1 — normalized events are neither sealed nor exercised by the semantic model

`SPEC.md` §0.2 says all four documents are sealed and carry
`document_digest`. The `normalizedEvent` schema has no such member, accepts an
unsealed event, and rejects the result of `seal_document`:

```text
unsealed-event True
sealed-event False
```

The executable ledger then expects an incompatible ad-hoc top-level
`session_epoch`, although the sealed schema places it under
`agent_session_ref`. Passing the schema-valid event into the ledger gives:

```text
event-ledger-schema-event BoundaryError event belongs to a different session epoch
```

Consequently the schema tests and semantic tests exercise two different event
contracts. Add `document_digest` to normalized events, feed schema-shaped
events through `EventLedger`, validate positive `source_seq` there, and add
tamper/reseal coverage for an event just as the profile has.

## P1 — consent/execution cardinality is internally contradictory

W151 binds one `runtime_attempt_id` to the offer and later assignment and
tracks separate consent-runtime and execution-runtime axes. This dossier
requires both a pre-claim consent session and a post-activation execution
session with different modes and capabilities, but repeatedly proposes “one
fresh session per runtime attempt.” A consent session cannot safely become an
execution session: it has no workspace or assignment and §4.2 says the
postures are never interchangeable. Conversely, starting the execution
session is a second provider session for the same manager attempt.

Choose and state one coherent identity/cardinality rule. The likely shape is
one fresh provider session per `(runtime_attempt_id, posture, session_epoch)`,
with consent and execution never sharing an epoch or connection; if that is
not intended, remove the consent session from this boundary. Add a trace that
runs offer consent through claim settlement into a separately bound execution
session so W151's fixed attempt identity is exercised rather than assumed.

## P1 — the Codex App Server adapter profile is not yet executable

The official OpenAI App Server documentation was re-opened during this review:
<https://learn.chatgpt.com/docs/app-server>.

Three gaps block approval:

1. App Server exposes no `protocolVersion` in its documented initialization,
   yet the Codex profile sets `pinned_wire_version: 1` and the common semantic
   rule requires a negotiated exact match. ACP's wire-version rule cannot be
   copied onto an unversioned provider. Define a provider-specific certified
   schema/build binding for App Server and reserve `protocolVersion`
   negotiation for ACP.
2. §4 requires an exact pinned mode, but §10 never maps consent/execution
   policy to App Server's actual `thread/start`/`turn/start` fields. The
   official surface exposes `approvalPolicy`, `sandbox`/`sandboxPolicy`,
   `cwd`, network and turn overrides. Pin the complete request operands for
   both postures and test drift/refusal; an ACP `session_mode_id` such as
   `acceptEdits` is not by itself an App Server policy.
3. Approval answers are request-family-specific in the normative prose but
   the model returns the string `"decline"` for every family. Official docs
   require `item/permissions/requestApproval` to receive a `permissions`
   subset (empty for no grant) and `mcpServer/elicitation/request` to receive
   an object with `action` and `content`. Implement typed fixed denial payloads
   per family and assert their complete shape; do not let a generic string
   test stand in for provider-valid JSON-RPC replies.

The current WebSocket explanation also names `--ws-auth` modes not present in
the current official page, which documents environment-variable remote auth.
The exclusion remains valid because the transport is experimental and
unsupported; remove the stale flag names so the rationale does not depend on
obsolete syntax.

## P2 — the closed error pair is open in JSON Schema

`errorCategoryCode.code` is any short string. The semantic model validates
pairs only when constructing `BoundaryError`; a persisted `policyFailure`
can therefore introduce a new code and still pass schema validation:

```text
invented-error-code True
```

Use W1439's exact code enum and validate category/code membership, with a
negative document vector for a valid code under the wrong category and for an
invented code.

## P2 — correct the ACP capability inventory

The vendored 1.3.0 type declaration marks `plan`, `auth`, `elicitation`,
`nes`, and `positionEncodings` unstable. `session` is present but is not marked
unstable in that declaration. The finding and §2.2 currently name `session`
as the fifth unstable capability and omit `positionEncodings`. The schema's
sealed capability object is conservative enough to remain safe, but the
recorded source fact and prose must be corrected.
