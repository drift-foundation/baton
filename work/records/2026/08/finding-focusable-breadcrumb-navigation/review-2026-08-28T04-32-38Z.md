## Findings

### [P1] Repeated Work crumbs share one focus key

**Observed:** `breadcrumb_items()` keys every Work crumb as `work:<id>`
(`src/baton_work/tui/app.py:1748`) while selection and movement recover the
position with `keys.index(...)` (`src/baton_work/tui/app.py:1828-1834`). A
dependency-graph recenter path can display the same Work more than once. For
example, recentering from sibling `alpha` to sibling `beta` produces:

```text
Jobs > root > alpha > deps > root > beta > deps
```

with `work:<root>` at both positions. Walking left from the final `deps`
produced this key sequence:

```text
page:1:links, work:<beta>, work:<root>, top:jobs, top:jobs
```

The second `root` resolves through `list.index()` to the first occurrence, so
one key press skips the earlier `deps`, `alpha`, and first `root` crumbs. Both
root tokens also satisfy the same selected-key comparison and can paint as
selected together. Direct Enter resolution likewise cannot distinguish the
two structural targets.

**Required correction:** make each displayed crumb key unique to its
structural occurrence while retaining stable identity across repaint and
resize. Add a graph-recenter regression with a repeated ancestor that checks
one-step horizontal movement, one selected token, and Enter/Back restoration
from both occurrences.

### [P1] Up/k falls through from breadcrumb focus into the body

**Observed:** `_handle_breadcrumb_key()` consumes horizontal movement, Enter,
and Down/j, but returns `False` for Up/k
(`src/baton_work/tui/app.py:1831-1840`). The generic single-body dispatcher
then forwards the key to the page handler
(`src/baton_work/tui/app.py:6379-6405`). On a contextual Jobs page with the
second row selected, Tab focused the breadcrumb; pressing `k` changed the
hidden body selection from the child to the root while
`crumb_focus` remained true.

The same fallthrough is present for search, graph, pokes, and Awaiting-me.
This contradicts the approved bounded focus graph: boundary Up enters the
breadcrumb, Down returns to the prior body focus, and breadcrumb focus owns
its navigation keys without moving the page underneath it.

**Required correction:** consume Up/k at the focused breadcrumb boundary (or
define an explicit approved transition that does not mutate hidden body
state). Cover every single-body page and both Up spellings; assert body cursor
and selected identity remain unchanged while breadcrumb focus remains active.

### [P2] Viewport fitting does not use terminal display cells

**Observed:** `breadcrumb_window()` budgets labels with `len()`
(`src/baton_work/tui/app.py:340-341`) even though the same module already
defines terminal-cell-aware `_cells()`. A six-character label
`界界界界界界` is accepted into a 10-cell window although it occupies 12
terminal cells. That can overdraw the reserved right edge or let curses clip
the supposedly whole token instead of falling back to its exact compact
selector.

**Required correction:** budget every label, separator, marker, footer
prefix, and painted column using the repository's terminal-cell semantics.
Add wide and combining-character regressions that prove the selected token is
whole, the compact selector fallback occurs, and filter/dispatch/participant
units survive.
