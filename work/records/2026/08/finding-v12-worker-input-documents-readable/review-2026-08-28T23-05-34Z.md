## [P0] A home symlink still gives two attempts the same roots

`assignment_workspace` rejects an existing home only when
`os.path.isdir(home)` is false. That predicate follows symlinks, so a home
symlink to another attempt passes. The child check then compares each entry to
`os.path.join(os.path.realpath(home), name)`. With an aliased home, both sides
are deliberately anchored under the wrong sibling and compare equal.

The additive reviewer case
`TheRuledTrustModel.test_a_colliding_home_cannot_alias_another_attempts_home`
allocates the first attempt and symlinks the second attempt's whole home to it.
The second allocation raises no refusal and returns the first attempt's roots.
This is the same accidental stale/corrupt manager state covered by ruling
M34768, and still contradicts unique per-attempt roots and exclusive collision
refusal.

Apply the no-link/exact-path structural proof to the attempt home before its
resolved location is used as the anchor for child proofs. Preserve the now-
valid child-entry checks and legitimate reopening of a real home at its own
path, plus distinct-attempt concurrency, exact cleanup/retry, sibling isolation
and all readable/read-only input behavior.
