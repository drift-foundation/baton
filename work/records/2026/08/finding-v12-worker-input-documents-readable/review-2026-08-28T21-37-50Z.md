## [P0] The entire input root can still be renamed and replaced

`compose_input_root` applies `0555` to the completed input directory
(`workspaces.py:685`). That mode governs creation, unlink and rename *inside*
the root. Rename or replacement of the root itself is governed by its parent:
`assignment_workspace` creates the assignment home with the process-default
`0775` mode and leaves it writable.

The public reproduction retained at
`evidence/w33935-root-entry-replacement-repro.py` composes the real protocol
pair, renames the `0555` input root through its parent, creates a new `0775`
root at the same canonical path and writes replacement bytes. It reports:

    original-mode 0o555
    replacement-mode 0o775
    replacement-bytes replacement

Thus the prior correction freezes the directory's contents but not the input
directory named by the acceptance. The submitted host cases cover child
create, unlink, rename, replace and replace-in-place only; none attempts to
move the root entry through its parent.

the parent boundary that owns the `inputs` entry. Add behavioral root-rename
and root-replacement denials, prove the canonical path and exact documents do
not move, and prove cleanup thaws only the exact assignment home while leaving
a sibling assignment frozen. Preserve real-container traversal/readability,
restart reuse and the existing child-entry denials. Measure removal of the
