`validateEnvelope` at
`tools/codex-event-bridge/src/codex_baton_bridge.mjs:166-168` rejects
`claimed` only when the field is present with a non-Boolean value. Absence is
accepted. The dispatcher then checks `claimed === true` at
`tools/codex-event-bridge/src/event_bridge.mjs:801-834`; absence is therefore
treated as false. `episodeVerdict` has the same dependency through the shared
validated envelope.

The additive cross-boundary regression
`a Work neighbour with no claimed verdict cannot answer that the slot is free`
constructs claimed Work A beside offered Work B, removes only A's `claimed`
field, and presents the otherwise canonical envelope to pre-turn
revalidation. Current behavior starts B's turn. The required behavior is zero
turns with B still queued: the authority answer did not establish whether A
owns the participant's one Work slot.

every field used to schedule. `participant_actions` at
`src/baton_work/projection.py:2784-2799` always emits a Boolean `claimed` for
every Work action, so omission is not a supported canonical variant. Require
the field as well as its type. The existing validator test at
`tools/codex-event-bridge/test/codex_baton_bridge.test.mjs:573-581` describes a
bare Work without `claimed` as valid. This review gives explicit case-specific
confirmation to revise that assertion: `claimed` became required when W11910
made it a scheduling input; genuinely descriptive fields may stay optional.
