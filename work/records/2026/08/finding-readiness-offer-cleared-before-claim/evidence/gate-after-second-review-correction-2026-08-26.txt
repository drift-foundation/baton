Both are defects in the claim-slot gate the previous correction added, and
both are mine.


[P1] THE CURRENT MATCHING ENTRY DECIDES, NOT THE EVENT

  The gate found the exact action key in the canonical read and then decided
  claim-slot occupancy from `event.action.claimed` — a bit that describes the
  world when the PRODUCER emitted the event, not the entry the read just
  returned. It also had no action-kind test at all. Two live states failed:

    an unclaimed offer CLAIMED while it waited in the dispatcher still said
      `claimed:false` in the queued event, so the delivery was deferred
      behind the very claim it now exists to recover;

    a non-Work obligation carries no `claimed` field, so `undefined !== true`
      read as unclaimed and the Work-only claim-slot rule swallowed it.

  Nothing had to be parsed or added to the event. The read already returns the
  exact matching action with its kind and its current claimed state:

    absent            -> over
    not a Work        -> live   (obligations, trials, pokes, refreshes keep
                                 their own rule; the one-claim WORK slot does
                                 not govern them)
    a claimed Work    -> live   (the participant's own assignment being
                                 recovered; it can never wait behind itself)
    an unclaimed Work -> deferred while any Work claim occupies the slot


[P1] ACP HAD THE SAME GAP, AND A BOOLEAN COULD NOT SAY OTHERWISE

  `episodeStillLive` answered exact-key membership only. The outer snapshot
  can admit unclaimed Work B while the slot is free; another adapter, an
  interactive turn or an operator can then claim Work A before ACP's immediate
  pre-turn read; B is still actionable, so the boolean said `true` and the
  turn was spent against a slot the authority had already given away.

  The boolean could not express the state: `false` meant the episode was over
  and withdrew the offer permanently, `true` started the turn, and a live
  offer waiting on another claim is neither. `episodeVerdict` derives the same
  three answers from one canonical envelope, and `runBridge` handles them:

    over      -> `markWithdrawn`, dropped, as before
    deferred  -> NEITHER delivery NOR withdrawal. No prompt, no
                 `markWithdrawn`, and no `markPresented` — a turn nobody spent
                 is not an attempt — so the offer is admitted again on the
                 next poll and the loop's own backoff keeps that from spinning
    live      -> the turn

  ONE DERIVATION, TWO ADAPTERS. The rule is the same sentence in both
  families, which is the point: the previous correction fixed the Codex path
  and left ACP answering a different question about the same authority.
