[P1] THE CANONICAL READ WAS THE ONE CONSUMER THAT DID NOT TYPE ITS ENVELOPE

  `EventBridge.#revalidate` accepted any reply carrying an actionable ARRAY
  and then scheduled from the matching entry's `kind` and `claimed`. A present
  array says nothing about the entries in it. An entry carrying this episode's
  Work key while claiming the `obligation` kind — a shape the contract rejects,
  because `obligation:<seq>` cannot equal `work:<id>:<ep>:g<gen>` — was read as
  an ordinary non-Work action and started a turn against an occupied slot.

  THREE CONSUMERS OF ONE ENVELOPE, AND ONLY TWO APPLIED THE CONTRACT. Both
  readiness producers have run `validateEnvelope` over exactly this command's
  output since W148; the ACP bridge revalidates through `waitOnce`, which
  validates. This dispatcher read the same envelope from the same binary and
  consumed it untyped. It applies the same contract now, at the same boundary,
  and any validation failure takes the identical bounded `uncertain` path,
  because a read that cannot be typed proves neither that the episode still
  exists nor that the claim slot is free.

  THE SECOND HALF OF THE RULING, AND IT WAS LIVE IN BOTH BRIDGES. The contract
  is deliberately liberal about kinds this build does not know: it drops them
  from the actionable set and files them under `ignored_actions` so a newer
  authority can add a primitive without breaking an older bridge. That
  tolerance is about DELIVERY. Reading the removal as withdrawal would clear a
  live level with something that is not a claim — this Work's own defect one
  layer down. An entry carrying the exact key is now `uncertain` in the Codex
  dispatcher AND in the ACP bridge's `episodeVerdict`, which had it too and
  was not named by the review.
