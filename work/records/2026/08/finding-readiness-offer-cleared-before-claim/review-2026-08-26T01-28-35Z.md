## Findings

### [P1] Codex uses the stale queued event to defer current claimed Work and non-Work actions

`EventBridge.#revalidate` finds the exact action key in the current authority
projection, but then decides claim-slot occupancy from
`event.action.claimed` (current `event_bridge.mjs` lines 717 and 738–741).
That bit describes the event when the producer emitted it, not the matching
action returned by the immediate read. The gate also has no action-kind test.

Two current states therefore fail:

1. An unclaimed Work offer becomes claimed while it waits in the dispatcher.
   Its action key is unchanged. The queued event still says `claimed:false`,
   the canonical matching entry says `claimed:true`, and the dispatcher
   defers the delivery behind the very claim it now exists to recover.
2. A non-Work obligation is live beside the participant's claimed Work. Its
   event has no `claimed` field, so `undefined !== true` and the Work-only
   claim-slot rule swallows the obligation.

The second outcome also follows structurally from `actionEvent` and
`normalizeAction`: they carry `claimed` when supplied but carry no `kind`
(`codex_baton_bridge.mjs` lines 354–361; `event_types.mjs` lines 31–69).
The dispatcher does not need to parse or extend the event key: it already has
the exact matching canonical entry, including `kind` and current `claimed`.

Required correction: after exact-key matching, use that current entry. A
matching non-Work action is live. A matching claimed Work is live as its own
recovery. Only a matching current unclaimed Work is deferred while a Work
claim occupies the slot. Keep the exact-key disappearance result as `over`.

Focused evidence:

```text
node --test-name-pattern='promoted to claimed|non-Work obligation' test/claim_slot.test.mjs
tests 2; pass 0; fail 2
- queued Work promoted to claimed: expected 1 turn, observed 0
- obligation beside claimed Work: expected 1 turn, observed 0
```

The additive cases are at
`tools/codex-event-bridge/test/claim_slot.test.mjs` lines 237–275.

### [P1] ACP's final authority read still spends a Work turn after another claim wins the slot

The ACP bridge's outer snapshot can admit unclaimed Work B while the claim
slot is free. Another adapter, an interactive turn, or an operator can then
claim Work A before ACP's immediate pre-turn read. Work B remains actionable,
so `episodeStillLive` returns true based only on exact-key membership
(`baton_readiness.mjs` lines 71–85), and `runBridge` starts B's prompt
(`acp_baton_bridge.mjs` lines 98–108 and 236–249). The authority already says
the participant holds A, but ACP spends the turn anyway.

The existing boolean cannot express the required state distinction: false
means the episode is over and permanently calls `markWithdrawn`; true starts
the turn. A live offer waiting on another claim is neither.

Required correction: derive `over` / `deferred` / `live` from the immediate
canonical envelope, as the Codex path intends to do. On `deferred`, retain the
exact offer without prompt, withdrawal, or presentation, and retry after the
slot can change. Apply this only to Work; preserve obligations, trials, pokes,
and refresh semantics.

Focused evidence:

```text
node --test-name-pattern='a claim acquired between polling and the ACP turn defers the offer' test/acp_baton_bridge.test.mjs
tests 1; pass 0; fail 1
expected: [deferred, live, prompt]
actual:   [deferred, prompt, live, prompt]
```

The additive case is at
`tools/acp-baton-bridge/test/acp_baton_bridge.test.mjs` lines 495–530.
