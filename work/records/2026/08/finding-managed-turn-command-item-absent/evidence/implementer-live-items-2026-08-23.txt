5. THE CAVEAT THAT KEEPS THIS HONEST

Both probes pin a `CODEX_HOME` with `gpt-5.6-sol` and NO provider custom tool,
and both executed through the BUILT-IN SHELL: `/bin/bash -lc '…'`.

The managed deployment's turns went through a provider `custom_tool_call
name=exec` — confirmed on the nonce probe and independently on the W7830
smoke.

SO THE EXECUTION PATH IS CONFIGURATION-DEPENDENT. A gate reading
`item/completed` would see nothing under the custom-tool configuration the
managed stack runs today. What is established is that the structured item
EXISTS and is reachable on this build — not that the managed stack as
configured emits it. That is the difference between "the gate can be built"
and "the gate passes today", and only the first is measured.

One more fact reported rather than smoothed: the command FAILED, `exitCode=1`,
under the probe's sandbox. That does not weaken the transport result — the
item carried the exact command and a truthful nonzero exit, which is what a
fail-closed oracle needs it to do — but a run whose command succeeds has not
been observed here.
