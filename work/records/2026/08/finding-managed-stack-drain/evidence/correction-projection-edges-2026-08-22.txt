1. [P2] THE HISTORY CURSOR DROPPED A CONTROL EVENT

An empty drain writes `drain_requested` and `pause_reached` at ONE authority
sequence — deliberately, because they are one commit. The reader ordered by
`seq` alone, limited ROWS, returned that sequence as `next_before` and resumed
with `seq < ?`, so a page size that bisected the pair made the second event
unreachable.

`limit` now counts INSTANTS: the page's sequences are chosen first, then every
event at those sequences is returned together, and the cursor names the last
INSTANT so the next page starts strictly below it. Sibling order inside one
instant is written out — `pause_reached` above the `drain_requested` that
caused it — rather than left to storage order, which is not an order.

An authority instant is indivisible for the reader for exactly the reason it
is indivisible in the writer.


2. [P2] DISPATCH STATUS READ TWO SNAPSHOTS

`dispatch_view` read the singleton and the live Handler rows as independent
SELECTs, so a final pass committing between them returned
`mode=draining, blocking_claims=0` — a tuple the authority never held, since
that same commit made it `paused`.

It is self-snapshotting now, and `wait_actionable` derives the action set and
the dispatch state under ONE outer reentrant snapshot. The regression
interposes the writer INSIDE the read, from a second connection, at the
blocker query — a sequential test cannot reach this.


3. [P2] AUTOMATIC PAUSE BYPASSED THE AUTHORITY CLOCK

`_settle_dispatch` called the private wall clock, so under an injected instant
the two same-sequence events disagreed: `drain_requested` at the injected time
and `pause_reached` at the host's, with the singleton inheriting the latter.
The writer now passes its own clock into settlement. Covered for the immediate
empty drain AND for a later final release, both under an injected instant.

5. ONE EXISTING TEST'S FIXTURE MOVED, AND WHY

`test_w321_readiness_cadence.py::test_an_action_committed_meanwhile_is_seen_within_one_interval`
committed its "meanwhile" Work on the SAME connection, from inside a patched
`participant_actions`. With `wait` now holding one read snapshot across both
reads, a connection in a read transaction cannot also write, so that fixture
raised rather than asserting. The commit moved to a second connection.

The assertion is unchanged — the very next read returns the new Work — and a
second writer is the more faithful "meanwhile" in any case: the point is that
somebody ELSE committed while this wait slept. The alternative would have been
to drop the one-snapshot boundary the review requires, which is not a trade
worth making for a fixture mechanism.
