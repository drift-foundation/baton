# Independent review — 2026-08-22T16:25:29Z

**Verdict:** changes requested. Claim admission and drain settlement are
serialized correctly, the finishing round remains actionable, and the
`stop-drained` divergence is the safer compatibility boundary. Three read and
audit edges prevent sign-off before deployment.

## [P2] A sequence-only history cursor drops a control event

`dispatch_events` deliberately permits two different event kinds at one
authority sequence. An empty drain proves why: `drain_requested` and
`pause_reached` are one committed instant. `dispatch_history`, however, orders
only by `seq`, limits rows rather than complete instants, returns that sequence
as `next_before`, and resumes with `WHERE seq < ?`.

When `limit=1` cuts through the empty-drain pair, the first page returns one
event and the next page excludes the shared sequence, so the other event is
unreachable. The same query also leaves the order of sibling kinds implicit.
The global audit journal is therefore complete only when callers happen to
choose a page size that does not bisect a multi-event instant.

Use a deterministic total order and a cursor capable of traversing it, or
keep authority instants indivisible by returning every event at the boundary
sequence. Add a `limit=1` traversal regression that proves both empty-drain
events are returned exactly once.

## [P2] Dispatch status does not read one authority snapshot

`dispatch_view` reads `dispatch_control` and then live Handler rows as two
independent SELECTs. It does not enter the projection module's
`_read_snapshot` context. A final pass can therefore commit between those
reads and return `mode=draining, blocking_claims=0`, even though the same
commit atomically made the canonical state `paused`. An interposed two-
connection reproduction returns exactly that impossible tuple.

`wait_actionable` compounds the boundary: `participant_actions` and
`dispatch_view` are also derived in separate snapshots. This contradicts the
pinned requirement and the implementation claim that home, status, wait and
the TUI describe one authority instant.

Make `dispatch_view` self-snapshotting for direct callers and derive the
action set plus dispatch state under one outer reentrant snapshot in `wait`.
Retain a deterministic interleaving regression; a sequential status test
cannot exercise this gap.

## [P2] Automatic pause bypasses the authority clock

Drain and resume journal timestamps use `store.clock()`, which honors the
authority's injected `BATON_WORK_NOW` instant. `_settle_dispatch` instead
calls the private wall-clock `_utc_now()` directly. For an empty drain under
an injected `2099-01-02T03:04:05Z`, the two same-sequence events currently
record `drain_requested` at the injected instant and `pause_reached` at the
host's 2026 instant; the singleton inherits the latter.

The writer-level settlement helper needs the same injected clock as the act
it is completing. Pass the transition instant or clock into settlement and
cover both immediate empty drain and a later final release under an injected
clock.
