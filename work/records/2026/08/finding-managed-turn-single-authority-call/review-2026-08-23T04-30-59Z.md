## Findings

### P1 — the live smoke gives the model contradictory instructions

`smoke/managed_baton_write.mjs` retains this thread-level developer
instruction:

```text
Perform exactly the one canonical Baton operation you are asked for and
nothing else.
```

The W7830 turn now asks for two operations. Developer instructions outrank the
turn input, so a model cannot obey both. This invalidates the current live
failure as a diagnosis of whether the agent followed the new standalone-call
rule. Replace it with a coherent contract: perform exactly the requested
canonical operations, each as its own standalone direct execution request, in
the stated order, and nothing else. Keep the literal commands in the turn.

### P1 — the readiness oracle treats nonzero execution as success

`readinessClaimOutcome` requires `status === "completed"` but never checks
`exitCode`. It therefore returns success for a read item with exit code 7 and
a claim item with exit code 0. The post-turn Handler assertion can detect a
claim that did not commit; it cannot detect a failed `detail` followed by a
successful claim, so the overall smoke can pass without proving the requested
readiness sequence succeeded.

Require `exitCode === 0` for both items after their terminal/completed checks.
Add one deterministic case for a nonzero completed read and one for a nonzero
completed claim. Preserve the exact command/order/count, agent-source and
approval checks.

## Operational findings

The implementer was right not to weaken the command-item oracle. Official
OpenAI app-server documentation says shell execution is represented by a
`commandExecution` item and that `thread/read(includeTurns=true)` returns turn
history. The observed absence remains a real incompatibility with the live
gate. It should be re-tested only after removing the prompt contradiction. If
it persists, record and route it separately, cross-referencing W2845, because
it is outside the W7830 rule/oracle correction.

The raw Python traceback is also not an acceptable typed refusal. Preserve it
as an operational finding; do not broaden sandbox authority to avoid it.
