## R82 — DEL and other non-C0 control characters pass the operation-id grammar

The accepted grammar is 1–128 UTF-8 bytes with no whitespace or control
characters. Both `_operation` and lifecycle `_op_tuple` reject `ord(ch) < 32`
plus whitespace, which admits DEL (`U+007F`, Unicode category `Cc`) and other
non-whitespace controls. The reviewer regression publishes successfully with
`bad\x7fid` when it must refuse before any operation record, event, or effect.

Use one shared exact grammar implementation for transition and lifecycle
paths, rejecting the full intended Unicode control category as well as
whitespace. Exercise both ordinary mutation and init/regen entry points so the
duplicated boundary cannot drift.

## R83 — fingerprints are computed before accepted input normalization

`_operation` fingerprints caller containers before the transition performs its
accepted normalization. For example, `create_discussion` accepts one label as
either a string or the equivalent one-element list, but an exact retry that
crosses those spellings refuses as conflicting reuse. `create_round` has the
same string-to-list normalization for verifier assignments. This contradicts
the approved semantic fingerprint over validated typed input and the promise
that API/CLI spelling does not change identity.

Normalize and validate operation input once before fingerprinting, and use the
same normalized values for optimistic validation, in-lock mutation, payload,
and retry identity. Audit every mutation for accepted shorthand/container or
other normalization; do not patch only the reviewer example. Add equivalence
and genuinely different-request cases, including source/library and packaged
CLI shapes where applicable.

## R84 — participant removal can commit between identity validation and replay

The current accepted generation is the replay disclosure boundary. The
optimistic path performs `_member`, then a separate `_op_replay` read without a
shared transaction/snapshot. The reviewer interleave commits generation 2
removing `lang.grace` between those reads; the subsequent lookup still returns
Grace's stored result instead of refusing. The replay therefore combines an
old identity observation with new authority state and violates the uniform
current-identity gate.

Make identity validation and replay lookup one coherent serializable
observation wherever replay may occur: optimistic transition lookup, in-lock
race replay, protected no-op recording/replay, regen, and existing-authority
init. A fix only in the first helper is insufficient because `_write` and
`record_noop` can return replays through their own later paths. Add both-order
config-removal races and prove an already-removed identity never receives the
stored result while a replay that linearizes before removal remains coherent.
