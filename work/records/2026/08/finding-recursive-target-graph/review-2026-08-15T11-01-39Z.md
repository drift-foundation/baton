## R69 — Work detail advertises removed Work-addressed operations

`projection.detail(...)["available_transitions"]` still returns
`post_message` and `mark_seen` for open Work. Slice B removed the
Work-addressed posting and seen functions and parser verbs; both surviving
public operations require a discussion id. The projection therefore tells an
agent it may execute operations for which no corresponding public Work
operation exists, contradicting the fail-closed bridge removal and the
projection's own promise that an agent reads what it may do rather than
discovering by attempt.

discoverability is retained or expanded, make its discussion address explicit
on a discussion projection; do not restore a Work alias. Cover direct/public
JSON and packaged behavior.

## R70 — TUI mark-seen can hide a message it never displayed

The discussion renderer reads `thread` but discards that response's
`last_seq`. When the user presses `s`, the console marks
`store.last_seq()`—a later global authority value. A message can commit to the
displayed discussion after paint and before the keypress; the mark then moves
past that unseen message and New becomes zero although its bytes never reached
the screen. The reviewer regression deterministically paints, commits the new
message, presses `s`, and observes the false clear.

Retain the displayed thread snapshot's last-message sequence and mark exactly
that value. Never derive a seen cursor from a later global read. Add the real
or model-console race regression and preserve pure viewing.

## R71 — wildcard `+` selectors that land nowhere publish silently

The pinned tag rule refuses a selector that matches no live endpoint. The
expander currently raises only when both selector components are exact, so
`ghost.*` and `*.ghost` expand to an empty set and the message commits with a
silent no-op include. This is especially misleading across a config race:
the optimistic expansion may reach endpoints, then the committing generation
may remove the last match and publish to nobody.

Apply the landing rule to every individual selector regardless of wildcard
shape, both optimistically and under the committing generation. Add exact,
team-wildcard, kind-wildcard, and generation-race cases through source and
packaged CLI; every refusal must leave the message/event/sequence untouched.
