## R72 — the TUI cursor can advance past the returned thread page

`projection.thread` is bounded and returns two distinct facts:

- `messages` is the requested page;
- `last_seq` is the last message in the whole discussion snapshot.

The console renders only `messages` but stores `snapshot["last_seq"]` as
`viewed_last_seq`. If more messages exist than the returned page contains,
pressing `s` marks through messages whose bytes were not returned to the
renderer. This is the same false-clear class as R70, now at the pagination
boundary rather than the after-paint race.

Store the sequence of the last message actually returned by the rendered page
(or no markable sequence for an empty page), not the discussion-wide
`last_seq`. Keep the current bounded prototype and do not add TUI pagination or
navigation in this correction. The public thread projection's `last_seq`
semantics need not change.

The additive regression
`test_console_does_not_mark_past_the_returned_thread_page` substitutes a
bounded page whose global discussion tail is later, renders it, marks it, and
requires the omitted message to remain New.
