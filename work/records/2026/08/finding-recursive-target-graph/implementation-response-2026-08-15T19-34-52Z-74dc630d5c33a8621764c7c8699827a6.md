## R101 — vocabulary and columns re-inventoried against the projection

The rows are **Work**; the counter is the personal, recursive,
deduplicated **`New`** (the `Unans.` counter is superseded — my
proposal wrongly revived it, and "objectives" with it). I re-read the
chronological rulings and the current projection; the Phase-2 column
set is exactly what the canonical projection already supplies per
row (`projection.home` → `_row_view`):

- `status` (+ `outcome` when closed) and `ready`;
- `title`;
- `phase` / `waiting_on` (typed);
- `progress` — direct children closed/total as supplied; no invented
  recursive roll-up;
- `dep` — the ruled count of open Work depending on this one;
- `current` and `next` endpoints (6/6 handles, never ambiguously
  truncated);
- `New` — from the supplied `new` (member-relative, subtree,
  deduplicated; `new_count` also supplies the per-child totals that
  make "jump to the unread child" honest).

No `last update`, no `blocker summary`, and no other field appears in
the TUI unless the projection already carries the ruled semantic
value; the TUI formats, it never invents or aggregates on its own.
If completing the confirmed focused view exposes a genuinely missing
semantic value, that returns for ruling before the shared projection
contract changes — it is not synthesized client-side.

## The bounded Gate B slice

1. **B1 — canonical rendering, real-PTY tested.** Home: the one-
   snapshot team summary plus the viewer's root Work table with the
   columns above. Drill: `children` tables repeating at every depth
   with the persistent `breadcrumb`. Focused Work view from
   `detail`: status/outcome/rationale, current/next endpoints,
   binding (root:path rN), effective revision, duplicate/follow-up
   links, discussions preview; `links` on demand for
   blocker/dependent neighbors; resolved children collapsed by
   default. Discussion opens within the selected Work; the explicit
   mark-seen interaction stays the ONE seen mutation. Everything
   through the versioned projection; refuse-before-curses holds.
2. **B2 — parity as the release gate.** One shared fixture through
   the JSON CLI and the TUI with semantic parity asserted for rows,
   counts, drill links, and actionable state — extending the parity
   suite to the full fixture.
3. **B3 — packaged scenario.** The ruled scenario through the
   packaged v11 artifact's TUI on a real PTY.
4. **Presentation prototypes in-slice.** Pane layout, responsive
   narrow-width behavior, sorting, and key bindings are proposed AS
   IMPLEMENTED prototypes with real-PTY evidence at the review stop,
   for reviewer disposition and human trial — no design-only phase,
   no semantic guessing.
5. Break-sweeps for every new guard; then stop: focused TUI/parity
   suites + `just test-v11` green, source+packaged evidence.
