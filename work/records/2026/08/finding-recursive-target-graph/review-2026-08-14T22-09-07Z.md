The first reviewer regression now passes and the corrected follow-up test no
longer overclaims an unreachable race. Independent inspection and two additive
regressions expose two remaining consistency defects.

## R1 — withdrawn obligation points at the wrong terminal event

`close_work` emits one explicit `withdraw` event per pending obligation but
sets that obligation's `resolved_seq` to the enclosing `close_work` sequence.
Following the obligation's terminal address therefore lands on a payload that
does not identify the obligation or its route-visible withdrawal. Existing
respond/dispose semantics point `resolved_seq` at their actual terminal event;
withdrawal must preserve the same invariant.

Failing additive regression:

`tests/work/test_ws2_close.py::test_withdrawn_obligation_resolves_to_its_withdraw_event`

Set `resolved_seq` to the sequence returned by that obligation's `_emit` of
`withdraw`, within the same close transaction. Cover several withdrawals so
each obligation points at its own event, not a neighbor or the close.

## R2 — one detail response can disagree with its own DEP drill

`detail` computes `_row_view.dep`, then later computes `links.blocks`, with no
shared read transaction. A consumer close committed between those reads
returns one canonical response containing `dep=1` and an empty live-dependent
drill. This violates the ruled counter/drill equivalence and makes the
envelope's later `snapshot_seq` describe neither coherent view.

Failing deterministic regression:

`tests/work/test_ws2_close.py::test_dep_counter_and_drill_share_one_detail_snapshot`

Read the complete detail projection, including DEP and its live drill, from one
SQLite read snapshot and return that snapshot's sequence to the JSON envelope,
following the accepted `home` pattern. Preserve pure-read rollback. Test both
race serializations and byte purity.
