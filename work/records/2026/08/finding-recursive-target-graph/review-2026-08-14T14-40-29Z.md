# Review — configuration correction C2

Date: 2026-08-14T14:40:29Z
Reviewer: `baton.reviewer`
Outcome: changes requested

The focused C2 suite passes (15 tests), and the config/authority triangle,
current-generation capability check, generation race check, and removal of
`WORK.json` are implemented in the intended boundary. Four correctness gaps
remain before C2 acceptance.

## R1 — concurrent initialization can overwrite the winner

**Confirmed.** `init_from_config` checks `work.sqlite3` for absence, builds a
temporary authority, and publishes it with `os.rename(staging, database)`.
On POSIX, rename replaces an existing destination. Two initializers can both
pass the absence check, then the second rename silently replaces the first
published authority. Publication must be an atomic **create-if-absent** step;
the loser must refuse and must not alter the winner. Add a real concurrent
initialization regression that proves one winner and byte-for-byte preservation
of that winner.

## R2 — stranding validation races authority writes

**Confirmed.** The open-Work and pending-obligation queries run before
`Authority._write` acquires `BEGIN IMMEDIATE`. A writer can create an affected
Work item or obligation after those queries and commit before acceptance takes
the write lock; acceptance then projects the removing configuration without
rechecking. Move the authoritative stranding check into the acceptance
transaction. A pre-check may remain for diagnostics, but it cannot be the
gate. Add a deterministic race regression.

## R3 — removed route names can be reused

**Confirmed.** `_project` retains removed routes with `removed=1`, but the
no-reuse check covers kinds, teams, members, and roles only. A later generation
can therefore reintroduce the same route handle with a different role or
meaning. Routes are named identities in the approved first-class route model;
include them in the historical no-reuse gate and test remove-then-reintroduce.

## R4 — the structural audit misses route-role changes

**Confirmed.** `_diff_summary` compares only each route's handler list.
Changing a route from one role to another while retaining the same handler is
not reported as `rerouted`, even though the approved audit requires structural
route changes. Compare the complete responsibility mapping (at least role plus
handlers) and add an audit regression.

## Reverification

Run the focused lifecycle suite and `just test-v11`. C3 and later correction
steps remain held until this C2 pass is accepted.
