# WS-5 design correction review — changes requested

Reviewer: `baton.reviewer`
Date: 2026-08-15
Reviewed: `WS5-DESIGN.md` post-review corrections for R76–R78

## Result

R76–R78 are substantively satisfied. Successful protected no-ops now consume
their operation identity without inventing a domain event; generation-1 init
has an explicit participant and existing-authority retry path; and the
three-shape `operation` field honestly distinguishes unprotected, committed,
and replayed calls.

Three narrow design inconsistencies remain. Implementation and product ruling
remain held until the design is internally executable.

## R79 — no-op operation records cannot use the event sequence as their page cursor

The design deliberately stores `seq NULL` for a successful no-op so dense
domain-event sequencing remains untouched. The proposed `operations --after
SEQ` listing nevertheless pages by that nullable event sequence. A no-op row
therefore has no position in the order and cannot participate honestly in
`next_after`; multiple no-op rows make this irreducible.

Give operation records their own stable, monotonically ordered cursor (or an
equivalent total ordering) and page by that cursor. Keep the nullable domain
event sequence as payload/provenance, not as the operation-history cursor. The
operation cursor must not allocate or perturb a domain-event sequence.

## R80 — the first acceptance case still asserts the withdrawn envelope

WF-12 case 1 still requires `already_committed: true`, although R78 explicitly
withdraws that field. Make all battery language assert the three-shape
`operation` contract: the first protected result is `committed`, its exact
retry is `replayed`, and the domain result plus original event sequence remain
the same.

## R81 — existing-authority init replay must state the current identity gate

The general ordering rule says a participant removed by a later accepted
generation cannot replay an old operation. The special existing-authority
`init` path says only that it performs a safe operation lookup after validating
the participant against the proposed generation-1 document. State explicitly
that an existing-authority retry first validates the participant against the
currently accepted authority as well as checking the proposed document and
fingerprint. Otherwise P6a has an init-only ambiguity exactly at the identity
boundary it is intended to make uniform.
