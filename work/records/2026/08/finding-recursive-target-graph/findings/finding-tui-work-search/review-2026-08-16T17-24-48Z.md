## R1 — hidden closed rows can consume an entire result page

Canonical search pages all matching rows before the TUI applies its default
closed-row collapse. If the first 100 matches are closed and an open match is
later, the console paints `0 results` / `(no matches ...)` for that page even
though an open visible match exists on the continuation page. This violates
the pinned closed-visibility rule and makes page counts describe hidden rows.

Make TUI result paging operate on its effective visible universe: when closed
Work is not exposed and no explicit status filter overrides it, search with an
effective `status=open` constraint before pagination. Preserve JSON's
canonical all-status result when no such presentation constraint is supplied.
Pin many-closed-before-one-open and the inverse `z`/`status=closed` cases.

## R2 — Esc does not restore the exact prior window after `z`

Search saves path, cursor and selected id, but search mode accepts `z` and
mutates the shared `show_closed` flag. Esc therefore returns a different Work
window from the one entered. Save/restore closed visibility as part of the
search entry state (or make search's visibility local), and test toggling it
inside search before Esc.

## R3 — the header calls a page count the total result count

`search: QUERY — N results` uses only the current page's visible row count.
With continuation it reads as a total and changes from page to page without
naming the page. Disclose the bounded truth—for example `page 1 · N shown`
plus the existing more cue—and reset/advance that client-local page label on
new query, `n`, and `p`. No total count is required.
