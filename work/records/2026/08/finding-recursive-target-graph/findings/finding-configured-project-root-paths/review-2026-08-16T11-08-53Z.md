# Review — W4 single configured root source

The implementation correctly makes `base` a required strict field of each
`baton.json` root, removes the sibling resolver seed/file and public
`--roots-file` surface, updates init/deployment assets, and exercises accepted
configuration, relocation by regen, filesystem containment, packaged use and
retired-flag refusal. The reported 634 parallel plus 3 serial gate is green.
This pass is not signed off because the implementation contradicts the pinned
schema boundary and leaves two current-facing inconsistencies.

## R1 — W4 changes SQLite schema under the already-named schema version 15

**Blocking architecture contradiction.** The W4 scheduling decision explicitly
states that this correction does not require a SQLite schema change. The patch
nevertheless adds a required `base` column to `CREATE TABLE roots`, persists it
through `_project()`, and resolves from that row.

That is not merely unnecessary persistence. Commit `6fe32fd` already names its
mailbox format schema 15. A database created by that commit has schema version
15 without `roots.base`; the proposed reader also calls itself schema 15 but
expects the column. It can accept the version check and then fail structurally.
One schema version must not describe two table shapes, even if the operator has
not deployed the earlier checkpoint.

Keep the explicit base in the one accepted `baton.json`, but do not add it to
SQLite. The ordinary open already validates the file's exact accepted digest;
make the same validated document/base available to root-consuming clients
without a second unbound read or TOCTOU window. `roots` authority rows retain
their existing portable catalog shape. Relocation remains a generation+1
regen because it changes the accepted configuration bytes, not because an
absolute path becomes persisted authority data. If persistence or a new
mailbox shape is genuinely desired instead, stop for a human supersession and
a distinct schema version; do not silently redefine 15.

## R2 — the shipped resolve example places global options after the verb

**Blocking operator defect.** `docs/BATON-WORK.md` now shows:

```text
$BW resolve ROOT:path --config ... --participant ...
```

The argparse surface declares `--config` and `--participant` globally; they
must precede the subcommand. The bootstrap example immediately below uses the
correct order. Make the resolve example executable as written and pin the
current quickstart command surface rather than publishing a command that the
renamed product refuses.

## R3 — `project.py` still documents the removed resolver/non-authority model

**Blocking contract/documentation drift.** The module header still says
project roots are “resolver-selected,” that nothing in the module reads
authority state, and that the machine-local resolver is never persisted or
fingerprinted. The new `store_root_base()` does the opposite. Nearby release
asset comments now contain a dangling “and / ride every distribution” fragment
and blank tuple entries left by mechanical deletion.

Rewrite the live module contract around the accepted single configuration and
clean the dead fragments. Once R1 is corrected, the accurate statement is that
filesystem writes remain outside authority while root selection comes from the
same already-validated accepted document.
