## Finding R1 — `status=closed` selects rows that the TUI then hides

`projection.tree(..., work_filter={"status": "closed"})` correctly returns
the matching closed rows, but `Console.visible_rows()` subsequently applies
the default closed-row collapse and removes them. A launched or interactive
TUI filtered explicitly to `status=closed` can therefore paint no matching
Work even while JSON returns it. That breaks the approved shared JSON/TUI
semantics and makes the filter appear ineffective.

An explicit `status=closed` filter must reveal its matching closed rows. Keep
the ordinary default collapse when no status filter requests closed Work. Add
wide/narrow PTY coverage, including a closed child retained below a
nonmatching open context parent, so the correction does not discard the
approved containment shape.

## Finding R2 — current clauses are displayed, not exposed for editing

The approved interaction says entering `filter` exposes the full current
clauses **for editing**. `_render_table()` shows the clauses and the command
bar renders them as a dim hint, but the editable command buffer remains only
`filter`. The operator must retype every clause; pressing Enter clears the
filter. The hint can also be truncated and cannot be navigated or changed.

Preserve bare `:filter` + Enter as clear. Provide an explicit editing path in
the command bar—for example, the first space after exact `filter` may seed the
buffer with the normalized current clauses—then prove a clause can be edited
without reconstructing the rest. The resulting replacement must remain
atomic, parser-owned and client-local.
