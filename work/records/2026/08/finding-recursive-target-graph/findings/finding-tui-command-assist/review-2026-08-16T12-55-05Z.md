# Review — W14 context-sensitive command-bar assistance

The first implementation establishes the basic presentation path: verb-prefix
matching, ordinary remaining required/optional keys, closed-value prefix
narrowing, dim right-side rendering, and yielding the hint when the row is
tight. It reads `cli.GRAMMAR`, opens no authority itself, and the focused W13+
W14 13-test target passes. The review is not yet clean because several pinned
assist states and the visible-input contract are unimplemented or unproven.

## R1 — assistance does not parse the command language it describes

**Blocking grammar-parity gap.** `assist_text()` uses `text.split()` and then
its own supplied/required logic. Quoted values containing spaces become
separate fake tokens, incomplete quotes cannot be represented honestly, and
the identity comparison `token is not last_open` is an unsafe way to select
completed tokens. Although the function reads `GRAMMAR`, it independently
reimplements only a subset of its interpretation and can therefore drift from
the parser.

Provide one pure partial-command tokenizer/analyzer owned with the CLI grammar
and consumed by the TUI. It must preserve the same first-`=` and shell-quoting
rules for completed tokens while tolerating an incomplete final token during
typing. Do not execute or open authority state. Use positions/slices, not
object identity, to distinguish the live final token.

Add pure and PTY cases for quoted spaces, embedded `=`, reordered keys, and an
open/incomplete quote. Assistance must remain useful and must never invent a
key from text inside a quoted value.

## R2 — conditional and invalid states are missing

**Blocking state-model gap.** W13's authoritative specification now includes
accept, phase, say, and close form conditions, but assistance considers only
unconditional `required` flags plus accept's `exactly-one` heading. For
example, after `accept create=true`, `kind=`, `title=`, and `classification=`
are still presented as optional; after `phase to=parked`, `reason=` is not
promoted to required; and the say carrier conditions are invisible.

Derive effective remaining required/optional keys and condition guidance from
the same declarative condition model the parser enforces. Cover accept's two
forms, parked/waiting phase requirements, say's exclusive/carrier/pass fields,
and close's duplicate outcome constraint.

The plan also explicitly requires invalid-token, unknown-key, and duplicate-
key assist states. Present a concise diagnostic from the shared analyzer
instead of silently continuing with a plausible-looking ordinary hint. Cover
malformed, unknown, duplicate-singular, and repeated-repeatable cases; the
repeatable case remains valid and available.

## R3 — the visible input and caret contract is not implemented

**Blocking TUI/UX gap.** The console hides the cursor at startup and never
shows or positions it while the command bar is active. The ruled visible caret
therefore does not exist. The typed buffer is painted with `addnstr(...,
width - 1)`, so input longer than the terminal is clipped from the right—the
active insertion point becomes invisible. The 44-column regression does not
exercise this: its entire test string is only 41 cells, and its assertion
would accept a 43-cell prefix anyway.

While command entry is active, show the cursor and place it at the insertion
point. When the command bar closes, restore the normal hidden-cursor mode. For
an input longer than the available row, preserve the complete buffer and render
an explicit horizontal viewport (with a left-clipped marker) that keeps the
insertion point visible; the assist yields entirely. Account for resize by
recomputing the viewport without changing the buffer.

Add real-terminal evidence for cursor visibility and placement, actual
over-width input with a visible tail/clipping marker, wide-to-narrow resize,
and Esc cancellation restoring the prior view without executing, marking seen,
or changing authority bytes.

After correction, rerun the focused W13/W14 target and `just test-v11`, because
the shared partial analyzer and curses cursor/viewport behavior have broad
command-bar reach. Reconcile the seven-row recreation proof after the final
implementation. W14 remains active and excluded from fresh-authority
recreation pending sign-off.
