# Review: W81 contextual `say` prefill

Independent review by `baton.codex`. No implementation or repository test file
was edited during this pass; the two reproductions ran from `/tmp` against
scratch authorities.

## Result

**Changes requested.** The ordinary selected-Thread seed, snapshot, purity,
assist, explicit-operand, and packaged paths are well covered, but two
integration boundaries delete or invent the destination.

## R1 — body text containing `thread=` deletes the real seed

`_reconcile_say_seed` uses `self.command.count("thread=") > 1` to decide that
the user supplied an explicit destination. That count is not operand-aware.
The sequence:

    :say body="diagnostic contains thread=value"

produces:

    say body="diagnostic contains thread=value"

instead of retaining the selected destination:

    say thread=T2 body="diagnostic contains thread=value"

The quoted text is a body value, not a second `thread=` operand. Removing the
seed silently changes a valid contextual reply into a command with no
destination. Detect an explicit `thread=` only as a real key-value operand
outside quoted values; arbitrary subject/body text must never displace it.

Add focused coverage for single- and double-quoted values, escaped quotes,
multiple occurrences in a value, and a genuine explicit `thread=` following
such a value. The incomplete command editor must continue to behave safely
while quotes are still open.

## R2 — Events seeds a hidden retained Thread

`_selected_thread_selector` checks detail mode and the retained Thread cursor,
but not the active detail tab. After switching to Events, typing exact `say`
still produces `say thread=T2 ` even though the visible context contains no
selected Thread. This contradicts the confirmed “reply where I am reading”
and “does nothing without one unambiguous selected Thread” boundary.

Require the Messages tab as well as a visible selected Thread before seeding.
Switching to Events after a seed remains snapshot-safe and must not retarget or
erase the existing buffer; starting `say` while Events is active must not
invent a destination. Cover both directions explicitly.

## Verification note

concurrent W159 implementation temporarily breaks W81's final delivery test by
reading its new `carrying` local before assignment; that moving-tree failure is
not attributed to W81 and was excluded from this disposition.
