## R3 — escaped whitespace inside a value is treated as an operand boundary

The command bar executes with `shlex.split`, but `_operand_starts` implements a
second partial tokenizer. It treats every whitespace character as a token
boundary even when that whitespace is escaped. For example:

```text
say thread=T2 body=diagnostic\ thread=value
```

is tokenized for execution as three tokens; the final token is the single body
operand `body=diagnostic thread=value`. `_operand_starts`, however, returns two
`thread=` positions (`[4, 31]`). `_reconcile_say_seed` consequently removes the
real `thread=T2` seed, silently changing a contextual reply into a command with
no destination.

The independent regression fails deterministically:

```text
assert Console._operand_starts(command, "thread=") == [4]
E assert [4, 31] == [4]
```

Do not extend a separate approximate lexer one escape case at a time. Reuse the
command grammar's partial `shlex` interpretation (or one shared equivalent) so
explicit-operand detection and execution cannot disagree about quotes,
backslashes, escaped whitespace, or escaped token characters. Add positive and
negative regressions for escaped whitespace and an escaped spelling that
`shlex` resolves to a genuine `thread=` operand.
