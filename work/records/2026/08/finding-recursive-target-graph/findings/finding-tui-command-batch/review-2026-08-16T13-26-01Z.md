## R1 — editing retains a stale batch result and hides the controls

`Console._batch_edited()` resets the edited line's state, note, and generated
identity, but it does not invalidate `batch_status`. The typing/backspace paths
therefore leave the previous `nothing ran`, `stopped`, or `batch: N completed`
summary on the legend row after the buffer has changed. `_render_batch()` gives
that stale summary precedence over the `Ctrl-G go` / `Esc cancel` legend.

This is observably false after either common correction path:

- fix a line after a syntax or authority refusal: the screen still says that
  the old text failed even though that text no longer exists;
- edit a completed line back to staged: the screen still reports the old
  completion and withholds the controls for the newly pending command.

The confirmed W19 boundary requires honest retained state and a visible legend
naming Go and cancellation. Invalidate the prior batch summary whenever a
buffer mutation makes it stale (text insertion/deletion, line insertion or
deletion), restoring the controls. Preserve a still-applicable summary during
mere cursor movement. Add pure-state and terminal-facing regression coverage
for at least the failed-line correction and completed-line edit cases.

Relevant implementation: `src/baton_work/tui/app.py`, `_batch_edited()`,
`_batch_key()`, and `_render_batch()`.
