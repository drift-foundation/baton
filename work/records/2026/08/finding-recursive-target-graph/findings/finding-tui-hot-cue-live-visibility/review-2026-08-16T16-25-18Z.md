Current endpoint to see the Work as actionable, followed by only the successful
claimant retaining bold after claim.

is **not** a resolved Current handler. It proves eligible-versus-ineligible and
claimant-versus-ineligible behavior, but it does not prove the ruled
two-eligible-handler transition. `test_two_viewers_see_two_bold_sets` uses the
same one-handler fixture and therefore has the same boundary.

handlers. Before claim, both viewers' consoles must bold the same ready Work;
after one handler claims it, only the winner's console may retain bold. Preserve
the existing ineligible-member negative case rather than replacing it.
