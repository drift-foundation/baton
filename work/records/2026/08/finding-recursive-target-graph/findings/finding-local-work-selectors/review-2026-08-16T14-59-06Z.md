# Review — W4 authority-local Work selectors

## Disposition

Changes requested.

The resolver, Work-valued command normalization, canonical/short retry parity,
JSON `local_id`, command-bar path, and ordinary Id-column rendering agree with
the pinned contract. Two responsive-layout defects remain at the exact point
where a variable-width, non-truncating Id column meets visibility and the
minimum table budget.

## R1 — hidden terminal Work incorrectly widens the visible Id column

`Console._render_table` computes `id_width` from every supplied row before it
removes collapsed closed rows. A hidden `W100000` therefore consumes visible
Title space and may drop other columns even though `z` has not exposed that
row.

The Id width must be computed from the rows actually painted in the current
view. When `z` exposes closed rows they participate normally; while collapsed
they must not affect the table.

Regression:
`tests/work/test_w4_selectors.py::test_a_hidden_closed_id_does_not_widen_the_visible_table`

## R2 — overwide visible identity bypasses the narrow-table refusal

The layout-fit calculation does not include the dynamic Id width. At 44
columns, a synthetic but valid future `W1000000000` row is painted and curses
clips the mandatory tail instead of using the existing explicit `terminal too
narrow` state. Identity remains whole, but the rest of the row silently stops
being truthful.

The minimum-width/refusal calculation must include the visible Id column. If
Id plus the minimum Title and mandatory fields do not fit, refuse the table
before painting any Work row.

Regression:
`tests/work/test_w4_selectors.py::test_an_overwide_visible_id_refuses_before_columns_are_clipped`
