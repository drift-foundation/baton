## R1 — destination phase is absent from pass retry identity

`post_thread` accepts `pass_phase` as typed semantic input, but the protected
`_operation(..., "post", ...)` fingerprint omits it. Consequently, after one
protected pass commits, an invocation with the same participant and operation
id but a different explicit destination phase can replay the first result
instead of refusing the changed operation. This violates the effectively-once
contract and can tell a caller that a phase choice committed when it did not.

Include `pass_phase` in the typed-input fingerprint. Cover both boundaries:
the exact same pass and phase replays one event, while the same operation id
with only the explicit phase changed refuses as an operation conflict and
leaves state unchanged.

## R2 — canonical transition discovery never advertises `claim`

`claim` is a public mutation and `detail.active` projects its result, but
`projection.detail(...)["available_transitions"]` never includes `claim`.
The canonical JSON surface therefore tells an eligible ready handler that the
operation is unavailable, forcing agents to discover it by attempting it.
This contradicts the existing availability contract and the approved JSON/TUI
parity requirement.

Advertise `claim` exactly when the viewer is the resolved Current handler and
the Work is open, ready, not waiting/parked, and unclaimed. Keep the writer as
the final authority. Add positive and negative projection tests for ready,
blocked, already-claimed, waiting/parked, outsider, and closed Work, plus a
focused CLI/JSON proof that the public verb reaches the same transition.
