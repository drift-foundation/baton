## R1 — explicit claimant recovery/release is absent

The confirmed finding requires explicit recovery to release a claimant, and
PLAN item 6 explicitly requires recovery coverage. The implementation has no
public recovery or release mutation: a claimant can disappear while the Work
remains open, ready, and permanently claimed unless somebody changes unrelated
workflow state by passing, parking, waiting, or closing it. Those transitions
must not be used as a substitute for recovering an abandoned execution claim.

The authority boundary still needs a ruling before implementation: who may
recover another participant's claim, whether the operation must compare-and-
swap against the expected claimant, and what durable rationale is required.
Once ruled, implement an explicit effectively-once release/recovery operation
that changes claimant identity only, preserves phase/Current/readiness, is
advertised canonically, and covers self-release, authorized forced recovery,
stale/mismatched claimant, race, retry, and unauthorized attempts.

## R2 — the waiting release branch is not tested

`test_entering_waiting_or_parked_releases_the_claim` exercises parked and
terminal close, but never enters `waiting`. Add the missing condition-bound
waiting case and assert both claimant release and the recoverable event
payload. Keep parked and close as their own named boundaries so test names do
not claim coverage they do not provide.
