## R1 — an unclaimed late gate leaves non-runnable Work queued

`_recompute_ready()` moves a row to `waiting` only when it releases a Handler.
Adding a dependency to already-unclaimed `queued` Work therefore commits
`phase=queued`, `ready=false`, `wait_type=null`. That contradicts W38's closed
definition of queued as runnable.

The additive regression
`test_a_gate_on_unclaimed_queued_work_moves_it_to_waiting` currently fails with:

```text
('queued', None, None) != ('waiting', None, 'gates')
```

Derive the unclaimed state whenever readiness changes, not only when a claimant
happens to be released.

## R2 — resuming parked Work can lie about readiness

`set_phase(..., phase="queued")` writes queued directly. If a dependency was
added while Work was parked, the resume commits queued plus `ready=false`.
Leaving a deliberate park must reveal the scheduler state beneath it:
`waiting/gates` while gates remain, queued only when runnable.

The additive regression
`test_unparking_gated_work_reveals_waiting_not_queued` exposes the same
contradiction.

## R3 — resolving one condition ignores another live gate

`_sweep_wakes()` treats satisfaction of the condition stored in `wait_type` as
satisfaction of the whole scheduler condition. Work can wait on a directed
obligation and acquire an independent dependency. Resolving the obligation
currently wakes it to queued, clears the wait condition, and mints an episode
while the dependency remains open.

The confirmed compound-wait rule is now pinned in `FINDING.md`. The additive
regression
`test_resolving_one_wait_condition_does_not_ignore_an_open_gate` requires the
row to remain waiting, retargeted to `wait_type=gates`, until the last gate
closes. Ensure only the genuine false-to-true readiness transition mints the
actionable episode.
