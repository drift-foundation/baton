# Review — W108 active ownership

## Result

Changes requested. This delivery implements the matrix that was superseded
while implementation was in flight. The test gate is green for that older
model, but the model contradicts the later confirmed decisions already pinned
in this finding.

## R1 — claimant identity is still conflated with phase

`phase --to active` currently acquires the claimant, every phase change away
from `active` releases it, and policy tells agents to enter phase `active`
before any implementation or review. The confirmed model makes claimant
identity orthogonal to phase: a reviewer must be claimable while phase is
`review`, and independent review/implementation Work must be active
concurrently.

Provide one explicit atomic claim operation. It records claimant identity but
does not change phase. `set_phase` must not generally acquire or release a
claim; only entry into explicit waiting/parked states releases it. Cover a
review-phase claimant, an implementation-phase claimant on independent Work,
and both claims coexisting.

## R2 — pass carries the obsolete queued/waiting phase rule

`post_thread` currently clears the claimant and derives phase `queued` or
`waiting` from gates. The confirmed handoff atomically changes Current and an
explicit destination phase: implementer to reviewer means phase `review`.
Readiness remains separate, so blocked review Work stays phase `review` but
cannot be claimed.

Make every pass name and commit its destination phase with Current. Release
the sender and never claim the recipient. Do not infer `waiting` from a gate
or use `queued` as a generic handoff phase. Add implementer-to-reviewer,
reviewer-to-implementer, blocked-review, retry, and race coverage.

## R3 — late gates rewrite phase instead of only invalidating execution

`_recompute_ready` currently demotes claimed Work to phase `waiting` when a
gate arrives. Preserve its honest work stage, set readiness false, and release
the claimant atomically. The causing event may carry that release; a separate
audit row is not required, but its payload/projection must make the released
claimant recoverable evidence.

## R4 — live coordination did not follow the policy being implemented

W108 remained Current `baton.impl`, phase `review`, while implementation and
testing occurred. It was never marked active before the completed handoff.
This is the exact ambiguity W108 exists to remove. Update the trial Work
honestly during the correction cycle, and keep the repository policy strict:
no implementation, review, or testing begins before a successful claim.
