# Review — W13 key/value command grammar

The parser replacement is directionally correct: CLI and TUI now share one
strict first-`=` tokenizer, operation operands use the ruled key/value dialect,
repeatable values append in occurrence order, and the focused five-test target
passes. The review is not yet clean because the purported shared declarative
specification cannot express the contract already required by W13 and its W14
consumer.

## R1 — the command specification is not complete enough to be authoritative

**Blocking contract gap.** `_key()` records only name, destination, required,
repeatability, primitive conversion, and default. It records no help text,
closed value vocabulary, mutual exclusion, or conditional form. Consequently
W14 cannot derive its ruled required/optional help and closed-value suggestions
from this specification; those truths remain hidden in `_dispatch()` and the
transition layer.

The omissions are already observable in W13 itself. Direct `create` requires a
concrete `classification`, but the grammar marks it optional. `close` requires
`rationale` and `outcome`, while the grammar marks both optional. `bind` and
`revise` likewise leave their required contract operands optional. `accept`
has exactly one of `into=` or `create=true`, with creation-only required keys,
but the specification cannot describe that form. Closed vocabularies such as
classification, phase, outcome, assessment, and disposition also cannot drive
generated validation or assistance.

Extend the one declarative specification so it carries the public grammar and
help metadata W13 step 1 and W14 require: descriptions, required and repeatable
keys, closed vocabularies, and alternative/conditional forms. Enforce
grammar-level missing keys, invalid closed values, and incompatible forms
before authority access. Retain transition-layer validation as defense for
non-CLI/internal callers; the declarative surface must not become the only
semantic guard.

## R2 — public CLI discovery regressed with argparse removal

**Blocking interface gap.** `baton --help` now refuses as an unknown launcher
option, and there is no generated command/parameter discovery surface. The
next W14 slice adds TUI assistance, but that does not replace standalone CLI
discovery for humans or scripts. Generate CLI help/discovery from the same
declarative specification, so it cannot become a second hand-maintained
grammar. If the exact operation-help spelling needs a product ruling, return
one narrow proposed syntax rather than inventing a parallel dialect.

Preserve conventional launcher option compatibility before the verb:
`--config PATH` and argparse's existing `--config=PATH` form (likewise for the
other two launcher keys), with duplicate globals refused instead of silently
overwritten. Operation flags after the verb remain retired as ruled.

## R3 — current public wording still exposes the retired interface

**Blocking consistency gap.** Sweep current source, errors, comments, and
operator documentation while preserving historical evidence and the internal
Python package name. At minimum:

- `src/baton_work/cli.py` still identifies the executable as `baton-work` and
  says "JSON in flags";
- TUI refresh validation reports `tui --refresh` instead of `refresh=`;
- accept refusals still instruct `--create`, `--kind`, and `--title`;
- the TUI safety comment still describes argparse option abbreviations even
  though argparse is gone; and
- current documentation still presents `baton-work` as the public product.

Also remove the duplicate `token.partition("=")` assignment in the parser.

## R4 — focused evidence does not yet prove several ruled boundaries

**Blocking regression gaps.** Strengthen the W13 target as follows:

1. Prove parser refusal occurs before authority access by guarding or
   monkeypatching `lifecycle.open_bound`; an unchanged event sequence alone
   permits an authority open followed by a semantic refusal.
2. Replace the repeatable-order assertion with a non-tautological assertion on
   the parsed or durably projected ordered values.
3. Drive the TUI command bar with quoted spaces and embedded `=` and read the
   exact stored values back through JSON.
4. Pin declarative-spec completeness and generated help/spec parity, including
   closed values and alternative/conditional forms.
5. Cover both conventional launcher value forms, unknown and duplicate
   globals, and the retained generated help surface.

Because the correction changes the shared parser and its public matrix, rerun
the focused target and the complete v11 gate before returning W13. Reconcile
the fresh-authority recreation proof again after the final implementation.
