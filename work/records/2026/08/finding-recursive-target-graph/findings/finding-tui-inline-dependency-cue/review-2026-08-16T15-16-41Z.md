# Review — W39 inline dependency cue

## Disposition

Changes requested.

The visible behavior agrees with the ruling: the Unicode `← Wn` / `← Wn +N`
cue names live blockers, containment retains its separate `↳` marker, satisfied
edges disappear, `Ready` is removed, narrow layouts omit the cue whole, and
`[b] deps` remains the complete graph view. The seven submitted focused tests
pass.

## R1 — first-blocker projection is an N+1 authority read

The finding and plan explicitly require the list projection to obtain blocker
selectors without an extra per-row authority read. `_row_view` currently runs:

```text
SELECT work.id FROM edges JOIN work ...
WHERE edges.work=? ... ORDER BY work.created_seq LIMIT 1
```

once for every projected row. A 16-row tree therefore executes that selector
query 16 times. Calling this “one snapshot” is true about consistency but does
not satisfy the separate no-N+1 boundary.

Fetch the current tree window's deterministic first-open-blocker summaries in
one batch and supply them to row construction. Detail/one-row projection may
use the same helper, but growing the visible tree must not grow selector-query
count. Preserve one read snapshot, blocker ordering, satisfied-edge removal,
and JSON/TUI parity.

Additive regression:
`tests/work/test_w39_dependency_cue.py::test_the_tree_fetches_blocker_selectors_in_one_batch`
