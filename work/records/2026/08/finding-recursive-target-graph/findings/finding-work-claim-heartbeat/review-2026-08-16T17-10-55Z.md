## R1 — `available_transitions` omits the claimant heartbeat

`detail()` advertises `release` to any resolved handler while a claim exists,
but never advertises `heartbeat`. This contradicts the canonical discovery
contract: agents should not discover a public transition by attempting it.
Advertise `heartbeat` exactly when the viewer is the recorded active
`team.member`—stricter than the route-handler test—and pin the positive exact
claimant plus negative teammate/other-team/unclaimed/closed cases.

## R2 — one `detail` read performs the journal lookup twice

`_row_view()` independently evaluates `_claimed_ats(store, [row["id"]])` for
`claimed_at` and again for `heartbeat_at` whenever its caller did not supply a
map. `home`/`tree` pass a batched map, but `detail` does not, so the same
claim/heartbeat statement runs twice for one Work. Resolve the tuple once per
row (or have every caller pass one map) and add a trace regression for
`detail`, not only `tree`.

## R3 — the new JSON shape still identifies itself as projection 4.1

`heartbeat_at` is a new canonical row field, but `jsonapi.PROJECTION_VERSION`
and its 4.1 field inventory still describe only priority/change identity.
Advance the additive minor version and update the inventory/tests so clients
can identify the first projection that carries heartbeat evidence. The major
remains compatible.

## R4 — the claimed writer-race proof is sequential

`test_only_the_exact_claimant_beats` releases the claim completely and only
then invokes heartbeat. That proves the ordinary stale call, not the stated
two-writer race. Add a two-connection/interleaved test proving whichever
transaction wins: a committed heartbeat followed by release is retained only
as history, while a release winning first makes heartbeat refuse without an
event or burned operation effect. At least one other automatic release path
(pass, waiting/parked entry, or close) should prove the same live projection
clearing rule.

## R5 — the test named “stale suffix paints” paints only a healthy cell

`test_the_stale_suffix_paints_and_narrow_omits_whole` renders immediately
after claim, strips the trailing healthy space, and accepts `:00`/`:01`; it
never advances the renderer's clock to six minutes and never observes `!` on
the table. Inject/patch the paint clock at 359/360 seconds and assert the
actual row cell changes from reserved blank to `!`, while narrow omission
still drops the whole field.
