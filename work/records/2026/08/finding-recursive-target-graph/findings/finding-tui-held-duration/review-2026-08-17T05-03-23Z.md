## R1 — canonical tree projection reintroduces a per-row handoff query

`home`, `search`, and `children` batch `_handoffs` for their complete windows,
but `projection.tree` does not. It builds the whole root/child window and then
calls `_row_view` without a `handoffs` map, so `_row_view` executes
`_handoffs(store, [row_id])` once per visible row. The TUI consumes this tree;
growing its visible Work set therefore grows authority reads, contrary to the
pinned no-N+1 boundary and W226 plan.

Batch `_handoffs` once for the tree's full `ids` set and pass that map to every
row, just like `_first_open_blockers` and `_claimed_ats`. Add a query-count
regression whose handoff-query count stays constant as the tree grows.

Also sample the derivation clock once per canonical response/window and pass
that instant into row projection. Calling `store.clock()` independently in
each `_row_view` can make otherwise identical rows disagree at the six-minute
boundary inside one snapshot.

## R2 — terminal Work projects a live pickup alarm

`_pickup_state` considers only claimant and handoff facts. Closing Work clears
the claimant but preserves the last handoff event, so canonical JSON projects
the closed row as `pending` or eventually `overdue`. The TUI hides that error
with its separate `status == closed` checks, but agents consume the structured
JSON and would see a pickup obligation that cannot exist on terminal Work.

Make terminal Work project a non-actionable pickup state (`null`), while
retaining `handoff_at` as history. Add a regression that closes handed-off
Work, advances beyond six minutes, and asserts `pickup is None` in both detail
and a window projection. No lifecycle mutation or history deletion is wanted.
