## R1 — a later clipped message is unreachable

**Navigation defect.** `paint_messages()` returns `next_skip=None` when one or
more complete messages painted but a later whole block did not fit. The detail
view then infers `viewed_has_more` only from an oversized first-message
continuation, the canonical page cursor, or `len(messages) == limit`. In the
ordinary case where two messages were fetched, the first fits and the second
does not, none of those predicates is true. The footer does not disclose more
content and `n` does nothing, so the later message cannot be read.

The painter/result must distinguish “all fetched messages were fully painted”
from “a later fetched block remains below.” `n` must advance from the last
fully painted message (or otherwise retain an honest continuation) whenever
unpainted fetched content exists. The visible more-state and the accepted key
must derive from that same fact. Do not mark the clipped message seen.

## R2 — unfolding the current root corrupts the back stack

**Navigation-state defect.** Every `u` appends the selected id to `path`, even
when that Work is already the current root. Repeating `u` therefore records
the same logical unfold twice; one Esc removes only one duplicate and leaves
the operator rooted where they started. The breadcrumb text happens to hide
the duplicate because it is reconstructed from authority ancestry, making the
extra required Back especially surprising.

Re-rooting at the current root must be idempotent. One logical unfold must
require exactly one Back/Esc to reverse. This does not require a new rule for
`u` on an ordinary leaf.

Added regression:

```text
tests/work/test_w71_navigation.py::test_unfolding_the_current_root_is_idempotent
```

It fails because one Esc still paints `the root` instead of returning to the
identity-led home view.

## R3 — the painted tree is not one canonical snapshot

**Projection/parity defect.** `Console.view()` composes one `home()` result
with a separate `children()` read for every root; a re-rooted view separately
composes `detail()`, `team_summary()`, and `children()`. A writer may commit
between any of those reads. The screen can therefore mix roots/summary from
one authority sequence with children from another. `children()` itself also
does not hold `_row_view()`'s multiple reads inside one read transaction.

The parity test repeats the same composition through separate JSON commands,
so it proves value agreement only when nothing races; it does not provide one
JSON result or one snapshot token for the tree an agent is meant to navigate.
This contradicts the canonical read model's one-snapshot contract and W71's
JSON/TUI-parity gate.

Provide one canonical bounded tree-window projection for roots plus immediate
children (and for a supplied re-root), with its summary and snapshot token
derived under one read transaction. Both JSON and TUI must consume that same
result. Add a deterministic interleaving regression showing that a commit
between internal row reads cannot produce a mixed tree.
