# Review: W27 round two

## Outcome

Changes requested. R1 is corrected for a bridge that starts in `new` mode: the
run creates once, publishes create-only once, and a replacement agent process
loads the retained id without rewriting the selection. The identity-bearing
recovery and missing-load-capability tests cover that path.

## R2 — configured load rereads the selection after process failure

For `session.mode=load`, `runSelection.published` remains false and
`runSelection.sessionId` remains null. Every replacement `AcpAgentSession`
therefore calls `readConfiguredSelection()` again. If `session.json` changes
while the bridge is running, an agent-process rebuild can load a different
session even though one bridge run must retain one continuity context.

Required correction:

1. Resolve and validate a configured-load selection once per bridge run,
   before Baton wait and agent spawn, and retain that exact id in run state.
2. Every first or replacement agent process loads the retained id; no rebuild
   rereads the file to choose its session.
3. Missing, malformed, or unreadable configured-load state fails immediately
   at bridge startup, with zero Baton polls and zero agent events.
4. Add a regression that starts a load run on session A, changes the file to B
   after the first agent-process failure, and proves the replacement still
   loads A. The bridge must not rewrite the externally changed file.

The accepted repeated-bootstrap guard, create-only publication, and corrected
`new`-run recovery remain unchanged.
