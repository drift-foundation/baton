## Disposition

Changes requested. The threadless Work-event boundary is implemented cleanly,
but moving the old transfer logic exposed an active-claim authorization hole
on shared routes.

## R1 — another route handler can transfer underneath the claimant

`pass_work()` rechecks live Current-route membership in the committing
transaction, but its live row omits `active_team` / `active_member`. It then
unconditionally clears the active claim while transferring Current and phase.

On a route with handlers Ada and Grace:

1. Ada claims the Work.
2. Grace remains an eligible handler of the same Current endpoint but is not
   the active executor.
3. Grace calls `pass`.
4. The operation succeeds, transfers the Work and silently clears Ada's claim.

That bypasses the explicit claimant-recovery protocol and violates the active
claim's purpose: route eligibility does not grant permission to move Work
underneath another recorded executor.

The additive regression
`test_another_route_handler_cannot_pass_the_claimants_work` in
`tests/work/test_w171_threadless_pass.py` constructs a real two-handler route.
It currently fails because Grace's pass exits successfully instead of refusing.

Required correction:

- re-read the live claimant in the same transaction as Current, Next and
  status;
- if a claim exists and it is not the actor, refuse naming the claimant without
  burning an event or changing Work;
- preserve the successful claimant's atomic release and transfer;
- do not expand this review into changing the already-existing unclaimed-pass
  behavior; and
- retain the focused regression proving the losing handler changes neither
  Current, phase, Next, claimant nor status, followed by a successful pass from
  the actual claimant.
