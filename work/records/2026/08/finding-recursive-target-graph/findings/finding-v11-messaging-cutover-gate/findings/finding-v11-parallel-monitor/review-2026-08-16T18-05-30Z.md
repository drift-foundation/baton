Changes requested. The source-local level-triggered loop is a good narrow
implementation of the one-bridge trial topology, and its focused tests pass,
but the end-to-end event path is not yet the compact trusted Baton path claimed

malformed typed actions into plausible wakeups.

## Required corrections

### R1 — wire and prove the compact trusted turn input

`actionEvent()` emits `source="baton-v11"` and
`type="v11-action-ready"`, but `formatEventMessage()` recognizes only source
`baton` with the three v10 readiness types. Every v11 event therefore takes the
generic multi-line `[EXTERNAL EVENT]` path, including the untrusted-data warning,
serialized locator details and generic inspect/fix instruction. That directly
contradicts the pinned compact trusted-event contract and the implementation
handoff.

Teach the formatter the explicit v11 readiness type and add an end-to-end
formatter regression proving the actual turn input is one compact
`[BATON READY]` line, retains the stable action locator and standing-policy cue,
and contains neither the JSON details nor the generic external-event language.
Do not broaden trust to arbitrary `baton-v11` event types.

### R2 — scope delivery memory by the same authority identity as the event

The event id is correctly scoped by authority UUID, participant and action key,
but the `delivered` map and `currentKeys` set use only `action_key`. If the
configured authority changes while the monitor stays alive, a same-named Work,
obligation or round in the new authority is suppressed by stale memory from the
old authority. Track the full authority/participant/action delivery identity
(or atomically reset memory when authority identity changes), and prove an
authority switch emits the new action while retiring the old set.

### R3 — make the refusal gate validate typed actions rather than their labels

`validateEnvelope()` currently accepts unknown action kinds and accepts known
kinds without the fields their compact locators require. For example
`{kind:"work", action_key:"anything"}` passes and produces a wake naming
undefined Work. It also ignores the W136 projection version, accepts missing or
non-boolean `timed_out`, permits a timed-out response with actions, and silently
coalesces duplicate action keys.

Require the projection-4.3 contract (compatible later 4.x additions are fine,
but older 4.x and another major must refuse), a valid snapshot token, boolean
timeout semantics, unique action identities, and exactly the three known action
kinds with their type-specific locator fields and key/field agreement. Add
negative tests for unknown kind, malformed each-kind payload, inconsistent key,
duplicate key, incompatible projection and contradictory timeout. This is the
adapter's stated refuse-not-guess boundary, not defensive validation of message
bodies.

### R4 — prove the real CLI invocation and executable boundary

Every current monitor test injects `runWait`, so none exercises the claimed
public invocation order
`--config PATH --participant TEAM.MEMBER wait timeout=SECONDS`. Add one focused
test through the real subprocess boundary using a controlled fake executable,
or inject the executor below argument construction and assert the complete argv.
Also make the new wrapper mode match the existing shipped wrappers (`0755`, not
group-writable `0775`).

### R5 — document the deliberately temporary launch topology

Add the exact standalone v11-monitor command to the bridge README: it feeds the
already-running v10 stack's existing socket and target, does not start another
app-server/bridge, and must be the sole waiter for that v11 participant. State
that stack integration replaces the v10 source only at the later retirement
gate. This is needed for the reviewed live proof and prevents an operator from
starting a second complete stack or duplicate participant waiter.

## Preserved strengths

- The v10 source and stack files are untouched.
- Multiple simultaneous action keys, claimed-Work stability,
  disappearance/reappearance, obligation/deadline generations, restart
  discovery and forward retry are represented in focused tests.
- Failed forwards do not mark a key delivered; bridge duplicate responses do.
- Persistent immediate results back off rather than spin.
- The monitor performs no Baton mutation.

No live process should change before these corrections receive independent
round-two review.
