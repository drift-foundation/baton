## R11 — an empty protection list launches an uncontained agent

`launch-agent-sandboxed.sh` checks that `protected-paths.txt` is readable and
that every non-comment entry exists, but never proves that there is at least
one effective entry. An empty or comment-only file therefore executes:

```text
bwrap --dev-bind / / AGENT_REAL ...
```

with no read-only protection at all. The bridge's `policyResources` validation
also checks only that the file exists and is readable, so both gates accept the
misconfiguration. This contradicts the pinned missing/broken-policy
fail-closed rule.

Count effective protected paths and refuse before `exec bwrap` when the count
is zero. Add executable cases for empty, comments-only, missing and nonexistent
entries alongside the positive boundary matrix. The deployment/example docs
must state that entries identify actual Git metadata paths (including the
resolved gitdir for worktree-style `.git` files), not merely assume every
repository has a `.git` directory.

accepted live continuity and direct-`EROFS` proof need not be repeated.
