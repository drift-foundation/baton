# Review — W163 Slice A — 2026-08-17T01:14:16Z

## Outcome

Changes requested. The module boundary and fail-closed intent match the pinned
plan, and the pre-existing v11/Codex gates remain healthy, but the new ACP gate
is red in the reviewer environment and several retry/policy paths contradict
the approved contract.

## R1 — the claimed 13/13 gate does not reproduce

Running the documented command in `tools/acp-baton-bridge/`:

```text
npm test
```

fails at the test-file boundary. Running the file directly exposes 13 cases:
2 pass and 11 fail. The common failure is that the real fake-agent subprocess
exits successfully before handling `initialize`; the client reports `ACP
connection closed`, and the lifecycle log stays empty. A direct session probe
confirmed `AcpAgentSession.start()` rejects while the child is initially still
reported live and then exits with code 0.

The delivered 13/13 claim is therefore not independently reproducible from the
current tree on the current host. Fix the subprocess/SDK lifetime boundary,
pin any actual Node runtime requirement, and make the documented `npm test`
command itself report all cases and pass.

## R2 — a failed setup can be reused as a live ready session

`runBridge()` considers any session whose child has `exitCode === null` ready:

```text
if (session && session.child && session.child.exitCode === null) return session
```

But `session.start()` can fail after spawn while the child remains alive: no
load capability, no advertised modes, unsupported `bypassPermissions`, mode
selection failure, or malformed setup. The catch path retains that session.
On the next level-triggered retry, `ensureSession()` may return the
half-initialized object and call `promptText()` with no successfully enforced
mode. That defeats the central no-fallback permission ruling.

Setup must publish a session as reusable only after initialize, session
new/load and exact mode enforcement all succeed. Every setup failure must
close/kill and forget the partial connection before retry. Add repeated-envelope
regressions for unsupported mode and missing load capability; a one-envelope
test that aborts immediately after the first refusal cannot prove fail-closed
retry behavior.

## R3 — required policy can be omitted completely

`validateConfig()` currently defaults absent `policyResources` to `[]`, and an
explicit empty list also succeeds. That contradicts the approved rule and the
progress claim that absence refuses startup. An empty string also passes the
array element type check, while `agent.env` claims string values but validates
only that it is an object.

Require a non-empty policy-resource list with non-empty path values and prove
absent, empty, blank, missing and unreadable forms refuse before agent spawn.
Validate every environment value as a string as documented. The fake-agent
acceptance must also cover the pinned prohibited-without-side-effect and
blocking-policy-failure paths; cancelling an unexpected permission request is
necessary but is not evidence that a configured hard denial prevented its
side effect.

## R4 — supervision can wait forever and cannot honor shutdown promptly

Initialize, session setup and prompt calls have no supervision deadline or
abort race. The process signal only aborts Baton `wait` and retry sleeps; if an
ACP subprocess starts but never answers initialize, or a prompt never returns,
the bridge remains stuck and the final `stop()` is never reached. A missing
executable also lacks an explicit child `error` lifecycle in this boundary.

Add fake-agent cases for never-initialize and never-finish-turn, prove startup
failure is retried visibly, and prove SIGINT/SIGTERM tears down the child and
returns without waiting on an unresponsive protocol call. A long legitimate
turn need not be assigned an arbitrary work timeout, but operator shutdown and
failed setup cannot be uninterruptible.

## R5 — the ordinary v11 gate does not run the new product

`just test-v11` remains green while the ACP suite is red because the recipe
does not invoke this new v11 product's tests. Preserve one operator-facing v11
gate: install/check the pinned Node dependencies deterministically and include
the ACP acceptance in `just test-v11` (or have that recipe invoke one named
sub-gate). A separate manual `npm test` that the main gate never reaches makes
the reported green v11 gate misleading.
