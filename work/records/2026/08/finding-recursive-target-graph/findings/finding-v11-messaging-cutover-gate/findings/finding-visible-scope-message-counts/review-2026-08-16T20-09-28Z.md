## Disposition

Changes requested. The direct-scope implementation is coherent and its
focused tests pass, but its published projection version contradicts the

## R1 — the shape and meaning change cannot be projection 4.5

Projection compatibility is explicit in `src/baton_work/jsonapi.py`: every
request for the same major is accepted because unknown additive fields are
ignorable. The durable plan and finding say the same thing. Breaking changes
have previously advanced the projection major.

W179 does two breaking things:

- changes the existing plain `new` field from recursive subtree count to
  direct count; and
- removes the existing explicit-breakdown field `total`, replacing it with
  `subtree_total`.

A client requesting projection 4.3 is nevertheless accepted by the candidate
and receives 4.5 with changed semantics and a missing field. That is exactly
the plausible-but-false output the version boundary exists to prevent.

Required correction: publish this as projection **5.0**, make 4.x expectations
fail clearly, update the projection inventory and compatibility tests, and
update every in-tree readiness client that deliberately pins the prior 4.3
contract. Do not retain 4.5 while claiming same-major compatibility.

## R2 — thread-less verification assignments need an explicit ruling

The implementation makes an operationally sensible exception: thread-borne
obligations follow directly labelled Threads, while a thread-less verification
assignment counts in `My` on its owning Work only. Without that exception,
the assignment disappears from every `My` counter. But the current W179
decision says `My` is the unresolved load in directly labelled Threads and
does not state the exception; the reviewer revalidation did not authorize it
either.

Obtain and append the product ruling before preserving this behavior. The
recommended ruling is:

- discussion `@` obligations count on every Work directly labelling their
  Thread (visible reuse);
- thread-less verification assignments count only on their owning Work; and
- neither flavor inflates ancestors merely through containment.

Pin both branches with focused tests, including a multiply-labelled Thread
and a child verification assignment whose parent remains at `My=0`.
