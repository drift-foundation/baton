## R1 — the changed JSON contract still announces projection 4.2

W136 changes `wait` from team-relative obligations to participant-relative
typed actions, adds routed Work, stable `action_key` values, and changes the
meaning of which entries appear. `jsonapi.PROJECTION_VERSION` and its inventory
still stop at 4.2 (W47 heartbeat). Advance the compatible minor projection
version and pin the new action shape/meaning plus same-major compatibility.

## R2 — the named reroute proof never reroutes anything

`test_obligations_wake_eligible_members_and_reroute_follows` starts with two
handlers but never changes the accepted route. Exercise an actual supported
configuration regeneration/reroute and prove eligibility moves for pending
`@`, routed Work, and a due round without rewriting history or changing their
stable action keys. This is an explicit acceptance row, not an inferred
consequence of `_endpoint_struct`.

## R3 — the new multi-part projection lacks its own interleaved snapshot proof

The existing team-obligation snapshot test predates routed Work and the new
participant projection. Interleave a claim/pass/respond or reroute commit
between `participant_actions` subqueries and prove the returned action set and
`snapshot_seq` are wholly before or wholly after, never mixed. Retain the
existing timeout/restart/deadline race coverage.

## R4 — endpoint resolution is N+1 in the continuous wait path

Every pending obligation, due round, and unclaimed Work calls
`_endpoint_struct`, which performs three queries. `wait_actionable` repeats the
projection every 50 ms, so N Works on one endpoint multiply identical route
reads on every poll. Resolve/cache each distinct `(team, kind)` once inside the
snapshot (or batch equivalently), and add a trace regression showing endpoint
resolution query count does not grow with the number of actions on the same
endpoint.

## R5 — the promised wide/narrow TUI proof is only a helper call

The personal-header test calls `breadcrumb_text` directly at no terminal
width. Add real render or PTY coverage at comfortable and narrow widths proving
one eligible and one ineligible member see their own `oblig`/`due` counts while
the team-wide parked fact remains common.

## R6 — `+` and New-only exclusions are asserted but never created

The exclusion test creates a plain post, but no `+` inclusion and no isolated
personal-New case. Create those facts explicitly and prove neither enters the
action set while remaining visible through its intended attention surface.
