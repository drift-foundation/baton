## R5 — Refresh producers still invalidate through separate code paths

**Confirmed.** Timer expiry calls `Console.tick()`, while command-bar mutations
and each direct `s` transition call `_cache.clear()` themselves. They currently
produce the same immediate effect, but they do not go through one named refresh
scheduler/path as now pinned in `FINDING.md` and `PLAN.md`.

Consolidate timer expiry and every successful local mutation through one
coalescing `schedule_refresh` (or equivalently named) operation. A literal FIFO
is not required: the empty/stale-cache state or a boolean due flag can represent
one pending request, and repeated requests may collapse. The event loop's next
render consumes that request through the same canonical projection reads.
Navigation, pure reads, refused commands, and unsuccessful/no-op acts must not
acquire refresh behavior accidentally.

Add a narrow regression or break sweep proving timer and successful-mutation
producers enter the same scheduler hook, while the existing counted-read
negative cases remain intact.
