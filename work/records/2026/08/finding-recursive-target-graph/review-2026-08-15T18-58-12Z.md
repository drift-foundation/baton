## R95 — root-only resolve input is not a canonical locator

`resolve pushcoin` and `resolve pushcoin:` both succeed and print the root base
with an empty path. The public help and WS-6 address form define the
independent locator as `ROOT_ID:relative/path`; the shared path grammar requires
a non-empty relative path. A bare Work id is the intentional separate form for
resolving a dossier root. Require a colon and non-empty contained suffix for
the independent root form; keep bare Work-id resolution.

## R96 — no-follow revalidation does not protect nested directory creation

The correction still creates directories by absolute pathname and invokes the
no-follow chain only after `FileExistsError`. If the already-created
`project/work` directory is replaced by a symlink immediately before
`mkdir(project/work/open)`, the pathname mkdir follows it and successfully
creates `open/` outside the project; success bypasses revalidation entirely.

Use the ruled dir-fd chain for the directory **creation itself**: open the
parent component-by-component with `O_NOFOLLOW`, call `mkdir(..., dir_fd=...)`,
and validate/open the created or existing child through the same parent fd.
No path-based phase-two creation may follow a swapped parent.

## R97 — roots.json is not parsed strictly

`load_resolver` uses ordinary `json.load` and checks only that a `roots` object
exists. Duplicate root keys silently take the last value, and unknown
top-level fields are ignored. This contradicts the specified strict resolver
document and can silently redirect a portable root. Reuse a strict
duplicate-key parse boundary and require the exact top-level field set
(`roots` only), then retain the existing root-id/absolute-path validation.

## R98 — short writes are reported as successful complete files

Both filesystem writers call `os.write` once and ignore its returned byte
count. A legal short write makes `init` return success with three truncated
managed files, and makes bootstrap return success with a truncated vendored
template, contradicting strict JSON/bootstrap byte parity and the partial-
failure report.

Use a write-all loop (handling interruption) or an equivalent full-write
primitive. If completion becomes impossible, return the same structured exact
partial-created report as an exception path; never report success until every
expected byte was written.
