## R41 — `review_at` is not a canonical instant

**Observed.** `create_round` and `extend_round` compare the caller's string
lexically with the clock. They accept arbitrary text, impossible calendar
dates, and non-UTC offsets. The resulting database can no longer support the
claimed canonical UTC ordering.

**Required correction.** Validate every deadline through one shared boundary:
it must be a real canonical UTC instant in the supported representation, not
merely a nonblank string. Refusal must leave no round, extension, audit act, or
sequence gap.

**Regression.** `test_review_at_refuses_noncanonical_or_invalid_instants`
currently fails for all three supplied forms.

## R42 — create and extend can commit an already-expired deadline

**Observed.** Both transitions compare time before entering `Authority._write`.
The committing transaction revalidates database state but not the deadline
against current time. If the deadline passes between those points, a new round
or extension is born due, contradicting the pinned loose-end rule.

**Required correction.** Recheck the validated instant against a transaction-
local current instant inside the committing write, before any durable effect.
Use one sampled current instant for each canonical read response as well, so a
boundary crossing cannot make its due count, detail, and actionable records
disagree.

**Regressions.** `test_a_round_rechecks_deadline_after_entering_the_write` and
`test_extension_rechecks_deadline_after_entering_the_write` both fail.

## R43 — the due alarm has no actionable locator

**Observed.** `team_summary` increments `due`, and round detail exposes
`due: true`, but `projection.obligations` still returns only pending message and
verification obligations. At the deadline, the responsible route therefore
sees an alarm with no actionable entry identifying the Work and round.

**Required correction.** Add one structured derived due-round entry per live
deadline generation to the common actionable projection. It must identify at
least the Work, round, candidate, deadline, generation, and live responsible
endpoint; appear exactly at/after the deadline; follow accepted Current/route
changes; and disappear after extension, abandonment, supersession, or close.
It remains a pure projection, never an audit or notification row.

**Regression.**
`test_due_round_is_in_the_responsible_routes_actionable_projection` fails.

## R44 — deadline-aware waiting is absent

**Observed.** Group 3 explicitly requires deadline-aware waiting, but the CLI
has no Work `wait` command or equivalent blocking surface. The implementation
can display a due count only after another caller happens to read it; it cannot
wake an idle agent at the nearest review deadline.

**Required correction.** Supply the smallest read-only wait surface described
by the ruling: return immediately for existing actionable work, otherwise
block no later than the nearest live deadline or caller timeout, then return
the same canonical actionable projection. It must create no claim, timer row,
audit act, or other authority mutation. Add before/at deadline, timeout,
restart, extension, close/abandon, and competing-message tests.

## R45 — the mandatory race/retry matrix is incomplete

**Observed.** The focused suite covers only one ordering of extension/close,
report/abandon, assessment/close, and new-round/abandon. It has no two-report
race and does not state or test the public retry limitation even though client
operation IDs remain unavailable. That is smaller than the mandatory matrix
in `WORKFLOW-TESTS.md` and cannot support the returned “complete” claim.

**Required correction.** Exercise both serialization orders of every named
race, including two reports, and assert the winner's exact audit/projection
plus the loser's structured refusal and absence of duplicate effects. State
and test the supported retry boundary when no operation ID exists. Preserve
the already-covered atomic rollback and restart cases.
