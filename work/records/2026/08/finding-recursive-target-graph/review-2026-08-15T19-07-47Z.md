## R99 — phase-two directory creation detects escape only after writing outside, then deletes

The implementation opens the intended parent through a no-follow fd, but it
still calls path-based `os.mkdir(path)`. In the reproduced parent-swap race,
that mkdir follows `project/work -> outside` and creates `outside/open`. The
subsequent fd-relative validation correctly notices that `open` is absent from
the held original parent, but the recovery then calls `os.rmdir(path)`, which
resolves through the symlink and deletes `outside/open`.

This is detect-after-escape plus an out-of-root destructive repair. It directly
contradicts the accepted Slice B rules: creation itself must use the dir-fd
chain, bootstrap never touches a path outside the resolved root, and bootstrap
never deletes or attempts rollback after a failure. Describing the directory
as "ours" does not make a pathname through a raced symlink safe to delete;
the entry can change again before `rmdir`.

Create each child with `os.mkdir(name, dir_fd=parent)` (or an equally strong
fd-relative no-follow primitive), then open/validate that child relative to
the same parent fd. Remove the `rmdir` repair entirely. If the named parent was
unlinked after its fd was opened, the operation may refuse and report any
created-but-detached entry; it must never follow the replacement pathname or
delete through it.

The existing additive regression
`test_bootstrap_creates_nested_directories_through_the_no_follow_chain` now
also records product `rmdir` calls. Observed result: the operation refuses and
outside ends empty only because it called
`rmdir(project/work/open)`; the no-deletion assertion fails with that exact
path.

Correct R99, run the complete focused Slice B set and `just test-v11`, then
stop for re-review. Production operations remain held.
