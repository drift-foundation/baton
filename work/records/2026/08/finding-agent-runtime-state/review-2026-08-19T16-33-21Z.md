# Review — slice 6 round 3

Status: changes requested.

R21's deployed Codex path is now correctly shaped: the readiness producer
forwards a control message over the real socket, the lease-owning dispatcher
answers only for its configured participant, failed publication remains
level-triggered, and no event queue or model turn is involved. R22's
older-observation conditional, R23's production `observed-at`, and R24's
fragment parsing are also present; the prior additive regressions pass.

Two ordering gaps remain.

## R25 — same-second refreshes reuse one action identity

`refresh_at` is both the request time and the action identity. Canonical Baton
instants have whole-second resolution, so two separately committed refresh
requests in one second both produce
`runtime-refresh:<incarnation>:<same timestamp>`. A consumer that already
marked the first key delivered suppresses the second as the same level-
triggered action. The observation-time conditional has the matching ambiguity:
an observation made earlier in that second compares equal to a request made
later in it and may clear it.

The additive regression
`test_two_same_second_refreshes_have_distinct_action_identities` is red. Give
each committed request a monotonic identity (the authority event sequence is
already available), carry that identity in the action/control/answer path, and
clear only the exact request generation answered. Exact `op-id` replay must
still return the original generation; a distinct operation must mint a new
one even when the wall clock has not advanced.

## R26 — default observation time may precede the lease opened after recovery

`RuntimePublisher.facts()` now freezes `observed-at` when the caller invokes
it, before its serialized task runs. The Codex dispatcher intentionally calls
`runtime.start()` and `runtime.facts()` without awaiting either. If lease open
is delayed, fails and recovers, or simply crosses a second boundary, the facts
task eventually publishes an instant earlier than the authority's
`started_ts`; the authority then refuses it under R20's lower bound. Thus the
startup inventory path is timing-dependent and can disappear precisely after
authority recovery.

Make the two contracts agree. Static startup facts may be observed only after
the lease has opened, or the lease must carry the adapter's actual launch
instant so a pre-commit observation is valid. Add a delayed/recovered-start
test that crosses a whole-second boundary and still publishes the startup
inventory with an honest accepted instant.
