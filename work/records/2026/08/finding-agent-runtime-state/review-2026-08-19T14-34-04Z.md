The shared publisher is the right boundary and the two adapters use the same
semantic verbs, but this slice cannot yet survive an ordinary process restart
or preserve the order of the events it reports. Four additive reviewer
regressions make the failures deterministic in
`tools/codex-event-bridge/test/runtime_publisher.test.mjs`.

## R5 — a process restart cannot replace the prior lease (blocking)

`runtime-start` requires `rationale=` whenever the participant already has a
lease. Both adapter launch paths call `RuntimePublisher.start()` without one.
That means runtime reporting works only for the first process incarnation in a
fresh authority; the next graceful restart, crash recovery, or adapter change
is refused by the reviewed authority surface.

The publisher deliberately performs no authority query, so every launch must
carry one safe, truthful generic replacement reason (harmless on a first
start), or use another equally query-free protocol shape that satisfies the
same invariant.

`a launcher always supplies a safe replacement rationale` is red.

## R6 — one transient start failure disables the publisher forever (blocking)

`RuntimePublisher.start()` sets `started = true` before the CLI write succeeds.
If the authority or executable is briefly unavailable, the failure is
swallowed as intended, but every later `start()` becomes a no-op and every
state write targets a lease that was never opened. The wake path survives while
its runtime diagnostics remain absent until the whole bridge is restarted.

Startup must remain retryable, and subsequent reports need a bounded way to
re-establish a lease whose opening failed without turning telemetry failure
into readiness failure.

`a failed lease start remains retryable` is red.

## R7 — Codex transitions can commit out of observation order (blocking)

The dispatcher intentionally fire-and-forgets publisher promises. The
publisher starts every `execFile` immediately, so `working`, `waiting-input`,
`idle`, and `end` can overtake the still-running `runtime-start` or each other.
The authority serializes the order in which the child processes reach it, not
the order in which the adapter observed the events. A quick turn can therefore
read `working` after completion, lose its first state because the lease does
not exist yet, or report a transition after goodbye.

Serialize publisher operations behind one per-incarnation queue. Failure of
one entry must not poison the queue; `end` must drain after earlier states.

`publisher operations preserve observed order while start is pending` is red.

## R8 — upstream error text crosses the secret boundary (blocking)

Trimming an upstream `error.message` to 400 characters bounds size but does not
make it safe. ACP delivery/readiness failures and Codex protocol errors are
currently copied into durable runtime detail verbatim. Such errors can contain
authorization headers, API keys, URLs with credentials, command arguments, or
provider payload fragments. The finding explicitly refuses credentials,
tokens, policy secrets, and raw environment values.

Persist a closed safe category plus adapter-authored text. If any upstream text
is retained, it needs a tested redaction boundary rather than truncation alone.

`secret-looking failure text is never persisted as runtime detail` is red.

## R9 — ACP identity metadata is configured nowhere (blocking before UI)

`runBridge()` passes `config.provider` and `config.model` to the publisher, but
`validateConfig()` accepts and returns neither field. Every ACP runner therefore
publishes adapter `acp` with provider/model absent; Teams cannot distinguish the
Claude and Gemini runners that motivated the inventory. Add explicit validated
runtime metadata to the deployment config and carry it through without
inferring from participant names or executable paths.

The same configuration boundary must carry an optional exact
`action-owner`. `runtime-start` already supports it, but neither publisher can
send it. Without it, the motivating `waiting-input` state can never become the
ruled actionable Inbox entry. No owner may be guessed.

## R10 — explicit state causes and clean exit are currently misleading

ACP maps every non-permission delivery failure to `transport`, including the
authentication, provider-overload, and rate-limit incidents named by the
finding. The operator cannot distinguish an unavailable network from exhausted
quota or invalid credentials. Add safe classification tests for credential,
limit/provider, transport, and internal failures.

Both bridges also publish a normal operator shutdown as
`runtime-end cause=internal`. The authority documentation explicitly says a
runner that exited cleanly did not fail. A clean goodbye should omit a failure
cause (and may retain safe adapter-authored detail); reserve `internal` for an
observed internal failure.

## R11 — live idle and long-running sessions do not renew their lease

The authority lease is intentionally bounded, but neither adapter renews it
while idle. ACP is actively completing Baton waits and Codex may remain
connected, yet after five minutes both become `unknown`. A turn lasting longer
than the lease also becomes `unknown` even while its adapter is still awaiting
that exact live turn. Add a bounded adapter heartbeat/re-state mechanism that
renews the last explicitly observed state without querying or waking the
provider, and cover idle plus slow-work expiry boundaries.
