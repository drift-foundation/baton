# Review — slice 6 round 1

Status: changes requested.

The per-fact storage shape, incarnation fence, closed key vocabulary, separate
provenance, cheap stored-state reads, and separation of adapter refresh from
conversational `poke` are good foundations. Four acceptance gaps remain.

## R17 — no production adapter publishes the inventory

`RuntimePublisher.facts()` exists and its unit tests call it directly, but no
production caller does. Neither `EventBridge` nor `runBridge()` invokes
`facts()` at startup, after session selection, or during its polling loop.
Consequently a real Codex or ACP runner creates a lease and state reports but
Member details receive none of the safe machine facts added by this slice.

Publish the facts each adapter actually knows without inference. At minimum,
the ACP bridge knows its service identity and configured working directory;
the Codex dispatcher knows its configured target/dispatcher identity. Other
fields remain absent when their source is not available. Add bridge-level
tests that exercise the production startup path rather than calling the
publisher method in isolation.

## R18 — `runtime-refresh` cannot reach an adapter

`runtime_refresh()` records `runtime_leases.refresh_at`, but that field is not
part of `participant_actions()`/`wait`, and neither production bridge reads the
runtime projection or otherwise observes it. The only green refresh test
manually calls `runtime_facts()` after recording the request; it does not prove
the adapter noticed anything. In a deployed system the request therefore
remains pending forever unless an operator separately publishes facts by hand.

Provide a level-triggered adapter-visible refresh signal, have both adapter
families consume it without forwarding a model turn, republish the safe facts,
and clear only the request that publication answers. Cover request delivery,
retry/redelivery, no model wake, and the race where an older already-queued
fact publication arrives after a newer refresh request.

## R19 — an allowed locator value can still persist a credential

The closed key set limits where data can be placed, but every allowed value is
still an arbitrary 512-byte string. The secret-pattern boundary accepts a
realistic signed log URL containing `X-Amz-Signature=...`, so the authority
stores the credential durably. Structural closure therefore does not yet
establish the claimed no-secret invariant.

The additive regression
`test_a_signed_locator_cannot_smuggle_a_credential` demonstrates the leak:

```text
1 failed, 75 passed
FAILED test_a_signed_locator_cannot_smuggle_a_credential
Failed: DID NOT RAISE WorkError
```

Harden the value boundary for credential-bearing URI/query forms (and keep the
adapter-side scrubber as defence in depth). A signed URL must be refused, not
stored in redacted form after the fact.

## R20 — freshness is receipt time, and every older fact is called stale

The API does not carry when the adapter obtained a fact. `observed_ts` is set
to the authority clock when the queued write finally commits, which can make
old observations look newer after queueing or retry. The projection then sets
`stale` by testing `observed_ts < now`, so virtually every fact becomes stale
as soon as the next read occurs. That boolean has no operational meaning.

Carry and validate the adapter's bounded observation instant so displayed age
means what the finding says it means. Until a field-specific expiry policy is
defined, expose the observation instant/age without inventing a stale verdict;
if a stale boolean is retained, derive it from an explicit ruled threshold,
not from the passage of any positive amount of time.
