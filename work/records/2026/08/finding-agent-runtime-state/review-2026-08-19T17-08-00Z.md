## R28 — `runtime-state` omits its reconnect and deadline operands

The command reference lists:

```text
runtime-state incarnation= state= [cause= detail=] [work= episode=]
```

but the actual grammar also accepts `session=` and `expires-at=`. These are
not incidental switches: `session=` is how a reconnect updates the live
session locator, and `expires-at=` is the explicit lease/freshness boundary.
The surrounding slice specifically promises reconnect and freshness
operation, so mentioning `session=` only on `runtime-start` leaves the manual
path incomplete.

Add both optional operands to the `runtime-state` reference. The additive
regression
`test_the_operator_reference_documents_runtime_state_reconnect_operands`
currently fails on `session=` and will guard both fields.
