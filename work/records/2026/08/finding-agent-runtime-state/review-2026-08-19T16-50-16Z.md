One queue-integrity defect remains in that same production path.

## R27 — queued fact publications reuse one operation identity

`RuntimePublisher.facts()` increments `this.sequence` before enqueueing the
publication but interpolates `this.sequence` only later, when its queue
callback runs. Two fact calls issued before the first callback executes both
therefore use the final value. The focused regression observes two different
fact payloads sent as `run-1:f2, run-1:f2`.

This is not merely an artificial concurrent API call. The Codex dispatcher
intentionally starts the lease and publishes startup inventory without
awaiting either. A runtime refresh can arrive while that inventory remains
queued. Against the real authority the second publication then reaches an
existing operation identity with different operands and is refused as a
mismatched replay; the refresh remains unanswered even though its adapter
handled it.

Reserve each fact event's sequence/operation identity at issue time and close
over that immutable value in the queued callback. Preserve the current
observation-time and refresh-generation behavior. The additive regression is
`fact publications queued together keep distinct operation identities` in
`tools/codex-event-bridge/test/runtime_publisher.test.mjs`.
