# Review — slice 6 round 2

Status: changes requested.

R17's startup publications, the adapter-only `runtime_refresh` action shape,
age-without-an-invented-stale-verdict, and signed-query refusal are present.
The ACP path now consumes refresh requests without a model turn. Four gaps
remain in the returned corrections.

## R21 — the Codex dispatcher refresh path has no production caller

`EventBridge.pollRuntimeRefresh()` is only invoked by its unit tests. No
production tick, stack entry point, readiness producer, or dispatcher path
calls it, and it has no production `read` implementation. Meanwhile the Codex
readiness producer explicitly drops `runtime_refresh` because it does not own
the lease. The result is that Codex refresh requests are removed from the one
consumer that sees them and never reach the dispatcher that could answer them.

Wire the signal end to end through the actual deployed Codex path. The proof
must start at a canonical `wait` envelope and end in the lease-owning
dispatcher publishing facts, with no injected/manual call to
`pollRuntimeRefresh()` and no model turn.

## R22 — an older queued publication still clears a newer request

`runtime_facts()` unconditionally sets `refresh_at=NULL`. The returned race
test calls `facts()` with no `observed_at`, so it describes a fresh observation
at commit time and does not model the race named in R18. When a fact collected
before the newer request commits afterward, it clears the newer request.

The additive regression
`test_a_fact_observed_before_a_newer_refresh_does_not_clear_it` is red. Clear a
refresh only when the publication demonstrably answers that request (for
example by an explicit request generation/identity, or an equivalently atomic
conditional rule). Ordinary/startup publications must not accidentally
acknowledge a request they never observed.

## R23 — production publishers still omit the observation instant

The authority accepts `observed-at`, but `RuntimePublisher.facts()` never
places it in the Baton operands. Both production bridges therefore continue
to fall back to authority commit time, preserving the original R20 failure on
the real queued path. Direct authority tests passing `observed_at` do not cover
that path.

The additive publisher assertion is red:

```text
42 passed, 1 failed
FAILED the inventory publishes locators the deployment already knows
actual observed-at: undefined
```

Capture a canonical UTC observation instant when facts are collected, before
enqueueing, and carry it through every publication and refresh response.

## R24 — OAuth fragment credentials still cross the durable boundary

The query-name check fixes signed query URLs, but URI fragments are not
examined. A realistic OAuth callback locator containing
`#access_token=...` is accepted and stored. The additive regression
`test_an_oauth_fragment_cannot_smuggle_a_credential` is red.

Parse and inspect both query and fragment authentication parameters (including
decoded names) or reject such locator forms more narrowly. The authority must
not durably store bearer material merely because it appeared after `#` rather
than `?`.

Focused result: **3 failed** across the two authority regressions and the
publisher observation-time regression.
