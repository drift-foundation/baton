## R12 — an ambiguously committed start cannot be replayed (blocking)

Every runtime verb is an authority mutation, but the publisher sends no
`op-id`. Consider the ordinary local ambiguity: `runtime-start` commits, then
the CLI subprocess is interrupted or loses its result. `start()` returns
false. Its retry submits the same incarnation as a new operation; the
authority correctly refuses it as an already-live incarnation. The publisher
then has a valid lease it believes does not exist and cannot recover it.

Give every logical publisher mutation an effectively-once operation identity.
In particular, all attempts to open/re-establish this incarnation's one lease
must reuse the exact start operation id, so an ambiguous result replays rather
than becoming a second start. Distinct observed transitions and renewals need
their own stable identities if retried.

`an ambiguous lease-start retry keeps one operation identity` is red.

## R13 — an idle runner never retries a failed initial start (blocking)

The next explicit state can re-establish a lease, but an idle runner has no
next state. ACP may continue completing read-only waits and Codex may remain
connected indefinitely while the authority shows no runtime evidence at all.
The renewal timer is scheduled only after a successful start, so it cannot
repair this case.

Schedule bounded start recovery after a transient opening failure. It must use
R12's same operation identity, stop on goodbye, ask no provider, wake no model,
and preserve the rule that telemetry failure never blocks readiness.

`an idle runner recovers from a transient lease-start failure` is red.
