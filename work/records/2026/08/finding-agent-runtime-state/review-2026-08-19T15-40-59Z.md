## R15 — `Since` currently reports last contact, not time in state

The pinned presentation defines `Since` as elapsed state age (`MM:SS`) and
Member details separately expose last contact. The implementation currently
breaks that distinction in three ways:

1. `runtime_state()` overwrites `changed_ts` on every identical renewal, so a
   continuously working runner appears to have entered `working` again every
   renewal period.
2. `_runtime_view()` derives `unknown` at lease expiry but leaves `since` at
   the prior reported transition rather than the deadline when the displayed
   `unknown` state began.
3. the Teams table renders the absolute `changed_ts` prefix instead of elapsed
   `MM:SS`/`∞`, spending sixteen cells while contradicting the ruled example.

Preserve state-transition time across a semantically identical renewal while
still advancing `last_contact`. A change in the reported state or its displayed
correlation may start a new interval; a byte-for-byte renewal may not. For a
derived `unknown`, project `since=expires_at`. Render Teams `Since` with the
existing elapsed-time vocabulary and overflow convention, while retaining the
absolute instants in Member details.

- `test_derived_unknown_begins_at_the_lease_deadline`
- `test_teams_since_is_elapsed_mmss_not_an_absolute_timestamp`
