Scope
-----

Observed implementation
-----------------------
v12/python/src/baton_v12/contracts/pod.py::own_record first constructs the
unexpected-name list and refuses immediately when it is non-empty. It computes
missing expected members only after that return. Neither refusal branch names
the total number of received members.

For a session reference carrying only authority_uuid and seven unexpected
members, the current message is:

  a session reference does not carry 'unexpected-0', 'unexpected-1',
  'unexpected-2' and 4 more; an extra member in an exact record is one the
  sender believes was read

It is bounded, but it omits work_id, participant, provider_session_id, and
"8 received members".

Public-boundary search
----------------------
The Python implementation has no ACP client-capability consumer or public
composition boundary. `clientCapabilities` occurs in the frozen schema assets,
not in a Python manager validator/caller equivalent. Consequently the primitive
can be corrected under W1593, but the black-box consumer acceptance cannot be
performed until separately scheduled manager composition work exposes the real
boundary.

Disposition
-----------
Changes requested. Keep the accepted bounds and inertness. Combine missing and
unexpected reporting into one rule-oriented diagnostic and add the exact total
received count. Do not change host-side Node code and do not invent a public
Python capability API in this Work.
