Confirmed implementation constraint:

JavaScript's own-key reflection APIs return complete arrays. The exact record
rule must distinguish an accepted record from one carrying any extra string,
non-enumerable or symbol member, so one complete own-key reflection is an
unavoidable O(n) lower bound. A correction cannot honestly promise work wholly
independent of the rejected record while preserving exactness.

Avoidable current work:

- `classify` always enumerates and concatenates own names although `describe`,
  `isPlainRecord`, and reconnect consume only Proxy/array/prototype facts;
- `recordFault` copies the complete key set again with `map`, sorts it, and
  joins every name into the message;
- once the reflected key count differs from the manager-owned expected count,
  exact mismatch is already established and no full sort/join is needed.

Proposed diagnostic decision (awaiting product authority):

- retain the current useful small-record behavior: a single unexpected member
  name remains visible, individually bounded;
- for a wide mismatch, report total own-member count plus a fixed number of
  bounded sample names and an omitted count;
- keep every refusal under 500 characters, matching W4's cross-boundary

- never expose Symbol descriptions or member values;
- preserve caller-local taxonomy and every signed-off exactness/inertness rule.

Implementation-ready boundary after ruling:

1. Separate shape classification from member enumeration so coarse `describe`
