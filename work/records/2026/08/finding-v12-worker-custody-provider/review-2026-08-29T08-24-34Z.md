## [P0] Directory shape is not allocation provenance

The revised `attempt_custody_root` still accepts a caller-owned mapping. It
now requires the two strings to share a parent and have basenames `inputs` and
`workspace`, then requires those three directories to be owned by the manager.
Those are properties any caller running in the manager process can reproduce:
create an unrelated parent, create two directories with the expected names,
and pass their paths.

The added `test_a_caller_cannot_forge_the_expected_directory_shape` does
exactly that. `attempt_custody_root` returns a valid capability instead of
raising `ContractRefusal`, so `custody_vector` will mount the unrelated
workspace. The earlier forged-mapping regression is green only because its
workspace basename is not `workspace`; it does not prove authority.

Required correction: consume provenance the caller cannot reconstruct by
spelling and `mkdir`. Either carry a nominal allocation capability minted at
`assignment_workspace`, or re-open from manager-owned durable storage using
the exact attempt identity and strict containment/no-link checks. Directory
shape may validate that authority; it cannot create it.
