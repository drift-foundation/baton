The sixth-round mutable-object bypass is corrected, but mount selection still

## [P0] `storage` is still a raw unrelated-host-path selector

`attempt_custody_root(workspace_group, storage, assignment_id, which)` at
`v12/python/src/baton_v12/worker_manager/custody.py:393` no longer reads an
`AllocatedRoots` object. It instead calls `_real(storage)` and derives
`<storage>/<assignment>/workspace`. Nothing authenticates `storage` as this
manager's configured workspace store.

A caller can create an ordinary manager-owned directory containing
`attempt-1/workspace`, pass that directory as `storage`, and receive a valid
`CustodyRoot` whose `place` is the unrelated workspace. The existing
`test_a_caller_cannot_forge_the_expected_directory_shape` creates its forged
`inputs`/`workspace` directly below the supplied root, so it fails only because
the new derivation looks one assignment component deeper.

Required correction: obtain the storage root from manager-owned durable or
configured authority and derive by attempt identity from that capability. Do
not accept an ordinary caller-selected host root at the custody mint.

## [P1] A refused result mint creates through a parent symlink

For `which="result"`, `attempt_custody_root` calls `os.makedirs(place)` before
validating the attempt home and workspace with `_no_link`. If the attempt-home
entry is a symlink to an unrelated manager-owned directory containing
`workspace`, the mint creates `workspace/result` in that target, then correctly
raises `ContractRefusal` for the parent link. Refusal after mutation does not
preserve the unrelated-path boundary.

Required correction: validate every existing parent component first, derive
the validated real workspace, and only then create the missing result directory
without traversing a link.
