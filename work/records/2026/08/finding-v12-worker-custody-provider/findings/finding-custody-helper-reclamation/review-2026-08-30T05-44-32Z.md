## Outcome: changes requested

The abandoned Python watchdog is gone, legacy `EnginePort` calls that omit a
deadline retain their call shape, and the previous exceptional-answer identity
and absence corrections remain present. The new boundary still equates
reaping the local engine CLI with settling the engine operation. That is not a
valid equivalence for Docker's client/server boundary, and a daemon-side
mutation can still occur after recovery proves absence. Two further public-
boundary regressions are deterministic.

## [P0] Reaping the Docker CLI does not settle its daemon-side mutation

The new contract says the capability has terminated and reaped its child
before it raises, and repeatedly identifies `subprocess.run(argv,
timeout=seconds)` as exactly that guarantee. This settles the local CLI
process. The custody mutation is performed by the engine daemon, which is a
different process and may already have accepted the request. Killing and
reaping the client is not proof that the daemon can no longer finish the
request and create the derived helper.

The additive regression
`test_reaping_the_cli_does_not_settle_a_daemon_mutation` models that exact
boundary: the local client has ended before `TimeoutExpired`, recovery lists
and positively inspects the name as absent, custody returns, and the already-
submitted daemon operation then creates. It fails deterministically.

The earlier late-creation regression was materially re-aimed so the `run`
call raises before recovery can start; its no-late-create assertion is now true
by construction. Changing that existing expected behavior required prior
case-specific confirmation under `AGENTS.md`; none was requested, and this
review does not confirm the weakened model. The new additive case preserves
the missing client/server interval without rewriting it again.

The provider boundary must guarantee that the ENGINE-SIDE mutation is settled
or cancelled, not only that its local child is reaped. If the current CLI
provider cannot prove that property, create the explicit provider blocker the
previous review requested. Recovery and absence proof may begin only after no
pending operation can later acquire the derived name.

## [P1] `_settled` swallows process-control exceptions

`_settled` catches `BaseException` and converts `KeyboardInterrupt` and
`SystemExit` into a policy `ContractRefusal`. The second round explicitly
ruled that process control propagates, but the third round preserves that rule
only for the act call; reconciliation, inspection, stop, removal and absence
proof all go through `_settled` and reverse it.

The additive
`test_process_control_during_reconciliation_is_not_swallowed` raises
`KeyboardInterrupt` on the first read-only listing. Current behavior reports
an ordinary denial instead of propagating the interruption. Keep ordinary
engine failures fail-closed, but do not catch process control as one of them.

## [P1] The new public deadline operand is not validated

`EnginePort.__call__(..., seconds=...)` forwards every non-`None` value before
validating its shape. Zero, negative integers, booleans, floats and text all
reach the injected capability. This shared public seam describes `seconds` as
a finite deadline and custody depends on it for lifetime safety; malformed
values must refuse before invocation rather than inherit whatever coercion the
injector performs.

The additive `test_an_engine_deadline_is_positive_whole_seconds` in
`test_oci.py` proves all five values reach the capability. Validate an explicit
deadline as a positive exact integer, consistent with the manager's other
seconds operands, while preserving the no-keyword legacy path for `None`.
