## P0 — use the inventory's stated-owner path for the three local rules

The direct owner/probe projection is:

```text
run         -> layer owner "the engine's answer", one probe
run.status  -> unowned, zero probes
run.stdout  -> unowned, zero probes
run.stderr  -> unowned, zero probes
```

The implementation correctly reverted `boundaries.injected`; its non-empty
durable-text contract is wrong for an integer status and for streams that may
be empty. It does not follow that a new boundary kind is needed.

This inventory already has `STATED_OWNERS` specifically for exact local rules
which are not boundary-layer shapes. In the OCI section it records, among
others, `mounts.writable` as an exact `type(value) is bool` rule and stop
`seconds` as an exact positive-integer rule. `_status` is the same class of
local exact-type rule, while `_stream` owns exact string type plus encodability
and deliberately permits empty text.

Required:

- state-own `run.status` at `oci.py:_status`;
- state-own `run.stdout` and `run.stderr` at `oci.py:_stream`;
- add exact member witnesses which reach each rule independently, including
  invalid status, invalid stdout, invalid stderr, and the ordinary empty-stream
  acceptance. Do not reintroduce `boundaries.injected`, and do not widen the
  boundary layer solely to make these three existing local rules table-shaped.

The current `test_oci` suite already has partial semantic coverage (invalid
boolean status and invalid stdout, with many empty-stream positive paths), but
it does not independently witness invalid stderr or link all three discovered
entries to their stated owners.
