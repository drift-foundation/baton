## [P0] The new declarations have no boundary witnesses

`test_boundary_inventory.py` adds thirteen `DELEGATED` entries: eight for
`custody.py`, three for `launch.py:adopt`, and two for `workspaces.py`. The
probe table adds none. A direct inspection of `EveryProbeProvesItArrived`'s
assembled table returned `[]` for all four affected site prefixes.

That is not optional coverage. `EveryProbeProvesItArrived.expected()` includes
every delegated `(entry, label)`, and
`test_every_owned_entry_has_exactly_one_probe` requires one exact driver for
each. In particular, the eight custody declarations at lines 1680--1699 have
real delegate labels (`an engine name`, `the engine's run operation`, `a
custody operation`, `a custody root name`, `an assignment identity`, and `an
image digest`) but no call in `all_probes()` can reach any of them. This also
misses the parent plan's explicit requirement for one refusal/corruption
witness per `(entry, label)`.

Add exact public-entry probes for every custody declaration and either add the
same for the five unrelated declarations or return those declarations to the
Works that own them. Each probe must prove the delegate's own refusal, not an
earlier envelope or capability refusal.

## [P0] The inventory universe still cannot see the injected engine answer

The pinned W43977 plan requires every injected custody engine
list/inspect/stop/destroy answer and every nested member actually consumed.
The implementation only registers public caller parameters. A direct
`receiving_entries()` projection shows seventeen `custody.py` entries, all in
the `caller` domain, and no injected entry at any `oci.py` site.

The reason is structural: the scanner's `CAPABILITIES` set does not include
`EnginePort._run`, while `EnginePort.__call__` receives the deployment's
answer through `self._run(...)` at `oci.py:400` and `oci.py:414`. Consequently
the universe cannot discover the engine answer document or its `status`,
`stdout`, and `stderr` members. Delegating the caller's `run` operand to
`EnginePort.__init__` proves only that the capability is callable; it does not
inventory what that injected capability answers.

Model this once at the real crossing, `EnginePort.__call__`, rather than once
per custody vector. Register its exact owners and witnesses, including the
nested members consumed by custody's listing, inspection, stop, removal and
act paths. The universe must discover these from the capability call itself;
a table entry alone would recreate the circular inventory this test file says
it replaced.
