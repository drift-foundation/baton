## Outcome: changes requested

The tenth-round correction closes the final authenticated-mount handoff:
durable lookup, root derivation, vector composition and invocation now stay in
`custody_act`, the public vector is gone, and the caller receives no host path

## [P1] Any JSON object is `ok`, and nested evidence remains mutable

`custody_act` parses the last JSON object from stdout and passes it to
`_answered` without validating it against the requested operation or an
operation-specific result shape. `CustodyAnswer.ok` then requires only status
zero plus a non-`None` object. A normalize act whose engine stdout ends with
`{"custody":"inspect","entries":[]}` is therefore reported successful.
Zero plus unrelated JSON is no stronger an account than zero plus no document,
which this round correctly refuses.

The answer's immutability claim is also only top-level. `MappingProxyType`
protects assignment to the outer mapping, but JSON lists and dictionaries
inside it remain live; a holder can change `answer["running_as"][0]` or an
entry record and make the retained account disagree with what the custodian
reported.

The two additive regressions in `test_custody.py` reproduce both gaps. Validate
the custodian document against the requested closed verb and its required
shape before `ok` can become true, and retain a recursively immutable account
(or an immutable canonical serialization with a read-only decoded view).
Refusals and failed acts must remain accountable without guessing at partial
documents.
