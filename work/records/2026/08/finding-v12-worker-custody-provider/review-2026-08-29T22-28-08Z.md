## [P0] The final path-bearing handoff is the returned argv

`custody_vector` authenticates and derives the source at
`custody.py:523`, places it in the `--mount` token at line 541, and returns the
ordinary list at line 545. The caller therefore holds a mutable path-bearing
object between the durable lookup and the engine use. Replacing the one list
member after `custody_vector` returns puts an unrelated host directory
verbatim in `--mount source=...`; neither the durable record nor `_derived_root`
is consulted again.

That is the same interval this dossier has ruled out since round six. The
latest comments say lookup, composition and use are “one act”, but execution
is not in this function and no production ending calls it at all. A tuple or
another frozen argv wrapper would not close the boundary: a caller can compose
a new engine argv. The owner that authenticates the source must retain it
through the engine invocation and return a typed custody result, so no caller
receives either a host path or an executable command vector to retarget.

The additive regression
`v12/python/tests/manager/test_custody.py:182` mutates only the returned mount
member. The unrelated path is accepted into the command that the current
engine tests would execute.
