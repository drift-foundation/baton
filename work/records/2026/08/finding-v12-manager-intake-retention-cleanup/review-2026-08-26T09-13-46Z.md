## Finding

### [P1] Authenticate surviving retention rows without freezing the original group

`_retain` (`intake.py:801-824`) deliberately stores one current decision per
artifact. Its conflict update allows a later policy to replace one artifact
without replacing its peers. `retentions_of` (`intake.py:827-906`) groups the
rows that are current now by `retain_operation_id`, derives a command from
each current group, and requires that derived artifact set to equal the
historical committed command.

Those two rules conflict. If one valid command decides artifacts A+B and a
later valid command replaces B only, A still names the authentic A+B act while
the current group for that act contains only A. The reader derives an A-only
operation, reports `integrity`, and blocks retention reads and cleanup even
though no durable row was forged.

Correction boundary: retain the per-artifact current-row model. For each
surviving row, load the committed `output.retain` result named by its stored
operation id and require that the result includes that artifact with the same
disposition and policy digest. Do not require every member of the historical
command to remain current. Preserve the existing forged-row failures and
operation-collision behavior. A deleted decision should leave that artifact
undecided for cleanup; it should not make a different, still-authentic row
invalid.

Regression:
`IndependentContractReview.test_a_later_policy_can_replace_part_of_a_grouped_decision`.
