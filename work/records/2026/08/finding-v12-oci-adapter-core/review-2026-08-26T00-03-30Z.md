## [P0] Exact resolved-label filters hide stale runtimes before comparison

`list_vector` asks the engine to filter on all eight runtime labels, including
`profile_digest`, `policy_digest`, and `adapter_digest`. A real engine applies
those filters before returning a row. Consequently a runtime from the same
attempt and assignment under an old policy is omitted from stdout, so
`OciAdapter.list` never reaches `_labels_of` or the new resolved-identity
comparison. `OciAdapter.start` sees an empty candidate set and invokes `run`,
attempting the second runtime the acceptance requires it to refuse before any
create side effect.

The additive
`OneDeliveryCarriesOneResolvedIdentity.test_a_stale_policy_runtime_is_not_filtered_into_a_duplicate_start`
uses an engine fake that actually honors the supplied filters: it returns the
stale row to a candidate query, but correctly returns no row when the expected
policy digest is itself a filter. Current behavior raises no refusal and the
recorded vectors contain `run`.

Candidate discovery must be broader than resolved-identity comparison. Query
by stable attempt/assignment identity sufficient to enumerate candidates,
then validate the complete label set and engine-reported image in-process,
before start can decide the set is empty. Ambiguous candidates must remain
closed. The existing
`TheVectorsAreClosedAndOrdered.test_the_listing_filters_on_every_label`
assertion pins the unsafe pre-comparison filtering; this review gives explicit,
case-specific confirmation to revise that assertion to the stable candidate
selector plus complete post-read comparison contract.

## [P1] Target traversal is erased before the rule checks for it

`_mounts` applies `os.path.normpath` to the target and only then checks whether
`..` is a path segment. The check can therefore never see traversal that
normalization consumed. A writable workspace requested at
`/workspace/../etc` is accepted and emitted as:

```text
type=bind,source=/srv/a-1/workspace,target=/etc,readonly=false
```

The additive
`AMountIsCanonicalAndNeverTheHosts.test_a_target_traversal_is_not_normalized_into_another_location`
records this redirection. Check the inert raw target spelling for `..` before
normalization, as `_canonical` already does for host sources, then emit only
the canonical target.
