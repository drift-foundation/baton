THE GENERAL RULE, WHICH IS WHAT WAS MISSING

  ANY assignment fact used as a filter hides a runtime that contradicts it,
  and a contradictory runtime is exactly what this adapter exists to refuse.
  There is no shorter version: it is not about digests, and it was never about
  generation either.

  So the selector is the MINIMAL OWNERSHIP KEY — the one label that answers
  "is this runtime this attempt's" and cannot disagree without meaning a
  different attempt entirely:

    _CANDIDATE_LABELS = ("runtime_attempt_id",)

  and the COMPLETE returned record is compared in process against the record
  that was asked for, member by member across the whole frozen label set. A
  candidate that carries this attempt id and contradicts the request is WRONG,
  not absent.

  TWO COMPARISONS, AND THEY ANSWER DIFFERENT QUESTIONS. The new loop asks
  whether this runtime is the one the CALLER named; the existing
  `_LABELLED_IDENTITY` loop asks whether it is the one THIS ADAPTER resolved.
  `list` is reachable without `start`, so neither implies the other and both
  are kept. The engine-image comparison and the ambiguity behaviour are
  untouched, as the review required.
