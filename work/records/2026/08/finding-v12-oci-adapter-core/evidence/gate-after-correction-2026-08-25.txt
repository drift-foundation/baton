WHAT THE SIX REQUIRED CORRECTIONS DID

  1. CANONICAL IDENTITY, NOT LEXICAL PREFIX. `_canonical` resolves a host path
     the way the kernel would, and BOTH the roots and the mount sources go
     through it -- resolution applied to one side only would refuse every
     legitimate mount under a symlinked root. The `..` check runs on the
     SPELLING, before resolution collapses it. The RESOLVED source is what
     reaches argv: proving the resolved path and then emitting the spelling
     would leave the engine free to resolve it again, which is the same defect
     with an extra step.
  2. NO ROOT CONTAINS ANOTHER, and no mount source or target contains another.
     Equality is containment's degenerate case and is refused by the same rule.
     A source inside two roots has no unique posture authority; nested targets
     shadow, nested sources alias.
  3. ONE RESOLVED IDENTITY. `RESOLVED_IDENTITY` is the image, profile and
     adapter digests; the adapter owns one record at construction, the argv
     names its image, and `start` refuses labels that disagree with it --
     BEFORE the engine is asked to create anything, because a start that
     created a container and then refused would leave exactly the state no
     reconciliation can undo. Mismatch, no-side-effect and
     restart-reconciliation probes included.
  4. THE OCI INVENTORY IS COMPLETE. Twenty receiving entries owned -- fifteen
     delegated to the private owner that actually decides them, five stated
     with witnesses -- and twenty-nine probes, each driving the real public
     vector or seam. `_canonical` was given a LITERAL label, because a computed
     one is a boundary the inventory cannot attribute.
  5. REAL ENGINE EVIDENCE. `tests/manager/test_oci_engine.py` drives the
     adapter against a real daemon: start, list by reconciliation labels, stop
     with proof, destroy with proof, the duplicate-start refusal, the applied
     restrictions read back from the engine's own record, a workspace mount
     resolved to the place this manager named, and positive absence for an
     identity that never existed. Every container is registered for removal
     before it can exist, and the engine is asked afterwards whether anything
     survived.

     SKIPPED PER ENGINE when the binary or its daemon is absent -- the policy
     this dossier requires, and deliberately the opposite of W6633's image
     gate, which builds THIS repository's own artefact and fails instead. A
     case requires the covered engines and `ENGINES` to be the same list, so an
     engine this adapter claims to speak cannot go unrun.
  6. This file and `PROGRESS.md`.
