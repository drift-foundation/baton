# W6632 review — constrained OCI adapter core

Reviewed 2026-08-24 by `baton.codex`.

Disposition: **changes requested**.

The closed-vector foundation is useful, and the original 33 focused cases
pass. The cut cannot launch the manager's real start operation, however, and
its inspection, absence, label and mount boundaries do not yet prove the facts
the dossier requires. Six additive reviewer cases make the gaps durable.

## [P0] The manager's real operation identity produces an invalid container name

`attempts._start_operation_id` deliberately returns
`runtime.start:<64 lowercase hex>`. `OciAdapter.start` copies that identity into
`baton-{operation_id}` at `oci.py:380`, so the emitted `--name` contains `:`.
Docker/Podman's closed container-name grammar does not admit that character;
the fake engine accepted a vector a real supported engine refuses. Derive a
stable engine-valid name from the operation/attempt identity without weakening
the manager's operation identity. The new cross-module regression is
`test_the_managers_real_operation_identity_makes_a_valid_runtime_name`.

## [P0] Inspection can settle the wrong runtime, and prose can manufacture absence

`observe` reads only `State.Running`; it neither requires nor compares the
inspection record's runtime identity. A state record with no identity and a
record explicitly naming `runtime-2` both report `runtime-1` quiescent. Require
the exact inspected identity before returning running or quiescent.

The non-zero path at `oci.py:463` treats either broad substring `no such` or
`not found` anywhere in stderr as positive absence. Thus “inspection helper not
found while daemon is unavailable” proves the runtime absent. This directly
contradicts the record's rule that engine prose is not death. Pin an
engine-specific, exact-identity positive-absence evidence contract; otherwise
return uncertain. Reviewer regressions cover both defects.

## [P1] Reconciliation labels are not the exact typed, closed identity claimed

`_labels` accepts any integer in any label and treats every other member as
generic text. It therefore accepts non-digest profile/adapter labels and a
negative generation. On readback, `_labels_of` requires the seven expected
keys but silently ignores an extra `baton.v12.*` key. The adapter can therefore
emit or accept a reconciliation identity that is not the frozen semantic
identity while reporting that its label set is exact. Own each member by its
real rule, enforce the finite positive generation domain, and reject unknown
manager-prefixed labels. Reviewer regressions cover malformed digests,
generation and an extra manager-owned label.

## [P1] Mount and resolved-policy enforcement is incomplete

`_mounts` forwards spellings such as `/srv//source/./` and `/workspace/./`
unchanged, so its “canonical” output is not canonical. More importantly, the
hard-coded system-path denylist cannot prove the dossier's prohibition on the
authority/config/database/repository internals or another worker's state: any
such path outside those eight prefixes is accepted. `OciAdapter` also has no
resolved profile/policy/adapter identity to compare with the caller's labels;
the fixed restriction table and arbitrary label digest can describe different
policies while reconciliation claims they are the same.

Canonicalize and prove mount sources against assignment-owned roots before
launch, use an allowlisted posture-specific mount topology, and bind the
resolved image/profile/policy/adapter identity to what is labelled and run.
The new canonical-spelling regression demonstrates the first visible gap; the
allowlist and resolved-policy boundary need focused negative tests as part of
the correction.
