## [P1] A well-shaped cursor the authority never returned can hide all Work

The correction records a decision that a token this authority did not mint is
refused. `_cursor_position` currently validates only that the value is a
base64-encoded five-member string with scheme `w1` and integer rank fields. It
does not bind the decoded position to any Work or canonical position in this
authority.

A client can therefore construct a syntactically valid token with impossible
ranks, a future sequence, and a nonexistent id. `actionable_work` accepts it,
compares every real row at or before that invented position, and returns an
empty page even while Work remains actionable. This recreates the discovery
failure through the cursor boundary rather than through offset arithmetic.

Durable reproduction:
`evidence/w26328-review-forged-cursor.py`.

Observed output:

```text
forged token accepted: dzEfOTkfOTkfOTk5OTk5OTk5H25vdC10aGlzLWF1dGhvcml0eS1XOTk5OTk5OTk5
still actionable: fefefefe-W2
returned rows: []
```

The same missing binding means a cursor row whose own priority/blocking rank
changes cannot trigger the documented deliberate-refresh path. The old
position is silently followed even though the dossier says continuing it now
means something different.

Required correction: inside the read snapshot, bind the decoded token to its
named Work and verify that the stored row's current total-order position equals
the token. Refuse a nonexistent row, impossible rank, changed position, or
other mismatch and direct the client to refresh. A row that merely stopped
being actionable must remain a valid cursor when its order position is
unchanged; that is the ordinary inter-page claim/reroute case already covered.
Add regressions for a well-shaped nonexistent position and for a cursor row
whose rank changes, plus a mutation that removes the binding check.
