--- 1. WHY THIRTY-THREE CAUGHT MUTATIONS DID NOT CATCH EITHER DEFECT

Twelve authority and twenty-one console mutations were caught on 2026-08-27,
and both reviewed defects were live the whole time. The reason is a property
of what was chosen to break, not of how many were chosen.

  NO MUTATION MOVED THE SET BETWEEN TWO PAGES. Every paging case walked an
  UNDISTURBED set, where an offset and a position are the same answer.
  `test_paging_traverses_every_match_once` is a real case and it passes on
  the defective code, because nothing claims or reroutes anything while it
  walks. The defect only exists at the boundary between two reads, and no
  case crossed one. The five new cases each cross it deliberately: a claim, a
  reroute, a claim of the very row the cursor names, an arrival ahead of the
  cursor, and a tie in the ordering itself.

  THE NARROW CASES ASKED WHETHER THE TABLE REFUSED, NEVER WHAT IT SAID.
  `test_no_width_that_draws_a_table_drops_it` skips exactly the widths where
  the refusal is drawn — `pytest.skip(f"{width} refuses the table whole")` —
  so the one line carrying the number was never read by any case. The
  refusal was measured as a BEHAVIOUR and never as a STATEMENT, and the
  defect was entirely in the statement.

--- 4. A TEST THAT HUNG RATHER THAN FAILED, AND WHY IT IS WORTH NAMING

The first run of the corrected authority harness DID NOT FINISH. The
"continuation is ignored" mutation makes every page return page one, so
`next_after` is never `None` and `test_paging_traverses_every_match_once`
looped forever; the harness aborted on its own 900-second subprocess
timeout. The source was restored correctly by the harness's `finally`, and
that was verified before continuing.

The lesson is not about the harness. An unbounded `while True` over a
continuation does not FAIL when the continuation stops advancing — it hangs,
and a suite that hangs reports nothing at all. Both walks now go through one
bounded `walk()` helper whose page bound is its own assertion, so that
defect is a named failure. This was an addition to an existing case's loop
control, not a change to any assertion it makes.

--- 6. WHAT WAS NOT DONE, DELIBERATELY

THE REFUSAL SENTENCE STILL TRUNCATES ON A VERY NARROW TERMINAL. It is drawn
with `addnstr` at `width - 1`, so below about twenty-one columns the message
is cut and below about twenty-nine the number is cut with it. That is
pre-existing presentation, it is not what the review raised, and widening or
wrapping the message is a presentation question this Work did not open. The
cases therefore compare against the whole intended line and tolerate only the
cut the terminal itself made, and skip the widths where there is no number on
screen to be right or wrong about.

NO GIT HISTORY OR INDEX WAS MUTATED. The pre-fix comparisons used
`git show HEAD:<path>` into a copy and restored the working file immediately;
`git show` reads and writes nothing.
