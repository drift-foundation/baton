## [P1] A continuation is not bound to its participant-relative view

`actionable-work` is a participant-relative query, but the `w1` token carries
only the row's canonical-order position. `_cursor_bound` checks the authority
and row position, not `viewer_team`/`viewer_member` (or an equivalent query
scope).

The durable reproduction configures two disjoint Routes. Ada can claim W2/W3;
Grace can claim W4/W5. Grace reads a real first page and receives the W4
continuation. Passing that unedited, authority-minted token into Ada's read is
accepted because W4 exists at the encoded position. Ada receives an empty page
while W2/W3 remain actionable. The row binding therefore fixes an invented
position but still permits a genuine cursor from a different query to recreate
the discovery failure.

Evidence:
`evidence/w26328-review-cross-view-cursor.py`.

Observed output:

```text
Grace page: ['W4']
Ada actionable: ['W2', 'W3']
Ada through Grace's cursor: []
```

Required correction: bind the continuation to the participant-relative query
that produced it. A scheme-bumped token may carry the resolved viewer identity
and compare it before the row-position check; another mechanism is acceptable
if it makes cross-view reuse refuse. Preserve the current whole-`work` row
binding so a cursor row that merely stopped being actionable for the same
viewer still continues. Add a two-disjoint-Route regression and a mutation
that removes only the view binding. Update the help/guide to state that a
continuation is valid only for the same participant view.

This is query integrity, not a request for cryptographic tamper resistance:
the defect uses a token genuinely returned by the same authority, unchanged.
