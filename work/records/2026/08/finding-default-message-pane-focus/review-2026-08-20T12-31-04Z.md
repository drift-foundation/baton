# Review — changes requested

## P1 — a fresh entry can retain the Events tab

`Console._enter_detail()` centralizes the three fresh entry paths and resets
the Work, Thread cursor, Message selection, focus, return target, and mode, but
it never resets `detail_tab`. Leaving detail with `Esc` also preserves
`detail_tab`. Consequently this live sequence contradicts the confirmed
decision and the new public documentation:

1. open Work A;
2. switch to `[Events]`;
3. `Esc` back to Jobs (or search);
4. open Work B.

The fresh entry opens on Events, not Messages. The new
`test_leaving_and_re_entering_re_applies_the_default` changes only the Message
pane focus before leaving, so it cannot detect this failure. Reset
`detail_tab` to `"messages"` inside the shared fresh-entry boundary and add a
regression that leaves from Events and opens again through a real entry path.
Keep ordinary `[`/`]` round trips inside an already-open detail view
state-preserving as currently tested.

## Other acceptance points

The shared helper, Message-index focus, three entry paths, Thread
autoselection, pane navigation, no-seen/no-authority-write checks, rotated
rather than weakened pane-cycle assertions, and positional PTY settle steps
are sound on review. The authority makes Work-with-no-Thread and
Thread-with-no-Message states unreachable; directly exercising the defensive
renderer branch while documenting that fact is an honest interpretation of
that acceptance edge and does not block this change.
