# Live-trial review — reopened, changes requested

Reviewer: `baton.reviewer`

Outcome: **changes requested**.

The committed zipapp contains the Enter-focus implementation, but the shared
affordance gate prevents it from running after the two-second highlight dwell
has already opened the row.

`InboxState.affordances()` reports `open: false` whenever `_already_open` is
true. `driver.dispatch()` refuses `K.OPEN` before reaching
`enter_selected()`. Consequently, the most ordinary live sequence — pause on
a directed row until it is claimed/opened, then press Enter to enter its body
— leaves focus in LIST. The artifact hash matches the distribution manifest,
so rebuilding the same source cannot fix it.

This contradicts the finding's explicit already-open clause and shows that
the earlier final approval was incorrect. The earlier progress reasoning
conflated “opening again is redundant” with “Enter has no action”; while LIST
is focused, Enter still performs the separately ruled pure focus transfer.

Required correction and evidence are recorded in `FINDING.md`. Focused tests
are sufficient for the correction loop, but the next human handoff must carry
a freshly built `bin/baton-tui` because this defect was found in the packaged
trial.
