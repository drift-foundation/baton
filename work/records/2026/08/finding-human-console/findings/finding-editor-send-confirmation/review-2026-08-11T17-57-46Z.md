## Accepted correction

`compose_body_requested` closes the in-session subject-only fallback for fresh
handled-message and seen-notice follow-ups. It is set on successful import and
explicit empty, reset by `begin_compose()`, checked by both message and notice
subject fallbacks, and is not inferred from `compose_is_reply`, so the lawful
quick follow-up remains valid. The original `Deploy` assertion is now genuinely
restored. Focused tests pass.

The persisted safety boundary remains incomplete and one attachment path
bypasses the marker.

## R1 — safety-critical field was added to draft version 2 without a bump

Severity: **blocking downgrade/mixed-reader defect**.

`drafts.VERSION` remains 2 and `READABLE` remains `(1, 2)`, while
`body_requested` is now an optional version-2 field. An earlier v2 console
accepts the same file and ignores the unknown marker, reopening an explicitly
emptied follow-up as an ordinary subject-only draft. This is exactly the
failure the adjacent `notice_scope` comments say a version bump prevents.

“Only scratch files exist” does not make same-version incompatible meanings
safe: those files are the human's retained unsent writing, and an older
next-generation candidate or worktree is allowed to read version 2 today.

Required correction:

1. Advance the written draft format to version 3 and make older v2 readers
   refuse it.
2. Read versions 1, 2, and 3. Migrate v1/v2 in memory to an explicit
   `body_requested` value; preserve a valid experimental field when present,
   as the v1 audience migration already does, otherwise derive the faithful
   old meaning (`bool(body)` is protective and preserves ordinary empty quick
   drafts as false).
3. Require a boolean `body_requested` in version-3 drafts rather than treating
   absence as the permissive default. Save only complete v3 records.
4. Add old-v1, old-v2, experimental-v2-marker, missing-v3-field,
   wrong-type-v3-field, older-reader-refusal, and rewrite-to-v3 regressions.

Frozen 1.0 artifacts remain untouched; their older reader should continue to
refuse the newer file.

## R2 — reply explicit-empty intent is still lost on restart

Severity: **blocking wrong-message path**.

`_draft_from_state()` writes `body_requested` only for compose/notice.
`reopen_draft()` restores a reply with:

```python
self.reply_body_requested = bool(self.reply_body)
```

An explicitly emptied quick/fresh reply has an empty body and a true
`reply_body_requested` marker in memory. Escape retains its subject/body but
not that marker. After restart it reopens false, and the next ordinary send can
publish the inherited subject shorthand.

Required correction: persist the same `body_requested` field for reply drafts
and restore it directly. Add quick-reply and fresh-reply explicit-empty
retain/reopen regressions that perform the later send attempt and prove no
disposition/message is written.

## R3 — the current restart regression cannot expose marker loss

Severity: **blocking hollow regression**.

`test_the_full_body_intent_survives_retention_and_reopen` is an ordinary
compose that first imports `"a real body"`, then refuses an empty edit while
preserving that non-empty body. Even if `body_requested` is dropped on restart,
the body remains non-empty and the subject fallback is unreachable. The test
asserts the field's value but does not exercise the wrong-message consequence;
it is not the fresh empty-body follow-up state the comment names.

Required correction: retain/reopen the seen-notice (or equivalent quoted)
fresh follow-up whose stored body is genuinely empty and whose marker alone
prevents fallback, then attempt the ordinary confirmation and prove no
publication. Deliberately remove serialization/restoration separately and
show the named regression fails for an actual write/refusal difference.

## R4 — an attachment bypasses full-body refusal

Severity: **blocking wrong-message path**.

Directed `send_compose()` checks `compose_body_requested` only inside:

```python
if not body and not attach:
```

An explicitly emptied full-body follow-up with an attachment therefore skips
the refusal and publishes the external attachment without the body the human
chose to edit. Attachment-only compose is lawful when no body editor intent
exists, but the marker means this particular draft must refuse until it has a
body.

Required correction: when `compose_body_requested` is true and the body is
empty, refuse before subject/attachment fallback regardless of attachment.
Keep ordinary attachment-only compose valid, and add both sides as regressions
using a real configured root/pinned external part.
