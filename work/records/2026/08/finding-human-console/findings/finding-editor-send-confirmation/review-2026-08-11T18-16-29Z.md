## R1 — the required v1/v2/v3 migration matrix is absent

Severity: **blocking regression gap on a wrong-message storage boundary**.

Re-review 4 required old-v1, old-v2, experimental-v2-marker,
missing-v3-field, wrong-type-v3-field, older-reader-refusal, and
rewrite-to-v3 regressions. None of the body-intent migration cases was added.
`tests/tui/test_tui_drafts.py` mentions `body_requested` only in the current
factory. The cross-version cases in `test_tui_notice_scope.py` assert the
current constants and the older notice-audience migration, but do not exercise
body-intent migration or version-3 validation.

The existing `test_the_frozen_console_refuses_a_file_this_one_writes` is not
the older-reader test this bump needs. It loads the released version-1 reader,
which already refused version 2; it would stay green if this implementation
still wrote unsafe version-2 files. The compatibility property under review is
that the immediately preceding version-2 reader refuses a version-3 draft
rather than accepting it and dropping `body_requested`.

Required correction: add explicit regressions that prove:

1. genuine v1 and v2 records without the field derive `False` for an empty
   body and `True` for a non-empty body;
2. experimental v2 `True` and `False` values are preserved rather than
   recomputed;
3. version 3 refuses a missing or non-boolean marker and leaves the stored file
   untouched;
4. loading an old record and saving it produces a complete version-3 record;
5. a representative version-2 reader refuses that version-3 record. The frozen
   v1 artifact remains useful coverage for the earlier audience bump, but it
   cannot substitute for this case.

Use raw fixture files only to represent older/damaged formats; normal current
writes should continue through `drafts.save`.

## R2 — the attachment regression does not reach the ruled UI state

Severity: **blocking integration-regression gap**.

`test_an_attachment_cannot_stand_in_for_a_deleted_body` starts an ordinary
compose, successfully imports a non-empty body, asks the editor to empty it,
correctly observes that the prior body survives, and then directly assigns:

```python
state.compose["body"] = ""
```

That unit-level mutation does exercise the final guard, but it is not the
explicitly emptied full-body follow-up required by re-review 4. The reachable
empty compose state is already available without manufacturing internals: a
seen-notice follow-up starts with an empty stored body and a non-empty quote;
deleting that quote sets `compose_body_requested` while leaving the stored body
genuinely empty. Attach the real configured-root evidence to that retained
state, attempt the ordinary send, and prove no message/external part is
published. Keep the existing ordinary attachment-only positive case.

This is the same fixture discipline earlier passes needed: the regression
should reach the dangerous state through the user transition that creates it,
not by assigning the postcondition under test.

## R3 — storage comments still describe version 2 / an optional marker

Severity: **non-functional but required boundary correction**.

The implementation comments now contradict the format they sit on:

- `_migrated_from_v1` says it reads as version 2 and will later rewrite as
  version 2;
- `_validate` says it validates a complete version-1 list;
- `reopen_draft` still says the marker can be absent and defaults permissively,
  although `load` now supplies it for v1/v2 and refuses its absence in v3.

Update these statements to describe the version-3 contract. They are local
storage/restore documentation, not historical finding text, so leaving the old
rules beside the new code invites the exact downgrade this version bump fixes.
