- Every launched service is recorded immediately as `provisional`, retaining
  PID, start ticks, session/process-group ownership, configured argv, and the
  first observed argv before readiness can block or the controller can die.
- Successful configured readiness re-reads PID/start ticks, atomically stores
  the then-current argv, and marks the entry `final`.
- Provisional state is never healthy or adopted by another start. Its bounded
  rollback omits only an argv claim that was never certified; PID reuse and
  session/process-group ownership still refuse before signalling.
- Final state retains exact argv comparison, so a post-readiness substitution
  remains `argv-mismatch` and fail-closed.

  rule exists in the implementation.

## One policy ruling still required

Recommend approving version-1 lifecycle documents as provisional during this
transition. A v1 `observedArgv` was never captured at a declared readiness
boundary, so treating it as final would certify the defect. Rejecting v1
entirely would also remove the controller stop path precisely when the old live
set must be recovered. The proposed reading authorizes only bounded rollback
using the recorded PID/start-ticks/session/process-group identity; every newly
written version-2 final entry resumes exact argv enforcement.

If approved, the operator—not an agent running inside this managed set—runs
the stop/start/status smoke. The stop terminates the current app-server and
Claude ACP sessions by design.
