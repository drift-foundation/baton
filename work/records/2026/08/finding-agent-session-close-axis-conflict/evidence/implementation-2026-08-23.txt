2. WHAT LANDED

SCHEMA 13 -> 14. The partial unique index on agent_sessions is REMOVED and not
recreated; a store at 13 or earlier is refused by the version check rather
than migrated, as every prior roll was. `posture_slots` replaces it:

  PRIMARY KEY (runtime_attempt_id, posture)
  occupancy CHECK IN ('available','occupied','recovery-required')
  session_epoch, reason, changed_at

The superseded index's own comment is kept in the schema and marked
superseded, with the reasoning, rather than deleted — the next reader needs to
know why the current rule is not the obvious one.

posture_slots.mjs is the new boundary:

  occupySlot          compare-and-set against 'available', called from INSIDE
                      openAgentSession's transaction so the slot and the
                      session row are one act
  requireSlotRecovery occupied -> recovery-required, with a reason
  releaseSlot         -> available, ONLY on RECOVERY_EVIDENCE
  postureSlot         the slot as it stands, or null

RECOVERY_EVIDENCE is a closed two: `provider-session-closed` and
`runtime-absent`. A stop REQUEST, an elapsed deadline and a disconnect are
deliberately not members, and a case asserts that by name so the omission
reads as a decision. `runtime-absent` REQUIRES the exact identity observed,
because "the container is gone" without saying which container is a claim
about nothing.

closeAgentSession is replaced. It is the NORMALLY OBSERVED end now: the
observation moves through the axis boundary — refusing every edge the frozen
table forbids, exactly as any other observation would — and the slot is
released on that observation as evidence. A session that did not close
normally is not its business; transport loss goes to handleTransportLoss and
the slot is returned by releaseSlot with whatever actually established
absence.


3. TWO SIGNED-OFF TESTS MIGRATED, ON THIS RECORD'S AUTHORITY

  "every epoch is FRESH, ACROSS LEGITIMATE CLOSURES"
      got its posture back by writing closed over not-started. It now uses the
      path the ruling added for exactly this case: the slot needs recovery and
      positive absence evidence returns it. An assertion was ADDED — every
      epoch's observation is still not-started — because recovery rewriting no
      history is the property the migration turns on.
  "only CLOSING frees the posture"
      is unchanged in what it proves and corrected in how. The unknown row
      still refuses a second open; what used to free the slot was writing
      closed OVER that unknown. Positive evidence frees it now, three
      non-evidence attempts are driven, and the unknown observation is
      asserted to SURVIVE.

Its title is now the one stale thing in it — the ruling is that closing is no
longer the only thing that frees a posture. Left alone deliberately: renaming
a signed-off case is a bigger edit than the ruling authorized, and the case
body says what it now means. Raised on the handoff instead.

P3 and P4 both fail the signed-off "the DATABASE refuses the second open
session" case, which is the evidence that the replacement is as strong as the
index it replaced: two managers on separate connections are still decided by
the database.

MEASURED: postureSlot's own occupancy-vocabulary check is UNREACHABLE through
SQL, because the column's CHECK constraint refuses an invented value first.
The case asserts the constraint that actually holds rather than the line that
cannot fire, and the check is kept as defence against a store built some other
way. It is not counted as a guard.
