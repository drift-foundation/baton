# Independent review — 2026-08-23T18:49:02Z

## Outcome

**Changes requested.** The schema now separates provider observation from
manager-owned posture occupancy, and opening a session occupies the slot in
the same transaction. The release and ambiguity mutations do not yet identify
the epoch or durable runtime fact they are acting on, however. Five additive
regressions demonstrate that stale or merely asserted evidence can move the
current slot.

## Findings

### [P1] Slot mutations are not bound to the session epoch

`requireSlotRecovery` and `releaseSlot` select and update a slot by attempt and
posture only. Neither accepts the epoch whose ambiguity or recovery was
observed. A delayed epoch-1 ambiguity report can therefore move epoch 2 to
`recovery-required`, and a delayed epoch-1 release or `closeAgentSession` can
free epoch 2.

Require the observed `sessionEpoch` on both mutations and compare it with the
slot's durable `session_epoch` inside the same write transaction. The
idempotent branches must perform the same comparison: an already-released
epoch may answer a retry, but evidence for an older epoch must not answer as a
retry after a later epoch has occupied the posture. `closeAgentSession` must
carry its normalized epoch through this boundary.

Regressions:

- `W771 review: delayed slot evidence cannot move a newer epoch`
- `W771 review: a delayed close cannot release a newer epoch`

### [P1] Evidence names are accepted without proving the named durable fact

`provider-session-closed` currently releases a slot while the matching
session observation is still `ready`; the existing positive case invokes
release before recording `closed`. `runtime-absent` rejects an empty identity
but accepts any non-empty string and never compares it with the attempt's
durable `runtime_id`. Thus the API checks the spelling of a caller assertion,
not the positive evidence required by the ruling.

Bind normal-close release to the same epoch's durable `closed` observation (or
make it an indivisible consequence of the operation that establishes that
observation). Bind runtime absence to the exact runtime identity durably
attached to the attempt and reject missing, foreign, or stale identities. Do
not rewrite the provider observation when runtime evidence recovers the slot.

Regressions:

- `W771 review: a provider-close label is not the observation`
- `W771 review: runtime absence binds the attached runtime identity`

### [P1] The product transport-loss boundary leaves an ambiguous slot occupied

`handleTransportLoss` records the same epoch as `unknown` but does not move its
slot to `recovery-required`. The durable result therefore contradicts the
confirmed transition "ambiguity moves it to recovery-required" and bypasses
the recovery API that later positive runtime evidence is meant to discharge.

Compose transport loss with `requireSlotRecovery` for the same epoch. The
composition must remain correct across retry and restart, including a crash
between the observation and slot movements; use one atomic operation or an
explicitly repairable durable protocol rather than relying on an in-memory
sequence. Plan item 5 still requires review of every W4 adapter consumer, but
the current product entry point must implement W771's own ambiguity rule.

Regression:

- `W771 review: transport loss itself enters slot recovery`

## Accepted direction

The schema-14 table split, removal of the observation-derived uniqueness
index, atomic open/occupy operation, unchanged terminal meaning of `unknown`,
and separation from output disposition all match the ruling. The focused
validation, retry, restart, and retained-output scaffolding is useful once the
three identity/transition gaps above are corrected.

The signed-off test title `W2929: only CLOSING frees the posture` is now false.
This review gives case-specific authority to rename it to describe positive
slot recovery while retaining and strengthening its assertions; the ruling
already authorized the behavioral migration.
