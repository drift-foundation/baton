## [P1] Real-container evidence omits the manager's runtime restrictions

`ContainerCase.talk` constructs `docker run` with interactive/stdin, cleanup,
name, and `--network none`, but none of the other unconditional restrictions
from `worker_manager.oci.RESTRICTIONS`. The filesystem inspection and both
cancellation starts likewise construct raw `docker run` argv with only the
network restriction. Consequently the recorded 23 green cases exercised
containers that retained the default capability bounding set, writable root,
ordinary privilege behavior and unconstrained CPU/PID/memory/tmpfs posture.

That does not establish the dossier's filesystem/user/**capability** acceptance
or the first review's requirement to run real consent/execution containers
under the approved restrictions. The adapter already owns the one authoritative
table: cap-drop ALL, no-new-privileges, label disable, fixed user, read-only
root, no network, PID/memory/CPU limits, and bounded noexec tmpfs mounts.

The additive daemon-free
`TheDaemonGateExercisesWhatTheManagerWillRun.test_the_channel_container_uses_every_unconditional_restriction`
captures the actual `talk` argv and derives the expected restrictions from that
table. It fails naming ten omissions; only `--network none` is present.

Use one shared test launch builder that applies every unconditional restriction
to the channel, inspection, and cancellation containers. Keep the derived
regression and add an in-container observation for the properties Docker can
report directly (at minimum effective capabilities and root writability), so
the gate proves what was applied rather than merely comparing argv.

## [P1] The alleged independent rebuild is allowed to be a cache hit

`ContainerCase.build` invokes the same builder and cache twice. A different
output tag does not isolate or invalidate the build cache; the second invocation
can simply attach its tag to the first build's cached result. Equal image IDs
then prove cache reuse, not that two independent executions of the recipe
produce one identity.

The additive daemon-free
`test_the_reproducibility_build_does_not_reuse_builder_cache` captures the build
argv and fails because it contains no `--no-cache` (or other cache-isolation
mechanism). Rebuild independently for the same explicit platform with cache
reuse disabled/isolated, then compare immutable identities. Preserve cleanup
registration for both tags and record the corrected daemon run.
