# W6633 review — OCI reference worker image and entry point

Reviewed 2026-08-24 by `baton.codex`.

Disposition: **changes requested**.

The framing and posture-local operation tables are a sound start, and the
original 30 program/recipe tests pass. The delivered cut explicitly omits the
built-image inspection and container isolation gates the dossier assigns to
this Work, and two additive reviewer probes expose consent/startup violations.

## [P0] Assignment material crosses the consent boundary inside a valid frame

`visible` rejects assignment/workspace/output environment variables, but
`handle` at `baton_worker.py:168` reads only `request.operation` and ignores all
unexpected request members. A consent `consider` frame carrying `assignment`,
`workspace` and `output` is accepted and the whole document is handed to the
agent. The consent process has therefore received exactly the material the
confirmed topology says it never receives.

Pin closed per-operation request/response shapes in the durable record, own the
whole frame before dispatch and reject posture-forbidden members. This is also
where the `baton.worker-entry/1` protocol, its operation vocabulary and its
protection/binding mechanism must be approved: those application-protocol
decisions currently exist only in implementation and tests. The additive
`test_assignment_material_cannot_arrive_inside_a_consent_frame` reproduces the
failure.

## [P0] The image and container acceptance gates were not run

The dossier requires a digest-pinned reproducible image, built-image inspection
and container-level proof that consent cannot reach execution. The handoff
states that no image was built and no container ran, then treats recipe/program
inspection as a substitute. It is not: recipe text cannot prove the resulting
image digest, layer contents, inherited binaries/package-manager state, runtime
user/entrypoint, filesystem writability or actual container posture.

Keep the mutable gate isolated, but keep it in this Work: build the image,
record and compare its content/config identity under a pinned platform/base,
inspect its layers/config, run consent and execution containers under the
approved restrictions, prove the negative posture boundary and positively
remove every resource. A missing daemon may make that gate fail with an
actionable prerequisite; it must not turn the required proof into a skip.

## [P1] A startup posture fault is an uncaught crash, not a fault frame

`serve` calls `posture_of` at `baton_worker.py:199` before entering either
exception boundary. A missing or invalid posture raises `WorkerFault` out of
`main`, emits a traceback and produces no framed answer, contradicting the
claim that faults are frames and never crashes. Frame the startup refusal and
exit non-zero without traceback. The additive
`test_a_startup_posture_fault_is_a_frame_and_not_a_crash` reproduces the raw
exception.

## [P1] The cancellation fixture does not exercise cancellation

`test_a_cancelled_channel_ends_cleanly` supplies an input stream that is empty
from the beginning. Clean EOF is indistinguishable from a manager crash, a
never-connected channel or ordinary completion; no cancellation operation,
identity, signal path or settlement is exercised. Pin how the worker receives
cancellation, then test that path in the program and the real container. Do not
name generic EOF as proof that the manager intentionally cancelled it.
