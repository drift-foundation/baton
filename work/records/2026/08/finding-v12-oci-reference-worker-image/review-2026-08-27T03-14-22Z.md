## Findings

### P1 — member-set derivation is mistaken for value validation

`_declarations()` derives the names of `outputDescriptor` and
`outputConstraints`, but validates only those sets, the path pattern, and two
nonnegative integer checks. It does not enforce the frozen types of `name`,
`type`, or `required`; the type and contents of `allowed_media_types`; the
`link_policy: forbid` const; or the schema maxima on `max_entries` and
`max_bytes`.

All seven additive subcases are contract-invalid and all seven reach the
sentinel agent instead of refusing as input. Numeric names/types and textual
required flags are especially material: those values are used for lookup,
control flow, and completion-envelope authorship. A ceiling above the frozen
maximum weakens the resource bound the schema pins.

Derive and enforce the value rules this worker consumes from the same shipped
definitions, before dispatch. This need not become a general JSON Schema
engine; it is the closed, bounded `outputDescriptor`/`outputConstraints`
subset already selected as this worker's boundary. Keep the additive subcases
and prove each guard can fail independently.

### P1 — directory symlinks bypass `link_policy: forbid`

`measured()` checks only entries in `files`. With the default
`os.walk(..., followlinks=False)`, a symlink to a directory appears in the
`directories` list and is then silently skipped. The additive agent creates
`out/linked-directory -> /output`; the worker returns success and publishes a
completion manifest claiming an empty declared tree while that tree still
contains the forbidden link.

Inspect directory entries as well as files and refuse every symlink before
publication. The claim that link policy is enforced “by construction” becomes
true only when every filesystem entry the traversal encounters participates
in that construction. Keep both directory-link and regular-file-link cases,
and measure the directory-link guard by removal.
