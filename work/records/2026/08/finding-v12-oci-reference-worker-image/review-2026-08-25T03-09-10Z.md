## [P0] The approved session and operation identity contract is absent

`REQUEST_MEMBERS` at `v12/worker/baton_worker.py:67` still admits only
`operation` and, in execution, `task`. Every approved common member —
`protocol`, `session`, and `operation_id` — is consequently refused as an
intruder. `handle` has no expected posture-session identity to compare, no
one-use operation ledger, and no replay check. `serve` at lines 243-256 emits
bare `{ok, answer}` or `{ok, code, message}` objects rather than echoing the
approved common identity. A wrong session cannot be distinguished from a
right one, and a duplicate legacy request executes twice.

Implement the pinned `baton.worker-entry/1` envelope in full: inject or
otherwise bind the manager-minted expected identity for this exact container,
validate all common members before agent dispatch, consume each operation ID
once per session, and echo the identity on every request-derived success or
fault. Consent and execution must receive different expected session
identities. Add positive, wrong-session, cross-posture-session, missing,
unknown, extra-member, and replay cases.

## [P0] Required image, container, and cancellation evidence remains absent

The prior review and `PLAN.md` already require the built-image gate in this
Work; it was not left for a later ruling. This host's Docker 29.1.3 daemon is
reachable, while the pinned base is not currently present locally. There is
still no isolated build/inspect/run/cleanup gate or evidence artifact. Recipe

Likewise, `test_a_cancelled_channel_ends_cleanly` still starts with an empty

creates even on failure. A missing daemon is an actionable failed prerequisite

## [P1] Closure is posture-wide rather than per operation

The approved shapes are per operation, but `REQUEST_MEMBERS` is keyed only by
posture. An execution `describe` request carrying `task` therefore succeeds,
even though `describe` has no operation-specific members. Use exact member sets
for `describe`, `consider`, and `work`, including their common envelope.

The scripted `work` answer also contains `task_digest`, while the pinned closed
answer is exactly `disposition`, `workspace`, and `recap`. Validate the whole
agent answer before framing it so missing, unknown, extra, or wrong-typed answer
members cannot cross the worker boundary.

## [Open] Startup faults and response identity need one explicit rule

The corrected invalid-posture path emits a frame before reading a request, so
it has no request `operation_id` to echo. That conflicts with the unqualified
statement that responses echo `protocol`, `session`, and `operation_id`.
Approver clarification is requested in the Work thread: either startup faults
have a separately pinned identity shape, or posture validation waits until a
bounded request envelope supplies the operation identity. Do not silently
invent a third response form.
