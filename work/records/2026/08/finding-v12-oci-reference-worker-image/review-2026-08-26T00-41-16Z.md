## [P1] Base-layer set overlap is accepted as pinned-base ancestry

`_base_facts` returns a `frozenset` of base diff IDs, and
`normalize_layout` at `v12/python/tools/worker_image.py:225-245` calls every
diff ID found in that set a base layer. It refuses only the two degenerate
cases where all or none match. A built layout that contains one of two claimed
base layers but omits the other is accepted, its other layers are rewritten,
and a digest is returned as though the pinned base had been established.

That contradicts the correction's central safety claim: image ancestry is an
ordered prefix, not set membership. Preserve the pinned base's complete ordered
diff-id sequence and require the built image to start with that exact sequence,
with at least one recipe-owned suffix layer, before rewriting anything. The
additive daemon-free
`test_a_partial_base_layer_match_refuses` at
`tests/tools/test_worker_image_build.py:222` fails because no refusal occurs.

## [P1] Concurrent builds for one destination share and delete one stage

`staging_tag` at `v12/python/tools/worker_image.py:85-92` always returns
`<target>-unnormalized`. `build_worker_image` then builds, saves and removes
that shared mutable tag at lines 300-314. Two simultaneous invocations for the
same destination therefore do stage over each other: one can save the other's
unnormalized image, and either `finally` can delete the tag before the other
has saved it. This is the opposite of the durable implementation decision and
the function's own stated guarantee.

Allocate a unique staging reference per invocation, thread that exact value
through build/save/cleanup, and retain destination correlation in its readable
prefix if useful. The additive daemon-free
`test_concurrent_builds_for_one_destination_have_distinct_stages` at
`tests/tools/test_worker_image_build.py:338` fails with one distinct tag rather
than two.
