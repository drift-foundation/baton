## Decision

**Changes requested. Do not accept run4 or close W51487.** The provider turn
produced a focused, otherwise credible test-only patch, but one required fact
is not actually protected: the nominated engine is not distinguished from the
production implementation's current literal value.

Return W51487 to `baton.impl` for a clean fresh result. Do not mutate the
retained run4 candidate or an isolated review copy, and do not apply anything
to the canonical checkout automatically.

## Blocking finding

The frozen task requires coverage that a successful probe uses **the nominated
engine**. In the retained patch:

- `TheProbeAsksTheEngineRatherThanTheHost.probed` always invokes
  `preflight._observed_readable("docker", place)`;
- `test_the_probe_asks_the_nominated_engine_about_the_exact_path` then asserts
  `asked[0] == "docker"`.

Supplying and expecting the same current production value makes the assertion
non-discriminating. If `_observed_readable` were changed from `[engine, "run",
...]` to `["docker", "run", ...]`, the nominated-engine case would still pass.
That is precisely the regression the task says this case must detect.

The run4 mutation evidence does not close the gap: its six mutations cover
network isolation, the read-only bind, uid/gid, stdout interpretation,
nonzero-process handling, and the absent-path short circuit, but it does not
replace the production engine argument.

This is established from the retained patch and current production expression;
no candidate mutation was needed or performed.

## Required correction

Keep the correction test-only and narrow:

1. Let the helper accept an engine value, or call `_observed_readable`
   directly, using a deliberately non-default sentinel such as
   `engine-under-test`.
2. Assert that exact sentinel is `asked[0]`.
3. Demonstrate that substituting literal `"docker"` for production's `engine`
   argument fails the focused case.
4. Preserve the remaining run4 cases and all frozen constraints: mocked
   process crossing, ordinary non-credential temporary file, no Docker daemon,
   no weakened assertions, no `preflight.py` change absent a genuine defect,
   and no broader W17110 boundary.

## Non-blocking observations retained from run4

The independent evidence otherwise supports the implementer's account: only
`test_harness.py` changed; the patch is additive; the outside-worker harness
ran 30 tests successfully; and the worker's two failures reproduce on the
unmodified frozen source in the same uid-65532 container posture. Those facts
do not compensate for the missing nominated-engine regression and need not be
re-litigated unless the next result changes them.
