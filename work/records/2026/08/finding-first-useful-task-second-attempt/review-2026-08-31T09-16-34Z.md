## Independent blocker confirmation

- `v12/python/src/baton_v12/worker_manager/credentials.py` fixes
  `VOLATILE_FILE` at `0o600` and creates the slot with that mode before writing
  the bearer. The file is manager-owned.
- `v12/python/src/baton_v12/worker_manager/oci.py` keeps the execution primary
  identity at 65532 and adds only the configured workspace group before
  read-only binding the credential file into the fixed credential root.
- `v12/worker/claude_agent.py::_prepared_home` checks
  `os.path.exists(slot)`, not whether uid 65532 can read it, then symlinks that
  slot into the private provider home.
- Existing credential tests explicitly pin `0600` and describe the slot as
  readable only by the manager. A correction therefore changes a deliberate
  security contract and needs its own decision, implementation and review.
- The credential-free reproduction in `evidence/w51487-run3/blocker.md`
  observes `exists=True`, `access(R_OK)=False`, and `PermissionError(13)` for
  uid 65532 over a manager-owned `0600` file. With mode `0640` and the already
  granted supplementary group, the same harmless file is readable. This proves
  a remedy shape, not yet the complete permission/ownership ruling.

The correction is tracked separately at
`findings/finding-runtime-credential-slot-readability/`. W51487 must be gated
on that Work; another unchanged provider attempt would deterministically
