THE CORRECTION

  ONE SOURCE -- the accepted `baton` section -- and TWO CARRIERS that cannot
  disagree.

  THE PROMPT. `runBridge` renders the block once, after `loadInstructions` and
  before the first wait, spawn, session or prompt, and passes it to
  `promptText` for every delivered action. Once, because a per-prompt render
  could read state that moved. There, because `launcherContract` throws on a
  missing or blank field, so an incomplete contract refuses the LAUNCH rather
  than producing a partial prompt some turn then acts on. Last in the text,
  for the reason the Codex path already gives.

  THE ENVIRONMENT. `validateConfig` derives the four into `agent.env` from the
  same section, and derives them LAST so they override whatever the parent
  exported -- a stale ambient BATON_BIN is the same untrusted carrier as a
  stale file. A conflicting explicit entry refuses startup BY KEY; the same
  value spelled explicitly is accepted, which is what keeps existing templates
  working.

  THE SHARED RENDERER, imported rather than re-spelled. A second textual
  format for the same four values is how two adapters drift into telling their
  contexts different things.
