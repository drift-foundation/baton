## [P0] Changed failure facts select a second act instead of colliding

`_start_failure_operation_id` hashes all of these into the operation id:
attempt, assignment, start operation, attached runtime, and typed failure.
`store.transact` can compare a changed signature only after the caller selects
the same operation id. Because changed runtime or failure facts change the id
first, they create another `runtime.start-failed` row and never exercise the
journal collision guard.

The submitted
`test_a_different_failure_is_its_own_act_and_rewrites_nothing` drives the
recording seam twice and requires two rows with different operation ids. It is
therefore durable evidence of the opposite contract. W32648 acceptance says
retry is bound to the exact attempt, assignment, start operation, attached
runtime and failure identity and that changed facts collide; `PLAN.md` and
`PROGRESS.md` repeat that claim.

Use one stable failure-record operation identity for the one start act,
derived from the attempt/fixed start operation. Keep the attached runtime,
settled execution axis and typed failure in the signed operands and result.
Then an exact repetition replays while any changed fact reaches the same id
with a different signature and fails closed, leaving the first record intact.
Correct the current two-record test to assert that behavior.
