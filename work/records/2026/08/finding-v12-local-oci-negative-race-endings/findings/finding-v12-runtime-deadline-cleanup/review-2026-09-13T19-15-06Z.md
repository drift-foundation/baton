## P1: a failed cooperative cancellation vetoes exact deadline cleanup

`v12/python/src/baton_v12/worker_manager/deadlines.py:advance_deadline` calls
request_cancellation and only reaches _authorize_deadline_cleanup if that call
returns normally. The existing attempts._order_quiescence contract deliberately
stops the runtime even when agent.cancel raises, then re-raises the agent fault.
The new composition treats that advisory failure as failure of the whole ending.

Independent probe-163016.py starts a known runtime, records the reached deadline,
and makes agent.cancel consistently raise OSError. Across two advances:

- The Authority cancellation/fence has committed and its exact gate is held.
- The runtime receives two successful stop orders.
- destroy_deadline is never called, cleanup remains pending and the lane stays
  occupied. Each retry repeats the same agent fault before cleanup.

An agent inside a stopped runtime may remain unreachable indefinitely; requiring
its cooperation before force-removal can therefore prevent the deadline from
ever completing. A second probe shows the analogous short-circuit when the
cooperative stop operation itself fails while exact removal remains available.
Both preserve the useful fail-closed hold; neither proves the required cleanup
composition can make progress.

Correct the deadline owner to distinguish a confirmed Authority fence from
subsequent cooperative agent/stop failure. Preserve the fault as evidence, but
allow the exact trusted removal/reconciliation path after positively resolving
the same fence, fixed assignment and runtime identity. Do not blanket-catch or
ignore Authority refusal, an unknown start/runtime, conflicting output, or
unsettled credential/launch providers. No lane reuse or remote discharge before
positive absence, retained custody and both applicable provider endings.

Add regressions for recurring unreachable agent and failed cooperative stop,
including retry after restart, fence failure negative control and sibling
preservation. The ordinary cancellation owner's error reporting must retain its
existing behavior. Prefer the already approved deadline composition boundary;
if a necessary source-scope change is discovered, name it before editing rather
than silently broadening the shared attempts.py hook.
