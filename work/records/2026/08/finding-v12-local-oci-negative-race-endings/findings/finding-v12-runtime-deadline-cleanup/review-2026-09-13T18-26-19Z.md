## Accepted architecture

The manager-journal approach is appropriate. Current request_runtime_start owns
the pre-adapter start intent and lane transaction; request_cancellation commits
its exact intent before Authority cancellation and only then asks agent/runtime
to stop. authorize_cleanup actually requires an intake receipt and returns
blocked-on-intake without one. abandon_attempt is an explicit separate declaration,
not a timer policy. OciAdapter._removed and _settle_recordless_cleanup already own
exact removal/provider settlement and retained directory custody. Reuse those
cores through a distinct typed deadline authorization, not an abandonment alias.

A deadline observation, policy-selected cancellation, cleanup settlement and remote
gate discharge are separate acts. Keep that separation, including effectively-once
identity and retained evidence for each. Do not add a schema/table, Job setting,
background driver, second clock, new engine backend or per-Job timeout meaning.

## Concrete interface and lifecycle requirements for implementation

1. The trusted manager supplies one optional deadline selection at the runtime
   start boundary. Use a closed policy value containing policy_digest,
   policy_generation, duration_seconds and action (report-only or cancel).
   Duration is finite and positive, bool is not a duration, and the policy digest
   must agree with the recorded attempt policy. Omitted selection means explicit
   no-deadline for new legacy/unconfigured starts. This is a manager configuration
   operand, not an input-manifest field accepted from the worker. Use the existing
   policy supplier/capability conventions; no new user-facing default is chosen.
2. Pin selection, fixed assignment and manager-derived start/deadline instants
   before adapter.start; preserve the runtime-start lane/intent transaction.
   A stable operation identity belongs to the attempt/assignment, with changed
   policy operands causing a collision. The hook checks the existing pin even on
   retry/omission. Do not derive a fresh deadline from restart time or insert one
   retroactively for an already committed legacy start with no deadline record.
   Such an old start remains explicitly legacy-unconfigured; adding a timer to it
   refuses. A crash after pin and before start retains the original pin. An
   expired cancel selection cannot silently obtain a fresh start window.
3. Expose a read-only deadline_of and a separate observe_deadline operation.
   Neither accepts now/deadline_at from the caller. Before-deadline observation
   must remain retryable; only the first reached observation is durable. Recheck
   fixed identity and nonterminal eligibility at the decision. Fresh stale or
   terminal requests refuse; exact already-committed observations replay without
   being reinterpreted. Clock rollback cannot move the pin or authorize early
   expiry. Observation alone never changes execution/disposition/output axes.
4. A separate advance_deadline composes the stored reached observation and
   stored policy. It accepts owner capabilities and required retention policy,
   not replacement timing/action operands. Report-only performs no destructive
   action. Cancel uses the existing request_cancellation owner with a stable
   reason tied to the deadline observation identity. Validate capabilities before
   committing/fencing. Read the matching committed intent/Authority fence; an
   unrelated cancellation reason is not relabelled or silently adopted.
5. For a receiptless deadline ending, the closed destroy authorization binds
   runtime_attempt_id, complete assignment, runtime_id, deadline observation
   identity/digest, cancellation/fence operation identity and retention policy.
   Compose it only from owner-resolved records. The deadline destroy wrapper
   delegates to _removed; it cannot authorize itself from a worker report,
   timeout string or destroyed axis. Ordinary receipted output keeps ordinary
   retention cleanup. Concurrent output arrival must recheck eligibility and
   select its actual owner path or hold, preserving all existing evidence.
6. Add a deadline-specific committed-cleanup proof reader and gate-discharge
   composition. Proof binds the same attempt/assignment/runtime, cleanup operation,
   positive absence, both applicable provider endings and retained custody.
   Reuse existing proof validators/settlement core without weakening ordinary or
   abandonment contracts. Unknown start/engine/provider facts keep capacity held.
   Committed start with no attached runtime is not a no-start proof: reconcile
   the exact start first. Truly unstarted cancellation uses W161230's six-fact
   reader. Local lane settlement and Authority gate receipt remain distinct;
   successor eligibility must honor both owners.

Function spelling may follow repository conventions; the operand ownership,
