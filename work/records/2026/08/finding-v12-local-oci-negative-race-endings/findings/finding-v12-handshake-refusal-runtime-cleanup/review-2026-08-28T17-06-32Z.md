## Findings

### [P1] A historical session row can authorize a fresh cancellation

`sessions._require_session` proves row identity and provider-session equality,
but it deliberately does not prove session state or active posture ownership.
The new operation checks only `posture == execution`. A caller can therefore
name an old execution epoch in `closed`, `unknown`, or another post-handshake
state, supply a mismatching version now, and derive a new
`unsupported-version` record that proceeds to `request_cancellation` for the
attempt.

A genuine negotiation refusal is evidence from one bounded handshake phase,
not merely from any row that once represented an execution session. Define the
allowed state/slot invariant from the actual session lifecycle and prove it in
the same concurrency boundary as the refusal record. Add negatives for every
terminal state, a released/reused posture slot, and a newer execution epoch.

### [P1] The refusal and its signed pinned version come from two profile reads

`negotiate_acp` reads and validates the certified profile to produce the
refusal. After catching it, `settle_unsupported_version` calls
`certified_agent_session_profile` again and subscripts the result for
`pinned_wire_version`. Profile certification is replaceable state. A
withdrawal/recertification between the reads can make the second result absent,
causing an untyped `None` subscript failure, or detach the signed evidence from
the exact profile snapshot that produced the refusal.

Use one owned certified-profile observation for both the negotiation verdict
and every profile/version member in the operation signature and result, under
the write/concurrency boundary that fixes the refusal act. Add a second-store
race regression for replacement/withdrawal between observation and commit.

### [P1] The accepted ending and engine evidence are still absent

The progress entry correctly states that the helper still stops at
`cancel-requested`: it does not drive force-removal, positive absence,
credential/launch teardown, cleanup settlement, or reuse ordering. It remains
private and has no production caller. There is still no genuine post-container
Docker refusal and no restart, multiplicity, uncertainty, mismatch, provider
retry, or sibling-preservation matrix.

Those are the Work's central acceptance, not follow-up hardening. Complete them
before the next review return.
