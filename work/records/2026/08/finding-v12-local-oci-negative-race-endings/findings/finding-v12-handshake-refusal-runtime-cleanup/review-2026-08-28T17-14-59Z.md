# Independent review — 2026-08-28T17:14:59Z

Changes requested. The correction blocks obvious post-handshake rows and uses
one profile snapshot internally, but it introduces a public certification
bypass and still does not make the refusal act replay-safe or slot-bound.

## Findings

### [P0] Exported `negotiate_acp` now trusts a caller-supplied profile

The new optional `profile=` parameter skips
`certified_agent_session_profile`. It is not owned, schema-validated,
seal-checked, or compared with the supplied `profile_digest`. Because
`negotiate_acp` is exported on the Worker Manager public surface, any caller
can now pass an uncertified digest together with arbitrary profile bytes and
receive a negotiation verdict from those bytes. A behavior-bearing mapping can
also execute through direct subscripting.

The single-snapshot requirement does not authorize widening the public trust
boundary. Keep public `negotiate_acp` responsible for reading the certified
profile. Factor a private helper that accepts the already owned/validated
profile document for `settle_unsupported_version`, or otherwise preserve the
same ownership and digest binding without exposing a bypass. Add a black-box
negative proving an uncertified/wrong digest cannot be paired with supplied
profile bytes.

### [P1] Handshake state is checked, but active posture ownership is not

The prior review required state **and slot** provenance. Both optimistic and
transactional checks inspect `row.state` and `profile_digest`; neither reads
the posture slot. These are deliberately separate axes. In particular,
runtime-absence evidence can release the slot without rewriting the session
state, leaving a `not-started` or `initializing` historical row that still
passes `_HANDSHAKE_STATES`.

Inside the same transaction that fixes the refusal, require the execution
posture slot to be `occupied` by this exact epoch. Add released-slot and
newer-epoch negatives, not only direct edits of the session state.

### [P1] Exact replay is still gated by today's mutable state

`settle_unsupported_version` checks the current session state and reads the
currently certified profile before it reaches `store.transact`/replay. After a
first refusal commits, an exact retry fails if the session advances or the
profile is withdrawn. The new withdrawal test deletes the profile after the
first answer but never retries, so it does not cover the acceptance it names.

Replay is a fact about the already committed operation. Arrange identity and
signature so an exact call can replay before new-act-only mutable
preconditions, while changed operands still collide. Cover retry after state
advance, slot release, profile withdrawal, and a newly opened store/process.

### [P1] Cleanup and real-engine acceptance remain absent

The handoff again confirms that the operation stops at `cancel-requested`, is
unexported/unused, and has no force-removal, positive absence, provider
settlement, reuse ordering, Docker refusal, restart, multiplicity,
uncertainty, mismatch, provider-retry, or sibling-preservation evidence.
W32576 cannot close until that central composition lands.
