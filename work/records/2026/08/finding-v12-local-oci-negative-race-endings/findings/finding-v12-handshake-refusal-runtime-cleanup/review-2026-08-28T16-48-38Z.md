## Findings

### [P1] The new operation is not on a production session path and accepts no session evidence

`handshake.settle_unsupported_version` is referenced only by
`tests/manager/test_attempts.py`. It is absent from `handshake.__all__`, the
package import/export surface, and every production caller. The test creates a
`ContractRefusal("refused", "unsupported-version", ...)` directly rather than
reaching the refusal through `negotiate_acp` after opening/adopting an exact
execution session.

The operation accepts a free `attempt_id`, `profile_digest`, and integer
version. It proves neither an `agent_session_ref` nor that the persisted
session's profile equals the supplied digest, and it does not even require the
supplied digest to equal the attempt's recorded profile. Any holder of the
manager capabilities can therefore manufacture the closed pair, name an
unrelated or uncertified profile/version, and fence a live attempt. Checking
the pair's spelling proves its type, not its provenance.

Required correction: compose the genuine negotiation refusal through the
public manager/session boundary, require the exact persisted four-part session
reference, and compare its attempt, assignment, posture, epoch, provider
session identity, certified profile, and pinned/answered wire version before
any journal or authority mutation. Add negatives for a stale/malformed session
reference, wrong attempt, wrong profile, correct (non-refusing) wire version,
and hand-constructed/unrelated refusal evidence.

### [P1] Changed operands create additional refusal records instead of colliding

The bound finding requires exact retry replay and changed operands to collide.
The implementation instead hashes profile and version into the operation id,
and `test_a_different_version_is_a_different_act` explicitly requires two
`session.unsupported-version` rows for one attempt. There is no session identity
in either record. A retry can consequently journal multiple incompatible
accounts of which profile/version one session refused.

Required correction: derive one fixed operation identity from the exact
session/refusal act and put assignment, profile, pinned and answered versions,
and the refusal identity in its signature. Exact retry replays; changing any
of them under that session identity refuses as an operation collision. Cover
both directions, including restart with a newly opened store handle.

### [P1] Cancellation ordering is not the accepted cleanup ending

The positive case stops at `execution_runtime == "cancel-requested"` and checks
that `adapter.stop` was called. `request_cancellation` deliberately proves only
that authority fencing and quiescence were ordered; it does not prove the
runtime was force-removed or absent, does not settle credential/launch
providers, and does not release or test lane reuse. The progress record
correctly acknowledges that the real-engine half is not attempted.

Required correction: drive the exact attached runtime through reconciliation,
force-removal, positive absence, provider teardown, and cleanup settlement via
the existing owners. Demonstrate no replacement before settlement and the
permitted successor after settlement. Preserve the sibling runtime and sibling
credential/launch roots.

### [P1] The required engine, race, and fail-closed evidence is missing

There is no real Docker session that creates a container and then reaches a
genuine unsupported-version refusal. There are also no focused cases for
runtime multiplicity, observation uncertainty, exact-identity mismatch,
provider retry, restart during the refusal-to-cleanup crossing, or sibling
preservation. These are explicit acceptance items, not optional hardening.

Add the daemon-free identity/collision cases plus a non-skipping Docker case
that traverses the production path. The Docker proof must fail if the live
engine is unavailable, as the dossier requires.

### [P2] The public-surface guard did not learn about the new operation

`TheCompositionIsOnThePublicSurface` still enumerates the pre-W32576 names, so
it passes while this new composition is private and unused. Extend the guard
when the corrected production operation is exported. Also remove the duplicate
`digest` import in `handshake.py`.
