## Finding

### [P1] Fresh bootstrap renders relative launcher sources as authoritative

`bootstrapThread` checks only truthiness for `--baton` and `--baton-config`
(`tools/codex-event-bridge/src/main.mjs`, current lines 146–151). It then sends
those strings to `readRoleInstructions` and ultimately to
`codexDeveloperInstructions`. The dispatcher path is protected by
`validateConfig`, which explicitly requires both `roleInstructions` paths to
be absolute; standalone fresh bootstrap never passes through that validator.

A relative executable is resolved by the process launch context, and a
relative config is interpreted from ambient working context. The resulting
Codex block labels those inferred locations “authoritative; do not infer.”
That contradicts the confirmed rule that a context must not infer launcher
values from repository paths, deployment symlinks, or filesystem context, and
misses the finding's explicit non-absolute-source fail-closed regression.

Required correction: reject relative `--baton` and `--baton-config` operands
in `bootstrapThread` before the instruction read or client factory is reached.
Keep the existing dispatcher validation and the four-field renderer unchanged.

The additive regression is
`tools/codex-event-bridge/test/bootstrap_thread.test.mjs`, test
`--start-thread refuses a relative Baton source before reading it`.
