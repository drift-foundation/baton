## Findings

### P0 — the proposed `1.1` transition violates the owning version rule

`work/records/2026/08/finding-v12-isolated-agent-workers/findings/finding-worker-control-api-manifests/SPEC.md` says that major versions change core meaning or required fields, while a minor version may add message kinds, manifest schemas, or capabilities but never changes an existing field's meaning. The corrected plan removes or changes required `consent_runtime` and session-posture semantics. That is not a compatible `1.1` addition.

The plan must either preserve the complete 1.0 core semantics or define an aligned major-version transition (nominally Worker Control 2.0, Agent Session 2.0, and Worker Conformance 2.0). The current `1.1` direction is not implementation-ready.

### P0 — the higher-precedence assignment contract is missing from the owner and path set

Both Worker Control and Agent Session declare `work/records/2026/08/finding-v12-isolated-agent-workers/findings/finding-v12-assignment-state-machine/SPEC.md` (W151) as their higher-precedence owner for assignment identity, generations, fencing, typed gates, runtime observation axes, and receipt authority. W151 currently defines the `consent runtime` axis as `not-started | running | quiescent | uncertain | destroyed` under `v12-assignment-1`.

A lower-level Worker Control/Agent Session revision cannot silently remove that axis. The correction must include W151's FINDING/SPEC/model/test ownership and an explicit compatible assignment-contract transition (or retain the axis). The current normative path set is incomplete and internally contradictory.

### P0 — product adoption is broader than schema selection, so the authorized path set cannot produce the claimed target

The current source tree hard-codes the 1.0 contract and consent-runtime model in multiple product/runtime owners:

- `v12/python/src/baton_v12/authority/identity.py` selects `v12-assignment-1`.
- `v12/python/src/baton_v12/worker_manager/schema.py` persists `consent_runtime`, includes it in the attempt axes, and defines its transitions.
- `v12/python/src/baton_v12/worker_manager/attempts.py` applies consent-runtime transitions.
- `v12/python/src/baton_v12/contracts/frozen.py` reads only Worker Control 1.0 and Agent Session 1.0.
- `v12/python/src/baton_v12/contracts/manifest.py` binds the assignment-1 contract.
- `v12/worker/Dockerfile` copies only `worker-control-1.0.schema.json`.
- `v12/worker/baton_worker.py` loads the Worker Control 1.0 filename.
- Runtime schema copies remain at `v12/python/src/baton_v12/contracts/schema/worker-control-1.0.schema.json`, `v12/python/src/baton_v12/contracts/schema/agent-session-1.0.schema.json`, and `v12/worker/worker-control-1.0.schema.json`.

Changing normative schemas, models, and conformance fixtures while merely selecting a parallel schema cannot make the W6636 reference composition implement the direct topology. The plan must either own the manager/store/authority/worker migration and its bounded test changes, including compatibility for persisted 1.0 attempts, or depend on a separately bound provider Work that does. Until then, a certification harness could describe a new contract while the demonstrated runtime still emits and stores 1.0 behavior.

### P1 — equivalence for carried-forward obligations needs an executable definition

The plan says unrelated 1.0 obligations and cases carry forward with byte-equivalent semantics. A new version necessarily changes version identifiers and digests. Define the exact projection and exclusions used to compare carried-forward requirements so the implementation and later reviewer cannot interpret “equivalent” differently.
