## Findings

### [P0] The object to be certified is not fixed

The record can be read two incompatible ways: certify the historical W6636
reference-worker composition, or certify the current production
Job-Manager/`tools.single_worker`/Claude runtime. Those are no longer the same
input, agent-session, exchange, workspace, or image contract. A report can
bind every digest it is handed and still certify the wrong runtime.

Before implementation, pin the exact manager entry point, adapter build,
runtime profile, engine(s), worker image digest, input-root contract, source
and workspace topology, exchange contract, credential/launch providers, and
applicable later rulings. State explicitly whether W71917/W85500 are inside
this certification target or excluded as a different later profile. If Podman
is claimed, W32391 is a prerequisite; if this is a Docker-only profile proof,
say so rather than letting `local-oci` imply both.

### [P0] The execution prerequisite graph permits a premature proof

The acceptance retains the full negative/restart/race matrix, but W32382 is
open and its sole remaining child W32577 is parked pending a runtime-deadline
ruling and implementation. W33755 has no dependency edge. An implementation
claim could therefore start an exhaustive campaign against a topology whose
required ending does not exist.

After the target decision above, install dependencies on every open provider
that owns a required target surface. W32382 is unconditionally required by
the dossier's present acceptance. W71917 and W85500 are required if the
current production runtime is the target; W32391 is required only for a
Podman claim. Keep certification blocked until those selected providers close
satisfying and are re-read.

### [P1] The supersession plan stops before an executable replacement contract

The dossier names the three obsolete cases but does not specify what replaces
their observations. The replacement must preserve the security properties
without inventing a runtime that the architecture forbids:

- pre-claim offer/reservation evidence proves that no agent session or
  container started and no input, output, workspace, tool, or credential was
  delivered;
- a lost race or expired reservation releases without runtime creation;
- one successful atomic claim is the only gate into one execution session and
  one execution container carrying the exact assignment; and
- retry/restart evidence proves the same identities without treating an absent
  consent runtime as an in-runtime observation.

Pin the replacements first in the owning conformance `FINDING.md` and `SPEC.md`,
including explicit dated supersessions of `A-17`, `C-01`, and `H-03`. Then
revise the generator and generated case documents together. Decide and record
the suite/document version transition; silently changing the semantics of
sealed `1.0` case identities would make old observations appear current.

### [P1] W6 evidence is lineage, not a reusable certification seed

The reviewed W6 pack's bytes are gone, the named rerun is partial and
`not-certified`, and its decline observation predates W33937. Its scripts and
transcripts are valuable reproduction lineage, but no W33755 verdict may
inherit an observation or claim continuity with the lost pack. The new target
needs a fresh named, refusal-on-overwrite evidence pack with independently
recomputed register, case, fixture, adapter/profile/image, observation, and
report digests.

### [P1] The complete audit boundary must include normative owners, not only case JSON

The same obsolete premise is live in three obligations, their prose table and
profile counts, the case generator, generated cases, and W6's classifier.
Plan item 2 should enumerate this path/symbol set and require a bidirectional
audit: every revised case maps to one revised obligation, every old fact name
is absent from the new current version, all unrelated cases remain
byte-identical unless a separately pinned later ruling requires otherwise,
and old versions/evidence remain traceable rather than overwritten.
