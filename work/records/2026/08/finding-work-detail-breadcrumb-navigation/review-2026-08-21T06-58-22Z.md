## Finding

### [P1] Preserve `Filter:N` when the global tab row becomes a breadcrumb

`src/baton_work/tui/app.py:1769-1772` returns from `_render_header` immediately
after `_render_breadcrumb` whenever `Console.nav` is nonempty. The existing
`Filter:N` painter at lines 1807-1813 is therefore reachable only at the top
level. W292 supersedes the global tab row inside a drill; it does not supersede
W5's approved contract that an active filter is always disclosed in the
header.

Direct reproduction with `work_filter={"status": "open"}`:

```text
top:            [Jobs] [Teams] [Inbox] ... Filter:1 lang.ada
Work detail:    Jobs > the root ................. lang.ada
re-root:        Jobs > the root ................. lang.ada
search:         Jobs > search: root ............. lang.ada
active state:   {"status": "open"}
```

Detail and search paint no filter disclosure at all. A re-rooted table still
paints the normalized clause line, but loses the separately ruled header tag.
Search results are themselves constrained by the active Work filter, so the
operator can now see a narrowed result set with no visible indication that a
filter is active.

Keep `Filter:N` right-aligned beside the participant identity on breadcrumb
headers, and budget/truncate the breadcrumb around both whole right-edge
units. Preserve the existing normalized-clause behavior rather than moving or
silently dropping it. Add focused coverage for active filters in direct Work
detail, re-rooted table, and search results, including a narrow width; each
drilled header must retain the filter tag and identity while still omitting
the global Jobs/Teams/Inbox tabs.
