## P1 — malformed `exact` markers can still manufacture Work correlation

`EventBridge.#provenAction` accepts an `exact` marker from only three field
checks: non-empty `work`, an integer `episode`, and non-empty `actionKey`. It
does not require the non-empty `turnId` whose match is what made the marker
`exact`, and its string checks accept whitespace-only values that the live
event normalizer rejects.

Those records did not prove an origin. A marker with `turnId: null` cannot be
the durable result of matching the approval request's authoritative turn id to
an immutable attempt, yet recovery publishes W30's locator. A marker with
`work: "   "` likewise passes the guard and is sent as a correlated incident;
the real Baton publisher may then refuse the malformed selector, losing the
required durable notice while the test stub reports success.

I added one case to the existing malformed-`exact` matrix and one additive
regression in `tools/codex-event-bridge/test/cross_work_fence.test.mjs`. Both
are red. Recovery should require an internally consistent exact proof and the
same nonblank text contract as `normalizeAction`; otherwise it must file the
incident uncorrelated. The action key remains opaque and must not be parsed.

## P1 — a finite but unusable marker instant aborts the whole dispatcher

`QuarantineStore.load` calls every finite `since` value usable. Restoration
later formats it with `new Date(record.since).toISOString()`. A JSON marker
containing `Number.MAX_VALUE` therefore passes `load` and throws
`RangeError: Invalid time value` during `EventBridge.start()`.

This contradicts the selected round-10 behavior and current documentation:
damaged evidence should load unknown-but-tainted so one corrupt marker fences
its own context without stopping unrelated healthy targets. I added
`W99: an out-of-range marker instant stays isolated to its context`; it fails
at startup before either target can open. Classify an instant as present only
when it is both finite and representable by the formatter used during restore.

## P2 — the new JavaScript source is recorded as binary

`src/quarantine_store.mjs` contains a literal NUL in the hash separator.
Node accepts it inside the template literal, but `file` reports the source as
`data` and Git renders its entire addition as `Bin 0 -> 5625 bytes`, hiding the
implementation from ordinary diff review. Use an escaped source spelling such
as `\u0000`, matching the existing context keys in `event_bridge.mjs`, while
preserving the same runtime bytes.
