# Independent review — 2026-08-28T22:39:46Z

Disposition: changes requested and one approver decision required. The schema,
grammar, live set and scope-resolved grant direction are sound, but replay and
read snapshots violate the approved contract, create-time labels are
unattributed, and the required race matrix is absent.

## [P0] Exact retry is denied after grant revocation

`_label_transition` calls `_require_capability` before `_replay`. An operation
that already committed is therefore re-authorized against today's policy
before the journal can return its recorded result. The reviewer regression
commits an addition, revokes `manage-work-labels`, retries the exact operation
identity and receives a denial instead of the first outcome.

The same ordering leaves a revocation race: authorization is read outside the
write transaction and a competing connection can revoke before mutation.
Move Work/scope lookup and authorization into the replay action, as the
existing receipt/close transitions do. Replay then bypasses current policy;
first execution serializes its decision, mutation, event and decision row.

## [P0] Projection and predicate results can be states that never existed

`project_work` reads its Work row and labels in separate autocommit statements.
The reviewer interleaving closes the Work and then adds `archived` between
those reads; the projection returns `status: open` with `archived`, although
the label existed only after closure.

`works_with_labels` first reads all label rows and then all Work rows. The
second reviewer interleaving atomically creates a Work carrying `excluded`
between those reads; `none_of=["excluded"]` returns that Work as unlabelled.
Both violate the parent's one-authority-snapshot rule. Wrap the complete reads
in one explicit read transaction/snapshot rather than relying on consecutive
queries over an autocommit connection.

## [P0 decision] Creation labels are not attributable

The approved parent requires creation labels to share the authorization
decision that permits Work creation. The current v12 tree still has only an
unattributed trusted-bootstrap `Core.create_work`. This cut accepts `labels`
there, while public `Authority.create_work` does not expose them. Its events
carry no public act identity and return `decision: None`; the submitted test
requires that absence.

The approver must choose whether W29400 expands to a canonical attributable,
replayable Work-creation decision, or create-time labels are deferred to a
separate provider. Deferral is recommended because this record explicitly
forbids inventing a parallel Work product when the current tree lacks one.

## Missing concurrency acceptance

The 28 submitted tests contain sequential convergence only. There is no
competing-connection add/add, remove/remove, add/remove, final-slot or revoked-
grant race. Add those after the transaction boundaries are corrected.
