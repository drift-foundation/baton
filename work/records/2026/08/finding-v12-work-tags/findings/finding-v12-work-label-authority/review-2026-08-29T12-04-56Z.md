# Independent re-review — changes requested

Work: W29400
Reviewer: `baton.codex`
Reviewed: 2026-08-29T12:04:56Z

The implementation has a replayable bootstrap method and declares schema 5,
but it does not implement the creation-attribution schema M34988/M35127
approved. Four focused regressions retain the missing boundary.

## [P0] An unlabelled Work is not bound to any creation act

The approved pipeline persists one immutable creation act keyed by Work and
unique operation identity, with a closed kind distinguishing
`trusted-bootstrap` from a future genuinely authorized creation. The delivered
schema has no `work_creation` table or equivalent Work-to-act relation.

Instead, `_bootstrap_decision` constructs an `AuthorizationDecision` carrying
a synthetic bootstrap principal, endpoint and `direct` grant, then records it
under `work-create`. Bootstrap was not authorized by such a grant; explicit
bootstrap provenance is a different arm of the approved cross-product. More
concretely, a Work created without labels has no row containing both its
`work_id` and creation `operation_id`. Starting from the Work, the authority
cannot recover the creation act or provenance, and the creation result is only
the ordinary Work projection rather than projection plus attribution.

`test_an_unlabelled_work_is_bound_to_its_creation_act` fails because schema 5
contains no immutable creation relation. Add the ruled creation act and make
the bootstrap face privately select its kind/provenance; reserve
`authorization_decision` linkage for the later authorized arm.

## [P0] Label-event act kind remains inferred rather than persisted

`work_label_event` still stores only `act_id`. `work_label_events` calls
`_act_kind_of`, which queries `work-label`, `work-unlabel` and `work-create`
decision rows until one matches. That is table guessing, even though it is not
string-prefix guessing. M34988 expressly requires an explicit act kind beside
the id, and M35127 carried that typed-event boundary into schema 5.

`test_a_label_event_persists_its_act_kind_with_its_act_id` fails because the
column is absent. Persist the closed kind and join exactly the attribution the
event names; remove inference and the fallback chain.

## [P1] Equivalent effective scopes collide on replay

Creation computes `effective = DEPLOYMENT_SCOPE if scope is None else
check_scope(scope)`, but signs the raw `scope` operand. Therefore an exact
retry that spells the default explicitly is rejected as reused for different
operands, although both calls create the same effective Work scope. M34988
requires effective scope in the canonical creation signature.

`test_default_and_explicit_effective_scope_are_one_exact_retry` reproduces the
collision. Sign `effective`, not the pre-default spelling.

## [P1] One atomic creation receives several instants

The Work insert, synthetic bootstrap decision and each initial label event
call `_now()` independently. With an advancing configured clock, one atomic
creation records different `created_at`, `decided_at` and event `at` values.
M34988 requires the creation instant to be captured once and used for the Work,
creation act and all initial additions.

`test_work_creation_and_initial_labels_share_one_instant` observes three
different instants. Capture the instant before the replay action and pass it
through every row, including the operation result record as the approved
pipeline specifies.

## Coverage

The submitted suite has no named creation exact-retry, collision or
attribution-forgery cases. Add that complete matrix around the immutable act
and creation result; incidental creation by label fixtures is not proof of the
creation contract.
