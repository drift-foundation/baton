# Independent re-review — changes requested

Work: W29400
Reviewer: `baton.codex`
Reviewed: 2026-08-29T12:12:56Z

The new immutable creation relation and typed event schema correct the prior
storage defects. Three read/result boundaries remain incomplete.

## [P0] Ordinary Work projection omits the creation act

`create_work` returns its immediate projection with a `creation` member, and
`work_creation(work_id)` exposes the row separately. The ordinary
`project_work` / `_projected` path does neither. A later reader of the Work
therefore cannot recover its creation attribution from the canonical Work
projection, although M34988 and the fourth review require the attribution on
both the creation result and Work read.

Added
`CreationAttributionIsAnImmutableAct.test_an_ordinary_work_read_carries_its_creation_act`;
it errors with `KeyError: 'creation'`.

## [P1] Label-event projection omits its persisted act id

Schema 5 now correctly stores `act` and `act_id`, but `work_label_events`
returns only `act`. For create-time additions it also obtains the creation row
by `work_id`, not by exposing and joining the event's exact persisted act
identity. Return `act_id` beside `act` and use that named key for exact
attribution.

Added
`CreationAttributionIsAnImmutableAct.test_a_label_event_projects_the_act_identity_it_persists`;
it errors with `KeyError: 'act_id'`.

## [P1] Operation-result time is not the captured creation instant

`create_work` captures one instant for the Work, `work_creation`, and initial
label rows. `_replay` then calls the configured clock again and supplies that
second value to the committed operation row. The fourth review expressly
required the operation result to share the creation instant as well.

Added
`CreationAttributionIsAnImmutableAct.test_the_operation_record_shares_the_creation_instant`;
it observes the operation row one advancing-clock tick later.

## Accepted corrections and remaining proof

The immutable `work_creation` relation, closed persisted label-event act kind,
effective-scope signature, and shared Work/creation/initial-label instant are
accepted. The named creation collision and attribution-forgery cases requested
in the prior review are still absent and remain required.
