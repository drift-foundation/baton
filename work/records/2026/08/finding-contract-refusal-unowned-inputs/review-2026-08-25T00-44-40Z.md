## [P1] `seal_refusal` reads an unowned public operand

Removing the unreachable message sub-boundary did not establish the enclosing
public input. The derived manager inventory contains

    ('caller', 'store.py:seal_refusal', 'refusal')

but that entry has no boundary-layer labels, `STATED_OWNERS` rule, or
`DELEGATED` owner. `seal_refusal` immediately reads `refusal.category`,
`.code`, `.message`, and `.durable`. Passing an object with hostile
`__getattribute__` runs caller behavior and escapes as raw `AssertionError`
before the manager can refuse it.

The additive
`ASealedRefusalReproducesTheFirstAnswer.test_public_sealing_owns_the_refusal_before_reading_it`
requires a caller-local `integrity.schema` refusal and no attribute access. It
is red. Establish that the operand is exactly the manager's
`ContractRefusal` before reading any member, then declare and non-vacuously
probe the public entry. This replaces the unreachable message check; it does
not restore double validation of a message already owned at construction.
