THE THREE MANIFESTATIONS, AND THEY ARE ONE DEFECT

  1. `category not in _PAIRING` and `code not in _PAIRING[category]` HASHED a
     rejected operand before the safe renderer ran. `__hash__` is caller code,
     so the check meant to OWN the operand was executing it, and an unhashable
     one escaped as a raw `TypeError` — the promised assertion taxonomy never
     reached.
  2. `_rejected` proved the operand and NOT the text it composed. Its redaction
     sentence and the type names it renders are text this build owns, and a
     live value may equal a substring of any of them. Safe provenance is not
     safe content — which is the containment error sixth review found in
     `SECRET_LEAK_MESSAGE`, in a second place.
  3. The message-type and durability-type assertions still used
     `type(value).__name__`, consulting a caller-controlled metaclass. This
     module has owned `type_name_of` since W6782 for exactly that reason.

  So the decision I recorded last round — "every diagnostic in this
  constructor is now behind the same rule" — was not established. The review
  is right, and it is right in the way that matters: I had fixed the two
  reproductions I was shown and written the general claim anyway.


THE CORRECTION IS A CONSTRUCTION, NOT THREE PATCHES

  `_defect(text, live)` owns the COMPLETE text of every assertion leaving this
  constructor, and every `raise AssertionError` in `__init__` passes through
  it. It composes nothing that re-enters the constructor, so there is nothing
  to bottom out: the preferred text, then `DEFECT_REDACTED`, then the empty
  string — each proved against the same snapshot, and the last one terminal
  because a non-empty value cannot be contained in it.

  THE PER-OPERAND RENDERER STAYS, and the two layers do different jobs.
  `_rejected` redacts only the operand, so an ordinary misspelled `integrty`
  is still quoted and the sentence still says what was wrong; `_defect`
  guarantees the invariant whatever `_rejected` or a type name composed.

  SHAPE BEFORE MEMBERSHIP. Category and code are established as text before
  any `in` operation can hash them — the rule `is_closed_pair` one screen up
  has followed since W6782, now applied at the site that raises.

  `type_name_of` at both remaining sites.


AND THE PART THAT MAKES IT A CONSTRUCTION RATHER THAN A CLAIM

    test_every_assertion_in_the_constructor_goes_through_the_one_owner

  reads `errors.py` with `ast` and requires every `raise AssertionError` inside
  `ContractRefusal.__init__` to pass its argument through `_defect`. A
  diagnostic added tomorrow is proved tomorrow instead of becoming the next
  reproduction. Its sibling requires no `.__name__` attribute lookup anywhere
  in the class.

  That is the difference between this correction and the last one: the last
  one was true when I wrote it and had nothing keeping it true.
