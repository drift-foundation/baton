  [P1] the substitute can itself contain a live bearer substring


THE FINDING IS RIGHT AND THE MISTAKE WAS IN MY OWN COMMENT

  The fifth correction exempted `SECRET_LEAK_MESSAGE` from the live-value test
  so that raising the substitute could not recurse, and justified it in a
  comment that reads, verbatim:

    "... which it can, if the live value happens to BE this build's
     substitute prose."

  BE. That is equality reasoning, three lines under a rule whose whole content
  is that the value test is CONTAINMENT and not equality. The registry admits
  any non-empty value and §13's own contract admits a 32-character claim
  token, so a live bearer can be a SUBSTRING of the constant — and the exempt
  replacement then carried the entire live value out.

    'a refusal quoted a live bearer v' unexpectedly found in
    'a refusal quoted a live bearer value; §13 keeps ...'


THE CORRECTION: THE REPLACEMENT IS PROVED, NOT EXEMPTED

  The exemption is gone. The replacement now passes the same containment test
  as every other message, and when the prose cannot pass it the message is
  EMPTY:

      live = _live_values()
      if _carries_live_secret(message, live):
          raise ContractRefusal(
              "integrity", "secret-leak",
              "" if _carries_live_secret(SECRET_LEAK_MESSAGE, live)
              else SECRET_LEAK_MESSAGE,
              durable=durable)

  THE EMPTY MESSAGE IS SAFE BY CONSTRUCTION RATHER THAN BY INSPECTION. It is
  the one string a non-empty value cannot be contained in, and
  `remember_secret` refuses an empty value — so there is no live value it can
  carry and no further fallback is needed. That is also what bottoms the
  recursion: the substitute's own construction re-enters this guard, and a
  substitute of `""` cannot fail it.

  THE CLOSED PAIR DOES NOT GIVE WAY. `integrity.secret-leak` is the
  diagnostic; the readable prose is the part that can be spent, and it is
  spent only when it would otherwise leak. Durability still propagates: a leak
  found while composing a diagnostic does not un-write what the raising site
  had already written.

  ONE SNAPSHOT FOR BOTH QUESTIONS. A refusal now asks the registry about two
  strings — the message it was handed and the replacement it would use — and
  asking twice would let the registry move between the two answers. The
  snapshot is taken once and passed to both, which is the same rule `_walk`
  follows for a whole document. `_carries_live_secret` takes an optional
  `live=` for exactly this; with none it takes its own, so every other caller
  is unchanged.


ONE OF MY OWN ASSERTIONS WAS THE DEFECT AND IS REPLACED

  `test_the_substitute_is_this_build_s_own_prose_and_cannot_recurse` required
  a refusal whose message IS the substitute prose to be constructed UNCHANGED
  while that prose was registered live. That is the equality exemption stated
  as an expectation, and it is now
  `test_the_substitute_is_proved_by_containment_and_never_exempted`, which
  requires the same construction to REFUSE and the answer not to contain the
  live value.

  Nothing was weakened: the replacement asserts strictly more.
