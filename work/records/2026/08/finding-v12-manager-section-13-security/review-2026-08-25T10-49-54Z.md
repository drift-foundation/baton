## [P1] Column validation can leak the live bearer before §13 runs

`boundaries.row` copies the row, validates its member set, then applies every
column shape/allowed-value rule before calling `check_no_durable_secret` at the
end. Several column refusals identify the invalid value with `name_value`.
Thus a live bearer in a malformed typed column is interpolated into a public
schema diagnostic before the secret walk gets a chance to replace it with the
bounded `integrity.secret-leak` refusal.

The additive
`EveryAdoptedRowIsWalkedOnTheWayOut.test_the_secret_walk_precedes_column_diagnostics_that_quote_values`
records an ordinary operation, hand-edits only its `settled_at` instant to the
held bearer, and reads it through public `operation_record`. Current behavior
is `integrity.schema`, and the refusal message contains the complete bearer:

```text
a persisted operation's settled_at ... this is
'bearer-9999999999999999999999999999999999999999'
```

This is the bounded-diagnostic failure §13's containment rule exists to stop:
the row itself does not leave, but the validator quotes its secret into the
refusal that does.

Move the dynamic secret walk to the first content check after the row is copied
(before any member/column rule can format caller-controlled values). Keep the
existing centralization and all five third-correction regressions; make the new
case refuse with `integrity.secret-leak` and a message containing no bearer.
