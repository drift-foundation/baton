## [P1] The derived sweep omits public surfaces, which can construct leaks

**Observed.** `EveryDurableWriterIsGuarded` derives every SQLite `INSERT` and
`UPDATE`, but it derives no universe of public surfaces. That is narrower than
PLAN item 5 and the acceptance boundary, both of which require durable **and
public** surfaces to be enumerated. The missing half is not theoretical:

- exported `manager_signature` serializes its operands as canonical JSON and
  returns that text. With a live bearer in an operand, it returns protocol
  identity containing the bearer verbatim. The later journal walk refuses the
  row, but §13 has already failed at the public identity constructor; “secret
  bytes stay outside protocol identity” cannot be established by a later SQL
  guard.
- exported `seal_refusal` returns the portable refusal document without a
  walk. An interpolated live bearer therefore leaves the sealing surface in
  `message`. The journal again refuses it later, but a direct caller already
  received the portable leak. This is precisely the bounded-diagnostic/public
  surface that the acceptance names.

**Regressions added.** The new
`ProtocolIdentityAndPortableRefusalsArePublicSurfaces` cases drive both
exported operations while the bearer is live. Current focused result:

```text
cd v12/python
```

Both failures are `ContractRefusal not raised`; the prior 39 cases pass.

**Required correction.** Guard the public construction boundary, not only the
eventual journal write: a manager signature must refuse live secret bytes
before returning protocol identity, and sealing must refuse a live secret
before returning a portable diagnostic. Extend the derived/enumerated gate to
cover the applicable public surfaces as PLAN item 5 requires, in both
directions, so another public constructor cannot bypass §13 while every SQL
writer remains green. Keep both regressions.
