The new closed documents and OCI sibling are directionally correct, but the
composition does not yet satisfy the approved abandonment contract. Three
additive regression witnesses fail against the implementation; two further

### [P0] A terminal exact retry changes the public answer's type

`abandon_attempt` commits only `_settle_recordless_cleanup`'s
`cleanup.settled` document under `runtime.destroy-abandoned`, then wraps that
document in `attempt.abandonment` only for the first caller. On replay,
`intake.py:1494-1499` returns the committed cleanup document directly. The
same public operation therefore answers `{intent, fenced, cleanup}` once and a
bare cleanup document thereafter. The dogfood operator immediately indexes
`ended["fenced"]`, so a resumed terminal attempt will fail as an implementation
error rather than replay its ending.

The terminal journal result must itself be the complete closed
`attempt.abandonment` document. Exact replay then returns the same document
without rereading the removed runtime or mutable terminal axes.

### [P0] Ineligible attempts are declared and fenced; worker/output eligibility is absent

The pinned contract requires a fresh declaration to prove
`worker_disposition == "none"`, `output == "open"`, and cleanup pending before
recording anything. The implementation checks neither worker nor output at
all. It commits `attempt.abandon` at `intake.py:1483-1485`, fences at
`1506-1508`, and only afterwards checks cleanup. A worker which already
answered `completed` is therefore destroyed and relabelled as operator-
abandoned; an already-terminal cleanup can acquire a new abandonment record
and authority fence before the eventual refusal.

Fresh eligibility must be checked atomically with creation of the intent,
before the authority call. A replayed intent may proceed across changed axes,
and a fully settled outer operation must replay before those mutable checks;
that distinction is why “check everything before `_abandon_intent`” alone is
not sufficient.

Witness:

`ExplicitAbandonmentFencesBeforeItRemoves.test_a_worker_answer_refuses_before_declaration_fence_or_removal`

### [P0] The deployment stops the runtime before the manager fences it

The central ruling is fence before any runtime control, and the dossier says
“no pre-fence stop.” `dogfood_operator._ended_however` still calls
`adapter.stop` unconditionally at lines 950-968, then enters
`abandon_attempt` only at lines 987-998. The new public operation fences before
its own force-removal, but it cannot undo the stop the deployment already
ordered. This recreates the unsafe boundary W44716 was introduced to remove:
the authority may still consider the worker live when the deployment stops
its runtime.

The receiptless branch must enter `abandon_attempt` without any direct runtime
control. Ordinary receipt-authorized cleanup may retain its own established
quiescence path; abandonment's composite owns its fence/removal order.

Witness:

`EveryPostStartBranchEntersTheEnding.test_receiptless_abandonment_does_not_stop_before_the_fence`

### [P1] The operation envelope's signature digest omits its operation id

`_abandoned_destroy_operation` computes the id inline and then hashes only the
five body operands for `signature_digest` (`intake.py:1676-1680`). Every
existing destroy-operation sibling first fixes `operation_id` and binds that
id beside the effective operands in the operation envelope's signature. The
new envelope consequently does not carry the binding its own `operation`
contract promises and does not mirror the siblings it says it mirrors.

Compose the id once, then derive `signature_digest` over kind plus operands
including that exact id, following `destroy_operation`,
`failed_start_destroy_operation`, and `refused_session_destroy_operation`.

### [P1] The committed authorization is only partially adopted, and final observation is unreachable

`_abandon_intent` validates attempt, assignment, runtime and decision, but not
the committed `authority_operation_id` or `reason`; the later fence uses the
caller's freshly derived values rather than the adopted record. The record is
the authorization, so all six closed members must agree and the fence must use
the adopted operation/reason rather than a parallel spelling.

Separately, `evidence["observed_after"]` was displaced below the unconditional
return in `_abandonment_reason` (`dogfood_operator.py:1020-1023`). It is now
unreachable and references names not in that function. Restore the final
read-only observation to the end of `_ended_however`; it is the evidence an
unsettled abandonment needs to tell an operator what remains.
