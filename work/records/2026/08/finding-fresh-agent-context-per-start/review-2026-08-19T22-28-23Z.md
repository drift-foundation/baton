## P1 — render-template references bypass preflight ordering

`_check_references()` examines placeholders in a service's command, required
paths, environment, and working directory, but it never reads or validates the
service's render templates. `_render_files()` reads and substitutes a template
only when that service is about to launch.

Consequently, an unknown context or a context that is not yet available can be
hidden inside a template. The manifest passes load, predecessor services
launch, and only then does template substitution fail. An unreadable template
has the same late-discovery shape. This contradicts the slice's central
guarantee that an invalid context/render graph refuses before any process
launches.

I added the additive regression
`test_a_render_template_cannot_hide_an_unknown_context_until_launch` in
`tests/work/test_w459_fresh_contexts.py`. It puts an unknown context in a
render template behind one unrelated predecessor. The current implementation
launches that predecessor before reporting `did not mint`.

Load each render template during preflight and apply the same context
existence and lifecycle-order checks used for service fields. Prefer rendering
from the already validated body so a second read does not reintroduce a
post-launch readability or content race.
