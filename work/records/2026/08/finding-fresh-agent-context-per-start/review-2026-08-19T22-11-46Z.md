# Slice 1 review — changes requested

## P1 — context availability is not part of lifecycle ordering

`_check_references()` verifies that a referenced context EXISTS, but adds every
declared context to one `minted` set regardless of its `after` services. It
does not prove that the context will have been minted before the referencing
service is launched, nor detect a cycle spanning service and context edges.

The added regression constructs `first -> worker -> late`, makes `worker`
reference `tuner`, and makes `tuner` wait for `late`. The manifest passes
preflight, `first` launches, and only then does `worker` fail substitution.
That contradicts the slice's central fail-before-launch guarantee.

Treat services and context availability as one ordering problem during
manifest validation. A service may reference a context only if that context's
`after` set is necessarily complete before the service; cross-boundary cycles
must refuse before lifecycle state or processes exist.

## P1 — rendered files can overwrite a symlink target

`_render_files()` opens its controller-owned target with
`O_WRONLY|O_CREAT|O_TRUNC` and then calls `chmod` by pathname. Unlike the
controller's lock, state, and logs, it does not use the existing `_open_owned`
boundary or otherwise refuse symbolic links, hard links, non-regular files,
or a pathname race.

The added regression has the context command place
`run/context/dispatcher.json` as a symlink to a file outside the mailbox.
Startup succeeds and truncates/replaces that outside file. Private directory
mode is not sufficient: the same user, a faulty context command, or a race can
still plant the entry.

Open rendered targets through the same no-follow, regular, private,
single-name ownership boundary as the controller's other files. Refuse rather
than following or replacing an unexpected entry.

## P2 — an empty `threadId` is accepted as a usable locator

`_mint_context()` checks only key presence. `{ "threadId": "" }` starts the
service and reports the stack healthy, even though `_load_state()` later
refuses that same state because it records no usable `threadId`. Reject an
empty locator before recording state or launching a consumer.
