# Slice 2 ACP correction review — signed off

No remaining slice-2 findings.

The corrected deployment contract now gives every managed start a random
32-hex start identity and uses that identity in the rendered ACP bridge
configuration's `stateDir`. A later managed start therefore reaches an absent
selection location and creates a genuinely fresh ACP session without deleting
or overwriting the preceding start's selection history.

This preserves the two boundaries that mattered in review:

- W459 controls managed restart boundaries, so a later `just start` does not
  resume an earlier managed ACP session.
- W27 still controls recovery within one bridge run and explicit persistent
  deployments. `session.mode` remains `new`, and the bridge's create-only
  selection and refusal rules are unchanged.

The lifecycle controller records the start identity in its private state and
uses that recorded value when checking a running service, so `status` compares
against the exact configuration that was launched. The shipped manifest and
ACP template agree on the per-start path, and both templates remain deployment
artifacts rather than mutable operator-maintained session locators.
