No implementation finding remains in the slice-3 regression or operator
guide.

The new test drives the real lifecycle controller and a real Baton authority
through two starts. It proves that the participant and actionable Work survive,
that both the Codex-shaped context locator and ACP selection location rotate,
and that the preceding ACP selection remains durable history. The focused
W459 suite passes **39 tests**, and `git diff --check` is clean.

This is not yet the terminal deployment proof. Both vendor processes are
explicit stand-ins: the test neither bootstraps a Thread through a real Codex
app-server nor opens a session through a real ACP agent. The implementer was
right not to describe that as vendor-level evidence.

The remaining gate is operational rather than another code change. After this
tree is committed and deployed, an operator must run the documented two-start
sequence and retain evidence that:

1. `startId`, every minted Codex `threadId`, and the rendered ACP `stateDir`
   change;
2. participant addresses and their actionable Work remain the same;
3. the first start's ACP `session.json` still exists and selects a different
   session from the second start.

W459 must remain open until that real Codex + ACP evidence is reviewed. The
implementation is accepted; the Work is handed to operations for the proof.
