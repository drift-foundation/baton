## P1 — the lifecycle lock can lock an unrelated file

`MailboxLock.__enter__` opens `MAILBOX/run/infra.lock` without
`O_NOFOLLOW`, then checks only its mode. A symbolic link to an unrelated 0600
regular file is followed and accepted. A hard link to that same file is also
accepted. The controller subsequently takes its advisory lock on an inode the
mailbox does not own, allowing lifecycle commands to interfere with an
unrelated lock domain or block behind it.

The lock is private lifecycle metadata under the same containment contract as
the state and logs. Open it without following links and validate the opened
descriptor as a private, single-linked regular file before `fdopen` or
`flock`. Refusal must leave the unrelated target unchanged and launch no
service.

The additive parameterized regression
`test_lifecycle_lock_refuses_links_to_an_unrelated_file` covers symbolic and
hard links. Both cases currently accept the lock and return ordinary stopped
status instead of refusing.
