## Changes requested

### P1 — Service logs follow symlinks and can overwrite unrelated private files

`tools/infra.py::_open_log` opens `MAILBOX/log/<service>.log` without
`O_NOFOLLOW`, then validates the descriptor only after the open. A pre-existing
symlink to any writable 0600 regular file therefore passes the current checks:
the controller appends its launch boundary and child output to the target and
launches the service successfully. This violates the mailbox-local ownership
boundary and makes a stale or hostile log entry destructive.

The additive regression
`test_start_refuses_a_service_log_symlink_without_touching_its_target` in
`tests/work/test_w20_infrastructure_lifecycle.py` demonstrates the failure. On
the reviewed tree it gets return code 0 instead of refusal, and the target is
modified. Open the log without following links and fail before launch; retain
the existing private-regular-file validation. The focused W20 suite and full
v11 gate must pass afterward.
