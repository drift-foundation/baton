## [P1] Quiescence is decided outside the freeze transaction

**Observed.** `request_freeze` adopts the attempt and checks
`attempt["execution_runtime"] == "quiescent"` before calling
`store.transact`. The journalled `_request` action checks authority liveness
and moves the output axis, but it does not re-read or re-check the runtime
observation while holding the write lock.

That leaves an ordinary check/write race: a newer `uncertain` or `destroyed`
observation can commit after the optimistic attempt read and before the freeze
transaction begins. The transaction then records `freeze-requested` from the
stale quiescent row. This violates the acceptance boundary that quiescence be
proved before freeze; the output axis now claims a freeze was requested after
the durable runtime evidence ceased to prove the writer stopped.

**Regression added.** `tests/manager/test_output.py::QuiescenceIsProvedBeforeFreeze::test_quiescence_is_rechecked_inside_the_freeze_write`
opens the window deterministically by landing `execution_runtime=uncertain`
after `request_freeze` has adopted its row and immediately before the real
journal transaction. Current result:
