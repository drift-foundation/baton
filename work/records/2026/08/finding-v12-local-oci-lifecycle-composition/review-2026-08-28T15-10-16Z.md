## Finding

### [P1] The lost-claim case drives a malformed answer, not a competing claim

`test_a_lost_claim_launches_nothing` sets `session.claim_answer = None` and
describes that as the authority saying somebody else holds the claim. The
authority port instead owns a claim answer as one assignment document, so
`None` is rejected as `integrity/schema`. The offer remains `accepted`; no
claim refusal or settlement is recorded.

The final no-engine assertion is therefore non-probative: `submit_claim` never
launches a runtime on any path, and the case does not attempt activation or
start after the failed claim call. It proves only that a malformed injected
document does not itself call the engine, a boundary already covered by
`test_the_injected_claim_answer_is_owned_before_recording`.

`evidence/w6636-review-lost-claim-shape.py` records:

```text
None claim answer -> integrity schema
reason: the claim answer's identity is one exact document; this is none
offer state after malformed answer: accepted
```

Model the race as the claim capability's typed refusal, settle that refused
operation through the existing `claim-refused` path, and then attempt the next
manager lifecycle step. Assert the offer's durable refused ending and that
activation/start is refused before any engine call. That establishes the
supersession's actual requirement: a loser cannot cross from reservation into
execution.
