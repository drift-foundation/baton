## Accepted direction

- The destroy-answer contract now names and validates the credential and
  launch provider endings instead of refusing the real adapter document.
- A destroy whose current answer is not an ending is not journalled as a
  replayable operation result.
- On the ordinary refused-start paths, the manager reconciles a created
  runtime into an attached identity or records `uncertain`, while preserving
  the original refusal pair and starting no replacement.

## Changes requested

### P0 — a provider teardown pending after runtime absence is skipped on retry

The first destroy can truthfully advance `execution_runtime` to `destroyed`
while leaving cleanup pending because a provider reports `unresolved`. On the
exact retry, `_destroyed` sees the already-destroyed runtime axis and returns a
synthetic absent answer without invoking the adapter. That answer carries no
provider endings. Because those members are optional, the retry records
cleanup `complete`, even though no provider was retried and the last known
provider state was unresolved.

The submitted retry case supplies a second positive adapter answer but never
asserts that the adapter received a second destroy call, so it passes through
this bypass. Provider applicability and the outstanding ending must survive
the runtime-axis transition and process restart. A pending cleanup with a
destroyed runtime must re-enter provider teardown; a missing provider member
must not erase a known unresolved provider. Add a regression that answers
`unresolved` twice, proves two adapter calls and a still-pending cleanup, then
answers terminal on the third call and settles.

### P0 — failed refused-start reconciliation leaves the attempt stranded

`_start_failed` catches a reconciliation refusal only to extend the exception
message. It does not durably settle `execution_runtime`. If adapter listing is
unavailable, the attempt remains `start-requested` with no runtime identity —
the exact stranded state this round is intended to eliminate. The submitted
test checks that both messages cross, but does not inspect the durable row.

Every exit from refused-start settlement must leave an ending other than
`start-requested`; where exact identity/state cannot be established, record
`uncertain` before re-raising. Cover missing capability/transport and the
adapter's non-`ContractRefusal` launch-fault boundary in the remaining
post-claim failure matrix.
