1. THE DEPTH FRONTIER — `ROW_DEEPER` NOW HAS SOMETHING TO REPORT

It was defined and unused since the first slice, and I named that gap myself
rather than leaving it to be found: depth-frontier tokens need the projection
to report what the DEPTH bound cut off, and it reported only what a BRANCH
PAGE cut off.

`dependency_neighborhood` gains `frontier`, a per-branch-key exact direct
count of the edges the depth bound did not walk. It is taken at the exact
point the walk declines to expand — `remaining <= 0` — with the same bounded
reader at limit zero, so it is a COUNT and no rows: naming what the bound cut
off materializes nothing.

It is SEPARATE from `omitted` because the two absences are opened by
different keys. A dense branch is widened with Enter; the depth bound is
lifted with `+`. One token for both would make the key that opens it a guess,
which is the reason the contract names two token shapes.

`graph.py` emits `[+N deeper blockers]` / `[+N deeper dependents]` through the
same branch anchor, and when a branch has both, the dense page comes first —
deterministically, so a reader who sees both always sees them in one order.


2. THE CONSOLE

`[b]` opens the dependency NEIGHBOURHOOD. The flat blocked-by/blocks page it
replaced is deleted rather than left behind a flag.

STATE. `graph_center`, `graph_depth`, `graph_anchor` and `graph_expanded`
join `NAV_STATE_FIELDS`, so Esc restores the exact prior graph — center,
depth, selection and branch pages together. Selection is an IDENTITY: a Work
id for a Work row, and a branch key for a token, because two branches of one
Work are two different things to open. Storing a row index would repeat the
selection drift the Jobs table already forbids, and a regression separates
the two answers by deepening UPSTREAM, which inserts rows above the
selection.

KEYS. `j`/`k` move by row and set the anchor from the row they land on.
Enter recenters on a Work — pushing one navigation frame, keeping the depth,
resetting branch pages, and making the selection the new center — or widens
exactly one branch page on an overflow token. On a depth-frontier token Enter
does NOT quietly widen a page: the console says `+` is the key, because a
plausible action on the wrong token is worse than none. `+`/`-` move depth
inside 1..3.

RE-ANCHORING happens after the act as well as before it. A depth REDUCTION
can remove the selected Work, and the ruling says selection returns to the
center when it does; waiting for the next key or the next paint would leave
the console briefly pointing at a Work it is not showing.

ROWS ARE DERIVED, NEVER STORED. Keys act on the graph rather than on the last
paint — a handler reading a cached row list would do nothing before the first
render and something stale after a resize. Width is passed only because the
renderer needs one: the row order and every row's identity are
width-independent, which is a property the first slice already asserts, and
that is what makes this sound.

REFUSALS ARE VISIBLE. A damaged store's `GraphInvalid` and a terminal too
narrow for one complete selector are both painted rather than raised through
the console.

EMPTY IS AN ANSWER. W17's `(no blocking or dependent neighbors)` is kept
verbatim: a lone token with nothing beside it reads as a view that failed to
load.


3. ONE PIECE OF SHARED MACHINERY CHANGED, AND IT IS RECORDED

`_nav_capture`/`_nav_restore` copied lists and not dicts. That was harmless
while no navigation state was a dict; branch expansions are one, and a shared
dict would let widening a branch after Back rewrite the frame the operator
came from.

RECORDED HONESTLY: the dict copy is currently UNWITNESSED and I could not
witness it. Every path that captures the expansion map also replaces it with
a fresh one — `_open_graph` and the recenter both assign `{}` rather than
mutating — so no reachable sequence lets a live mutation reach a frame that
is still on the stack. It is defence for the paths the next slice will add,
named as unwitnessed rather than counted as covered, and the mutation result
that says so is in section 5.

A CAPABILITY IS GONE AND THE APPROVER SHOULD SEE IT NAMED. The old page's
Enter performed a deliberate cross-team drill-through: it unwound the whole
navigation stack and re-rooted the Jobs tree at the far Work, rebuilding that
Work's own ancestry (W292 round-1 [P1], R105). The approved W4996 contract
replaces Enter with recentering and says explicitly that it "does not jump to
the Jobs table", so that jump is no longer reachable from `[b]` at all. The
contract authorizes the change; it does not obviously intend the capability
to vanish, and no other key was invented for it here because inventing one is
not mine to do. If it should survive, it needs a key and a line in the
contract, and I would rather ask than choose.
