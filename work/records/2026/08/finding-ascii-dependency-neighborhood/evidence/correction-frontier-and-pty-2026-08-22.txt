2. [P2] DISCLOSURE DEPENDED ON EDGE CREATION ORDER

Clearing the frontier entry when a later path expands a branch handles
longer-first. With the SHORTCUT older, the branch is expanded first and a
later, longer path reaches it at `remaining == 0` — and recorded a frontier
for edges already drawn. Same false claim, other direction.

CORRECTED: a depth-bound visit asks the same memo the expansion sets. If
`branch_key(work, side)` is already in `state["walked"]`, the branch has been
expanded in this response and is not a frontier, whichever path arrived
first. The later-expansion pop stays, so both orders are covered by two
mechanisms that agree rather than by one that happens to fire.

The added case asserts the two orders AGREE rather than asserting each
separately — two corrections were needed and each covered one direction,
which is exactly the shape that made this survive a round.

A second case pins that the correction did not silence a REAL frontier: a
branch nothing expanded is still disclosed with its exact count, and stops
being disclosed when the depth reaches it.


3. THE PTY MATRIX — AND IT FOUND A CRASH THE FOCUSED SUITE COULD NOT

`tests/work/test_w4996_dependency_graph_pty.py`, 11 cases covering the
contract's own list: many-to-one, one-to-many, both sides at once, the
containment/duplicate text that must be absent, the empty state, the footer
legend and its depth, a narrow terminal keeping every relationship, a resize
in BOTH directions, the stacked fallback, and Enter-recenter with Esc back.

THE CONSOLE DIED ON A 30-COLUMN TERMINAL. `_graph_row_key` assumed every row
carried a `work`, and the STACKED renderer's presentation rows carry no
identity by design — that is its own documented rule: source, arrow and
target on three rows, and only the row that displays its own Work is
selectable. Reaching that fallback raised `KeyError: 'work'` and exited 1
with a traceback.

Every focused case passed while this was true. They drive the console at
widths where the layered form fits, and the narrow REFUSAL they do assert is
a different boundary from the narrow FALLBACK. This is precisely what the
review asked the PTY matrix for.

CORRECTED: a row with no `work` is not selectable. Pinned in the focused
suite too, at the width that reaches the stacked form, and
mutation-checked there.

ONE PTY CASE IS DELIBERATELY NOT THE ONE I FIRST WROTE. The narrow REFUSAL
needs a terminal narrower than one complete selector, and the console's own
table cannot start at such a width — it exits before the graph is reached. So
the refusal stays asserted in the focused suite where it can be measured, and
the PTY case asserts the boundary a real operator actually reaches: the
stacked form, which is what was broken.

The matrix drives the centre through SEARCH rather than by counting table
rows. The Jobs table orders by readiness and priority, so which row leads is
a property of the dependency shape these cases vary — and searching also
exercises the search entry path the contract requires.
