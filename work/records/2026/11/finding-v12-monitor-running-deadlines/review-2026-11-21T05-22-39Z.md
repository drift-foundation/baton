## Observations (non-blocking; recommended for the composition pass)

1. **"running" for an ended provider.** When the provider process has ended but the stage is still non-terminal (the attempt continues into verification), `stage_timing` reports the frozen provider duration under the label `running` (the structured result carries `ended_at` and `scope`, and the provider limit is correctly dropped). The owner asked for invocation duration, so the number is right; the word `running` is imprecise for an ended process. Suggest `provider ran 12m30s (ended)` or equivalent when `ended_at` is set and the stage is live.
2. **Publication cadence.** `_tick` republishes `invocation.json` every `ACTIVITY_SECONDS` (1 s) with an fsync'd stage-and-replace, whether or not the fact changed; the activity count publishes only on change. Over a 3600 s provider turn that is ~3600 unneeded writes per worker. Suggest publishing on change only (start, end), keeping the final sample on stop.
3. **View shape.** `exchange.observation` sets `view["invocation"]` only when a document was read or refused; with no document the member is absent rather than `None`. Consumers use `.get`, so harmless, but a stable shape (`None` default) would be cleaner. Also `created_at` may be `None` for a Job whose submission row is absent; that path is untested (the emitter passes the member through).

Cosmetic: `running {running:<8}` misaligns for `not started` (11 characters).
