## Assessment

**The race is real and the diagnosis is correct.** The failing case waits on `action.json` by existence only (`await_file`, then `json.loads` at the first byte) while the composed fixture child created the file with `Path.write_text`, which opens with `mode='w'` — creating a visible empty pathname — before writing and closing the JSON. A parent reading in that window sees an empty file: the owner's `JSONDecodeError` at position 0. This is fixture publication, not product code: the writer is the test module's composed child (`ManagerComposition`), and no product module writes `action.json`. The deterministic probe makes the schedule certain instead of probabilistic, with no sleep and no swallowed JSON (the probe catches the error only to report the negative control; the fixture reader parses strictly, unchanged).

**The correction is fixture-only, atomic, and ordered.** `publish_action` writes and closes `partial.txt` first (the retained partial output the kill/stop cases assert), then writes and closes the JSON to the sibling `action.json.tmp`, then `os.replace` renames it to `action.json`: the ready pathname never exists incomplete, and when it exists the partial output is already present. Same-directory rename is the correct interprocess publication primitive here; no durability claim is made. The base order (action.json, then partial.txt) is reversed by design so readiness implies both.

**Manager-loss guarantees are unchanged.** `test_manager_loss_retains_unknown_and_restart_does_not_repeat` still SIGKILLs the manager by the pid read from the ready marker, asserts the controller's `without final enforcement report` fault, the retry's exit 1 and byte-identical `action.json` (no repeat); the deadline/exclusion, author-exception, parent-loss and operator-stop cases are untouched except for the shared writer. Production manager/guard/enforcement code is not in the delta.

**The new regression rejects the legacy writer without copying the implementation.** `ActionPublication` hooks the real `Path.open` and, at the post-open/pre-write instant of any `'w'` open of `action.json`/`action.json.tmp`, asserts the ready marker is absent and the partial output complete, then asserts the final JSON and the removed temporary. Against the legacy primitive the first open IS `action.json`, so the marker exists at that instant and the test fails (my probe); against the new helper the open is the temporary and the test passes. It inspects the boundary, not the helper's steps.
