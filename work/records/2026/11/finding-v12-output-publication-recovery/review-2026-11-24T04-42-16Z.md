### C5.1 Start effect can escape signal cleanup (confirmed, both scripts)

`qualify-w385695.sh:543–545` and `option-a-setup.sh:195–196` record MANAGER_STARTED only after the blocking start command returns. Their finish functions consult only that variable. A TERM after the stack start effect but before the assignment invokes finish with it empty, so cleanup never reconciles the stack it just started.

`probe-cleanup-cuts.py` extracts the exact serve/failures and finish functions, substitutes only stack/engine operations, and sends a real TERM at that boundary. Both exit143 after the simulated start effect with zero stop calls. These are local deterministic command doubles, not actual manager/container launches. The fake start marker and stack_live readback identify the effect; no real stack is left behind.

Required: retain start intent and pre-start ownership evidence before the external action, then reconcile it on every exit, including interruption/lost reply. Stop only positively owned processes; unknown ownership must be unresolved rather than permission to stop. Keep the positive clean-failure/partial-failure/preexisting-stack cases. Exercise interruption before start, after the effect but before acknowledgment, and after acknowledgment in both scripts. Reuse the supported stack identity/ownership mechanisms rather than treating a PID alone as ownership.

### C5.2 Failed cleanup inspection is incorrectly treated as absence (confirmed)

`qualify-w385695.sh:111–119` maps every failed inspect to `absent`, then says “nothing to release.” An unavailable daemon/timeout does not prove that the selected paused container is gone. The second inspect after failed unpause has the same uncertainty problem: a non-true/error answer is reported as no longer paused.

Independent probe returns125 with “daemon unavailable” from the fake engine. Exact reconcile_pause exits0 and prints “no longer exists or did not answer (absent); nothing to release”, without an unresolved marker. Required: distinguish positive absence/not-paused from unreadable/failed inspection; retain the selected intent and report unresolved cleanup and truthful phase outcome when state cannot be confirmed. Do not blindly unpause an unverified runtime. Extend tests to failed initial inspect and lost/failed unpause plus failed readback, as well as positive gone/unpaused cases. The author's current adapted probe equates a generic return1 with gone and therefore does not establish positive absence.

The watcher is now awaited before reconciliation, an improvement. Preserve that ordering and ensure a terminated watcher cannot leave an in-flight engine child able to pause after reconciliation; this is a source-review concern, not a reproduced engine race here. In particular, waiting only for the shell PID is not evidence that its external engine operation ended. Keep any remaining uncertainty explicit.

### C5.3 CLI driver's host cleanup is not owned (confirmed selection; no destructive run)

`cli-in-image-driver.py:32–43,128–132` scans all visible `/proc` entries for `sleep 30*` and SIGKILLs every match in finally. Its documented host mode can therefore terminate another task's process.
