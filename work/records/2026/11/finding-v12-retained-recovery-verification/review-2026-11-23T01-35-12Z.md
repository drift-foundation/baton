## What the delta does, and my findings

### 1. Recovered checkpoint (`review_cycles.freeze_recovered_checkpoint`)

**Behaviour.** This is a new, separate entry point. Ordinary
`freeze_checkpoint` keeps its public signature and behaviour; it now
delegates to `_freeze_checkpoint` with `_recovery=None`, and every ordinary
branch is unchanged. Before freezing, the recovery path proves that:
- the original writer exists for `(attempt, generation)`;
- the writer's committed `review-line.release-writer` act names this writer
  and this line;
- the release fence is committed;
- the original attempt shows `execution_runtime=destroyed` and
  `cleanup=retained`, which is positive cessation and retained custody.

Inside `BEGIN IMMEDIATE` it also refuses when:
- the writer is not `revoked/released`;
- the line's state or `current_checkpoint_id` has moved since the release;
- any later-generation writer exists on the line.

**What it creates.** It creates no writer, assignment or reopened producer.
The checkpoint fence is the committed release fence, and no new Authority
fence is minted.

**Candidate binding.** Frozen evidence must equal the approved retained
`base` and `head`. This is checked both inside `_freeze_checkpoint`, before
`validate` and the frozen record, and again by the outer function after
replay. A replayed checkpoint that names another candidate therefore refuses.
The pin is re-proved against the durable line row, as before.

**Evidence.**
- The joined drift case (`git checkout --detach base` in the line) refuses
  with `digest`.
- The reviewer examines nothing, the engine counts one start, and the
  original frozen output and custody bytes are unchanged.
- The full `test_review_cycles` module passes 167/167.

### 2. Composition and pinned input (`stage_execution`, `single_worker`)

**Resolution in prepare.** For a review stage whose Job has a durable
`handoff_of`, `_prepare` resolves the recovered checkpoint from the handoff's
producer attempt, generation and candidate. It then re-reads the line and
requires that checkpoint to be current. Ordinary Jobs have no handoff, so
their path is untouched.

**The input document.** `recovery_document_for` emits
`baton.recovery-review-input/1`, containing `{handoff, handoff_digest}` with
the digest computed over the durable handoff record.

**Delivery.** `single_worker` both publishes and proves this document as
`recovery-review.json` in the attempt's pinned input root. It is added to the
declared input name set, which gives it the same lifetime and proof as the
task and handoff documents.

**Original task.** The original admitted task is not rewritten.

### 3. Verdict binding (`review_driver`, `claude_agent`)

**Host side.** `end_review_from_result(..., recovery_digest)` passes the
expected digest to `review_verdict_from_result`. Before any verdict is
recorded, that function requires exactly one present output claim

The stage stays `answering` with nothing owed. This is the existing
report-and-hold behaviour: visible, truthful, and with no verdict.

**Worker side.**
