## 2. R1 — pre-start release, uncertain-start waiting, fencing

**Corrected for the reported case.**

- **Release (D1).** After a launch delivery refused before any start, the
  holder's evidence is `not-started`, `ended_before_start: true`, and a
  successor acquires the same home through the worker's own hold. The
  evidence releases only its own holder; altered forms of it do not release.
- **The released holder cannot come back (D1).** Its start is refused
  `already-terminal` with no adapter call and no start operation journalled.
  Its own request for the home is now pending behind the successor.
- **Fence inside the transaction (D2).** On the real worker path I committed
  a preparation ending after the start caller's preliminary checks and
  immediately before its start transaction, as a second manager process
  would. The start was refused inside the transaction: no start operation,
  axis still `not-started`, no adapter call, no provider run.
- **The orders cannot cross.** A start operation can commit only when no
  ending exists; release requires an ending and no start operation. An
  ending recorded after start intent (D3) leaves the evidence at
  `start-requested`, not released, and a successor stays pending with the
  record unchanged.
- **Uncertain start waits (D4).** With start intent recorded and the engine
  refusing the start, the axis is `uncertain`, cleanup `pending`, and the
  home is not released. That is the approved rule.
