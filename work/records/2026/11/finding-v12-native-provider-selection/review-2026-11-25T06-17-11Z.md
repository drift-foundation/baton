## Limits and follow-ups (none blocks import)

- **L1 — D1 has no operator command.** The recovery operation is a Python API with no caller in `tools`. Until one exists, a failed first initialization can only be recovered by hand-written code. Needed before Q4 relies on it, not for Q1.
- **L2 — D1 covers failure before any write into the home.** The seed step writes its own marker and temporary file into the home first, so an interrupted copy changes the snapshot and stays held with no recovery path. This is the ruling applied strictly; it means the common "copy failed halfway" case is not recoverable by this operation.
- **L3 — the leak guard is whole-file.** The login file is registered as one byte string. A durable write containing only a token from inside that file is not detected. Decoding the file to register its tokens would contradict the exact-bytes rule; the gap should be stated in SEC-3 terms rather than assumed closed.
- **L4.** `oci.py` selects the file slot by the literal `"codex"` behind a flag named for image receipts. Correct today because the slot name is `codex`; derive it from the policy.
- **L5.** With this candidate a Codex worker composes under production policy. Nothing activates it, but the remaining barrier to a native launch is now selection and image, not code.
- **L6.** The three baseline failures belong to `review_cycles` and the secret inventory, not to this Work. They need their own Work; every focused run that includes `test_secrets` exits 1 until then.
