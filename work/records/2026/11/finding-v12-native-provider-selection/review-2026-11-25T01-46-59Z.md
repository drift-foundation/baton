- **C2 (before Codex selects this mode). A failed first start is
  indistinguishable from an interrupted copy, and there is no recovery
  operation.** Probe P1: the source is absent on the first start; nothing
  is copied (home state `empty`, no marker); the external receipt stays
  `initializing`; a retry with a corrected source refuses. A wrong source
  path is the most likely first-run mistake, and it leaves that Job
  worker's home refused with no supported way out. Exact correction, one
  of: (a) when the callback fails and the home is still verifiably
  `empty`, withdraw the `initializing` receipt; or (b) keep the refusal
  and document the operator recovery procedure. This needs the owner's
  choice, because the ruling says incomplete initialization is never
  reseeded. In either case "explicit recovery" needs a written procedure:
  today it is a refusal only.
- **C3 (before Codex selects this mode). The manager's delivery bound is
  4,096 characters** (`credentials.MAX_BEARER`); the seeding callback goes
  through it. The qualification helper allows 1 MiB. A subscription login
  file larger than 4,096 characters would pass qualification and refuse
  in a native Job. The real size is not known and I did not read it; the
  owner can supply the byte count alone.
