## 2. Required in the disjoint step

**R1 — the prompt operand must not be parseable as anything else.**
- Observed in the retained help: `codex exec [OPTIONS] [PROMPT]` and
  `codex exec [OPTIONS] <COMMAND>`, with commands `resume`, `fork`,
  `review`, `help`; and a prompt of `-` reads stdin.
- So a prompt that begins with `-`, or is exactly a command word, is not a
  prompt. After the join every Codex prompt begins with D's label (`[`),
  which makes this safe by construction, but the adapter should not rely
  on another slice for that.
- Required: the Codex adapter refuses, before the provider, a prompt
  operand that is empty, begins with `-`, or equals a subcommand word. One
  focused test. No `--` separator is asked for: the help does not show one
  and I do not propose an unevidenced operand.

## 3. Conditions on the shared join (after D's imported checkpoint)

needed.**

  member, including `credentials` with a path. The packet correctly leaves
  the credential path, the managed-instruction path and the session path
  null; N3 established none of them.
- Consequence: the join can add the hooks, the entry binding and the
  guards, but a `codex` entry in `REALIZATIONS` cannot land with a null

  auto-loading is not needed; the path only has to be one Codex does not
  own. For the credential path there is no such freedom: it must be where
  the pinned build reads its login.

  credential path for 0.169.0 — a further offline exact-image observation,
  or the N5 seed-login step. Neither is selected. I recommend deciding it
  when the join is scheduled, not now.
