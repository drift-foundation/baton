# Review — TUI scoped-notice audience picker

Reviewer: `baton.reviewer`

Reviewed: 2026-08-11T15:29:59Z

Outcome: **changes requested**

## Findings

### R1 — Blocking: retained scoped drafts reopen as global

The ruled acceptance boundary says the chosen audience survives draft
retention and restart/reopen. It currently does not:

- `InboxState._draft_from_state()` snapshots a notice's subject, body,
  recipient, attachment, answer relation and reply marker, but not
  `notice_scope`;
- `src/baton_tui/drafts.py` has no audience field in the version-1 schema;
- `InboxState.reopen_draft()` restores notice mode and compose buffers, but not
  `notice_scope`.

An independent minimal probe constructed a `web.*` notice, snapshotted it,
reopened it in a fresh `InboxState`, and observed `notice_scope is None`.
`send_compose()` deliberately maps both `None` and `*` to protocol-global
`scope=None`; therefore confirming the reopened draft would broadcast it to
everyone. This violates acceptance 4 and the no-global-fallback requirement in
acceptance 7.

Required repair: persist an explicit notice audience, validate it at the local
draft boundary, and restore it for a reopened notice. Preserve compatibility
with existing version-1 notice drafts that lack the new field; they represent
the historical global-only composer and should reopen explicitly as `*`, not
become unreadable. Add a real retention/restart/reopen regression that sends
the reopened draft and measures the frozen authority audience as only the
chosen team.

### R2 — Important: scoped success is reported as global

After every successful notice publication, `send_compose()` formats the status
as `to everyone (notice)`, even when the supplied scope was `web.*`. The wire
operation is correct but the console tells the human the wrong audience.
Capture the chosen audience before clearing composition state and name it in
the success report; keep the existing everyone wording for `*`.

### R3 — Lifecycle coverage and state cleanup are incomplete

The new tests demonstrate in-session survival across confirmation decline and
core refusal, but do not cover the ruled external-body editor or retained
draft restart/reopen paths. `notice_scope` is also not explicitly reset after
a successful send, after retained cancellation, or when a scope picker is
cancelled. Make the audience lifecycle explicit so a previous notice cannot
leak into later state, and cover the editor and cleanup boundaries with driver
tests.

### R4 — Handoff state is stale

`PROGRESS.md` still says implementation is starting although the handoff says
it is awaiting review. The implementer owns that file; update it with this
review outcome and the repair evidence before the next handoff.
