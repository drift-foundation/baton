## R5 — Blocking: version-1 format lets the frozen console drop the audience

The repair adds an optional `notice_scope` field but keeps
`src/baton_tui/drafts.py::VERSION` at 1. That is unsafe across versioned-console
selection or rollback:

1. The new console writes a scoped notice draft as document `version: 1` with
   `"notice_scope": "web.*"`.
2. The frozen 1.0 `bin/baton-tui` accepts version 1 and its validator ignores
   unknown fields.
3. Its `InboxState.reopen_draft()` reopens the subject/body in `MODE_NOTICE`
   but has no audience state.
4. Its `send_compose()` calls `store.send_notice(...)` without `scope`, which
   is a global notice.

This is the original wrong-audience defect through a cross-version path. The
existing future-version refusal test documents the intended safety property:
an older console must refuse a format whose semantics it cannot preserve.

Required repair:

- advance the writer to a new draft document version;
- let the new reader explicitly load/migrate historical version-1 drafts,
  mapping their notice kind to explicit global `*` because 1.0 could only
  author global notices;
- require a nonempty audience for every notice in the new format rather than
  treating it as optional there; and
- add a compatibility regression proving the frozen 1.0 artifact refuses the
  new document version. Do not modify the frozen artifact.

If the migration also accepts experimental version-1 files already carrying
`notice_scope`, it must preserve and validate that value; it must never erase
it to global. The candidate was not deployed, so this is resilience rather
than production migration authority.
