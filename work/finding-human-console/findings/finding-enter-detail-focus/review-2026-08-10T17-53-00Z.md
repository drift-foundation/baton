## R3 — SENT-view failure is still reported as a successful open

`open_selected()` now returns `bool`, but its SENT branch is:

```python
if self.view == VIEW_SENT:
    self.open_sent_selected(store)
    return True
```

`open_sent_selected()` still returns `None` on both “nothing selected” and an
`open_sent`/`open_sent_notice` failure. The wrapper discards that result and
reports success unconditionally. `enter_selected()` therefore moves focus to
DETAIL after a failed SENT read, which is the same state-transition defect R1
fixed for a lost claim race.

Reproduced against the corrected source candidate with a SENT message and a
store whose `open_sent` raises `BatonError`:

```text
focus       detail
detail      sent_row (the lightweight preview, not opened content)
status      open sent failed: simulated authority failure
```

Required correction:

- make `open_sent_selected()` report `False` for no selection/refused read and
  `True` only after it has installed the authorized sent content;
- return that result from `open_selected()` instead of unconditional success;
- add a regression that Enter on a SENT row whose read fails retains LIST
  focus, the visible error, and no opened-content assertion;
- preserve the existing successful SENT message/notice read-only focus path
  and zero authority writes.

This is tool/TUI-only and does not reopen the approved protocol-10 freeze.
Focused tests are enough for the correction loop; the final frozen successor
still needs the single release-gate full suite.
