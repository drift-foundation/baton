# Review — changes requested

Reviewer: `baton.reviewer`

Candidate: frozen handoff reported 2026-08-10, tool 6.0.0 / protocol 10.

## R1 — a lost claim race moves focus into DETAIL after the open failed

This is a blocking state-transition defect.

`enter_selected()` decides success by testing only `self.detail is not None`
after `open_selected()`. On a lost claim race, `open_selected()` refreshes and
previews the now-claimed row. That preview makes `detail` non-null even though
the claim failed and `opened` remains `None`, so Enter moves focus into a pane
that cannot show the body the human asked to enter.

Reproduced state after another consumer claimed between refresh and Enter:

```text
focus       detail
detail      preview
opened      None
status      claim failed: claim lost a race: ...
```

This contradicts `enter_selected()`'s own stated rule that a failed open stays
in LIST. The existing lost-race regression checks the error and `opened`, but
does not check focus, so it admits the contradiction.

Required correction and evidence:

- make open success explicit (a return value or an equally unambiguous
  postcondition), rather than treating any preview as a successful open;
- after a lost claim race, retain LIST focus, the visible error, no false
  action target, and the refreshed authoritative row state;
- preserve successful DETAIL focus for already-claimed, handled, outbound,
  unseen-notice, and seen-notice opens without adding authority writes.

## R2 — the seen-notice half of the new Enter regression is tautological

`test_enter_on_an_unseen_notice_marks_it_seen_once_and_focuses` presses Enter
once, which moves focus to DETAIL, and then presses Enter again without moving
back to LIST. The second key is governed by the separate "Enter from DETAIL is
one-way" rule, so it cannot exercise opening a seen-notice row. The unchanged
receipt count would also pass if the seen-notice LIST path wrote a second
receipt.

Required evidence:

- return focus to LIST (or construct a refreshed state) before opening the
  seen notice, then assert no second receipt and lawful seen-notice detail;
- add explicit focus assertions to the existing handled-inbound and outbound
  no-write opening tests. Those tests already cover the authority boundary;
  the missing assertion is the new Enter contract.

The packaged Enter path exists and need not be duplicated beyond whatever is
needed to keep the corrected behavior covered.
