The main transition is correctly shared: both driver entry paths call
`arm_send_after_import()`, which delegates attachment/root preflight and the
confirmation transition to the existing `arm_send()`. Successful ordinary
reply, compose, and notice imports enter `MODE_CONFIRM_SEND`; editor exit
publishes nothing; decline restores the draft; and one later affirmative key
publishes exactly once. The focused implementation cases and packaged PTY case
are green.

Two body-boundary defects nevertheless violate the finding's explicit
successful-**non-empty** and empty-refusal rules.

## R1 — whitespace-only protocol content is incorrectly refused

Severity: **blocking semantic mismatch**.

`arm_send_after_import()` tests the imported body with `.strip()`:

```python
if not (body or "").strip():
	return False
```

That disagrees with the existing, documented send boundary in
`send_compose()`: emptiness is exact, and a whitespace-only body is non-empty
protocol content because indentation and blank lines are meaningful Markdown
bytes. `send_reply()` likewise uses exact truthiness. The new helper therefore
leaves a successful body such as `"   "` in the draft without entering the
ruled confirmation, even though the same body is lawful when sent through the
ordinary path.

Required correction: use exact zero-length emptiness for the imported body and
add reply, compose, and notice regressions showing whitespace-only editor
content enters confirmation and publishes the exact bytes only after an
affirmative key.

## R2 — an emptied compose/notice body can later send a different message

Severity: **blocking wrong-message path**.

`edit_body_externally()` first replaces `compose["body"]` with the empty
result and reports a successful import. `arm_send_after_import()` then returns
`False` silently. A subject-bearing compose or notice remains in its ordinary
mode with no marker equivalent to `reply_body_requested`. The next ordinary
Enter can consequently arm and publish the subject-only shorthand. The human
chose the full-body editor, deleted that body, and can be sent a different
message without ever seeing the required empty-body refusal.

Direct model reproduction against the reviewed tree:

```text
before empty edit: body "a real body", confirmation armed
after empty edit:  mode compose, status "draft imported", body ""
later Enter + y:   one subject-only message published
```

The new `test_emptying_the_body_in_the_editor_never_arms` asserts only the
intermediate empty buffer and zero writes. It therefore positively accepts the
state that makes the later wrong-message send possible.

The reply branch avoids the later fallback only because
`reply_body_requested` persists the full-body intent, but its first visible
status is still the false success `draft imported`; the empty warning appears
only after the human tries to send. That violates the ruled visible failure at
editor return.

Required correction:

1. Treat an exact empty result as an immediate editor refusal in reply,
   compose, notice, and browse-full-reply/follow-up paths. Show the empty-body
   warning as soon as the editor returns and never arm confirmation.
2. Preserve the prior body and every other draft/context field. In particular,
   emptying an existing compose or notice body must not replace it with `""`;
   this is the smallest way to keep a later ordinary send from falling through
   to subject-only shorthand without adding a new persisted draft-state bit.
   If a different design is used, it must retain the full-body intent across
   decline, retention/reopen, and later send.
3. Keep the existing fresh-editor distinction: cancellation/unchanged editor
   output may restore browse, while an explicit empty-body refusal must retain
   the protected draft behavior already pinned for full replies. A richer
   transition result is preferable to overloading one boolean if the driver
   needs to distinguish those outcomes.
4. Extend the emptied-body regression through a subsequent ordinary
   Enter/affirmative key and prove no subject-only message or notice is
   published. Cover existing-body compose, notice, full reply, and fresh
   browse reply/follow-up, including visible warning and unchanged buffers.

## R3 — source documentation still states the superseded transition

Severity: **blocking contradictory local contract**.

`edit_body_externally()` still says that “The ordinary Enter and `Send now?
[Y/n]` still stand.” The finding explicitly superseded that extra Enter. This
stale statement sits directly on the implementation boundary and will invite
the old behavior back.

Required correction: update the docstring to say that a successful non-empty
import immediately arms the existing confirmation, while editor exit itself
never publishes.
