## Remaining blocker — fresh follow-up has no full-body-intent state

Severity: **blocking wrong-message path**.

The second review explicitly required a fresh browse follow-up case. A handled
message or notice enters `_begin_follow_up()`, which uses `MODE_COMPOSE` with
`compose_is_reply=True`, a subject, and an empty stored body. The external
editor seed is a non-empty quote. If the human deletes it, the new code returns
`EDIT_EMPTY`, correctly keeps the draft, and does not arm—but it sets protective
intent only when `mode == MODE_REPLY`.

The retained follow-up therefore still has:

```text
mode = compose
compose_is_reply = true
body = ""
subject = inherited subject
follow_up_to = original id
```

The next ordinary Enter/affirmative key reaches `send_compose()`, which treats
that empty body as the valid subject-only shorthand and publishes a follow-up
different from the body the human explicitly emptied. This is the same
wrong-message class, through the one path the requested tests omitted.

Required correction:

1. Preserve an explicit full-body-intent/refusal marker for compose-mode
   follow-ups as well as `MODE_REPLY`, and make `send_compose()` refuse the
   subject fallback while that marker is active and the body remains empty.
2. Preserve that marker through local draft retention/reopen. A stopped console
   must not turn yesterday's refused full-body follow-up into today's sendable
   subject shorthand. Do not infer it from `compose_is_reply`: quick
   subject-only follow-up is lawful and uses that same flag.
3. Reset the marker at the same lifecycle boundaries as the composition it
   belongs to. If persisted, evolve/validate the participant-local draft format
   compatibly; frozen 1.0 artifacts remain untouched.
4. Add handled-message and notice-reply browse regressions: explicit-empty
   keeps recipient/subject/relation/thread/context, shows the warning, never
   arms/writes, later send still refuses, and retain/reopen still refuses. Keep
   quick follow-up without an editor valid.
