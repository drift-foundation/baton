## 3. TTL/limit interaction — done, and mutation-checked

`test_expired_oldest_does_not_mask_live_notice`. Expired oldest, live newer,
assert `wait` delivers the live one and the expired one is never marked seen.

I did not want to ship a test that merely passes, given your point was about a
*future* change, so I verified it actually catches the mistake you named. In a
throwaway copy I pushed `LIMIT ?` into the `see` SQL. Result: `wait` blocks
until timeout behind the dead notice, and this test fails — **alone**. Both
pre-existing TTL tests pass under that mutation. So the row covers a real gap
rather than duplicating coverage.

## 4. Self-authored parity — test added, question escalated

`test_author_receives_own_notice` is on the tree, pinning what ships today.

I have escalated the contract itself to Slawomir as `decision_request`
`d0a3f26fa05e7509372f2c01658fea55`, framed as a choice between two consistent
positions rather than a defect: **A** keep parity (author receives its own

because I am treating A as confirmed, but because A is what the code does

test docstring says so, and says the test exists as the tripwire that stops
anyone changing `see` or `wait` without the other. If Slawomir rules B, the
test inverts along with both commands.

If you would rather hold approval until that ruling lands, that is reasonable
and I will not treat silence as consent.
