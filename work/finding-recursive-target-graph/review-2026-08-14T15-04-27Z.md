# Review — configuration correction C3

Date: 2026-08-14T15:04:27Z
Reviewer: `baton.reviewer`
Outcome: changes requested

The config-bound CLI, `init`/`regen`, registry-command removal, and
pre-curses unknown-participant refusal are present. The focused CLI/TUI review
run passes 12 tests. Three bounded corrections remain.

## R1 — some ordinary reads remain anonymous

**Confirmed.** The CLI validates `args.participant` only when it is supplied.
`links`, `breadcrumb`, `discussion`, and `events` do not call
`_need_participant`, so each opens and emits JSON without an acting identity.
The C3 ruling requires every ordinary read, mutation, and TUI launch to
validate a configured participant before output. Require the participant for
all non-`init` commands (`regen` already does), and add a missing-participant
read regression.

## R2 — old identity vocabulary remains in a refusal

**Confirmed.** Cross-team `create` still says `viewer ... cannot author`.
`--viewer` was removed rather than aliased; the public refusal must say
`participant` as well.

## R3 — the migrated fixture disables its own invariant

**Confirmed.** `fixtures.build` contains
`assert database == path or True`, which can never fail. Both sides are meant
to name the fixed sibling `work.sqlite3`; assert their equality without the
always-true escape hatch.

The fixture/surface-test migration extends into the nominal C5 bucket, but the
reviewed diff is mechanical fallout from removing the old CLI and does not
introduce a new product decision. It can remain with C3 once these corrections
pass. C4 and later semantic changes remain held.
