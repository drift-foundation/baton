# Review — v11 implementation-plan draft

Reviewed `IMPLEMENTATION-PLAN.md` after K revalidated the complete finding.
This is a planning review only; no implementation is authorized.

## Outcome

**Awaiting rulings / changes requested.** The vertical-slice structure,
authority/projection boundary, serial S1–S9 ordering, same-fixture TUI/JSON
parity, and end-to-end scenario are a sound implementation direction. Schema
freeze remains blocked on the two gaps K identified and the two clarifications
below.

## R1 — application version must match protocol generation

**Confirmed conflict.** Historical “Baton 2.0.0” prose conflicts with the
deployed major-equals-generation rule. Recommend application version `11.0.0`
for protocol 11 and retain “2.0” only as superseded historical wording, not a
second product version.

## R2 — compact identities need canonical handles plus display names

**Confirmed conflict.** A fresh v11 authority means protocol-10 participant
identities do not need rewriting. Recommend canonical team, member, and
endpoint-kind handles validated at registration by terminal display-cell width
(wcwidth semantics), with arbitrary descriptive display names. The 6-cell
canonical limit must never be implemented as render-time truncation.

## R3 — pure projections need an explicit seen-cursor transition

**Required correction.** The draft correctly requires `projection.py` to be
write-free and also requires per-member `New` cursors, but S1–S9 never define
the operation that advances a cursor. A plain list/show/projection read remains
pure. Add an explicit idempotent `mark_seen` or `open_discussion` transition
that advances only the acting member's cursor after an intentional open, and
return its committed state through JSON/TUI. The shared fixture and end-to-end
scenario must prove `New` decreases for that member only and that list/search/
count operations never advance it.

## R4 — explicitly retire at-most-once delivery

**Required ruling.** The no-notice, re-readable-discussion model structurally
omits protocol-10 delivery receipts, but the loss of at-most-once delivery is
not yet named in the current ruling. Pin that v11 messages are re-readable,
that personal `New` is attention tracked by a seen cursor rather than a
delivery receipt, and that no message read consumes or hides content. If that
is not the intended product rule, the schema and search design must change
before S1.

## Nonblocking notes

- Deferring unresolved single-destination `@` withdrawal is schema-safe because
  the obligation already has explicit state and cardinality bounds the damage.
- Exact package/executable names (`baton_work`, `baton-work`) are provisional;
  deployment products still need to conform to the approved v11 layout before
  packaging, but this does not block the authority slice.
- Clean start with the retained v10 authority is consistent with the ruled
  restart and avoids an identity/history migration in this slice.

After Slawomir rules R1, R2, and R4, K should revise the draft for those rulings
and R3, then return it for one focused acceptance review. No source, schema,
test, `PROGRESS.md`, or deployment change begins before explicit authorization.
