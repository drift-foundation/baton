## R49 — accepted-provider state must be public structured JSON

`WS3-DESIGN.md` D3 specifies an `edge` member in the canonical mutation result,
and D7 requires a projection that exposes `accepted -> provider`. The current
result omits `edge`. The only projection named `obligations` deliberately
returns pending actionable rows, so the accepted row disappears; the focused
tests then prove `status='accepted'` and `accepted_into` by reading SQLite
directly. Agents outside this repository cannot do that, and mining an audit
payload is not the declared semantic projection.

Return the ruled structured edge from `accept`, and expose the terminal
obligation association through a canonical public read surface. The exact read
shape is K's implementation choice, but it must let an agent determine
`obligation N is accepted into Work W` without SQL, prose parsing, or inference
from an edge alone. Pin source and packaged CLI/JSON parity.

## R50 — the two CLI forms must reject each other's options

`accept --into W --parent X` currently succeeds and silently ignores
`--parent`; the same applies to `--kind`, `--title`, `--classification`, and
`--phase` without `--create`. A typo can therefore commit a materially
different operation from the one displayed on the command line.

Make the forms fail closed: `--into` accepts no create-only option;
`--create` requires its required creation fields; exactly one of `--into` and
`--create` remains mandatory. Refusal must occur before any event or state
change. Cover every incompatible option, not only the reviewer exemplar.

## R51 — explicit empty enum input is not omission

Normal `create_work` defaults classification/phase only when the value is
`None`. `accept --create` uses `value or default`, so explicit empty strings
silently become `unknown` and `queued`. The authority must not normalize an
invalid supplied value into an omitted value. Use the same `None`-only default
semantics as ordinary creation and keep both surfaces behaviorally identical.

## R52 — bind the new structural relations

Every existing structural Work relation is schema-bound with foreign keys.
The new `edges.via_obligation` and `obligations.accepted_into` columns are bare
integers/text. They can therefore name nonexistent records while SQLite still
reports referential integrity as healthy. Bind them to `obligations(seq)` and
`work(id)` respectively, or provide an equivalently strong authority/doctor
invariant with adversarial evidence. Also pin that ordinary edges keep NULL
and non-accepted obligations do not acquire an accepted provider.
