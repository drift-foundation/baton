The proposed foundation is sound: discussion identity is independent of Work;
one message belongs to one discussion; `#WORK` is a foreign-key-bound inert
many-to-many relation; obligations remain scoped to exactly one Work; seen
cursors move to discussions; WS-3 retains its explicit provenance edge; and a
fresh schema is honest because no v11 authority has been deployed.

Implementation remains held. Several proposed dispositions need correction or
more exact contracts before source work can begin.

## R54 — a Work has a discussion set, not one substituted timeline

The design replaces `messages.work` but still says the bounded TUI can render
“the now discussion-backed message list.” One Work may have many discussions,
and one discussion may label many Works; there is no single list to substitute.

Canonical JSON needs both directions: discussion detail lists labels, and Work
detail lists related discussion summaries with stable ids, last-message
sequence, New for the viewer, and deterministic pagination/order. Opening a
Work must not merge several conversations into a plausible but false single
thread. Work creation returns the id of its atomically born discussion, but
that discussion is not a permanent primary/home relation.

## R55 — bare operator scope counts eligible Work, not all labels

The confirmed ruling permits a bare endpoint tag when exactly one eligible
local `#WORK` exists. D2 instead tests total label cardinality. A discussion
labelled to one Push Work and three foreign provider Works still has exactly
one Work the Push handler may operate on; foreign context must not create
ceremony or become selectable authority.

Resolve and record the eligible set under the operation's existing Work gate.
Omission of `--on` is allowed only when that set has cardinality one; zero or
many refuses. An explicit `--on` must name one currently labelled Work and pass
the same operation-specific authority. One act still affects exactly one Work.

## R56 — obligation lifecycle does not replace participation lifecycle

An `@` obligation explains accountability, but not the lasting fact that the
receiving team can find and follow the discussion after the obligation is
responded, disposed, accepted, or withdrawn. Likewise `=>` must make the new
Current team able to find the discussion. D8 is therefore only half closed.

Recommended smallest model: discussion-team participation is monotonic in
WS-4. A team's own `#WORK`, `+`, incoming `@`, or incoming `=>` adds that team
once; no operator removes it in this slice. The obligation state remains the
entire responsibility lifecycle, while participation is attention/discovery,
not authority or an ACL. Record exact endpoint expansion in the event even
when several endpoints deduplicate to one participating team. Expose a
follower/participating-discussion JSON surface with personal New. Do not call
only `+` rows “followers” while silently omitting `@` and `=>` participation.

## R57 — deduplicated New needs an exact decomposable projection

Distinct-message counting gives the correct total but does not preserve the
current navigational promise `own + children = total`: a discussion labelled
to two children makes each child count truthful while their raw sum exceeds
the parent's distinct total.

Return at least `own`, per-child counts, `overlap`, and `total`, with the exact
identity `total = own + sum(children.new) - overlap`. `overlap` is the raw-sum
excess over the distinct union, not pairwise inclusion/exclusion data. This
keeps “jump to the unread child” honest while making ancestor dedup visible.
Follower-surface New is separate from Work-table New but uses the same
per-discussion member cursor.

## R58 — recommend live context, not postable orphans

D3/D4 would allow unlabelled discussions that remain postable and are
discoverable only through followers or audit. That weakens the confirmed
follow-up rule and makes contextless evidence normal: after all labelled Work
is closed, later evidence can accumulate without creating the new Work that
must carry a new decision.

Recommended correction:

- discussion creation requires at least one authorized `#WORK` label;
- removing the final label refuses;
- terminal Work may remain labelled and may gain/lose a label when at least
  one label remains; and
- plain posting requires at least one labelled open Work. If all context is
  terminal, first create/label open follow-up Work, then continue. A discussion
  spanning closed and open Work remains postable; carrying operators still
  require an eligible open target.

This preserves reusable cross-phase conversation without reopening or quietly
extending closed-only work. Slawomir should explicitly choose this boundary or
K's always-postable orphan model.

## R59 — WS-3 reconciliation needs collision and general-response rules

Approve acceptance adding the provider label, but define the legal prelabel
case. Because D1 lets provider-team members label independently, `accept` may
find `#PROVIDER` already present. It should succeed, guarantee the label exists
after commit, and audit `provider_label: added|existing`; duplicate-label
refusal remains the ordinary manual-label rule. Add both-order provider-label
add/remove races. Removing the consumer label never cancels its Work-scoped
obligation; acceptance still answers into the immutable originating discussion
and creates the explicit edge.

The new `obligations.discussion` address applies to every response obligation,
not only `accept`: ordinary `respond` also writes its answer to the originating
discussion, and terminal/public obligation JSON names that discussion.

## R60 — slice boundaries must not certify a temporary false public API

The two-gate split is appropriate, but Slice A's “operators keep their current
call shape against the Work's born discussion” is a temporary compatibility
rule that becomes ambiguous as soon as more discussions are labelled. It may
exist as an explicitly internal bridge to keep intermediate tests executable;
it must not be documented, packaged, or accepted as the new public discussion
API. Slice A must expose and test explicit discussion create/list/detail,
label/unlabel, plain post, and seen/New semantics. Slice B replaces the public
operator surface and removes the bridge before WS-4 acceptance.
