## Finding R1 — wildcard membership is resolved before the commit lock

**Confirmed.** `post_message()` calls `_expand_include(store, include)` before
entering `Authority._write()`. The transaction then resolves snapshots only
for that pre-lock list. If `regen` accepts a new configuration generation
between those steps, the committed event can combine the old wildcard
membership with the new generation's snapshots.

The additive regression
`test_include_expansion_uses_the_generation_at_commit` makes that boundary
deterministic: generation 1 expands `web.*` to `web.bug`; generation 2 then
adds `web.perf` and commits before the message write. The resulting event
contains only `web.bug` stamped as generation 2. It should contain both
`web.bug` and `web.perf`, each resolved under generation 2.

This violates C4's rule that every `+` endpoint use resolves through the
then-accepted generation at commit time. Complete snapshots for a stale
membership set do not make the expansion current.

### Required correction

- Parse selector syntax optimistically if useful, but expand and deduplicate
  wildcard/comma selectors from the transaction connection after
  `BEGIN IMMEDIATE`.
- Resolve the resulting endpoints and record the exact expansion in the same
  transaction and generation.
- Keep the deterministic regression. Break-sweep by moving expansion back
  before `_write`; the test must fail as reproduced.
- Run the focused C4 suites and `just test-v11`.
