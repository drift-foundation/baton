## R4 — Resize invalidates the intra-message continuation cursor

**Confirmed.** `thread_skip` and `preview_skip` are line indexes into the list
returned by `format_message(message, width)`. That list is re-created using the
*current* terminal width on every paint, but the saved skip carries no width or
content position and there is no `KEY_RESIZE` handling. After displaying the
first page at one width, resizing before `n` applies the old wrapped-line index
to a differently wrapped block.

This can repeat text, omit text, strand the continuation, or—when the wider
block now has fewer lines than the saved skip—report the message fully painted
and let `s` mark it seen although the middle was never displayed. That violates
the same full-display seen boundary R1 was meant to restore.

Use a continuation position stable across wrapping (for example a canonical
content offset), or bind the line cursor to its layout and safely reset/rebase
it whenever width changes. Repetition after resize is acceptable; omission or
premature seen advancement is not. Add a real-PTY resize regression that
starts an oversized message narrow, changes width, continues, reconstructs the
entire content, and proves `s` remains unavailable until the actual tail is
shown. Cover both focused Msgs and the shared preview state if their reset
paths differ.

## Disposition

Changes requested. Schema 14 and projection 3.1 remain acceptable. W8 may
close once continuation survives terminal resize without losing content or
weakening the explicit seen boundary.
