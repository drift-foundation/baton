# W8 review — changes requested

Reviewed W8 against `FINDING.md`, `PLAN.md`, the repository diff, and v11
authority snapshot 44. The shared formatter, canonical per-message personal
`new` fact, and whole-block seen bound are directionally correct. Three
viewport boundaries remain.

## R1 — A message taller than the viewport is permanently unreachable

**Confirmed.** `paint_messages()` refuses to paint a block unless the entire
block fits (`src/baton_work/tui/app.py:149-166`). If the first message after
the current cursor is itself taller than the available budget, nothing is
painted and the returned cursor is `None`. Both Msgs handlers allow `n` only
when that returned cursor is non-null. The operator is therefore stuck before
the oversized message forever: its body is neither readable nor pageable.

The existing clipped-block test covers a long *second* message and proves it
is not falsely marked seen, but does not press `n` and prove that message can
then be read. Add intra-message continuation (or another explicit bounded
navigation model) so every message is readable while `s` advances past it
only after the full block has actually been displayed. Add a real-PTY
regression with one first message taller than the viewport and navigate
through its entire body.

## R2 — The split preview's seen bound includes the global status row

**Confirmed.** Split rendering gives `paint_messages()` a budget that extends
through terminal row `height - 1` (`app.py:292-296`, `app.py:470`). The command
bar or status is then painted over that same row (`app.py:303-306`). A message
whose last line occupied the bottom row is recorded as fully painted even
though the final composited screen replaced that line. After a command leaves
status text there, pressing `s` can therefore advance through content the
human did not see in full.

Reserve the global command/status row from the preview budget (or otherwise
derive the seen bound from the final visible composition). Add a PTY
regression that paints a boundary-sized block, overlays status, then verifies
`s` cannot count the overwritten line as viewed.

## R3 — Long references are clipped, not readable

**Confirmed.** Bodies are wrapped, but each reference is emitted as one
unwrapped line (`app.py:144-145`) and curses truncates it to the pane width.
The pinned requirement says references are readable; a long configured
root/path currently loses its tail, including the part most likely needed to
locate the asset.

Wrap or continue reference lines without changing their canonical value, and
cover a reference longer than a narrow pane.

## Disposition

Changes requested. SQLite schema 14 remains intact and projection 3.1 is an
appropriate additive client projection revision, but W8 must keep every
message/reference navigable and preserve the final-screen seen boundary before
it can close.
