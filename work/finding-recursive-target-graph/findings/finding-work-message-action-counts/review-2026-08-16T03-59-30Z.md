## R1 — `My` silently excludes verification `@` obligations

**Confirmed defect.** `_my_pending()` restricts its query to
`flavor='response'`. Protocol 11 also creates pending
`flavor='verification'` obligations for candidate-round assignments. The round
contract explicitly describes each assignment as an `@` verification
obligation, actionable by the selected route handler until it is reported or
withdrawn.

The finding rules `My` as every unresolved directed `@` obligation in scope
for which this participant is an eligible handler. It does not rule that only
ordinary reply obligations count. Excluding verification assignments makes a
participant with assigned testing work appear to owe nothing, defeating the
column's purpose of showing whether the viewer is the blocker.

Count every pending directed obligation flavor that the current participant
can actually discharge. Preserve each flavor's own completion transition:
`respond` for response obligations, `report` for verification obligations,
and withdrawal where applicable. Add a regression that creates a candidate
round, observes `My` for the assigned handler and a non-handler, then reports
or withdraws the assignment and observes the count clear.
