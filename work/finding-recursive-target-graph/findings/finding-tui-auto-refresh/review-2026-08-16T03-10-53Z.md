# W5 review — changes requested

Reviewed W5 against `FINDING.md`, `PLAN.md`, v11 authority snapshot 51, the
implementation diff, and the focused tests. The projection cache, read-only
tick, and Work-id selection anchor are aligned. Three timer/invalidation
boundaries remain.

## R1 — Continuous input postpones refresh indefinitely

**Confirmed.** `run()` calls `screen.timeout(refresh_ms)` once and refreshes
only when `getch()` returns `-1` (`src/baton_work/tui/app.py:1047-1067`). This
is an inactivity timeout: every key arriving before the timeout satisfies
`getch()`, the next call starts another full wait, and `tick()` never runs.
Continuous navigation or typing can therefore keep the TUI stale forever.

The pinned contract is a seconds-based timer, not an idle timer. Track a
monotonic refresh deadline independently of input; keys before the deadline
must use the cache, while reaching the deadline must refresh even if input
keeps arriving. Add a PTY regression that sends keys more frequently than the
configured interval for longer than one interval and proves externally
created Work appears on schedule without any key itself acting as a poll.

## R2 — Every command-bar attempt invalidates the cache

**Confirmed.** `Console.execute()` unconditionally clears `_cache` after the
CLI returns (`app.py:825-827`). A refused command, a parse-valid pure read, or
another successful non-mutating command therefore makes the following repaint
query the authority. The ruling permits refresh after an explicit *workflow
mutation* commits; it does not make every command a hidden refresh trigger.

Invalidate only after a successful mutating act (including the existing
direct `s` mutation). Add counted-read coverage for a refused command and a
successful pure read remaining cached, plus a successful mutation refreshing
its committed result.

## R3 — Positive infinity passes validation and fails after curses starts

**Confirmed.** `--refresh` uses `float`, and validation checks only
`args.refresh > 0` (`src/baton_work/cli.py:292-297,393-397`). `inf` satisfies
that check; `int(refresh * 1000)` then raises while initializing the loop after
curses has claimed the terminal. Other unrepresentable timer values need the
same refuse-first treatment.

Validate a finite, usable interval before `curses.wrapper`, with a clear JSON
refusal. Add non-finite and boundary coverage.

## Disposition

Changes requested. SQLite schema remains 14 and no migration is implicated.
W5 may close once refresh is wall-clock driven, cache invalidation is limited
to successful mutations, and invalid timer values refuse before curses.
