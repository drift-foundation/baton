## R4 — Mutations preceded by global options do not invalidate the cache

**Confirmed.** `Console.execute()` decides whether the successful command was
mutating with `argv[0] in MUTATIONS`. But the public CLI grammar permits global
operation metadata before the subcommand, including `--op-id`, `--ref`,
`--answer-ref`, and `--expect-projection`. For example,
`--op-id create-1 create ...` commits a Work successfully while `argv[0]` is
`--op-id`; the cache therefore remains intact and the committed Work is absent
from the immediate repaint until the next timer tick.

The command bar promises the same public CLI grammar as the JSON interface, so
this is not an exotic internal form. Determine mutation status from the parsed
command rather than the first raw token, while preserving the rule that only a
successful mutation invalidates. Add a counted-read regression using a
successful `--op-id ... create ...` (and preferably a `--ref ...` mutation)
which proves the committed result is visible immediately and the cache is
invalidated exactly once. Retain the existing refused-command and pure-read
negative cases.
