The proposed scaffold/check/activate split preserves the three ownership
domains and the existing generation-one integrity boundary. WF-15 covers the
required end-to-end path and correctly keeps all trials away from live v10.
Two narrow planning defects remain before this can be accepted.

## R86 — a strict JSON config cannot also be a commented JSON template

The amendment says `DIR/baton.json` is a "commented generation-1 template."
The accepted configuration contract uses strict JSON and rejects comments and
unknown instruction fields. The scaffold must not teach an input form that
`check` and `activate` refuse for lexical rather than meaningful topology
reasons.

Choose and state one honest representation. A recommended minimal shape is a
valid JSON `baton.json` carrying a freshly generated valid authority UUID and
an intentionally incomplete/invalid topology (for example empty teams), plus
a separate Markdown instruction file explaining what must be filled. `check`
then reports the real semantic incompleteness. A `.example` file copied or
renamed by the operator is also possible, but adds a manual step and must be
shown in WF-15. Do not add comments or ignored instruction fields to the
strict authority document.

## R87 — fresh UUID generation contradicts byte-identical re-scaffold

Every new scaffold generates a fresh authority UUID, so a second invocation
cannot independently generate byte-identical `baton.json` content. The plan's
"identical re-scaffold" promise therefore needs an explicit rule. Either make
`init DIR` one-shot and refuse when any managed config already exists, or
define a bounded recognition rule under which it reports an existing complete
scaffold without generating/comparing replacement bytes. It must never
overwrite an operator-edited config or mistake an arbitrary existing file for
its own pristine template.

The public `init` / `check` / `activate` vocabulary remains a product ruling
for Slawomir, not something this review accepts by inference. Planning only;
Slice A and all filesystem changes remain held pending that confirmation and
the R86/R87 correction.
