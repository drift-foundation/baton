## R89 — configuration acts implement a weaker, independent-only reference type

`lifecycle._parse_config_refs` treats every left-hand token as a root id. A
generation-one activation naturally cannot cite Work because none exists yet,
but `regen` runs against an existing authority and the mutation-wide ruling
does not make it an independent-only island. It must accept a dossier-relative
reference to existing bound Work, pinning the effective binding revision in
the committing transaction under the same retirement rule as every other act.
Because that lookup can disclose authority state, preserve the WS-5 identity
information boundary when adding its optimistic/in-lock validation.

The configuration parser also accepts `drift:proof\\config-change.md`, while
ordinary mutation parsing correctly refuses the backslash as not normalized
POSIX syntax. One typed reference vocabulary must have one normalizer and one
fingerprint representation; configuration acts cannot accept paths that the
other nineteen mutation families reject.

- `test_regen_may_cite_an_existing_bound_dossier`
- `test_config_references_share_the_normalized_posix_path_grammar`
