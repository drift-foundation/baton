## R92 — resolve accepts non-canonical and unconfigured locators

`cli._dispatch` joins the raw text after `:` directly onto the resolved base.
It does not apply the shared normalized POSIX containment grammar. Both
`pushcoin:../outside` and `WORK-ID:../outside` therefore succeed and print an
absolute path outside the addressed portable root/dossier.

The machine-local resolver also acts as a second root catalog:
`ghost:docs/note.md` succeeds whenever `roots.json` maps `ghost`, even though
the accepted authority has no live `ghost` root. The accepted design says the
resolver maps accepted root ids; it does not authorize new logical roots.

Correct `resolve` through a pure shared locator parser: require the ordinary
contained relative-path grammar for root and dossier suffix forms and require
an independent root to be live in the accepted authority. Keep the resolver
explicit and read-only. The dossier form continues to obtain its root/path
from the canonical binding projection and appends only a validated relative
suffix.

## R93 — bootstrap follows a parent symlink inserted after validation

The approved phase-two rule requires creation through an `O_NOFOLLOW` dir-fd
chain. The implementation instead calls path-based `os.mkdir`/`os.open` after
phase-one realpath checks. If absent `project/tmpl` becomes a symlink between
the phases, `mkdir` raises `FileExistsError`, which is treated as identical
intent without revalidation; the subsequent file open follows that symlink
and writes the template outside the project root.

Use the ruled component-by-component directory-fd creation/open boundary (or
an equally strong no-follow primitive) in phase two. `EEXIST` must revalidate
the actual entry under that same no-follow chain rather than mean success by
itself. Preserve the exact partial-created set on refusal.

## R94 — phase-two failures escape without the required partial report

Both filesystem writers lose the operator's cleanup evidence on ordinary
write failures:

- bootstrap propagates a raw `PermissionError` after creating `tmpl/`, rather
  than a structured `WorkError` naming `tmpl/` as created;
- init propagates a raw `OSError` when the second file's write fails, and does
  not report the already-created partial `BATON-SETUP.md` target alongside
  `roots.json`.

The one-shot-init ruling and bootstrap plan require every phase-two failure to
stop, remain non-destructive, and report every target this invocation created
(including a file created by `O_EXCL` whose content write then failed). Catch
and translate filesystem failures at the operation boundary; do not clean up
automatically.
