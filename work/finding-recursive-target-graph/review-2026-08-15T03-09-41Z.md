## R1 — verification assignments accept classic terminal verbs

The ruled verification-flavored exact `@` subtype completes only through
`report` or withdrawal. `respond_obligation` and `dispose_obligation` do not
check flavor, so both accept a pending verification assignment. That creates
`responded`/`disposed` assignment states outside the closed verification
vocabulary; `_round_view` then counts the non-actionable assignment as pending.

Failing regression:

`tests/work/test_ws2_rounds.py::test_verification_assignments_refuse_classic_terminal_verbs`

Refuse classic respond/dispose for verification flavor before writing, just as
`report` refuses classic response obligations. Preserve the pending assignment
and audit bytes on refusal.

## R2 — report audit omits candidate and evidence identity

The immutable `report` event names its assignment, round, and observation but
omits the exact candidate and evidence reference. Those values happen to be
recoverable by joining current implementation tables, but the pinned audit
contract requires the act itself to preserve exact candidate and evidence
identity.

Failing regression:

`tests/work/test_ws2_rounds.py::test_report_audit_pins_the_candidate_and_evidence`

Resolve the assignment's round/candidate in the committing transaction and
record candidate plus evidence in the report payload. Keep the stored raw
observation/evidence immutable.

## R3 — reassessment is ordered but not an explicit supersession

Assessment rows are append-only and projection selects the last sequence, but
a later assessment does not name the prior assessment it supersedes. The ruled
operation is an explicit superseding audit act, not an implicit “latest row
wins” convention.

Failing regression:

`tests/work/test_ws2_rounds.py::test_reassessment_explicitly_supersedes_the_prior_act`

In the transaction, find the effective prior assessment and put its sequence
in the new assessment event as `supersedes`; the first assessment has no prior
act. Preserve the full ordered projection history.

## R4 — canonical JSON does not declare the new round actions

`detail.available_transitions` remains at the pre-Group-2 vocabulary even
though `round` and `abandon` are now public CLI operations. A provider agent
must discover them by knowing or attempting CLI verbs, contrary to the shared
projection rule that clients read what they may do.

Failing regression:

`tests/work/test_ws2_rounds.py::test_detail_declares_the_round_actions_available_to_the_handler`

Declare `create_round` for the live Current handler of open Work, and
`abandon_round` when that handler has an open round. Non-handlers and closed
Work must not receive either declaration. Keep the decision in the same detail
snapshot as the round state.
