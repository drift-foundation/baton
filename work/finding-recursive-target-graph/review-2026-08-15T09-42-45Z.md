## R61 — a read-named mutation violates the explicit seen contract

`IMPLEMENTATION-PLAN.md` pins one unusually simple invariant: every read is
pure, and only an explicit audited `mark_seen` transition advances a cursor.
The new public `read DISCUSSION --up-to` command instead calls
`seen_discussion` and writes a `mark_seen` event. A verb named `read` therefore
has the exact side effect the ruling was designed to make impossible to infer.

Make the canonical public mutation `mark-seen DISCUSSION --up-to ...` (or an
equally explicit spelling containing `mark-seen`), and keep thread/detail/list
reads byte-pure. The Work-addressed `discussion WORK` and `mark-seen WORK`
bridge also remains advertised by the packaged CLI. R60 allowed a test-only
internal bridge, not a second public API whose meaning becomes false when Work
has several discussions. Remove it from the packaged parser or isolate it
behind a genuinely internal test adapter; existing packaged workflows must
not certify it as the v11 surface.

## R62 — seen accepts future cursors and loses the lower-mark race

`seen_discussion` accepts any non-negative integer, including a value greater
than the authority's current sequence. That cursor then hides future messages
until the global sequence eventually passes it. It also checks idempotence
before acquiring the write lock: if a concurrent higher mark commits after
that check, the stale lower call emits another event, returns `advanced: true`
and reports the lower cursor even though `MAX` preserved the higher committed
value.

The two additive regressions in `tests/work/test_ws4_review.py` reproduce both
failures. Bound `up_to` to an actually observed authority snapshot, revalidate
the current cursor and active member inside the committing transaction, and
return the committed cursor truthfully. A lower or equal losing mark is an
idempotent no-op, not another audit act.

## R63 — collection pagination and ordering are not yet deterministic contracts

R54 and the Slice A release require deterministic pagination/order for both
directions of the Work/discussion relation. `thread` pages messages, but
accepts negative/unbounded pagination values and exposes no explicit next-page
state. Work detail and `discussions_for` return unbounded discussion sets with
no cursor at all. `thread` orders labels and participants only by `added_seq`,
although several initial labels and several expanded participant teams may
share the same sequence; those projections have no total tie-break order.

Provide bounded positive limits, non-negative cursors, explicit continuation
state, and total ordering (`added_seq` plus stable identity at minimum).
Expose a paged Work-to-discussion set and paged participating-discussion set;
do not make an agent fetch an indefinitely growing Work detail to navigate.
Exercise same-event ties and multi-page joins through source and packaged
CLI/JSON without skips or repeats.

## R64 — the new `New` result can tear and silently dropped its identity

`new_count` now performs many queries across own labels, every child subtree,
and the final union without entering `_read_snapshot`. A concurrent post or
label change may therefore make child counts and the total describe different
states, while the JSON envelope samples a later sequence and presents it as
the consistency token. The public result also dropped the existing `id` field
without a ruling or projection-version transition.

Run the whole decomposition inside one reentrant read snapshot, return its
snapshot sequence to the envelope, and preserve the Work id. Add an
interleaved-writer coherence regression proving `own`, child counts,
`overlap`, `total`, and the token all name one state.

## R65 — configured-member authority and label audit evidence are stale-raceable

The new mutations call `_member` only before `_write`; that helper also accepts
historical `members` rows without checking `removed=0`. A config acceptance
that removes an otherwise non-stranding participant between precheck and lock
can therefore be followed by that removed member committing a discussion,
label, unlabel, post, or seen act. D1 authorizes configured members, not every
identity ever configured.

Revalidate active membership inside every new committing transaction and add
both-order config-generation races. In addition, `label` records
`work_status` from its pre-lock read but permits a concurrent close before the
label transaction; either derive that evidence in-lock or omit it. Audit must
describe the committing state, not an optimistic diagnostic.

## R66 — WS2-WF-04's phases are listed correctly but attached to the wrong work

The executable pin requires candidate A to be produced after
`research -> active`, then staged by `active -> review`, with the failed report
and assessment demonstrably leaving Work in review. The changed workflow
instead creates and evaluates candidate A while Work is still in research,
then moves to active only after the failure. It later manufactures the desired
phase list around candidate B, so the final list passes while the scenario it
was meant to prove never occurred.

Reorder the workflow exactly as pinned: research, active, candidate A, review,
failed feedback, active rework, candidate B, review, successful feedback,
explicit close. Assert event ordering between phase acts, round creation,
reports, and assessments—not only the phase subsequence—in both source and
packaged modes.
