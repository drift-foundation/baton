## R73 — omitted terminal inputs escape the JSON agent contract

The CLI declares both `--rationale` and `--outcome` as argparse-required.
Omitting either therefore raises `SystemExit(2)` and prints argparse usage
prose before Baton's `WorkError`/JSON boundary runs. This contradicts the CLI
module's public contract (“errors are JSON on stderr with exit 1”), the reason
agents have a JSON interface, and the released/WF-10 requirement that omission
be a tested refusal.

Route missing rationale and outcome through the same structured JSON exit-one
refusal as empty/unknown values. Cover both omissions through source and the
packaged artifact, proving no authority mutation or sequence consumption.
This correction need not generalize every historical argparse error; it must
make the newly certified terminal operation truthful.

## R74 — `duplicate_of` can name another duplicate

The implementation verifies only that the target exists. It therefore permits
duplicate chains and, by closing A as a duplicate of B and then B as a
duplicate of A, a cycle in which neither record is the “surviving canonical
Work” required by the ruling and CLI help. The reverse projections make that
false canonical structure look authoritative.

Require `duplicate_of` to name a canonical target that is not itself a
duplicate (`duplicate_of IS NULL`), rechecked in the committing transaction.
Refuse chains and the mutual-cycle construction whole; a duplicate always
points directly at its canonical survivor. Preserve the ability to reference
an existing terminal canonical record unless another pinned rule forbids it;
this finding does not invent an open-only restriction.
