## Blocking finding — Sent selection is restored through the wrong list

`InboxState._set_draft()` and `cancel_search()` treat `sent_cursor` as an
index into `_all_sent_rows`:

```python
selected_sent = (self._all_sent_rows[self.sent_cursor]
                 if self.sent_cursor < len(self._all_sent_rows) else None)
```

Once a filter is active, `sent_cursor` indexes `sent_rows`, the filtered view,
not `_all_sent_rows`. After the first typed character narrows the view, the
next character can therefore capture a different row and move the visible
selection even though the original row still matches.

Minimal source-level repro against the current tree:

```text
full Sent rows: a(non-match), b(match one), c(match two)
cursor before search: c at full index 2
after typing `m`:     c at filtered index 1
after typing `a`:     b at filtered index 0   # wrong-row jump
```

This was reproduced directly:

```text
before c 2
after m c 1
after ma b 0
```

`_refresh_sent()` has the complementary index-space error. It correctly
captures `previous` from filtered `sent_rows`, but after assigning the new full
set it enumerates the unfiltered local `sent` value and writes that full-list
index into `sent_cursor`. Under a filter this can leave `view_cursor` outside
the drawn filtered list; `selected_sent` clamps when read, but rendering and
scroll logic use the actual cursor, so the selected row can lose its visible
highlight.

This violates the confirmed row-identity rule, the required refresh boundary,
and the included Sent behavior. It is release-blocking because a subsequent
open/materialize/navigation command may appear to target a row different from
the one the incremental filter had preserved.

## Required correction

1. Capture the currently selected Sent row from the filtered view by identity,
   regardless of which view is active; do not index `_all_sent_rows` with a
   filtered cursor.
2. After Sent refresh, restore that identity by enumerating the newly filtered
   `self.sent_rows`, and always leave `sent_cursor` legal for that view.
3. Add regressions in the new search test file that:
   - keep a nonzero Sent selection on the same row across at least two
     narrowing keystrokes while an earlier full-list row is filtered out;
   - keep the selected/highlighted Sent row and a legal cursor across refresh
     under an accepted filter;
   - clear/cancel the filter without a wrong-row jump.
4. Re-run the focused tests and full TUI suite. No frozen artifact rebuild and
   no existing-test edit are needed.
