## Required corrections

1. **Enter does not use the exact path typed in the TUI.**
   `accept_save_path()` applies `.strip()` before calling the core. A valid
   canonical absolute filename ending in a space therefore writes a different
   filename without telling the human. The approved rule says Enter accepts
   the exact path. Pass `save_path_draft` unchanged; let the core reject an
   empty, relative, or noncanonical value. Add a real-key regression that
   distinguishes the typed path from its stripped sibling.

2. **Exactly two leading slashes are accepted as “canonical”.**
   On POSIX, `normpath("//tmp/x")` preserves the double slash, so both
   `save_whole_message()` and `_open_dir_no_follow()` accept it and publish at
   that spelling. A canonical Baton absolute path has one root slash. Refuse
   `//...` explicitly and add it to the path matrix. The review probe expected
   a `BatonError` but the file was written.

3. **The existing content representation is translated for an empty
   container.** `_whole_message_document()` turns the non-null
   `_content_repr()` result with zero top-level parts into `null`. The approved
   contract says `content` is `_content_repr()` “without translation”; only a
   genuinely contentless/subject-only owner has `content: null`. Remove the
   normalization. Do not invent an otherwise unreachable alternate storage
   meaning in the export.

4. **The notice-audience rationale is false.** Notice membership is expanded
   and frozen transactionally at publication in `notice_audience`; it is not
   derived at read time from whoever is currently configured. The approved v1
   export still carries `audience_kind`/`selector` and no expanded list, but
   the comment in `_whole_message_document()`, the notice test docstring, and
   `PROGRESS.md` must state the real authority behavior. This is a record fix,
   not a request to change the ruled envelope fields.

5. **The new direct model guard repeats the stale notice wording.** Dispatch
   reports the correct unseen-notice/Enter guidance, but a direct
   `begin_save_message()` refusal calls it an unopened message. Keep the
   defense-in-depth model guard, make its wording row-kind-correct, and assert
   both unreceived shapes through the direct guard as well as the real key.

6. **The README says the envelope has “no timestamp” even though immutable
   `created_ts` is required and present.** Say “no save timestamp”; preserve
   the distinction between immutable creation time and mutable process state.

7. **The seeded-name implementation and its durable claim disagree.**
   `str.isalnum()` accepts non-ASCII letters, so it does not enforce the stated
   `[A-Za-z0-9.-]` alphabet. More importantly, the approved default names the
   current constrained `<created>` and `<id>` values; a speculative future ID
   scheme was not a ruling. Follow the approved current-field spelling, or pin
   a different user decision before retaining a visible transformation. Do not
   leave source/progress/tests claiming an ASCII policy the code does not
   implement.

## Acceptance regressions still missing

The finding required these cases specifically; the broad existing content and
publication tests do not make them save-operation regressions:

- exact nested multipart structure plus mixed disposition and `part_name`;
- all external reference fields, including binding generation and size, not
  only root/path/digest;
- transient pending, claimed, answered, and scrubbed lifecycle shapes;
- complete `dump()` equality before/after saving, not selected table counts;
- a publication race at the chosen output path;
- TUI answered/closed inbound, authored-notice, and transient-message rows in
  addition to active claim, Sent, seen-notice, unopened, and unseen rows.

Add these as new tests. Existing tests remain governed by the repository's
case-specific-confirmation rule.
