# Implementation review 1 — active-view and persistence boundaries

Reviewer: `baton.reviewer`

Date: 2026-08-12T00:02:57Z

Implementer handoff: message `018fed83727d7c6e5b94084be07d5461`, claim
`ef0ae6a6744441eed6bc7c9bc3510bbb`

Outcome: **changes requested**

The implementation establishes the correct broad shape: a separate local
archive file, identity-keyed partition and selection, a third view with its own
cursor/top, real Space/Ctrl+A/U/x keys, Archived metadata search, one-cell
marks, local/device documentation, explicit eligibility, authority-dump
isolation, focused storage/model coverage, and a packaged PTY path. The review
does not accept it yet because several missing boundaries can hide or act on
the wrong work.

## R1 — Archived dispatch can claim/open a different hidden MESSAGES row

`selected_in_view` is view-generic, but `preview()`, `open_selected()`,
`selected`, refresh/filter cursor restoration, and related commit paths still
deliberately treat `self.selected` as the MESSAGES selection. The driver calls
`select_row()` after switching views. In the reproduced boundary, Archived had
one handled row while MESSAGES had one pending row; pressing `a` displayed the
handled Archived row but immediately claimed and opened the hidden pending
MESSAGES row, bypassing its dwell.

Audit the whole active-view path, not only the one call site: view entry,
navigation, preview/open/Enter, detail/action-target revalidation, refresh,
filter editing/accept/clear, materialize, whole-message save, and follow-up
must all address the identity actually displayed in Archived. Sent keeps its
special read-only open path; MESSAGES behavior and claim dwell stay unchanged.
Add regressions with a different pending MESSAGES row deliberately under its
cursor proving Archived entry/navigation/read/materialize/save/follow-up touch
only the displayed archived identity and create no claim or notice receipt.

## R2 — a valid local index can hide unresolved work

`rows`/`archived_rows` partition solely on index membership. A valid version-1
index containing a pending/claimed inbound message or unseen received notice
therefore removes that obligation from MESSAGES on startup even though the UI
would refuse creating the entry. Local state is not authoritative enough to
override the safety boundary.

Fail open for obligations: pending/claimed inbound messages and unseen received
notices must remain visible in MESSAGES even when their identity is present in
a structurally valid index. Do not rewrite the file from polling/refresh. Make
the stale/ineligible entry recoverable or explicitly prunable only through a
successful human archive/restore write, without letting it re-hide the row
when the lifecycle later changes. Add direct seeded-index restart tests for
pending, claimed, damaged pending, unseen notice, and eligible terminal/seen
controls. Keep obligation counts unfiltered in every view/header as the finding
requires.

## R3 — `Ctrl+A` and `U` cannot share Space's current-row affordance

The single `select` affordance asks whether the row under the cursor is
eligible, then gates Space, Ctrl+A, and U together. `Ctrl+A` must select every
visible eligible row even when the cursor is on an ineligible pending row, and
U must clear an existing set regardless of the current row. K's own official
set exposed the issue during review:

```text
74 passed, 2 failed
test_ctrl_a_selects_every_visible_eligible_row_and_no_others
test_bulk_archive_and_restore_on_a_candidate_console
```

The same tests can pass under a different same-second id order, so prior green
evidence was order-dependent. Give toggle, select-all, clear, and archive their
honest event-specific gates/reasons while preserving a shared source of truth
for display and dispatch. Add an explicit cursor-on-pending control with two
eligible rows and a clear-selection control after the cursor becomes
ineligible.

## R4 — Archived filtering strands its cursor

Search captures/restores only `selected`/`cursor`/`inbox_top` and Sent state.
In Archived, narrowing three rows to one leaves `archived_cursor == 2` while
the only row is at index 0; `selected_in_view` silently clamps reads, but the
renderer marks no cursor row. Generalize filter restoration to the active
view's identity/cursor/top, keep every cursor in range while typing and after
accept/clear, and use the active view's total in status text. Cover a selected
Archived row that remains, one that stops matching, clear, accept, and live
incremental typing.

## R5 — the archive file is not yet a no-follow/private bounded read

The pinned baseline requires no-follow regular-file reads and the draft
store's safety class. `_checked_target()` currently accepts a `0644` file;
review proved it loads successfully. It also `lstat`s one pathname and later
uses `getsize()` plus unbounded `open().read()` on that pathname, so a swap can
follow a symlink or grow past the checked size.

Open the exact file with no-follow semantics, then `fstat` that same descriptor
for regular type, exact private mode, and size; perform a bounded read that
detects growth. Apply the same exact-mode refusal on save. Add mode, swap/race,
and grow-after-check regressions. Do not rewrite arbitrary path text with
`str(error).replace("draft", "archive")`; a projection path containing that
word must be reported exactly.

## R6 — post-replace fsync failure violates all-or-nothing state

When file replacement succeeds and directory fsync then fails, `save()` raises
`ArchiveError`; the state model reports “nothing changed” and retains the old
in-memory map, but the target file already contains the new map. The review
probe observed exactly that. This violates the pinned requirement that a
failed write leave both prior file and visible memory intact and creates a
restart surprise.

Define and test an honest commit point. Meet the pinned prior-file/visible-state
contract if feasible. If a post-replace durability failure cannot truthfully be
rolled back, do not report it as an unchanged ordinary failure: return a
distinct committed/uncertain outcome that lets the model match the actual
target and state the durability problem, or return for an explicit ruling
before changing the confirmed contract. Include file-fsync, replace, and
directory-fsync failure tests at their exact boundaries.

## R7 — preserve stable human order and clean stale claims

The archive document claims to preserve human order, but a batch target comes
from `list(self.selection)` where selection is a set. Append new identities in
stable displayed/backing order so the same batch does not acquire hash-seed
order. Also update the stale `RESERVED_ROW_KEYS` comment that still says `x`
marks and `#` trashes and that neither is bound; it contradicts the shipped
Space/x contract.
