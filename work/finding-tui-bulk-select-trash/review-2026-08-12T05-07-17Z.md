Two independent boundary probes nevertheless failed:

1. A stale index identity released while its row was ineligible remains in
   `archive_released` after the human later explicitly archives that now-
   eligible row. The successful write contains the identity but `is_archived`
   continues to release it, so the row stays visible.
2. Archiving the currently opened handled row removes it from MESSAGES but
   leaves it in `opened`/detail as the action target while the cursor highlights

   therefore remain attached to a row no longer displayed in the active view.

Those defects confirm that the current bytes are not independently approved,
but they are not separate protocol-11 requirements. The future SQLite design
must revalidate the underlying stale-state and invisible-action-target safety
boundaries against its own transaction and view model.
