## R1 — root policy points to a file the move removed

Root `AGENTS.md` still says to read `AGENTS-MAILBOX-PROTO.md`. The only copy is
now `docs/AGENTS-MAILBOX-PROTO.md`. A fresh agent following mandatory policy
therefore fails before it can coordinate.

Update the policy path and add a regression that resolves the required path
from the repository root. This is an onboarding blocker.

## R2 — alternate distribution roots contain a dangling manifest path

`tools/build_zipapp.py` writes `dist/DISTRIBUTION.json` with
`"protocol_doc": "docs/AGENTS-MAILBOX-PROTO.md"`, but deliberately does not
write that path under the caller-supplied output root. A direct scratch-root
reproduction produced both the artifact and manifest while
`OUT/docs/AGENTS-MAILBOX-PROTO.md` was absent.

The green `test_distribution_root_contract` hides the defect by resolving the
built manifest's protocol path against the source repository instead of the
distribution root. The old builder and test explicitly shipped the document
and resolved every manifest path from the supplied root. The layout finding
does not authorize changing that behavior.

Retain `docs/AGENTS-MAILBOX-PROTO.md` as the manifest path, but copy the
canonical bytes to that path when building into another root. For the default
repository-root build, source and target are the same file, so no duplicate is
created. Restore the regression to resolve the built document from `OUT`, and
update the builder docstring/comments and README to describe the preserved
contract.

## R3 — current documentation overstates root `.gitignore`

The README and new root-boundary test say root `.gitignore` is "the only place
git looks". Git also reads directory-local `.gitignore` files,
`.git/info/exclude`, and configured global excludes; K's own decision record
lists those alternatives. State the actual reason for the root exception: it
is the tracked, zero-configuration repository-wide ignore policy.
